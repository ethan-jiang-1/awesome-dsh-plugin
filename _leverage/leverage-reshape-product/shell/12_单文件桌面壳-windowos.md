## 它想干什么 · 为什么值得借鉴

**意图。** 把“给 Windows 上的 DSH 配一个窗口”压到**一个约 4.8 MiB 的裸 exe**：不打包运行时，只接管窗口与生命周期。它交付的是“壳 + 插件半区”两件东西（npm `1.5.12` 与应用 `v1.6.63` 两条独立版本线），并写死一条：**不会静默下载任何东西**——找不到 dsh 就把五个出口摆给用户。代价也不藏：目标机必须已有 Node（^22.19 或 ≥24）。

**意义。** 三条宿主路线里它最轻，正好补上另两条的空缺：官方桌面应用自带运行时，`tauriapp` 把运行时打进安装包，而它只解决“运行时从哪来”的**可发现性**。它改了两条惯例：启动不是“拉一次”，而是一条**五跳候选链**，每跳有独立就绪窗口（已安装 120 秒、npx 300 秒）与失败记录；进程有**所有权**，3080 已有人在跑就附加、退出时不动别人的树，只 `taskkill /T` 自己拉起的。发布通道并没有代码闸门：稳定通道就是 GitHub `releases/latest`，预发布排除由 GitHub 语义完成；转正是作者手工动作，且 v1.6.72 的资产改名会让更新器解析失败。

**用户价值。** 装之前，用户的 dsh 可能在 PATH、在 npx 缓存、在某个项目的 `node_modules`，或者根本没装，壳只会报一句“找不到”；装之后，双击 exe 有 dsh 就几秒进 webchat，没有就在启动页选一键全局安装、等 1–3 分钟，装完还会回读 `node_modules` 验证真落地。感到“值”的是 Windows 上已有 Node、但不想每次记命令和端口的人，以及接手别人机器、不知道 dsh 装在哪的场景。代价清楚：Windows only、首次过 SmartScreen、附加模式可能连上另一个 profile，而“不静默下载”意味着用户得自己做一次选择。

**表达（界面与交互）。** 第一屏是**启动页**而不是白屏：五跳每跳都报进度，全空时五个出口（一键 `npm i -g`、npx、手填路径、重新检测、退出）没有一个写着“自动”。出错时给的是**定位到 Error 行的摘要 + 手动修复命令 + 一键回滚之前版本**（后台执行、不卡界面），而不是一坨堆栈。日常只剩托盘：关窗口是收起，右键才有“重启后端 / 前后端重启 / 检查前端更新”。通知最能说明“不打扰”也是设计：抑制条件是“可见 && 未最小化 && 聚焦”，所以隐藏、最小化、失焦都会弹；cookie 来自壳自己的启动 token 兑换（无 token 的附加后端会静默停摆）；为了让裸 exe 的 Toast 不被 Windows 静默吞掉，启动时还得先写 `HKCU\…\AppUserModelId\com.dsh.desktop`——一个用户永远看不到的动作。

## 1. 它在产品里的位置

**七层坐标**:**2**(表层:自绘标题栏 + 常驻 webchat 窗口)+ **6**(首启:启动页/候选链/一键安装)+ **7**(分发:裸 exe、GitHub latest 通道、自更新)。第 5 层它不碰——模型与默认值仍归 DSH。

**它和上游的缝**:它**不占** `desktop` profile(那是官方 Electron 应用的,见 `lib/bin.js:35-37`),而是复用 `web`;也不自带运行时,而是把"运行时从哪来"做成**用户可见的选择**。这是三条宿主路线里最轻的一条:**只接管窗口与生命周期,不接管运行时**。

**代价**:用户必须先有 Node;dsh 的来源、版本、更新全在壳外,壳只做**发现与兜底**。所以它的产品力几乎全在 §2 的"找不到/坏了"路径上。

## 2. 机制(可照抄)

### 2.1 五跳候选链:每一跳都可超时、可降级、可记录

```
DSH_CMD(失败即降级,不卡住)
  → 自定义路径(启动页填,永久记住,存 settings.json)
    → PATH 全局 `dsh web`
      → 本地 node_modules\.bin\dsh.cmd(exe 同目录 / 工作目录 / 用户目录)
        → 已确认过的 npx(--yes @deepseek-ai/dsh web)
          → 全空:notfound 事件 → 启动页给 5 个出口
```

- 每跳**独立就绪窗口**:已安装 120s、npx 300s;
- 每跳失败**记日志并降级**,不是直接报错;
- 判据是 `POST /api/host.describe` 的 `result.ok === true`,**不是"进程起来了"**;
- 启动页的五个出口:一键全局安装(应用自己执行 `npm i -g`)、npx 备选、手填路径、重新检测、退出。

> **照抄点**:把"启动"写成一个**有序候选集合**,每个候选有超时、有健康判据、有失败记录。这样"找不到"就是一个有下一步的状态,而不是一句错误。

### 2.2 附加 / 拉起 / 干净退出:三态进程所有权

| 状态 | 行为 | 退出时 |
|---|---|---|
| 3080 已有人在跑 | **附加**,不 spawn | **不动**别人的进程 |
| 没有 → 自己拉起 | spawn `cmd /S /C`(`CREATE_NO_WINDOW`,绝对路径) | `taskkill /T` 只杀**自己拉起的**树 |
| 用户点 X | **隐藏到托盘**,DSH 继续跑 | 只有托盘「退出」才真退 |

> **照抄点**:**进程所有权**要显式建模。"我拉起的"与"我先看到的"是两种东西,混在一起就会出现"退出时把用户的 dsh 杀了"。

### 2.3 监护 + 熔断:自愈不能无限

- 意外退出(市场更新自重启 / 崩溃)→ 自动重拉 + 刷新界面;
- **连续快速崩溃 → 熔断报错**,不再重拉;
- 崩溃原因以 `ERROR` 写日志,并显示在启动页错误视图(摘要**定位到 Error 行**,不是堆栈尾巴)。

> **照抄点**:自愈要有**计数器与冷却**。没有熔断的自愈 = 崩溃循环放大器。

### 2.4 升级回滚:先记账,再升级

- 升级 dsh 后端前**保存当前版本号**;
- 升级后启动失败 → 错误界面给「回滚之前版本」;
- 回滚**后台执行**,不卡界面。

> **照抄点**:任何"换二进制"的动作都要有**可执行的反向动作**。"重装"不是回滚,回滚是**一键、知道回哪一版**。

### 2.5 配置自修复:备份 → 修 → 校验 → 落盘

`settings.yaml` 被 Web UI 写坏(如 `key:value` 少空格)时:自动**备份** → **修复** → **round-trip 解析校验** → 才写回。

> **照抄点**:"我修好了"这句话必须由**读回校验**背书,不能由"写成功"背书。

### 2.6 通知:AUMID + 事件边沿

1. 启动时注册 `HKCU\Software\Classes\AppUserModelId\com.dsh.desktop`(否则裸 exe 的 Toast 被静默丢);
2. 监听 `ws://127.0.0.1:3080/api/remote.mux` 的 `$events`,带 webchat 登录换来的浏览器会话 cookie(适配 `0.1.2+` BrowserAuth);
3. 判据是 `api-session/status` 的 `running` **true→false 边沿**,且**主窗口隐藏**;
4. 用 `session/list` 拿标题,弹两个按钮的通知(打开窗口 / 明白),不点几秒后收起。

> **照抄点**:"任务完成"不是一个轮询,是**状态边沿 + 前台/后台判定**。窗口在前台时不要打扰。

### 2.7 发布通道与双版本线：人工转正 + 资产命名风险

- 每个迭代先发 **pre-release**(GitHub `latest` 天然排除,自动更新不碰);
- 检查版与修 bug 迭代**仍留 pre-release**;
- 只有作者确认真实稳定才转 latest,**自动更新才开闸**。
- 插件(npm)与应用(GitHub Releases)**各走各的版本线**:npm 只在插件代码变化时发;应用启动时把已装插件对齐到 npm 最新(**只升不降**),装完**回读 `node_modules` 验证真实落地**。

> **照抄点**:**"发布通道"是产品功能,不是发布流程细节。** 用户能不能被自动更新,取决于你把哪一版推成 latest。

## 3. 体验

- **第一次**:双击 exe → 若本机有 dsh,几秒进 webchat;若没有,启动页列 5 个出口,选"一键全局安装"等 1–3 分钟。
- **日常**:关窗口 = 收托盘;托盘双击唤回;右键有"重启后端 / 前后端重启 / 检查前端更新"。
- **出错**:启动页直接显示错误摘要 + 手动修复命令;能一键回滚。
- **完成**:后台任务跑完弹 Windows 通知,两个按钮直接操作。

## 6. 失效条件与降级

- **平台**:Windows only;WebView2 依赖系统(Win11 自带)。
- **Node 前置**:没有 Node 直接起不来——它把"装 Node"留给用户,这是最轻路线换来的硬前提。
- **无签名**:首次运行 SmartScreen;可移植的代价是没有安装器生态。
- **附加模式的边界**:如果 3080 上跑的是**另一个 profile**,壳会连上去但界面/数据可能不是用户以为的那份。
- **熔断后**:应用停在错误页,只能看日志/回滚/重装——这是"自动恢复"的终点,必须有**人能读的下一步**。
