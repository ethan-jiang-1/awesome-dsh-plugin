## 一、上游接缝原文（DSH `0.2.1-rc.3`，本机 checkout）

| 接缝 | 原文 | 位置 |
|---|---|---|
| **`desktop` profile 独占** | `error: profile "desktop" is managed exclusively by the Electron application` | `lib/bin.js:35-37`（`rejectElectronProfile`） |
| **`desktop` profile 必须先由应用初始化** | `Open DeepSeek Harness Desktop once to initialize its profile, then fully quit it before running dsh plugin --profile desktop.` | `lib/plugin-BiveYA7h.js:10-12`（`requireDesktopProfile`） |
| **`desktop` profile 不自动建目录** | `if (profile !== "desktop") await mkdir(dir, { recursive: true });` + 随后 `requireDesktopProfile(dir)` | `lib/plugin-BiveYA7h.js:38-40` |
| **profile 从模板初始化** | `--from-default-profile <name>`：replace a custom profile with a fresh copy of a shipped profile template | `lib/bin.js:105`；空值报错见 `lib/bin.js:62` |
| **profile = `$DSH_HOME/profiles` 下的一套有序 patch 栈** | `dsh: boot a DeepSeek Harness profile — an ordered stack of plugin-bundle patch layers under your own overrides.`；`--profile <name>` = the profile under `$DSH_HOME/profiles` to boot | `lib/bin.js:105` |
| **自定义 profile 不能冒用出厂名** | `profile … names shipped profile … and cannot be a custom profile target` | `lib/profile-boot-C14i-8IN.js:154` |
| **可核验挂载** | `--dump-config` / `--dump-config-schema` / `--dump-default-config` | `lib/bin.js:105` |

**这七行的含义**：DSH 把「表层」留给了外部进程，但把 **`desktop` 这个名字**留给了官方 Electron 应用。第三方桌面壳要么用别的 profile 名（`web` / `tui` / 自建），要么自带运行时另起炉灶——这正是本 lever 样本各自选的路（本文件覆盖桌面三张 + 终端一张）。

## 三、2026-10-31 复核：四个 `[OPEN]` 关闭三个

### 3.1 本地实测：CLI 拒绝 `desktop`（`DSH_HOME` 用临时目录）

```console
$ DSH_HOME=$(mktemp -d) dsh --profile desktop --dump-config
error: profile "desktop" is managed exclusively by the Electron application
$ DSH_HOME=$(mktemp -d) dsh plugin --profile desktop add left-pad
error: profile "desktop" is managed exclusively by the Electron application
$ DSH_HOME=$(mktemp -d) dsh --profile desktop --from-default-profile web --dump-config
error: profile "desktop" is managed exclusively by the Electron application
```

`--from-default-profile` 也救不回来：`desktop` 在参数解析阶段就被拒（`lib/bin.js:35-37`）。

### 3.2 `tauriapp` 怎么绕过去

- `desktop/src-tauri/src/runtime/builtin/launcher.mjs:1`：
  `// dsh-launcher.mjs —— 桌面壳内置 dsh 启动器：直调内部 runProfile API，不经 CLI。`
- 同文件 `:25`：`const initFromDefault = rest.includes("--init-from-default") && profile !== "web" ? "web" : undefined;`
  → 它用自己的参数名 `--init-from-default`（**不是**上游 CLI 的 `--from-default-profile`），把 `desktop` 从 `web` 模板初始化。
- `desktop/src-tauri/src/profiles.rs:104-113`：手写 profile 模板文件，`dsh.profile.bundles = ["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app"]`；`:26-27` 注释“desktop 等非出厂模板首启时，启动器需追加 --init-from-default”。
- **结论**：技术上能建，但建出来的就是 `$DSH_HOME/profiles/desktop`——**与官方 Electron 应用同名同目录**。

### 3.3 `DSH Desktop` 用哪个 profile

`docs/architecture.md`（2026-10-31 抓取）：

- `:42`：`harness/   DSH_HOME`（在 **Electron userData** 下，不是 `~/.dsh`）
- `:29`：`… while inspecting the web Profile`
- `:72`：`The normal web profile may contain community plugins…`
- `:35`：`Safe Mode starts a separate profile containing official core bundles`

→ 正常态是 **`web` profile**，数据根是应用自有的；Safe Mode 另起一个只含官方 core 的 profile。

### 3.4 SeekTTY 与 dsh-TUI 是否共用 `tui` profile

- `dsh-TUI` README：`dsh plugin --profile dsh-tui add @deepseek-harness-tui/dsh-tui`、`dsh --profile dsh-tui` → **`dsh-tui`**。
- `seektty` README：`dsh plugin --profile tui add …`、`dsh --profile tui` → **`tui`**。
- 两者 `package.json` 都声明 `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}`；两个 patch 都**按 id 覆盖宿主行**（`system-prompt` / `hmr` / `session-query-sqlite` 等）。
- 结论：**profile 名不同，不撞车**；冲突面在“装进同一个 profile”时——两套 patch 会抢同一批行 id。
