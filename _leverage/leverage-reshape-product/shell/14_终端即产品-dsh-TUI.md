## 它想干什么 · 为什么值得借鉴

**意图。** 让 DSH 在终端里长成一个**独立产品**,而不是给 Web 壳挂一行 patch:交付单位是一整套表层——带真输入框的 launchpad、四步首启、自有的 `~/.dsh-tui/settings.json` 与权限文件、自带更新器,以及 `doctor` / `safe` 两条自检命令。作者要解决的麻烦很具体:终端用户得自己拼 profile、自己判断终端支不支持 OSC 777,装坏了还没有入口自检。它明确不做的,是 fork 宿主或新增模型能力——"Zero core changes",只消费公开导出,"install to enable; uninstall leaves no patches behind"。

**意义。** 它补的是第 6 层首启在 Web 上的那块空白:官方只有一个几乎没人用的 `settings.onboarding` 槽,而在 TUI 里"你自己就是应用,接缝随你定"。这也是本 lever 最重要的一次边界示范:换表层不必 fork,前提是把承诺写成可验收的——只写自己的 profile,卸完无残留。它还改了一条惯例:插件默认"缺能力就什么都不做",它要求每一档都给出落点,最差档也不许静默。

**用户价值。** 装之前,用户要先选定 profile 名、pnpm 版本与终端配色,再赌一把剪贴板能不能用;装之后,Windows 一键安装器(per-user、免管理员、全离线、无需预装 Node)或一条 `npm i -g` 就能跑,首启只问四件事,`/setup` 还能重跑。真正觉得值的是两类人:要带非终端同事上手的团队,和在 tmux/SSH 里工作、常遇到"通知不响、图片变问号"的人——现在通知会一路退到**响铃**,而不是消失。代价主要落在作者身上:要维护 52 条降级原文那样的能力矩阵;用户则要接受它不是"零配置",而是"配置被收进产品里",外加 Windows 默认 `danger-full-access` 的安全警告。

**表达（界面与交互）。** 每次普通启动都先落在 launchpad:大字、鲸鱼、快捷动作,外加一个**真输入框**,窄终端则整块丢弃、直接进 chat——"窄了就删"本身就是体验。四步向导的顺序是"能跑起来 → 好看 → 好用 → 记得住"(凭据 / 语言主题 / 模型+工作区 / 快捷键,`?` 随时重看),更新检查放在后台、"永不阻塞首帧",屏先于会话出现。最见功力的是"不显示":宿主缺实验特性时 `/plugin list` 整段消失,身份未验证的面板只标"本次运行的编号"、立即生效但不保存并提示重选,另留了 `DSH_TUI_HOST_ENTRY=0` 与 `DSH_TUI_DISABLE_WIN32_INPUT_MODE=1` 两条回退。

## 1. 它在产品里的位置

### 1.1 装配链(一句话给全)

```
dsh profile → dsh-base → dsh-TUI Cordis patch → agent preset + DSH services
   → session/event → Channel projection → React components → Ink/Yoga → terminal
```

它**不往 `ctx.slots` 注册**(那是 web Renderer 的槽),但它挂在**同一个 Cordis 装载器与 fiber 生命周期**上。上游"声明即独占渲染权"(single 槽不许并存)在 TUI 里对应"**整棵树由 Ink 渲染**"。

### 1.2 为什么它是本 lever 最重要的一张反证

| 层的判断 | Web 上的事实 | TUI 上的事实 |
|---|---|---|
| 6 首启 | 官方只有一个 `settings.onboarding` 槽,几乎没人用 | **四步向导 + 落地页 + `/setup` 重跑** |
| 5 默认值 | 由宿主管 | **自有 `~/.dsh-tui/settings.json` 与权限文件** |
| 2 表层 | 只能改槽位与 CSS | **整棵树重画** |

> **结论**:6 层在 Web 里"没有接缝",在 TUI 里"**你自己就是应用,接缝随你定**"。所以"首启层是空的"这个判断**只对 Web 成立**——这是本 lever 必须写清的口径边界。

## 2. 机制(可照抄的部分)

### 2.1 零核心改动 + 卸=无残留(可验收)

> "Zero core changes: it consumes only DSH's public exports … **Install to enable; uninstall leaves no patches behind.**"

**为什么这条能验收**:它只往自己的 profile 写(`dsh plugin --profile dsh-tui add …`),不写 `$DSH_HOME/cordis.patch.yml` 这类全局层。对照 `12_厚工作台`:后者必须提醒用户"页面出现两个 sidebar 时删掉老式手动挂载行"——**残留是要用户处理的,那就不是零残留**。

### 2.2 可插拔后端:声明与实现分离 + 懒 import + 授权前置

`tui.dsh/v1alpha1` 的 `Backend` contribution,五条约束:

1. 启动时**扫描 profile 声明的 bundle**;
2. 准入并注册每个包**根部的 `dsh-plugin.json` 声明**;
3. 实现从包的 **`backend` export** 读,且**只在真的选中该 backend 时才 import 那个模块**;
4. 每个 bundle **最多一个** backend,handler id 必须与声明一致;
5. **等待授权的条目不探测也不加载**,即使启动时被点名请求。

> 这是"可插拔后端"的模板:**声明(数据)与实现(模块)分离、懒 import、授权在探测之前**。第 5 条最容易漏——很多系统"先探测再问",等于把未授权模块也拉进了内存。

**插件子组件的准入规则**(可直接抄成校验器):导出的子组件按其 **ESM entry 最近的 package manifest** 做准入,**包括 import-only 与条件导出**;它们**不继承外层包的 identity**。含义:monorepo 里 re-export 别人的组件不会被误判成你的包。

### 2.3 输入解析:hold 窗口的三条铁律

| 铁律 | 值 |
|---|---|
| 起点 | **从首捕获起算** |
| 延长 | **不被后续输入延长**(否则高频输入会让 hold 永不结束) |
| 上限 | **1 秒 / 64 字节**,超界 → **按到达顺序原样重放为普通按键** |
| 承诺 | "literal input can be delayed, but is **never dropped**" |
| 认领条件 | "证据受限":"**没有查询在等回复就不认领任何东西**",所以 `Esc` 后立刻打 `[?61;4c` 仍照常进 prompt |

同一个 1 秒 / 64 字节出现在三处:不完整 Win32 输入记录、终端响应(DA1/DA2/DSR/DECRPM/XTVERSION)、SGR 鼠标报告。

> **抄这条**:凡"要等后续字节才能判定"的解析器(模糊输入、粘包、代理协议),**必须有一个从起始时刻算起的硬窗口 + 字节上限**,并且超界时**原样放行**。否则一次半截输入能让输入框卡死。

### 2.4 能力缺失:每档一条"退化为 Y"

| 能力 | 退化链 |
|---|---|
| 通知 | OSC 777(Ghostty/WezTerm,**分 title/body**)→ OSC 99(Kitty)→ OSC 9(iTerm2/Warp,**标题前缀**)→ **响铃** |
| 通知兜底 | Windows 写不进 `AppUserModelID` → **回落响铃,不允许静默** |
| 通知让位 | 运行 profile 里有**启用中**的第三方通知插件 → **让位**(不 toast 不铃);**装了但禁用则不抑制** |
| 通知不该发 | "**重放、取消、失败不通知**" |
| 图片 | 能力缺失 → **文本回落** |
| 剪贴板 | PowerShell 两条路径(各 **2 秒**超时)→ **OSC 52**(需终端支持);"**SSH 永不写远端原生剪贴板**" |
| 面板 | "窄终端与 inline 模式保留**全屏**面板"(侧栏重排不了就整屏) |
| 浮层 | "`/btw` 在其侧栏渲染不出来时用**浮层**" |
| sixel 自愈 | 允许 **1 个挂起回复(500ms)**;无应答或 **10 秒内 3 次修复** → **暂停 60 秒** |
| 颜色 | monochrome / 16 / 256 / truecolor 四档;`NO_COLOR` / `FORCE_COLOR` 沿用既有策略 |
| 终端标记 | 私有模式只在**真的进了**才启用重组;"一台机器**可能**跑该模式" ≠ 已进入 |

> 抄这条的判断顺序:**先列能力,再列每一档的落点,最后检查最差档是否"不静默"**。响铃、纯文本、不激活——三种都算合格落点;"什么都不显示"不合格。

### 2.5 恢复:宁可报错,也不猜

| 情形 | 行为 |
|---|---|
| 恢复目标不确定(记下的 backend 已不存在) | **报错退出 1**;"never a silent cold start, never another backend's session, never a new session" |
| 唯一例外 | safe mode 的 "retry normal startup" 若 backend 没了 → **降级为一条 warning + 冷启动** |
| 宿主缺某实验特性 | `/plugin list` **整段不显示**;`/team` 只在团队服务挂载后出现在 Help 与 `/` 补全 |
| 身份未验证的面板 | **临时**:设置里显示"本次运行的编号",开关**立即生效但不保存**;`actN:panel` 旧条目**无法安全映射** → 提示移除并重选 |

> 最后一条是本卡最罕见的诚实设计:**承认"我这次没法把你的选择存下来"**,而不是存一个会错位的 id。

### 2.6 更新与预算:数字要能当合同

| 项 | 值 |
|---|---|
| 安装器墙钟上限 | **30 分钟**(`DSH_TUI_UPDATE_TIMEOUT_MS` 改);**输出活动不重置该截止时间** |
| 取消 | POSIX 先杀自己的进程组,**2 秒**后强杀剩余后代;Windows 用 Job Object,"installer 在**挂起状态**下原子入 job" |
| 成功判据 | "**只有最终进程退出码才算成功**;打印 `Done` 不算" |
| 失败后果 | 超时/取消/未确认清理 → 非零退出,并**阻止重试、陈旧文件移除、修复与 TUI 替换** |
| 退出 | 终端清理后只 drain 渲染器自己的输入 + **150ms** 静置 |
| 堆取证 | `DSH_TUI_HEAP_WATCH=1` 才开;**每 15 秒**采样;阈值 **1024/1536/2048/2560/3072 MiB** 各一张快照;保留**最多 4 个 64 KiB 日志 + 2 张快照、合计 ≤1024 MiB** |
| 通知正文 | 单行纯文本、**≤200 字符**(剥 Markdown);OSC 777/9 额外 **2048 字节**序列预算 |
| 插件命令结果块 | 每块 **≤200 行 / 65,536 UTF-16 单元 / 每行 4,000 cell**,超出加**可见截断标记**;旧块在**共享 600 行**预算内驱逐 |
| TPS | 含隐藏推理时间、**不含工具执行时间**;**≤500ms 的解码段不计入 TPS 样本**(token/成本仍计全) |

### 2.7 版本:白名单 + 三档行为

| 档 | 触发 | 行为 |
|---|---|---|
| **硬停 + 修复指引** | DSH 0.1.7 上 `/settings` 需 `@deepseek-ai/schemastery 3.18.3+` | "宁可起不来,也不给一个不能编辑的设置页" |
| **拒绝 + 升级指令** | DSH `< 0.1.2-alpha.3` | 拒绝 `/model` 热切换(这些版本的子代理会继承原路由) |
| **降级 + 一次性说明** | safe mode 记录的 backend 不存在 | warning + 冷启动 |

配套:主兼容目标写在最显眼处;**两条"不要用 git 装"的实测结论**(源码 manifest 留 workspace 依赖、`vendor/dsh-std` 是 submodule、pnpm ≥11 拒绝 git-hosted `prepare`);**"没测什么"写进 README**:如 Codex 0.160.1 后端"通过九项无凭据离线检查与八项 daemon 恢复检查,无模型回合、无计费;**真实订阅登录、带凭据的模型调用与真实 TTY 交互未运行**"。

### 3.3 权限与边界:把"我不是安全边界"写出来

- "**Grants are behavioural constraints, not a security boundary.**"
- "授权**按 component id 记**,所以留下的条目会让任何后来复用该 id 的包**静默继承**它们。"
- "授予写失败**永不阻塞**安装/启用,只报告。"
- **`enable` 永不被 gate 2 拒绝**——"它是修复动作"。
- Windows profile **默认 `danger-full-access` + approval `never`**,README 顶部给了安全警告;且"**不自带沙箱**,用当前 profile 的 fs/shell/sandbox/approval 策略"。

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 终端不支持某协议 | `OSC 7501` 等**被忽略**(序列无害);通知降到响铃 |
| Windows 写不进 `AppUserModelID` | **回落响铃**,不静默 |
| tmux 未开 passthrough | OSC 通知需 `set -g allow-passthrough on`;focus 需 `set -g focus-events on` |
| 嵌入宿主不兼容私有模式 | `DSH_TUI_DISABLE_WIN32_INPUT_MODE=1` |
| 终端从不进入该模式(mintty/GitBash) | 保留经典 VT 路径:单独 `Esc` 不延迟,超时后字母**不被吞** |
| 不可捕获退出 | 无法保证清理,交给终端或外部监管 |
| 新启动路径出问题 | `DSH_TUI_HOST_ENTRY=0` 回到旧路径 |
| sixel 光标错位 | 自愈;无应答或 10 秒内 3 次 → 暂停 60 秒;`DSH_TUI_SIXEL_CURSOR_HEAL=0` 关 |
| 宿主没带实验特性 | 相关命令/段落**整段不显示** |
| 授予写失败 | **不阻塞**,只报告 |
| 取消装插件太晚 | "**等它装完**",不假装取消成功 |
| workspace 失去注册 | 降级为 "**History only**"(仍可读,不可改名/移除) |
| 库迁移 | 用官方 `node:sqlite.backup()`,**先探测能力再只读打开源库**,含已提交 WAL 得一致快照,"**绝不手工拷活库/WAL 对**" |
