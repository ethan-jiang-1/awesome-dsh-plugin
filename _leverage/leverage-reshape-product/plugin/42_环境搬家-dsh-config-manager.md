## 它想干什么 · 为什么值得借鉴

**意图。** 新机器上的 DSH 是个空壳：它把旧机器（或别的 agent）的设置、插件、MCP、技能、工作区、全局指令连同对话历史装进一个 ZIP，再到另一台机器上还原。交付单位不是"一个配置文件"，而是**一个自包含包 + 一份逐项计数、可逐条否决的导入计划**。它明确不做两件事：`$DSH_HOME/profiles/<name>` 不进备份（profile 是机器本地的），Claude Code 的 hooks、slash commands 之类没有对应物的结构只报跳过码，不硬塞。

**意义。** 首启只回答了"该装什么"，没人回答第二个更硬的问题——"你原来那套东西怎么过来"；它补的正是这个空缺，而且答案是可验证的：还原后配置真的长回来，还能读回核对。更关键的是它改了一条惯例：导入不是一次写入，而是**先计划、后写入的流水线**；确认后先落快照与 journal，再逐项 apply。30 个来源也不是 30 套导入器——先翻译成自家标准包，再走同一条预览/冲突/快照/回滚，这条边界让"支持新来源"退化成写一个翻译器。

**用户价值。** 装之前，换机要么 `cp -r ~/.dsh`（不处理密钥、不重映射路径、抓不到 `link:`/`file:` 安装），要么照着记忆重配一遍。装之后，用户拿到的是「18 项设置将更新 / 3 个密钥需重填 / 2 个冲突待处理」这样一张账单，冲突逐条二选一，路径一次前缀替换把 `C:\Users\alice\` 换成 `/Users/bob/`。最觉得值的是**要把环境复现给别人的人**（换机、交接、给同事搭同款），因为失败会按补偿日志逐项回滚（但不卸载新装插件，需事后用快照 Restore）。代价也清楚：流程要走完，没有"稍后决定"，密钥要重填，30 个来源的翻译器由作者长期养。

**表达（界面与交互）。** 装完重启，设置里多一个「Backup & Migration」，只有 Home / Library / Sync / Environment 四个顶层页；导出时推荐分区已勾好，导入第 0 步**什么都不写**，先跑校验链再出计划。冲突页只给「保留当前 / 用备份」两个按钮加批量，**没有"稍后决定"**——向导在主按钮上阻断未决冲突；但这是 UI 保证，`/execute` 并不校验。本机没装的来源**置灰但仍列出**，读不到的分区写"read failed"而不是 0，确认页上"失败自动还原"可关：这些"不装、不猜、可回退"的选择本身就是体验。

### 1.1 它回答的是「首启的第二个问题」

[`04_首启观察`](./_证据/04_首启观察-dsh-bootstrap.md) 把首启拆成两个问题：第一个是"怎么装 DSH"，第二个是"**然后呢**"。`dsh-bootstrap` 回答第二个问题是"你该再装哪些插件"；这一张回答的是另一条更硬的路径——**"你原来那套东西怎么过来"**。

两者的差别不在功能，在**证据**：推荐是按人气猜的，迁移是**可验证的**（还原后配置真的长回来了，且能读回核对）。所以同样是 6 层，迁移类样本的影响力比推荐类高两个数量级（见 §4）。

### 1.2 它和同赛道四个产品的分工

README 自己列了一张对比表，值得直接抄进选型文档 `[CAT]`：

| 产品 | 最强在哪 | 它多走了一步 |
|---|---|---|
| `xiaoyuyu6420/dsh-backup` | 一条命令做 `~/.dsh` 快照 + rescue console | **写前 GUI 评审**（dry-run、逐项冲突、自动回滚）、跨机路径重映射、加密凭据、配置市场 |
| `muyifc/dsh-config-sync` | 导出/导入到加密文件，可从 tool call 调 | 13–14 个分区、定时备份、四条同步通道、带路径 rebase 的会话迁移 |
| `dickpy/dsh-cloud-sync` / `weibaohui/dsh-sync` | 靠 WebDAV/S3/私有 Git 保持多机一致 | 同步只是它五个能力之一（导出/导入/定时/市场/profile 实例启停） |

## 2. 机制（可照抄的部分）

### 2.1 导出：先剥密钥，再算校验和

```text
读配置 → 剥掉密钥（SecretScanner）→ 生成 manifest → 每区 SHA-256 → 打包 ZIP
```

三条可抄的细节：

1. **分区是"可拆分到最小单元"的**：`分区 → 可拆分单元`，逐个勾选；推荐分区（可移植、非设备相关）默认勾上，随时可改。
2. **读不到的分区不许装成 0**：原文要求"unreadable sections say loading / read failed instead of a fake 0"——**报告里宁可写"读失败"，也不写一个假的 0**。
3. **导出是只读的**：不写任何配置；结果 ZIP 自动下载到浏览器下载目录，报告里再给一次链接。

### 2.2 导入：计划阶段只读，写入前先快照

```text
选 ZIP → 校验文件 → 查完整性 → 查 schema → 兼容性检查
      → 扫描内容 → 生成导入计划 → migration consult（判决 + 证据）
      → 选择要导入什么 → 逐项冲突裁决 → 路径映射 / 密钥重填
      → 确认导入 → 自动备份当前配置 → 应用 → 校验 → 完成
                                   └─ 中途失败？→ 自动还原（可在确认页关掉）
```

**为什么这个顺序值得抄**：它把"可能出事的判断"全部排在"第一次写盘"之前。用户在第 1 步到第 11 步之间随时可以退出，成本只有时间；一旦点了确认，失败也有自动回滚兜底。**"先检查、再预览、后写入、可回滚"是四件事，不是一句 UX 口号。**

### 2.3 别的 agent 的配置：翻译成标准包，而不是第二套导入器

这是全卡最值得抄的一处 `[CAT]`：

> "**Translation, not a second import path** — the source is converted into a standard bundle v1 ZIP and handed to the **existing** import wizard: same preview, same per-item conflict decisions, same pre-import snapshot and rollback, same dry-run."

| 做法 | 收益 |
|---|---|
| 为每个来源写一套导入器 | 30 个来源 = 30 套预览/冲突/回滚，行为必然分叉 |
| **先把来源翻译成自己的标准包，再走同一条流水线** | 预览/冲突/快照/回滚只实现一次；新来源只写"翻译器" |

四条配套纪律：

1. **本机没装的来源也列出来，只是置灰**——"没有这个工具"不能被误读成"没有这个功能"。
2. **不搬结构上没有对应物的东西**：Claude Code 的 hooks、slash commands 等，报**显式代码**而不是静默丢弃。
3. **诚实地跳过**：没有记录 `cwd` 的对话无法定位，报"跳过"，不猜进某个项目。
4. **已知有损项在导入前就列出来**，不是导入后再说。

### 2.4 冲突：必须逐条裁决，没有"稍后"

| 选项 | 含义 |
|---|---|
| **保留当前** | 目标机上的同名项不动 |
| **用备份** | 用备份里的值覆盖 |
| 批量按钮 | 「全部保留当前」/「全部用备份」 |

> 向导确实在主按钮上禁用未决冲突（`hasUnresolved`），但 `/execute` 不重新校验：直连 API 时 merge 策略会静默跳过、replace 策略直接覆盖。**这是 UI 保证，不是引擎不变量**——要当契约用，必须把校验放到服务端。

### 2.5 死路径：检测 + 批量前缀映射

`C:\Users\alice\projects` 在新机器上不存在时：

1. 自动检测失效的绝对路径；
2. 让用户选新路径；
3. 支持**批量前缀映射**（一次把 `C:\Users\alice\` 换成 `/Users/bob/`）。

> 抄这条时注意：**路径映射要作用于"所有引用它的地方"**（workspace、MCP 命令、技能路径），只改顶层配置会留下半坏状态。

### 2.6 密钥：只记键名，值要另给

| 场景 | 行为 |
|---|---|
| 默认备份 | **不含任何密钥值**，只记录"需要哪些键" |
| 加密备份（显式勾选） | scrypt + AES-256-GCM，每份随机 salt/IV；密码**从不写进文件** |
| 加密备份导入 | 必须输入导出时的密码：输入 → 校验 → 还原凭据；**无密码则不导入** |
| 非加密导入之后 | 计划里写「3 个密钥需重填」，值只在内存里 |

### 2.7 快照与还原：一行一行给你看

- 写之前**自动快照**；
- Library 里对快照点 "Restore"：先看**逐行还原计划**（git 风格的行级对比，dry-run 零写入），再决定；
- 还原动作是"整文件恢复 + 卸载新增插件"，不是"合并"。

### 2.8 Profiles：备份之外的那一块

`$DSH_HOME/profiles/<name>`（决定启动哪套插件栈）是**机器本地**的，不进备份。它被单独放在 **Environment → Profiles**：列出 / 新建 / 重命名 / 删除，外加**启动或停止一个独立实例**。

> 这是一个很聪明的边界：**备份搬的是"配置内容"，不是"这台机器的 profile 目录"**。把两者混在一起，跨机还原就会把别人的 profile 名带过来。

### 2.9 安装本身：三个真实的坑

README 用三节写了安装失败，**这本身就是"上手体验"的一部分** `[OBS]`：

| 坑 | 现象 | 处理 |
|---|---|---|
| **pnpm 发布年龄闸** | `@latest` 装到旧版本 | 按版本逐次评估：新发布在阈值（约 30 天）内对 `@latest` 不可见；可把该包加进 profile 的 `minimumReleaseAgeExclude` |
| **全局旧副本遮蔽** | pnpm 日志说装了 `^0.1.66`，DSH 却报 `0.1.44` 不兼容并回滚 | 兼容性检查会**重新解析** patch 行里的包名，Node 解析链吃 `NODE_PATH`；`npm ls -g` 查全局副本并升级/删除 |
| **git 源要跑构建** | `ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED` | 把 pnpm 打印的完整行（含 git URL 与 sha）原样写进 `allowBuilds`；更省事的是用预构建的 npm 版 |

> 抄这条：**"装完之后的第一次失败"也是首启体验**。把已知的安装坑写进 README，比在 issue 里等用户报错便宜得多。

## 3. 体验

### 3.1 首次使用逐屏（两台机器）

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装 | 一条命令 + 重启一次 | 明写"重启"是必经步，不假装热加载 |
| 打开 | 设置里多一个「Backup & Migration」，只有 **4 个顶层页**：Home / Library / Sync / Environment | 页面少，动作集中 |
| 导出 | 工具栏 Export → 推荐分区已勾好 → 命名/备注 → 开始 | 一步一屏，不塞长表单 |
| 换机导入 | 选 ZIP → 等分析 → **读 consult 判决与证据** → 勾内容 → 解冲突 → 映射路径 → 确认 | 每屏只问一件事 |
| 夹缝操作 | 右上四个图标：⌘K 命令面板 / 活动 / 迁移历史 / 关于 | 重操作有第二入口，但主路径不依赖它 |
| 失败 | 自动还原 + 报告 | "失败"不等于"你的环境被我改坏了" |

### 3.2 三处"诚实"的文案（建议直接抄措辞）

- 读不到的分区写"loading / read failed"，**不写 0**。
- 本机没装的来源**置灰但仍然列出**，并写明"仍会列出，只是不可选"。
- 搬不动的结构（hooks / slash commands）给**显式代码**，不给一句"部分功能可能不可用"。

> 这三条是同一个原则：**降级要说清楚降到哪**，而不是把未知糊成一个 0 或一句免责声明。

### 3.3 模型看到的

迁移过程**不进模型请求**；它改的是 settings / 文件 / 会话日志。模型侧唯一的入口是 CLI `dcm import --from <source> [--dry-run]`。

> 这是它的 `[OPEN]`：**没有"让模型读一下你的旧项目、建议保留哪些技能"**这一步。首启推荐（bootstrap）做了"该装什么"，但没人做"该留什么"。

## 5. 可迁移洞察

| 触发问题 | 可迁移洞察 | 机制依据 | 为什么有效 / 代价 | 移植时改什么 | 成立边界 | 抄错后果 |
|---|---|---|---|---|---|---|
| 一次导入会写很多文件，用户怕写坏 | 计划阶段零配置写入；确认后、动配置前先落快照（计划内会写的 target）+ journal/WAL，再逐项 apply。 | `[SRC-TARGET]` `/analyze`、`/plan` 只读；`/execute` → snapshot → `markApplying` → planned entries → `applyOne`。 | 失败可定位、可补偿；代价是“确认后”已产生快照/journal 写入，不是零写盘。 | 明确“读阶段/暂存写/配置写”三段的边界与用户可见状态。 | 收尾 `finalizeApply` 产生的写入不在快照目标集。 | 宣称“确认前什么都不写”却在确认出错，或只备份计划内条目 → 收尾文件无法回滚。 |
| 中途失败要“自动还原” | 把回滚实现成逐条补偿 undo，并把无法回读的项（凭据原值、原本不存在的 namespace）标记 failed + manualHint；报告区分 full/partial。 | `[SRC-TARGET]` rollback 分支只有 settingsNamespace/credential/patchLine/file/workspaceRecord；`rollbackOnError` 默认 false，warning 非致命。 | 诚实降级，不假装等价；代价是插件安装与收尾写不在自动回滚范围。 | 定义 undo 覆盖矩阵与人工修复清单，明确哪些要事后用快照 Restore。 | 自动回滚不卸载导入期间新装的插件；插件撤销只在 Library Restore 路径。 | 承诺“整笔事务回滚” → 残留插件/收尾文件，用户以为已复原。 |
| 未决冲突必须阻断写入 | 若产品要求“无未决不得导入”，把该不变量放在服务端执行入口，而不只在向导按钮。 | `[SRC-TARGET]` UI `disabled={collector.hasUnresolved}`；`/execute` 不校验未决 Conflict；merge 下跳过、replace 下覆盖。 | UI 阻断给普通用户保证；代价是 API 直连可绕过，需服务端 409/校验。 | 把冲突决策写进计划并在 execute 重新校验，返回明确错误码。 | 本样本只有 UI 保证；loopback 围栏限制但不能替代契约。 | 脚本/第三方 UI 直连 → 未决项静默跳过或覆盖。 |
| 多来源导入容易分叉 | 外部来源只翻译成版本化标准包（manifest+分区+checksums+foreign 元数据），复用同一条预览/冲突/快照流水线。 | `[SRC-TARGET]` `/foreign-import` 只产标准 bundle v1 到 tmpDir，复用 writeZip/buildManifest/buildChecksums；凭据值在翻译层剥离。 | 一套安全/回滚只实现一次；代价是翻译器维护与元数据失真风险。 | 标准包 schema 版本化，兼容评分基于来源真实版本而非目标机。 | 外部包 `source.dshVersion` 填目标机版本 → 兼容评分被构造性拉满。 | 评分恒过 → 用户以为兼容，实际装完才失败。 |
| 读不到的数据被显示成 0 | 对“未知/读失败”设独立状态（loading/failed/—），不渲染假 0；但只在真正实现的状态机范围内声明。 | `[SRC-TARGET]` 导出/总览 `SectionCompositionState = ready / loading / failed`；导入侧用 `import.readFailed` 与 `unreadable[]`，但预览计数 `?? 0`。 | 避免 0 被当决策依据；代价是每处汇总都要 NULL 通道。 | 为每个计数定义 null 语义，并统一 UI 呈现。 | 本样本导入预览计数没有 NULL 通道，不能整体宣称已做到。 | 把“读失败”写成 0 → 用户/上游据此做错误决策。 |
| 密钥与明文包容易泄漏 | 导出侧扫描剥离、翻译层再剥值、值只经内存、日志先 redact；加密包未解密直接硬失败；解出的明文 ZIP 要有删除时限。 | `[SRC-TARGET]` secret scanner + `redact()` + `encrypted` 硬拒绝；明文 ZIP 成功即删、失败保留到 24h 保留期。 | 减少明文持久化面；代价是失败/取消路径仍有窗口，需清理与告警。 | 定义临时文件生命周期、失败清理、权限 0600 与用户可见残留提示。 | 失败/取消时明文包可能保留至保留期；本卡未实测。 | 认为“加密了就安全” → 解密产物留在 tmp 目录。 |
| 压缩包处理易被 Zip Slip 攻击 | 默认 `parseZip` 最严（路径安全/重复名/符号链接/限额），并避免“解压到磁盘再导入”；防线落在 adapter 目标路径围栏。 | `[SRC-TARGET]` zip.ts 判定；`safeExtract*` 无调用方；导入内存解析。 | 减少攻击面；代价是围栏要覆盖所有 adapter 写入点。 | 对每个目标路径做 canonical containment 并写负例测试。 | 本次未运行恶意样本；围栏实现未逐一审计。 | 依赖通用解压函数 → Zip Slip/符号链接写入。 |
## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 备份里有本机没有的插件版本 | 计划里标"需安装"，按精确版本优先；装不上进失败清单 |
| 源对话没有记录 `cwd` | 报"跳过"，不猜项目 |
| 目标已有同名项 | 向导要求逐条裁决；但 `/execute` 不校验未决冲突（merge 跳过、replace 覆盖） |
| 中途写入失败 | `rollbackOnError` 默认 false（继续并报告）；开启后做逐项补偿回滚，不卸载新装插件 |
| 加密快照没有密码 | 不导入，只提示 |
| 分区读取失败 | 导出/总览写"读失败"不写 0；导入侧为 `import.readFailed`，但预览计数仍可能落 0 |
| 全局 npm 有旧副本 | 安装被 DSH 兼容性检查回滚；README 给排查命令 |
| profile 目录 | **不在备份里**；由 Environment → Profiles 单独管理 |
