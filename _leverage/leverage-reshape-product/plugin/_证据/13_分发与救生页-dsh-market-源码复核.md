## SRC-TARGET

### 1. 救生页：谁在服务、在哪个地址、写什么

- **不是一个进程，是两个**。`scheduleRestart()` 先把恢复配置写到 `tmpdir()`，再 `spawn(node -e <helper>)` 并 `unref`，500ms 后给自己发 SIGTERM（[`src/restart.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L689-L723)）。helper 只做等待与拉起：先 connect 探活等旧端口安静（最长 30s），再 spawn 替代进程，要求端口**连续应答 8s**（`SETTLE_MS`）才算起来；「已退出」立即结束等待，未退出则最多等 45s+8s 的“起来预算”，再放宽到 **240s 硬上限**，避免把仍在冷启动的替代进程的端口抢走（[#L559-L668](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L559-L668)）。替代进程没起来时才 `handOff()`：`spawn(process.execPath, [recovery.js, config, --exit=…, --bound=0, --pid=…])`，`detached` + `stdio:"ignore"`（[#L543-L557](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L543-L557)）。
- 因此 README 的“served by the detached restart helper”是**合并说法**：HTTP 由另起的 `lib/recovery.js` 进程服务；而该脚本路径只在构建产物存在时才有（`recoveryScriptPath()` 只找 `./recovery.js`，源码 checkout 为 null，[#L460-L467](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L460-L467)）。没有脚本、没有端口或配置写失败时，helper 退回“记一行日志、不提供恢复面”的旧行为（[#L695-L714](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L695-L714)）。
- **地址**：恢复服务器只 bind `127.0.0.1`（[`src/recovery.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L1005-L1010)），每个请求先要求回环 peer（否则 403，“loopback only”，[#L898-L906](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L898-L906)）。端口取自重启请求：优先 `socket.localPort`，回退 Host 头（[`restart.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L191-L205)）——源码注释说明这是为了隧道场景不把代理端口交给 helper（#859）。
- **同一地址上的“宿主形状”**：恢复进程不只渲染页面，还答 `/dsh-market/status`（`recovery:true`、`applying`、失败摘要与 implicated 计数，[#L921-L939](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L921-L939)）、`/dsh-market/recovery`（完整 payload，[#L917-L919](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L917-L919)）、`/dsh-market/logs`（脱敏文本，[#L941-L962](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L941-L962)）；对 `/dsh-market/restart` 明确回 409“宿主没在运行”（[#L964-L971](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L964-L971)）。这正是“页面还在轮询原地址 → 由恢复进程接管回答”的接线。
- **单决定与写入**：payload 把“被归咎且可切换”的插件预置为关（[#L343-L374](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L343-L374)）；`applyRecovery()` 收到的是**完整的目标启用集合**，只对差异写：普通插件走 `disableRow`/`enableRow`，disable-carrier 额外 `addProfileBundle`/`removeProfileBundle`，失败逐条收集（[#L393-L430](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L393-L430)）。写入不完整时**不重启**，带着 `lastErrors` 回到恢复页（[#L1120-L1136](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L1120-L1136)）；新一轮启动又失败则重新解析、带着新失败再服务（[#L1144-L1146](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L1144-L1146)）。成功判据同样是端口**连续**应答 `settleMs`（默认 8s），不是应答一次（[#L497-L513](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L497-L513)）。
- **UX 的边界**：独立页确实只有两类动作——“保存并重启”和“释放端口并退出”，另加空闲 15 分钟自动释放（[#L587-L628](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L587-L628)、[#L1029-L1042](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L1029-L1042)）。所谓“只做一个决定”指**决策对象**只有一个（下次启用哪些），不是只有一个按钮；页面还允许勾选任意可切换插件、展开原始日志、点“释放端口”。
- **写入是对宿主同一持久层的复用**：`patch.ts` 与 `profile.ts` 是热开关与救生页共用（[#L38-L41](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L38-L41)）。一个容易被忽略的差异：恢复清单里**市场自己的行是可切换的**（注释明说“turn the market off and start”是逃生口），而活页面会保护宿主基础设施（[`src/routes.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L1320-L1348)）。
- **安全**：恢复页 HTML 由模板字符串生成，嵌入的只是静态文案（`scriptJson` 只转义 `<`），用户数据一律 `textContent` 填充（[#L632-L635](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L632-L635)、[#L647-L825](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L647-L825)）；写端点要求 POST + 同源（[#L973-L981](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L973-L981)），写集合不是自由输入——只有调度时交给它的插件名与行 id 能被写（[#L26-L29](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L26-L29)）。日志导出前套用 `redactHomePaths` + token/password 形状遮蔽（[#L559-L575](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/recovery.ts#L559-L575)）。

### 2. “重启会不会把我也杀掉”：三个独立闸门，不是一布尔

- **supervisor 检测**：`detectedSupervisor()` 要求“环境里有 `INVOCATION_ID` 或 `JOURNAL_STREAM`”**且**“父进程是 PID 1，或父进程 comm 为 `systemd`”；只认 systemd，pm2/launchd 明确不猜（[`src/restart.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L60-L122)）。注释给出两个真实事故：systemd 默认 `KillMode=control-group` 会连 detached helper 一起杀（#229）；`ppid===1` 只对 system unit 成立，user unit 会漏判，于是补 `comm=systemd`（#471）。
- **默认值语义**：`restartAllowed()` 是“显式值优先；未配置时 supervisor 为 null 才允许”（[#L171-L178](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L171-L178)）。所以**显式的 `allowRestart: true` 会覆盖 systemd 检测**——文档/卡片说“自动隐藏”时应带这个限定。
- **debugger 闸门**：`detectedDebugger()` 认 `inspector.url()`、`execArgv`/`NODE_OPTIONS` 里的 inspect 家族参数；它是运行时 latch，**显式 `allowRestart:true` 也不能覆盖**（[#L124-L160](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L124-L160)）。路由对 debugger 直接 403（[`src/routes.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L6794-L6816)），前端也据此隐藏按钮（[`MarketSection.tsx`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/client/MarketSection.tsx#L7082-L7095)）。
- **请求面**：重启路由先 `restartAllowed`，再 debugger，再 `trustedRestartRequest`，再运行中/已调度两个 409（[#L6803-L6822](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L6803-L6822)）。`trustedRestartRequest` 接受两条形状：**直接回环**（peer 回环、无转发头、Host 为回环 authority，[`restart.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L217-L229)）或**宿主声明过的 authority**（`dsh web --trusted-host`，[#L246-L275](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L246-L275)），并始终要求 Origin 与 Host 同 authority（[#L363-L370](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L363-L370)）。Desktop 代理那种“无 Host/无 Origin”的形状只对**自卸载**开放，不放松重启（[#L327-L348](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L327-L348)）。
- **自证字段比卡片多**：`/dsh-market/status` 同时返回 `restart`（配置/检测的结论）、`supervisor`、`debugger`、`restartReachable`（对本次请求的预测）、`selfUninstallReachable`（[#L4434-L4451](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L4434-L4451)）。`restart:true` 仍可能因反代/Origin 被 403；前端要三者同时满足才渲染按钮（[#L7087](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/client/MarketSection.tsx#L7087)），提示文案按 debugger → 不可达 → supervisor 的优先级选一句（[`market-data.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/client/market-data.ts#L360-L381)）。

### 3. 外部目录：目标自己的信任边界比 DSH 的索引源宽

- **抓取与形状校验**：`loadRegistry()` 按 region 的候选源依次尝试，每源两次；`asRegistry()` 只校验 `plugins` 是非空数组、每条有可用 category，并规范化 category/previousNpm（[`src/registry.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L203-L219)、[#L251-L360](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L251-L360)）。**没有**逐条 URL/协议/凭据/fragment 校验，也没有 format 版本号；图标与大图被当作不可信输入，交给客户端再验（[#L41-L46](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L41-L46)）。
- **源 URL 的处理**：`DSHM_REGISTRY_URL` 只做 `trim` + 去尾斜杠，然后**替换**整个候选列表；没有协议、凭据、规范形式检查（[`src/regions.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/regions.ts#L221-L225)、[#L309-L340](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/regions.ts#L309-L340)）。目标里真正执行“https + 无凭据 + 无 query/fragment”的是 **GitHub 加速前缀** `normalizeGithubProxy()`，不是目录源（[#L234-L247](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/regions.ts#L234-L247)）。
- **超时/字节/并发**：响应头 15s；正文 15s 无数据即失败；总有上限 600s；正文最多 256 MiB，边收边判（[`src/body-progress.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/body-progress.ts#L22-L53)、[#L122-L142](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/body-progress.ts#L122-L142)）。**没有** `redirect: "error"`，undici 默认跟随重定向；**没有**同 URL 并发共享 promise（源列表串行，同一源两次尝试串行）。
- **缓存**：唯一缓存是模块内存里的 `served`（ETag/Last-Modified/版本号 + 上次解析结果），每次请求都向源再验证，网络失败**绝不**回退到 `served`（[#L167-L196](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L167-L196)、[#L231-L249](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L231-L249)）。npm 载体的目录包以版本号当校验器（[`src/catalog-npm.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/catalog-npm.ts#L79-L124)），不校验 tarball integrity。
- **失败处理**：错误串带原因、耗时、尝试次数、配置的代理（proxy userinfo 被掩码），以及“更早失败过的源”各一条原因（[#L373-L394](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L373-L394)）。**凭据缺口**：`sourceKey()` 把完整 URL 拼进失败记录（[#L197-L200](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L197-L200)、[#L350-L356](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L350-L356)），两次尝试都失败时 `earlier` 会带回该 URL（[#L387-L392](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L387-L392)）；若操作者把 `user:pass@` 写进 `DSHM_REGISTRY_URL`，这段会进入横幅与导出的日志。属于窄条件下的低危泄漏（配置来自操作者自己的环境），但正好是“目标没有 DSH 式凭据剥离”的具体表现。
- **目标不消费 format-1 索引**：全仓运行时代码没有 `format: 1` 解析/`normalizeIndexUrl`；`scripts/build-site.mjs` 只是把上游校验过的 `index.json` 原样镜像到站点（[`scripts/build-site.mjs`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/scripts/build-site.mjs#L336-L360)）。因此卡片 §2.3/§2.4 描述的是**宿主**的索引源，不是本样本的目录源。

### 4. 安装/更新：来源约束与“能证明才回滚”

- 安装端点先同源（[#L7417-L7420](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7417-L7420)），再把请求 URL 与精选目录逐字匹配，不在目录里就 400（[#L7450-L7455](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7450-L7455)）；npm 目标会先 pin 到 registry 的 latest，避免 pnpm 11 的 fresh-release hold 静默装成更旧版本（[#L7456-L7505](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7456-L7505)）；GitHub 源先经 region 路由解析到 commit 再交给 pnpm（[#L7506-L7525](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7506-L7525)）。
- 构建脚本默认拦截（pnpm ≥10），放行是逐包写 `pnpm-workspace.yaml` 的 `allowBuilds`；写入用一组精确形状的正则（普通名 / `git+https` 键 / commit 或 ref 的 archive 键），不匹配的键不会写入，键还会按 YAML 规则加引号（[`src/profile.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/profile.ts#L1616-L1705)）。
- 更新按**来源**而不是名字：archive URL 装的插件只有在目录条目同时拥有该 repo 与该 npm 名时才允许按名字更新，否则 400 并保持插件不动（[#L5135-L5147](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L5135-L5147)）；git 源保留 subpath/fragment 的重建（[#L5108-L5128](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L5108-L5128)）；自更新跟随用户选的频道（[#L5148-L5155](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L5148-L5155)）。
- **回滚计划在更新前就生成**：先抓 manifest 与 lockfile 精确快照，再按来源分类决定“能否精确回滚”。Release tarball 没有不可变内容标识、monorepo subpath、commit 无法确认、lockfile 与磁盘版本不一致、npm 版本无法证明——这些情况都**明确拒绝**声称可回滚，并把人工处置写进提示（[#L5516-L5615](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L5516-L5615)）。失败后自动回滚（能证明时）[#L5703-L5712](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L5703-L5712)；事后手动回滚是一个带 `rollbackId` 的 token，且要求 profile 状态仍与操作后一致，否则拒绝（[#L7329-L7400](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7329-L7400)）。
- **安装失败**只回滚 manifest/lockfile 残留，不生成 profile 快照，也不承诺卸载已落盘的文件（[#L7758-L7770](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L7758-L7770)）。profile 快照只用于顺序变更、手动快照、快照恢复与宿主的 sanitize 恢复（[`src/snapshot.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/snapshot.ts#L39-L42)、[`src/routes.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/routes.ts#L3569-L3587)）。
- **中断更新的修复**：journal 记录 terminal facts（无提示词/环境值/路径），市场挂载后 8s 尝试修复上次中断的更新（[`src/drain-journal.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/drain-journal.ts#L1-L20)、[`src/index.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/index.ts#L24-L31)）。

### 5. 状态归属与作用域

- 市场自有持久状态是 **profile 级** 的 `<profile>/.dsh-market/state.json`（禁用集合、分组、备注、收藏、频道、region 等，[`src/hot.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/hot.ts#L215-L260)、[#L507-L520](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/hot.ts#L507-L520)、[#L648-L660](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/hot.ts#L648-L660)）；快照在 `<profile>/.dsh-market/snapshots/`，默认保留 20 份（[`src/snapshot.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/snapshot.ts#L25)、[#L231](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/snapshot.ts#L231)）。
- 开关的权威写入面是 profile 的 `cordis.patch.yml` 行 + `package.json` 的 `dsh.profile.bundles`（救生页与热开关共用）；`allowRestart` 另有一条宿主 settings 命名空间的门，仅当宿主仍有 `register()` 时存在（0.1.0-rc.7 起、0.1.7 之前）；0.1.7+ 是 `unsupported-by-host`，只剩 profile patch 一条路（[`src/settings.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/settings.ts#L131-L176)、[#L184-L200](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/settings.ts#L184-L200)）。
- **恢复面的状态在 tmpdir，不在 profile**：恢复配置 `dsh-market-restart-<stamp>.recovery.json`、stdout/stderr 日志、`.recovery.log` 全在 `os.tmpdir()`（[`src/restart.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/restart.ts#L689-L714)）。系统清理 tmp 或换机后，救生页的“失败上下文”不存在；它写回 profile 的动作则持久。
- 目录缓存是**进程内存**的 `served`，更新检查缓存 TTL 30 分钟（[`src/registry.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/registry.ts#L187-L195)、[`src/updates.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/updates.ts#L147)）；region 是模块级可变状态，跨请求共享（[`src/regions.ts`](https://github.com/dsh-market/dsh-market/blob/81d03b611d1a61cae5865c442e3e7d9cf7f6ae05/src/regions.ts#L371-L376)）。
- 作用域结论：全部是 **profile 级**，不是 session/全局；重启能力是“每个 profile 的这次 web 宿主”的能力，不是账号级。

## SRC-DSH

- `@deepseek-ai/dsh@0.2.1-rc.3` 的 `dsh-plugin-market` 才是卡片 §2.3/§2.4 的来源：配置默认 `fetchTimeoutMs = 15000`、`maxBytes = 128 MiB`、`cacheTtlMs = 600000`（`node_modules/@deepseek-ai/dsh-plugin-market/lib/index.js:364-367`）；`sources()` 每次使用前用 `normalizeIndexUrl` 复验、重复 URL 只算一次、不合规只列错误不抓取（同文件 `502-521`）；抓取用 `AbortSignal.any([lifetime, timeout])`、`redirect:"error"`（同文件 `551-560`）；同 URL 并发共享 `pending` promise（同文件 `523-548`）。`normalizeIndexUrl` 拒绝对 URL、非 http(s)、带 username/password 或 fragment（`lib/types/index-url.js:10-24`）。
- `dsh-plugin-market-index` 定义 format 1：`format` 必须为 1（`lib/index.js:284`）、commit 必须 40 位小写 hex（`30`、`187-188`）、`publishTimestamp` 为 `[0,10^11)` 的整数秒（`231`）、版本数组（`239`）、安装 spec `git+<url>#<commit>[&path:/<dir>]`（`311-317`）。
- 全有或全无的启动前提来自 `dsh-app-boot`：`auditStartupEntries` 在必需条目未激活时抛 `StartupError`，消息由 `startupDiagnostic` 生成，首行为 `… startup failed: N required plugin(s) did not activate`（`node_modules/@deepseek-ai/dsh-app-boot/lib/index.js:4421-4450`、`4464-4478`）。**这一文本形状是下一节“救生页标红能力”争议的关键**；`plugin(s) failed to load:` 与 `failed to apply loader entry …` 在本次安装的 DSH 包中检索不到（可能来自旧版或未安装的 loader 层）→ `[OPEN]`，但目标解析器的 fixture 里有第二种（`tests/boot-recovery.spec.ts:112-120`）。
- `sanitizeProfile` 确实把 `cordis.patch.yml` 改名为 `…bak-<epoch ms>` 并写一个空 stub（`dsh-app-boot/lib/index.js:1242-1245`），目标仓的 `host-recovery.ts` 就是针对这个破坏性恢复做的检测/还原（见目标源码）。
