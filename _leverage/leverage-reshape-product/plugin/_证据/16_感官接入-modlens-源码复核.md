### 2. 三条主入口（外加默认关闭的 autoRead），宿主路由都不被替换

- `[SRC-TARGET]` **工具入口**：模型显式调用 `modlens_read_image`，参数是路径/URL/附件 id；它不依赖模型选择器、不依赖 wrapper，只要 `tools`+`attachments` 可用。适合“纯文本模型 + 已落盘的图/截图路径”。
- `[SRC-TARGET]` **wrapper 入口**：`registerVisionProvider` 为每条合格上游 route 注册一个**新 provider**（`modlens-<upstream>`；`deepseek-official` 保留历史 id `deepseek-modlens`），不是给原 provider 改名。`withVision` 复制上游 model info、补 `image` modality，`listModels` 过滤 `shouldWrap` 并加 `(modlens vision)` 后缀，见 [`dsh/index.js:842-L881`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L842-L881)。`resolveModel` 每次重新读上游 `resolveModelInfo`，若模型已原生支持 image 或离开 family，抛带解释的错误，见 [`:882-L903`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L882-L903)。`stream` 在请求时把 messages 里的 image block 转成证据文本，再 `llm.stream({ ...options, provider: upstream, messages, via: providerId })` **委派回原上游 provider**，见 [`:923-L936`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L923-L936)。所以“请求仍由同一条底层 route 回答”在 stream 委派层成立，但选择器里多出来的确实是一个**新 provider route**，不是纯元数据条目。
- `[SRC-TARGET]` **paste-to-path 入口**：`webServer.register({kind:'exact', path:'/modlens/paste'})` 注册独立路由；GET 返回 takeover verdict，POST 收 bytes、25 MiB 上限、magic-byte 嗅探、写入 0600 私有临时文件并返回 `{path}`，见 [`dsh/index.js:546-L665`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L546-L665)；上限/嗅探常量见 [`:400-L438`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L400-L438)。这条路径让消息里根本没有 image attachment，从而不触发宿主 image admission。
- `[SRC-TARGET]` **autoRead（默认关闭）**：`agent/pre-step` 里在 `next()` 之后把 image block 转成证据文本，失败退化成固定解释块而不是 reject step，见 [`dsh/index.js:1525-L1559`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1525-L1559)。默认关闭是因为 wrapper 在请求时转换、且保留 durable log/缩略图，见 [`:193-L198`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L193-L198)。

### 3. 检测与准入：“absent means unknown” 有四个不同落点

- `[SRC-TARGET]` **paste takeover verdict** 采用严格语义：`pasteTakeoverVerdict` 要求 label 中出现的**每一个** model 都被“正面确认 text-only”才返回 true；`!Array.isArray(modalities) || modalities.includes('image')` 一律 false，见 [`dsh/index.js:494-L526`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L494-L526)；provider catalog 读不出来也直接 false（“unknown too, a veto rather than a shrug”），见 [`:477-L493`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L477-L493)；自己的 wrapper 与 `(modlens vision)` 标签跳过/不接管，见 [`:466-L470`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L466-L470)、[`:477-L487`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L477-L487)。这是“缺失 = 未知 = 不接管”的**唯一严格落点**。
- `[SRC-TARGET]` **wrapper 自动发现**采用另一套：`families` 默认 `['deepseek','glm','mimo']`，`matchesFamily` 按 id/bare id 前缀判断；命中 family 后**即使 `inputModalities` 缺失也返回 true**（只有显式 image、原生视觉名字、MiMo 非 `-pro` 才 veto），见 [`dsh/index.js:758-L783`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L758-L783)。只有 `families: ['*']` 分支要求显式含 `text`，见 [`:770-L776`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L770-L776)。也就是说：**默认路径把“family + 名字不像视觉模型”当作文本-only 证据，而不是把缺失当未知**。
- `[SRC-TARGET]` 文档承认这个分叉：`families: ['*']` 要求显式 `text`；显式前缀“retain the existing behavior when modalities are absent”，见 [`docs/harness-setup.md:88-L99`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/docs/harness-setup.md#L88-L99)。测试把两套语义都钉住了：takeover 的 “missing inputModalities means UNKNOWN” 在 [`src/dshPlugin.test.ts:2909-L2925`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/src/dshPlugin.test.ts#L2909-L2925)，wrapper 的 “wraps MiMo text-only pro models when catalog modalities are absent” 在 [`:3021-L3037`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/src/dshPlugin.test.ts#L3021-L3037)。
- `[SRC-TARGET]` **媒体类型**：从附件 store 读出的 `mediaType` 不在 `MEDIA_EXT` 里就抛“unsupported pasted media type …”，见 [`dsh/index.js:1863-L1873`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1863-L1873)；paste 路由以 magic bytes 定类型，不信任扩展名/Content-Type，见 [`:400-L437`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L400-L437)。
- `[SRC-DSH]` 宿主 admission 的语义又不同：只有 `inputModalities !== undefined && !includes('image')` 才拒绝（`MODEL_DOES_NOT_SUPPORT_IMAGES`）；**缺失时放行**，随后 adapter 把图片投影成 `[image omitted because this model accepts text only; attachment sha256:<8>]`，见本机 `dsh-api-session-controller/lib/index.js:940` 与 `dsh-llm/lib/index.js:559`（`dsh-llm/lib/types/content.js:49` 同文）。
- 结论：把“absent = unknown = 放过”当成全局纪律会误读该版本。它在 **takeover verdict** 和 **`families:['*']` opt-in** 成立；在 **默认 wrapper 自动发现** 不成立（缺席会被接管）；在 **媒体类型** 则“缺失就拒绝”。

### 4. 不替换宿主路由：机制与缺席退化

- `[SRC-TARGET]` wrapper 不调用 `replace` 上游 provider，而是 `llm.registerAdapter([providerId], adapter)` 新增 route；上游 provider 继续注册、继续被 `listModels`/`resolveModelInfo` 读取。上游消失时 `dropWrapper` 注销自己的 wrapper，见 [`dsh/index.js:966-L972`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L966-L972)、[`:1189-L1193`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1189-L1193)。pinned upstream 未注册时等待 `llm/adapters-updated` 而不是“对着不存在注册”，见 [`:1075-L1100`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1075-L1100)。
- `[SRC-TARGET]` web 路由用 `kind:'exact'` 的独立 path（`/modlens/paste`、`/modlens/config`），没有注册 fallback/SPA 路由；注册失败被 try/catch 成一条 console 日志，不影响工具或 wrapper，见 [`dsh/index.js:232-L253`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L232-L253)、[`:2518-L2577`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L2518-L2577)。
- `[SRC-DSH]` 宿主 `webServer.register` 对重复 `(kind,path)` 直接抛错，且 fallback 只能有一个 owner，见本机 `dsh-host-webserver/lib/index.js:326-L332`、`lib/types/index.d.ts:174`（“Duplicate (kind, path) throws …”）。所以插件不会、也不能覆盖宿主同名路由；冲突时是插件这条路由缺席，而非宿主路由被替换。
- `[SRC-TARGET]` **llm 注册面缺失**时 `registerVisionProvider` 直接 return（“quietly stays a read-only-tool plugin”），见 [`dsh/index.js:789-L792`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L789-L792)；工具注册失败也只记录，见 [`:384-L389`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L384-L389)。但 required 的 `attachments`/`agents` 缺失时整个 apply 不运行——**“缺席就退化”只覆盖 llm 注册面与 webServer/settings，不覆盖 required inject**。
- `[SRC-TARGET]` `/modlens/config` 与 `/modlens/paste` 都先过 `isTrustedRequest`：Host 必须是 loopback、`Sec-Fetch-Site: cross-site` 拒绝、Origin 必须与 Host 同源，否则 403 共享拒绝语，见 [`dsh/index.js:2295-L2324`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L2295-L2324)。这把“不起代理/不改宿主”与“新增两个本机 HTTP 面”区分开：安全边界是 loopback + 同源，不是“没有新面”。

### 6. 全部引擎失败时

- `[SRC-TARGET]` CLI 侧：链长 1 时保留该 provider 的原始错误；多 provider 全失败时抛 `Every configured vision provider failed for this image. <provider>: <error> | …`，并附 reuse hint，见 [`src/analyzer.ts:345-L360`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/src/analyzer.ts#L345-L360)；入口捕获后写 stderr、`process.exitCode = 1`，见 [`src/main.ts:101-L111`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/src/main.ts#L101-L111)。
- `[SRC-TARGET]` dsh **工具**路径：`parseCliResult` 对非零退出抛 `modlens failed (exit N): <stderr/stdout 前 500 字>`，对非 JSON 抛 `modlens produced no JSON: …`，见 [`dsh/index.js:115-L123`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L115-L123)；同一个路径的失败在 60 s 内命中缓存，见 [`:67-L107`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L67-L107) 与 `TOOL_READ_FAILURE_COOLDOWN_MS = 60_000`（[`:29`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L29-L29)）。模型看到的是错误本身（含 exit code 与 stderr 头），不是结构化 attempts。
- `[SRC-TARGET]` dsh **wrapper** 路径：`readImageBlock` 永不 reject；任何 stage 失败只 `console.error` 细节并返回**固定占位文本**：store/media/engine 三段各自一句，engine 是“A pasted image could not be read: the vision engine failed. Tell the user, and suggest running `npx @liustack/modlens doctor`.”，见 [`dsh/index.js:1566-L1573`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1566-L1573)、[`:1581-L1623`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1581-L1623)。失败缓存 60 s（`EVIDENCE_FAILURE_COOLDOWN_MS`），期间同一附件返回同一占位文本，见 [`:1284-L1321`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/dsh/index.js#L1284-L1321)。**请求继续发出**，上游文本模型收到的是这段“读取失败”的文本，不是异常，也不会自动回退到原生视觉（上游本来就没有）。
- `[SRC-TARGET]` 一个引擎都没配置：链为空直接抛 `No vision provider is set up on this machine…` 并给 agy/ gemini key 的安装提示，见 [`src/analyzer.ts:146-L151`](https://github.com/liustack/modlens/blob/ac278f885386f785dc1a35ddfbd8994bb5e744d7/src/analyzer.ts#L146-L151)；在 dsh 上仍走上面两条固定失败路径。源码里没有 toast/错误页路径，只有消息里的占位文本或工具错误（`[OBS]`）。
- `[OBS]` 这套设计的代价：**失败是 fail-open 到“告诉模型去建议用户运行 doctor”**，好处是一张坏图不会中断整轮会话；坏处是宿主日志之外没有任何“哪个引擎失败、花了谁多少额度”的痕迹，和 README 的“never silent”叙事相反。

## 复核结论与边界

1. **版本坐标可用于复现**：`@liustack/modlens@3.27.2` = tag `v3.27.2` = commit `ac278f8`；tarball 与源码归档共有文件逐字节一致。卡片无需改版本号。
2. **卡片把“dsh 集成”讲窄了**：固定版本至少有四条面——tool、wrapper provider、paste-to-path（web）、可选 autoRead hook；README 的“no hooks, no wrappers”与 `docs/harness-setup.md:61` 自相矛盾。机制正文应以源码为准：**新增一个委派型 provider route + 两条本机 exact 路由 + 可选 pre-step**，不是“只加一个元数据条目”。
3. **“absent means unknown”必须分落点写**：takeover verdict 是严格 unknown=不接管；默认 wrapper 自动发现对 family 模型 absent 也接管；`families:['*']` 才是显式 text 要求；媒体类型 absent 直接拒绝。把四者混成一条纪律会误导移植者。
4. **回退可观测性在 dsh 上不成立**：CLI 的 `meta.attempts`/`meta.warnings` 被插件丢弃；工具输出只有 result，wrapper 证据只有 summary/OCR/uncertainty，失败是固定占位文本 + console 日志。卡片“回退永不静默”应限定为“CLI 直调可见”，并补“dsh 插件面静默”的失效条件。
5. **凭据边界清楚但环境继承面宽**：插件不把 key 传给浏览器/不给 key 落副本、card 只传 `hasKey`、config 0600、错误脱敏、复用逐项 grant、空 proxy 显式直连；但它会读共享 config 判断 `hasKey`，且 spawn 继承完整 `process.env`，`MODLENS_DSH_CLI` 可覆盖 CLI 路径——移植时要替换“环境即凭据”的假设。
6. **限额存在两套**：paste 25 MiB / magic-byte / 6 类；附件 store 20 MiB / 4 类 / 归一化 ≤4 MiB。HEIC/HEIF 只能走 paste-to-path；wrapper 路径收到的是归一化后的图。25 MiB 边界无测试。
7. **全失败是 fail-open 的固定文本**：wrapper/autoRead 不 reject，tool 抛带 exit code 的错误；60 s 冷却；没有自动切回原生视觉（上游本来不支持）。卡片应把“某引擎失败链条继续”和“全失败后用户看到什么”分开。
8. **零配置是“无需新 key/新配置”，不是“无需引擎”**：无引擎时链为空、读取失败；install 命令不配置引擎。卡片应补这一句。
9. **测试强度高但非端到端**：6511 行 dsh 测试覆盖 wrapper/verdict/paste/证据 store/凭据边界；缺 25 MiB、真实宿主、`via` 计量、required inject 缺失。CI workflow 完整（3 OS × 2 Node），但该 commit 的 check-runs 本轮未验证。
