## SRC-TARGET：服务契约与生命周期

- [SRC-TARGET] Client `apply` 先创建 layout/settings store 与 service，再 `ctx.provide('workbench', service)`，之后在命名 `ctx.effect` 中挂 UI；effect cleanup 幂等卸载 React root、移除 host/style 并调用 `service.dispose()`。mount 异常被 catch、记录并立即 cleanup。故服务可先被注入者取得，而 UI mount 有独立失败边界；失败回收已实现，不等于浏览器/DSH 实测无崩溃。见 [`src/client/index.ts:1-53`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/index.ts#L1-L53)。
- [SRC-TARGET] 契约比卡片提到的六个注册 API 更宽：插件元数据、activity item、panel、editor view、status item、command、setting；另有 layout、view instance/floating window、open-path handler、查询和订阅。所有 registration 返回 disposer；各 registry 用 `Map`，重复 id throw（open-path handler 是单槽替换，disposer 只在仍是同一 handler 时清除）。方法、类型与注释见 [`contract.ts:1-40`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/contract.ts#L1-L40)、[`contract.ts:70-106`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/contract.ts#L70-L106)、[`contract.ts:177-287`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/contract.ts#L177-L287)；实现见 [`service.ts:105-195`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/service.ts#L105-L195) 与 [`service.ts:323-335`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/service.ts#L323-L335)。
- [SRC-TARGET] Registry disposer identity-checks current descriptor before deletion, preventing stale disposer from deleting a later replacement; duplicate IDs otherwise throw, so replacement requires unregister then register. Base-owned settings/entries and subscriptions are explicitly disposed; one caveat: the service's general registry `listeners` set is not cleared by `dispose()` itself, so external subscriptions still rely on their own returned disposer/fiber cleanup. See [`service.ts:114-195`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/service.ts#L114-L195) and [`service.ts:397-440`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/service.ts#L397-L440).
- [SRC-TARGET] `dock-files` requires `inject = ['workbench']`; its `apply` checks absent workbench and returns, publishing no file service/UI rather than hard-failing. Its scoped `ctx.effect`s register metadata, setting, open-path handler, activity, panel, views and status item with disposers. See [`dock-files@0.4.0 package.json`](https://github.com/AKS1st/dock-files/blob/d24224beb8cf024a9c6e79fe97445001d73150b8/package.json) and [`dock-files/src/client/index.ts`](https://github.com/AKS1st/dock-files/blob/d24224beb8cf024a9c6e79fe97445001d73150b8/src/client/index.ts). ## SRC-TARGET：状态所有权、作用域和恢复

- [SRC-TARGET] `createLayoutStore()` and `createSettingsStore()` run once per client activation. Layout is owned in memory by that store and persisted globally in browser localStorage key `dock:layout`; no session/profile identifier is incorporated. Defaults are empty tabs, right dock, autoHide off. Valid fields are selectively migrated/normalized; malformed JSON/read errors return `null` and defaults, with invalid original key retained. Writes apply in memory first and swallow storage exceptions, so unavailable/full storage gives current-session operation but no persistence guarantee. See [`layout.ts:1-35`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/layout.ts#L1-L35), [`layout.ts:48-120`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/layout.ts#L48-L120).
- [SRC-TARGET] Settings are independently owned in a second activation-local store and one global key `dock:settings`. Parse failure/non-object uses empty in-memory persisted map; unknown/unregistered setting values are retained so later plugin re-registration can restore them. Registration clones JSON-safe defaults/candidates, validates candidate and falls back to default; `set` rejects non-JSON-safe/cyclic values, but an ordinary schema-invalid value is replaced by default and persisted. Invalid raw setting candidates remain in persisted storage until registration writes back the default for that id. localStorage unavailability falls back to memory store; storage set failures are swallowed. `validate` therefore is not a throwing write gate for all invalid values. See [`settings.ts:1-64`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/settings.ts#L1-L64), [`settings.ts:130-224`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/settings.ts#L130-L224), [`settings.ts:226-298`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38/src/client/settings.ts#L226-L298).
- [SRC-TARGET] Floating geometry has additional per-view global keys `dock:floating-geometry:<viewId>`; malformed geometry is ignored, writes are best-effort. Open floating windows and editor tabs are in `dock:layout`, while this extra key remembers closed-window geometry. Thus state has no conversation/session scope in these stores; editor `sessionId` is a view prop, not a persistence partition. See [`service.ts:36-75`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/service.ts#L36-L75), [`contract.ts:16-27`](https://github.com/AKS1st/dock/blob/8535f6e24670931d9e93fb087ab474e38aa01856/src/client/contract.ts#L16-L27).
- [OBS] The default global layout can preserve open paths/tab metadata across conversation changes in one browser profile; whether that is desirable depends on whether an open view is intended to be workspace-global or session-bound. No target test establishes cross-session safety or privacy properties. Do not copy global scope into a session-oriented app without deciding ownership and path lifetime.

## Focused takeaways and open items

- [OBS] When a plugin family needs independently installable features, a provider service with typed registrations, synchronous lookup/snapshot and disposer-per-registration gives a narrow runtime collaboration boundary. Dock implements this in target source, but unlike a generic abstract registry its `openPath` handler is a single replaceable slot and descriptor IDs are global within one client activation; adapt collision policy and multi-provider dispatch deliberately.
- [OBS] When persisted data is user-editable or privacy-sensitive, make scope explicit in the key and decide whether corrupt bytes should be retained, quarantined or deleted. Here layout/settings/closed floating geometry are browser-global activation stores, not per-session; tests/source do not prove those paths are safe to share across conversations.
- [OBS][OPEN] Optional peer metadata alone does not prove graceful absence when the entry statically imports that peer. Verify module resolution/materialization behavior in the actual host before reusing the “optional UI means no activation, no crash” claim.
- [OPEN] Download and verify npm tarball bytes against SRI and compare its packaged file tree/source map to the pinned Git release; pin all sibling package manifests/commits; inspect `dock-files` filesystem routes plus DSH authorization boundary; inspect exact rc.3 runtime DOM fallback selector; run actual tests/CI or host lifecycle only in explicitly approved disposable environment.
