## 核心校正

现有样本卡不是可靠实现引用：其所称 `dsh.sidebar-right.v1.${sessionId}`、layout node `minted`、`validateReferences()` 的七点规则、比例和≈1 / split 恰二子 / 全节点可达，**在 v0.28.2 的 `src/client/state.ts` 中均不存在**。真正的插件自有持久键是 `dsh-sidebar:v1:<sessionId>`，布局是 bottom workbench 的 `bottomSplits` 树，由 `sanitizeState` / `sanitizeNode` 局部结构清理；没有独立引用完整性遍历，也不校验 `sizes` 总和为 1。见 [`state.ts:1-10`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L1-L10), [`:644-708`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L644-L708), [`:719-779`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L719-L779), [`:852-893`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L852-L893)。“split 至少 2 children”实际是源码要求，只有卡中那组 `minted` / sizes 总和 / 所有引用全可达规则不成立；以 [`state.ts:875-891`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L875-L891) 为准。

## 持久布局、结构恢复、session state

- [SRC] Storage prefix `dsh-sidebar:v1`;完整 state 被 JSON 序列化，session key 独立。`loadState()` 对 localStorage 缺失/读取或 JSON 异常回默认；schema/sanitize 失败也回默认，但**不会移除无效 key**。显式 query `?dsh-sidebar-reset` 才尝试删除该 session key，供挂载坏 tab 导致 freeze 时脱困。写操作在 200ms per-session debounce 后 `setItem`；写失败 catch 并吞掉，状态继续保存在内存。见 [`state.ts:644-708`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L644-L708), [`:1195-1216`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/src/client/state.ts#L1195-L1216)。因此卡中“坏数据主动删 key”“写失败 console.error”均不符 tagged source。

## v0.28.1 -> v0.28.2：冷 cwd fan-out 与 single-flight

- [README/CHANGELOG] 作者归因 v0.28.1 为十二个 `/sidebar/*` API 的同一 session + client cwd hint cold resolution in-flight 合并；但启动风暴其余入口绕过这个 API-local map：每个展开目录的 fs-watch 帧、`/sidebar/file|html` 资源、upload/write。v0.28.2 对 detached session 改读持久化 header，不再解码全 zstd 日志；README 公布的本机 40.2 MB fixture 测量为 12 cwd + 36 bypass 调用、1 header / 0 full read / 3ms / +0.3MB；这是**作者报告的本机测量**，不是本次重跑。见 [`README.md:101-116`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/README.md#L101-L116)、[`CHANGELOG.md:5-17`](https://github.com/omdsh-dev/DSH-better-sidebar/blob/b0e0fab50e68f54b07a1fc1e7898030409c7d979/CHANGELOG.md#L5-L17)。

The claim that this reads only a header/first zstd frame comes from plugin source/README, not a backend implementation independently examined here; the locally installed `dsh-session-persistence@0.2.1-rc.3` declaration describes `stat` as lightweight and log-free, but is not proof for RC1. - Existing sample card was used only as a list of claims to investigate and is not cited as evidence.
