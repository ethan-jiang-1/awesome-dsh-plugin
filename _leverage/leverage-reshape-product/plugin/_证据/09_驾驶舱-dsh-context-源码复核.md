## SRC-TARGET：面板数字从哪来

- `[SRC-TARGET]` **不是调 `ctx.tokenMeter` 服务**：全仓 `tokenMeter` 只出现在面向用户的一句 i18n 说明里（`src/client/i18nEn.ts:467`），没有任何 `ctx.tokenMeter`/`ctx.get('tokenMeter')`。真实读法是会话标准 props 上的 `useProjection(key)` 泛型面，键名直接取上游投影名：`contextPressure` / `contextBreakdown` / `tokenUsage`（[`src/client/sessionData.ts:13-21`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/sessionData.ts#L13-L21), [`src/client/services.ts:148-150`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/services.ts#L148-L150), [`contextModal.tsx:57-59`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/components/contextModal.tsx#L57-L59)）。这是“同源出数”的准确机制表述：读的是**宿主投影**，不是宿主服务。
- `[SRC-TARGET]` 每份投影在边界处逐字段重证并归一：`contextPressureOf` 只收三个 finite number 字段，`contextBreakdownOf` 三字段缺一即整份 `null`，`tokenUsageOf` 四桶缺一即 `null`（[`services.ts:372-402`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/services.ts#L372-L402)）。形态不对 = 视为没有，而不是补零或抛错。
- `[SRC-TARGET]` 头部占用率有一条**四级回退链**：`projectedTokens → pressureTokens → derived（上次请求 prompt + 当前 total 差）→ 折叠 current.total`，窗口取 `pressure.contextWindow ?? timeline.contextWindow`；回退来源**不写进 `Headline`**（接口只有 `tokens/window/pct/parts/reserve`），界面上无从区分“官方投影”与“自己推的”（[`src/client/headline.ts:17-47`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/headline.ts#L17-L47)）。
- `[SRC-TARGET]` 六/七色条是**估算分类 + 实测锚定**：`officialParts` 先用官方 `systemTokens/toolsTokens/messageTokens` 定三段，再把 messageTokens 按折叠面五类占比**比例拆分**、舍入余数塞给最大类（[`categories.ts:32-60`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/categories.ts#L32-L60)）；`anchoredParts` 再把整套分类**等比缩放到目标总量**（[`:62-71`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/categories.ts#L62-L71)）；Token 环用 `billedParts` 把 prompt 侧锚到 `uncached+cacheRead+cacheWrite` 实测值，输出侧按 reasoning/answer/call 内容比拆（[`:88-145`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/categories.ts#L88-L145)）。所以“分类之和 ≠ projectedTokens”是**锚定前**的事实；环上看到的是已被实测输入总量强行对齐的版本。卡里这句话要区分“总占用”和“分类环”两个口径。
- `[SRC-TARGET]` 计费桶来自**宿主侧折叠**而非投影：`assistant/message` 的 `data.usage` 读 input/cacheRead/cacheWrite/output，`record.prompt` 为三者之和，并立刻 `accumulateCost` 记入 `(provider, model, period)`（[`src/host/fold.ts:733-780`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/host/fold.ts#L733-L780)）。period 在**入桶时**按事件时间判：只有 DeepSeek 系 provider 的谷时才进 `off`，其余一律 `peak`（[`foldMetering.ts:29-57`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/host/foldMetering.ts#L29-L57)）。
- `[SRC-TARGET]` 成本是**客户端在读取时算**：`sum(cacheRead*hit + uncached*miss + cacheWrite*write + output*out)/1e6`，DeepSeek 的 `peak` 桶再乘 `PEAK_FACTOR=2`；币种按 UI locale 选，CNY 用固定 `USD_PER_CNY=0.15` 除（[`src/client/cost.ts:17-19`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L17-L19), [`:361-388`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L361-L388), [`:86-88`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L86-L88), [`:451-453`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L451-L453)）。即“账单数字”是本地估算 + 固定汇率 + 固定倍率，不来自任何计费 API。

## SRC-TARGET：价格表归属与刷新

- `[SRC-TARGET]` 价格书的 owner 是第三方库：`import { Models } from '@opencode-ai/models'`，默认 loader 直接 `Models.make().providers()`（[`src/client/modelPrices.ts:1-1`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L1-L1), [`:53-53`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L53-L53)）。插件只做 shape 收缩：`input/output` 必填且为有限非负数才收，`cache_read/cache_write` 缺失则回落到 miss 价（[`:7-44`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L7-L44)）。
- `[SRC-TARGET]` 刷新语义：**懒加载 + 单例 + 退避重试**。首个订阅者触发一次加载；失败置 `failed` 并以 `30s × 2^(n-1)`（上限 8 倍即 240s）重试，成功后清零；最后一个订阅者离开后重试停摆，新订阅会再踢一次；`reset()` 只清内存态（[`:55-72`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L55-L72), [`:74-108`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L74-L108), [`:110-119`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/modelPrices.ts#L110-L119)）。价格书**不落盘、不进 session state**，每次页面加载重取；因此“同一账单刷新前后变化”是设计内行为。
- `[SRC-TARGET]` 解析结果自带 source 与置信度：`via` 取 `direct/branch-suffix/branch-normalized/provider-alias/org-branch/canonical-maker/family/index`，confidence 取 `high/medium/low`；未知/歧义/无条目分别产出 `model-unknown`/`ambiguous(n)`/`no-entry`（[`src/client/cost.ts:25-62`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L25-L62), [`:288-334`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/cost.ts#L288-L334)）。provider 别名表是插件自己拥有的一张固定字典（`deepseek-official→deepseek`、`codex→openai` 等，[`src/shared/providers.ts:1-25`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/shared/providers.ts#L1-L25)），随插件发布更新，不随价格书刷新。
- `[SRC-TARGET]` 诚实披露做在 tooltip 里：列出命中的 `pid/mid` 与各桶单价、“按量计费”说明、未列出/歧义的 route、`canonical-maker/family/index` 三类回落的“参考估算”提示、CNY 提示、DeepSeek 峰谷提示，以及加载失败提示（[`statsContext.tsx:305-365`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/components/statsContext.tsx#L305-L365)）。注意：**未定价 route 只是从总和中跳过**（`estimateSessionCost` 内 `continue`），UI 里的总价本身没有“部分合计”标记，只有 tooltip 的 misses 段说明——这是可改进的边界。

## SRC-TARGET：状态 scope

- `[SRC-TARGET]` **会话级**：`contextTimeline/contextHeaders/contextActivity` 三份投影注册进宿主 `sessionProjections`，按 session 持久化/冷折，过期行从持久日志重折（[`src/host/index.ts:24-49`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/host/index.ts#L24-L49), `docs/compatibility.md:100-109`）。计费桶 `cost` 存在 timeline 状态里，因此也是**每会话**。
- `[SRC-TARGET]` **工作区级**：Insights 的行不是插件自建表，而是宿主 `sessions.list.getSnapshot()` 的全量会话快照里逐行的 `projectionValues`，再用 `useWorkspaces` 的 `archivedSessionIds` 判归档；父行把子孙会话的 `contextTimeline` 合并成 family、`contextActivity` 合并成活动（[`overview.ts:135-165`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/overview.ts#L135-L165), [`:177-235`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/client/overview.ts#L177-L235)）。范围 = 该宿主会话清单（工作区/未归档集合），不是跨机器。
- `[SRC-TARGET]` **日账**：按 `dayKeyOf(initiated)` 分桶并按 step 发起时刻计费，注意 `dayKeyOf` 用**宿主本地时区**（[`src/shared/days.ts:5-13`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/shared/days.ts#L5-L13), [`activity.ts:238-255`](https://github.com/bowenliang123/dsh-context/blob/32982aa6aa2c70fbda6b81281de98a72ea625001/src/host/activity.ts#L238-L255)），而峰谷判定固定按北京时区（`foldMetering.ts:29-35`）——**两套时间基准并存**：非北京部署里“日界”与“峰谷界”会错开，兼容文档的日账 Limitation 只讲了“发起 vs 结算”时点差，没讲时区差。

## SRC-DSH：上游接缝对得上什么、哪里漂了

- `[SRC-DSH]` 三份投影确实由上游 token-meter 注册：`contextBreakdown`、`contextPressure`、`tokenUsage` 三个 key 与四桶字段（`uncachedInputTokens/outputTokens/cacheReadTokens/cacheWriteTokens`）都在（本机 rc.3 `dsh-token-meter/lib/index.js:199-202,448-451,394`）。插件读键名成立。
- `[SRC-DSH]` **占用率镜像有精度漂移**：上游 rc.2 与 rc.3 的 `contextOccupancy()` 都是 `Math.min(100, Math.round(used/window*100))`，即**整数百分比**，且只有 `projectedTokens ?? pressureTokens` 一个来源（[rc.2](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/client/ui-conversation/src/client/context-occupancy.ts#L20-L27), [rc.3](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.3/packages/client/ui-conversation/src/client/context-occupancy.ts#L20-L27)）；插件 `occupancyPercent` 是 `Math.round(tokens/window*1000)/10`，**一位小数**，并加四级回退（`headline.ts:13-15,36-41`）。因此同一会话里面板可显示 67.4%，输入框环显示 67%——卡上“复用同一公式”要改成“同源口径、不同精度、多了回退”。
- `[SRC-DSH]` 其余镜像对得上：`estimate.ts` 的 `CHARS_PER_TOKEN=4`/`BLOCK_OVERHEAD=4`/`ROLE_OVERHEAD=4` 与 system 只加 role 的写法（本机 `dsh-token-meter/lib/types/estimate.js:1-24`）、`fileHandleText` 的“路径不可达”分支（本机 `dsh-llm/lib/index.js:614-621`，并经 `route-pricing` 的 `priceSurface` 以 handle 文本计价）、`compaction-basic` 默认 `thresholdRatio=0.8`、`headroomTokens=65536`（本机 `dsh-compaction-basic/lib/index.js:15,63-64`）。插件镜像的是出厂默认值这一限制，兼容文档已自述。
- `[SRC-DSH]` 双门禁叙述成立：宿主在 `engines.dsh` 存在时**只看它**，否则回落到 `@deepseek-ai/dsh*` peers（本机 `dsh-app-boot/lib/index.js:252-304`）。本机 rc.3 内**没有**任何读取 `dsh.compatibility.dshReleases` 的代码（安装树 `@deepseek-ai/*/lib/*.js` 的 grep 无命中，未逐包穷举），它是给插件市场/安装证据用的声明；仓库测试把这份枚举与基线、CI 拉取的 tag 三者锁死（`tests/compat/manifest.spec.ts:20-40`）。

## 与样本卡需要对齐的几点

1. **版本**：卡上 `0.78.2` 正确，且**能**钉到 `32982aa6`；本轮 gitHead=t 一致，无需“用 HEAD 推断发布行为”的免责。
2. **“读 ctx.tokenMeter”**：准确说法是“读宿主 `contextPressure/contextBreakdown/tokenUsage` 三份**投影**（`useProjection`）”，不是调 tokenMeter 服务。
3. **“复用官方占用率公式”**：同源但**精度不同**（整数 % vs 一位小数）、**多了三级回退**；这正是“面板数字与输入框环差一格”的机制来源，卡上应保留这条张力，不要写成“完全一致”。
4. **“分类之和 ≠ 总量”**：环图实际把分类**等比锚定到实测输入总量**；不等发生在锚定前的估算面。卡上这句话需要限定口径。
5. **“价格表=models.dev”**：成立，但 owner 是第三方 `@opencode-ai/models`（devDependency → 打进 client bundle），刷新是页面级懒加载+退避重试、不落盘；价格数据是内置快照还是联网取，`[OPEN]`。成本=列表价×固定倍率+固定汇率，不是账单。
6. **缺数据**：多数路径是“缺就不画/不算”，但**未定价 route 的总价是部分合计**且数字本身不标注；“日界本地时区 vs 峰谷北京时区”是卡和兼容文档都没写的一条边界。
7. **未复核**：TTFT/计时卡、Fleet 的会话寻址与右栏 slot、账户余额胶囊均不在本轮 focus，卡上相关行仍只算 `[OBS]`/文档级。
