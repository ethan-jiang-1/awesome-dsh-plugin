## SRC-TARGET

### 1. 配对码：43 位、只存摘要、单次消费、120 秒窗口

- `[SRC-TARGET]` 生成：`opaqueToken()` = `randomBytes(32).toString('base64url')`，固定 43 字符；`digest()` = SHA-256，[`src/access.ts:142-L148`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L142-L148)。这与 README 的“43 位”一致，也解释了为什么码里没有 `dsh1.`/`dsh2.` 前缀（那是 App 侧密钥格式）。
- `[SRC-TARGET]` 开窗：`openPairing()` 把 TTL 夹在 `[10_000, pairingTtlMs]`，**用新窗口直接覆盖旧窗口**（新码作废旧码），内存里只有 `{digest, expiresAt}`，从不保存明文，[`src/access.ts:299-L311`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L299-L311)。
- `[SRC-TARGET]` 默认窗口 **120 秒**（可配 10 s–600 s），设备令牌 90 天（60 s–366 天）、会话 8 小时（30 s–24 h，且不得长于设备期），[`src/config.ts:396-L398`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/config.ts#L396-L398)、[`src/config.ts:433`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/config.ts#L433-L433)。
- `[SRC-TARGET]` 单次消费：`pair()` 先在串行队列外做一次“长度 ≤512 + 窗口未过期 + timingSafeEqual 摘要”的预检，避免无效猜测排队；进队列后再查一次（期间可能被新窗口替换），通过后立刻 `pairingWindow = undefined`，[`src/access.ts:320-L345`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L320-L345)。同一设备记录里只落 `tokenDigest: digestHex(deviceToken)`，[`src/access.ts:346-L358`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L346-L358)。
- `[SRC-TARGET]` 限流：失败按 `sourceKey` 计——网关传的是 `request.socket.remoteAddress`，[`src/gateway.ts:1895-L1900`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L1895-L1900)；默认窗口 60 s、**每对端 8 次**、键表上限 256，**表满时 fail closed**（未知 key 直接拒），[`src/access.ts:104-L140`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L104-L140)、[`src/config.ts:444-L445`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/config.ts#L444-L445)。有效码不消耗预算（只有 `rejectPairingAttempt` 才 `take`），[`src/access.ts:314-L318`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L314-L318)。
- **重放窗口结论**：这里的“防重放”是**一次性窗口 + 摘要比对**，不是请求级 nonce/时间戳。配对码在窗口内可被重放直到被消费；消费后重放落到 `401 authentication_failed`。设备令牌与会话 Cookie 都是 bearer，8 小时会话期内可原样重放（`assertCsrf` 只拦“无 CSRF 头的变更”，不防 Cookie 重放），[`src/access.ts:436-L443`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L436-L443)。卡片的“一次性码”成立，但不应外推成“整套协议抗重放”。

### 2. 令牌、会话与 CSRF

- `[SRC-TARGET]` 设备令牌同样是 32 字节 base64url；持久化 JSON 只有 `id`（16 字节 hex）、`label`、`tokenDigest`（64 hex）、时间戳与可选 `nativeInstanceId`，版本 1/2 都收，[`src/storage.ts:22-L31`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/storage.ts#L22-L31)、[`src/storage.ts:47-L58`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/storage.ts#L47-L58)。加载时拒绝符号链接、非普通文件、>1 MiB、重复 id/摘要，[`src/storage.ts:98-L140`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/storage.ts#L98-L140)。
- `[SRC-TARGET]` 会话是**纯内存** `Map`：key = `sha256(sessionToken)`，另存 `csrfDigest`；默认 8 h、上限 64 个，超出按 `createdAt` 淘汰最旧，[`src/access.ts:272-L296`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L272-L296)。**宿主重启 = 所有会话失效**，App 必须走 renew（设备 Cookie）换新会话。
- `[SRC-TARGET]` Cookie 形态：`dsh_ma_session`（HttpOnly）、`dsh_ma_csrf`（非 HttpOnly）、`dsh_ma_device`（path 限定到 `/mobile-access/auth/renew`）；TLS 下另发 host 前缀的孪生 cookie，[`src/http-security.ts:5-L7`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/http-security.ts#L5-L7)、[`src/gateway.ts:1837-L1868`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L1837-L1868)。变更请求要 `x-dsh-mobile-csrf`，[`src/http-security.ts:8`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/http-security.ts#L8-L8)。

### 3. 撤销：先删持久层，再杀会话，不留墓碑

- `[SRC-TARGET]` `revokeDevice(id)`：过滤掉该行 → `store.save()` → 更新内存 → 逐个 `removeSession(key,'revoked')` → 最后 `emitDevicesRemoved([id],'revoked')`；**没有写 `revokedAt`**，未知 id 返回 `false` 且不发事件，[`src/access.ts:451-L467`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L451-L467)。`resetDevices()` 同理清空并撤销全部会话，[`src/access.ts:470-L489`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L470-L489)。
- `[SRC-TARGET]` 旧版墓碑的清理发生在 `initialize()`：`snapshot.devices.filter(d => d.revokedAt === undefined)`，有删除就回写，[`src/access.ts:203-L209`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L203-L209)。**但 `revokedAt` 没有从类型/解析/`DeviceSummary` 里移除**（仅旧数据路径可见），[`src/storage.ts:17`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/storage.ts#L17-L17)、[`src/access.ts:171-L175`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L171-L175)。所以准确说法是“**当前版本不再产生墓碑**”，不是“协议里没有 `revokedAt`”。
- `[SRC-TARGET]` 拆除顺序的可观测性：事件在持久化提交后才发；监听器抛错被就地吞掉，不影响授权结果，[`src/access.ts:232-L245`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L232-L245)。

### 4. 网关拓扑：自有 TLS 监听 + 回环上游 + 一枚共享上游 Cookie

### 7. 失败边界：谁死了会发生什么

- `[SRC-TARGET]` **进程模型**：网关与 DSH 同进程（`startGateway` 在插件里 new 出 listener）。所以“宿主死”= 网关一起死，没有任何 supervisor；手机侧看到的是连接失败/重连，而不是网关返回 5xx。
- `[SRC-TARGET]` **上游被单独打断**（DSH 的 3080 不可用、或认证 cookie 交换失败）：代理返回 `502 upstream_unavailable`，超时返回 `504 upstream_timeout`，[`src/gateway.ts:2746-L2820`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L2746-L2820)、[`src/gateway.ts:3035-L3123`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L3035-L3123)。**但 `/mobile-access/health` 永远 200 `{ok:true}`**，它只证明网关活着，不证明上游活着，[`src/gateway.ts:2173-L2176`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L2173-L2176)。三个 API 超时的默认值：`upstreamTimeoutMs 30 s`、`upstreamApiTimeoutMs 0`（**API 请求不设总超时**），[`src/config.ts:441-L443`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/config.ts#L441-L443)。
- `[SRC-TARGET]` **网卡消失**（保存的 LAN 接口不在了）：网关进入 dormant，每 2 s 轮询，DSH 继续运行；非“网络选择”类错误仍然向外抛、让启动失败，[`src/plugin.ts:896-L910`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/plugin.ts#L896-L910)。
- `[SRC-TARGET]` **发现通道降级**：Windows 上 TCP/UDP 端口排除表不同，UDP 可能被拒；这被记为 `discoveryError` 而不是启动失败，[`src/gateway.ts:1367-L1376`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L1367-L1376)。
- `[SRC-TARGET]` **证书/身份**：默认 `instanceId = sha256(absolute(stateFile))`；若提供 `pairingCaFile`，其 `fingerprint256` 必须等于 `instanceId` 且自签，否则启动失败，[`src/gateway.ts:1518-L1524`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/gateway.ts#L1518-L1524)。**移动 state 目录会改 `instanceId`**（路径变），旧 CA 钉随之失配；显式 `instanceId` 才能跨路径保留。
- `[SRC-TARGET]` **关闭**：`close()` 先等持久化队列排空，再清空配对窗口与会话，[`src/access.ts:530-L547`](https://github.com/saya-ch/dsh-mobile/blob/86286af1f874507309ab0c7ad28030a553267a77/src/access.ts#L530-L547)。
