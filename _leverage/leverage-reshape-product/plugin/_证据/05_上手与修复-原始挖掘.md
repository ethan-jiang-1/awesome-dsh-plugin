### 1.1 导入流水线（README:150-158）

```text
Select ZIP → validate file → check integrity → check schema → compatibility check
    → scan contents → build import plan → migration consult (verdict + evidence)
    → choose what to import → per-item conflict decisions → path mapping / secrets re-entry
    → confirm import → auto-backup current config → apply → validate → done
                      │
                      └─ failed midway? → automatically restored (rollback, can be switched off on the confirm page)
```

### 1.2 外部来源：翻译，而不是第二套导入器（README:340-345）

> - **30 sources recognized** — Claude Code, Hermes, Cursor, Codex, Antigravity, Gemini, OpenCode, Mimocode, ZCode, Grok Build, OpenClaw, Pi, Kimi, Kilocode, Qoder, ChatGPT, WorkBuddy, Qwen, Continue, Cline, Goose, Zed, Crush, TeleAgent, Trae, Vibe, Reasonix, Copilot, and DSH itself … Sources **not** installed on this machine are still listed (greyed out, not selectable), so "this machine has no such tool" is never mistaken for "the feature is missing".
> - **Translation, not a second import path** — the source is converted into a standard bundle v1 ZIP and handed to the **existing** import wizard: same preview, same per-item conflict decisions, same pre-import snapshot and rollback, same dry-run.

同节还给了"诚实跳过"的原文：没有记录 `cwd` 的对话无法放置，报 skipped，"never guessed into some other project"。

### 1.3 冲突：不提供"稍后"（README:327）

> Note: a "decide later / review" option is intentionally **not** offered — an undecided conflict would block the import from proceeding. Every conflict must be resolved before continuing.

### 1.4 读不到就写读失败（README:290）

> **unreadable sections say "loading / read failed" instead of a fake 0**

### 1.5 密钥（README:351-354）

> | Default backup | **No secret values at all** — only records which keys are needed |
> | Encrypted backup (explicit opt-in) | scrypt + AES-256-GCM, random salt & IV per export; secrets never leave as plaintext, and the password is **never written to the file** |

### 1.6 安装坑（README:183-224）

- 发布年龄闸：`minimumReleaseAge` **按版本、在解析时**评估；约 30 天内对 `@latest` 不可见，且每发一版都重新计时（README:183）。给 `minimumReleaseAgeExclude` 的修法在 188 行之后。
- 全局旧副本遮蔽：安装后 DSH 的兼容性检查会**重新解析** patch 行里的包名，Node 解析链吃 `NODE_PATH`；全局 npm root 里的旧副本会让它报一个"pnpm 从没装过的版本"并回滚（README:222）。
- git 源要跑 `prepare`：pnpm 11 默认拦截，报 `ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`，需把打印出的完整行（含 sha）写进 `allowBuilds`。

### 1.7 其它可复核的说法

- profile 目录（`$DSH_HOME/profiles/<name>`）**不进备份**，由 Environment → Profiles 单独管理（README 开头 "What is this?" 段落）。
- 定时备份保留策略：last N + 每月一份 + 每年一份，连续失败标红（README:约 4459 字符处）。
- 配置市场：供应链警告始终显示，**每个分区必须显式批准**才写入（同上）。

### 2.4 发现规则（README:141 起）

> Claude Code fork sessions … the main-transcript test looks at **both ends** of the file: if the file name's stem appears at either end, the file owns that session. ## 三、`EasonMWS/dsh-plugin-health`（README 24,902 字符）

**坐标**：`data/plugins/EasonMWS__dsh-plugin-health.yml`（`dev`）· npm `dsh-plugin-health` · 版本 `1.1.0`
**指标（2026-10-31）**：★ 4 · npm 近 30 天 4,377
**注**：registry 条目的描述仍是旧的"只读 `plugin_health` 工具"，与 README v1.1 的修复能力不一致。

### 3.1 四层（README:29-36 表格，37 行结论）

> | **1** | **Detect** | Scans every installed plugin — bundles, `dependencies`, `cordis.patch.yml` inserts (including nested ones) and `node_modules` — and compares each declaration against the version you actually run |
> | **2** | **Verify** | Rehearses the rejected plugin in a **throwaway DSH home**: grants the exemption *there*, installs it, boots it, checks every entry activated |
> | **3** | **Repair** | If the rehearsal booted, writes a single official `allow-version` exemption to *your* profile — recorded, one click to undo |
> | **4** | **Escalate** | If it did not boot, changes nothing and offers two real decisions |

> **Layer 2 is the reason this exists.** Without it, layer 3 is a guess.

### 3.2 顺序即安全（README:54-70）

```text
scan finds a rejected plugin
  ↓
rehearse in a throwaway home: exempt the gate, then really boot it   ← your profile is untouched
  ├─ it boots → the code is fine, only the declaration is stale
  └─ it fails → genuinely incompatible; exempting it would not help
```

> **The order is the safety property.** Exempt-then-test leaves you running a plugin the gate no longer warns about but which still crashes.

三个实测例子（README:41-49）：`@nanmicoder/dsh-agent-teams@0.1.27` 被拒但 94 个入口全激活；`dsh-find-plugin@0.4.0` 被拒但能跑；`@feng0531/dsh-vcs@0.4.10` 被拒且起不来（等一个宿主不再提供的服务）。

### 3.3 宿主起不来的三条命令（README:141-158）

> `dsh-plugin-health boot diagnose --profile desktop` … `boot safe --profile desktop --apply` … `boot restore --profile desktop --apply`

> `boot safe` only appends `disabled: true` overlays to the profile's own patch layer: **no files are deleted, no plugin is modified, host entries are never touched, and this tool never disables itself**. Both default to a dry run; add `--apply` to write.

### 3.4 打扰与安全（README:237、99、约 100 行附近）

> - **If nothing is wrong, nothing is shown.** The plugin adds no badge, no banner, no sidebar entry.

> | Use DSH's official `allow-version` exemption | ❌ modify plugin source or anything on npm |

安全通告（README:约 93 行）：1.1.0 修了 1.0.2 的 7 个问题（含一个 high）——写路由的 control key 曾由**未认证的 status 端点**下发；回环接口即信任边界。

### 3.5 影响力证据（README:198-210）

> Scanning the top 120 plugins across a host bump found 5 that load on `0.2.1-rc.2` but are rejected on `0.2.1-rc.3`. Reports were filed for each, and maintainers acted — **4 of the 5 have shipped fixes** (verified 2026-10-26), and the count of affected plugins went **5 → 1**.
