# 会话搬家 · dsh-chat-import:让旧对话在新家里继续说话

> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3`（声明兼容 `0.1.5-rc.1+`，0.1.x / 0.2.x 都验过） · **读于**:2026-10-31
> **类**:`4` 上手 · **层**:**6**（首启）→ 3（槽位：侧栏面板）→ 7（反向导出）
> **★ 270 / npm 月下载 15,185**（2026-10-31；GitHub API + npm last-month）
> **一句话**:用户换 agent 时，最舍不得的不是配置，是**几百个已经聊过的会话**；它把这件事做成"侧栏一个按钮 → 勾选 → 导入"，并且可以**撤回**、可以**搬回去**。

## 1. 它在产品里的位置

| 七层 | 动作 | 说明 |
|---|---|---|
| **6 首启** | 装完之后，把旧 agent 的会话变成"可以继续聊"的会话 | 不是"看历史"，是**可续聊**（resumable） |
| 3 槽位 | 左侧栏一个入口 + 一个导入窗口 + 一个 History 页 | 它没有另起页面，挂在会话列表旁边 |
| 7 分发 | 反向导出回 Claude Code | 让数据可以带走，降低"试一下"的心理成本 |

### 1.1 它和 `42_环境搬家` 的分工

两张卡都在 4 类，但搬的东西不同，机制也不同：

| | `42_环境搬家` | 本卡 |
|---|---|---|
| 搬什么 | 设置 / 插件 / MCP / 技能 / 工作区 / 全局指令 +（顺带）会话 | **只搬会话**，但搬得深 |
| 核心难点 | 冲突裁决、路径映射、密钥重填、回滚 | **发现、保真、身份判定、可撤销** |
| 确认方式 | 计划 + 逐项冲突 | 逐行 dry-run 预览 |
| 失败处理 | 自动回滚 | 列出解析器放弃原因 + 给下一步 |

> **抄这条判断**：数据迁移不是一种产品，是**按数据类型分的几种产品**。配置迁移怕"覆盖错"，会话迁移怕"认错人"。

### 1.2 为什么"可续聊"是分界线

导入一段历史有两种做法：

- **只读归档**：把旧记录塞进一个"历史"列表。用户得到的是墓碑。
- **可续聊**：重建 DSH 的会话日志，让模型下一次发言时**看得到上下文**。

只有后者改变交互契约。这也是它必须处理"工具调用、推理、系统提示"保真的原因——**上下文不完整，续聊就会答错**。

## 2. 机制（可照抄的部分）

### 2.1 发现：每个来源都有"它自己的真相"

README 把几个来源的发现规则写到了行级，这几条最能说明"为什么迁移难"：

| 来源 | 真相在哪 | 坑 |
|---|---|---|
| **Codex** | 标题优先读 `session_index.jsonl` 的 `thread_name`（用户在 Codex 里改过名也跟着走）；没有索引才回落到第一条真实用户消息 | 标题索引要**逐行流式**读，最后一条合法记录胜出 |
| **Codex 时间** | 在转录的**头尾两个有界窗口**里取最新合法时间戳，跨 rollout 页合并；都没有才用文件 mtime | 一条被截断记录里的时间戳会漏 |
| **Claude Code fork** | fork 的转录开头是父会话的逐字拷贝，后面才是自己的；所以"主转录"判定要看**文件两端** | 只扫末尾 → 被当成子代理辅助转录整份跳过 |
| **会话身份** | 取转录里**最后一条** `sessionId` | 取第一条 → fork 会被认成父会话 |
| **Cursor** | 按 conversation id 优先读本地 workspace 注册表，**只接受真实存在的目录** | 目录不存在还硬导 → 挂到一个不存在的 workspace |
| **Windows Hermes** | 同时扫 `%LOCALAPPDATA%\hermes`、`~/.hermes`，再回落 `~/AppData/Local/hermes` | 只认一个路径 → 一半用户说"没有我的数据" |

> **抄这条**：发现逻辑要写成一张"来源 × 真相位置 × 失效模式"的表，而不是一个 `if/else` 堆。**每加一个来源，先回答"它的身份字段是什么、时间从哪来、主转录怎么判"。**

### 2.2 预览：一次真解析，但零副作用

**双击一行**打开预览，它是**只读 dry-run**：

- **插件注入跳过**：预览不触发别的插件往上下文里塞东西；
- **工具调用折叠成一行**：长记录也能一眼看完；
- 不改任何文件、不建会话。

> 这条比"弹一个确认框"贵得多，但它是"敢点"的来源：用户在看的是**真实解析结果**，不是一句"将导入 N 条"。

### 2.3 导入：勾选、拖拽、或从任意文件

三条路径，同一套解析器：

1. **勾选列表里的行** → 一键导入；
2. **把行拖到左栏的 workspace 上** → 按那个 workspace 导入，并把**时间戳平移**让新会话排在最上面；
3. **Import from file** → 任意本地文件或目录，三级探测：**显式格式 > 内容标记 > 逐个解析器试**；目录会先问"要不要搜子目录"。

第 3 条的关键在失败路径：**每个候选解析器放弃的原因都会列出来**，然后给一条**可直接发给 agent 的任务说明**，并注册一个 `dsh-chat-import-convert` 技能。

> **抄这条**：解析失败时，产品应该交付的是"下一步"，不是"格式不支持"。

### 2.4 保真：保留什么、折叠什么、丢弃什么

| 内容 | 处理 |
|---|---|
| reasoning、工具调用结果 | 保留 |
| 系统提示 | **可选**（默认不保留？——README 写 "system prompts (optional)"） |
| 插件注入 | 预览时跳过；导入时按来源能拿到什么算什么 |
| 无法放置的会话 | 没有 `cwd` → 报"跳过"，不猜项目 |
| 超大转录 | 分块流式导入，不设内存上限（`maxTranscriptBytes`） |

### 2.5 反向与撤回：把"单向门"拆掉

| 能力 | 入口 | 为什么重要 |
|---|---|---|
| **Retract Import** | History 页，逐条删除**本插件创建过**的会话 | 导入错了不用重装/清库 |
| **Export** | 上下文工具，序列化回别的 agent 格式 | 用户随时能走，反而更敢来 |
| **Ignore** | 自动登记（归档/删除/移除 workspace）+ `/ignore` `/unignore` | 避免"每次扫描都把你删掉的东西又找回来" |

> **抄这条**：迁移产品要把**入口和出口**一起设计。只做入口的产品，用户的第一反应是"先备份一下再说"，转化率就死在这。

### 2.6 给第三方留一个宿主服务

它暴露 `chatImport` 宿主服务：`scanDiscover()` / `importPath()` / `importAll()` / `resumeSummary()`，第三方插件可以复用同一条发现/导入/批量/交接摘要流水线；**服务不存在时调用方要优雅降级**。

> 这是"厚客人"的典型做法：能力不只给自己的 UI 用，也给别的插件用，但**用可选服务表达**，不强制依赖。

## 3. 体验

### 3.1 首次使用逐屏

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装 | `dsh plugin --profile web add dsh-chat-import` + 重启 | 声明兼容 0.1.5-rc.1+，0.1.x/0.2.x 都验过 |
| 打开 | 左侧栏底部「Import sessions」 | 放在会话列表旁边，符合"我在找我的会话"的心智 |
| 浏览 | 一张可搜索的表；标题搜索 ↔ **In content** 切换 | 两种搜索对应两种意图 |
| 确认 | 双击 → 只读预览 | 先看后导 |
| 导入 | 勾选 → 一键；或拖到 workspace | 批量与归位都在原地 |
| 回看 | History 页：导入记录 + 撤回 | 可逆 |
| 重复 | 归档/删除自动登记；`/ignore` 管理 | 不反复打扰 |

### 3.2 两处诚实

- 解析失败：列出**每个解析器为什么放弃**，不是一句"不支持"。
- fork 会话：**明确保留父会话那一段拷贝**，因为"fork 的上下文里真的包含它"——父与 fork 因此有一段历史重叠。README 把这个"冗余"写出来，而不是静默去重。

> 第二句尤其值得抄：**保真与去重冲突时，选保真，并把代价写出来。**

### 3.3 模型看到的

- 导入后，模型在续聊时看到的是**重建的会话上下文**（工具调用、推理按保真规则保留）。
- 它自己提供的工具（`import_chat` 等）**默认注入上下文**，照顾 TUI 用户；设置里可改成不注入/部分注入以省 token。
- 预览时插件注入被跳过——**模型不会因为"看了一眼"就被塞进别的插件的上下文**。

## 5. 借鉴食谱表（本卡的产出物）

| 要解决的问题 | 照它的做法 | 你要改的地方 | 抄错的后果 |
|---|---|---|---|
| 用户有一堆旧数据不敢搬 | **入口 + 只读预览 + 可撤回 + 反向导出**，四件一起给 | 撤回范围要限定"本插件创建的" | 缺撤回 → 用户不点；缺出口 → 用户不敢试 |
| 支持很多来源 | **一张"来源 × 身份字段 × 时间来源 × 主转录判据"的表** | 每个来源先定身份规则 | 用统一 `id` 猜 → 认错会话 |
| 预览怕有副作用 | **dry-run 跑真解析器，但跳过插件注入、折叠工具调用** | 明确"预览不写、不注入" | 预览触发副作用 → 用户再也不敢预览 |
| 来源不在支持列表 | **任意文件/目录 + 三级探测** | 探测顺序写死（显式 > 标记 > 试） | 只认白名单 → 长尾全丢 |
| 解析失败 | **列出每个解析器放弃的原因 + 一条可发给 agent 的任务说明** | 任务说明要能直接粘 | 一句"不支持" → 用户流失 |
| 会话归到哪个项目 | **拖到 workspace + 时间戳平移** | 平移规则要可预期 | 随机排序 → 新导入的被埋到底部 |
| 重复扫描 | **归档/删除/移除时自动登记 + `/ignore` 管理** | 登记表要可查看可撤销 | 删了又回来 → 用户以为没删掉 |
| 身份判定 | **取最后一条 `sessionId`；fork 看文件两端** | 写清"为什么不是第一条" | 取第一条 → fork 被认成父会话 |
| 保真 vs 去重 | **选保真，并写出重叠代价** | 重叠要可解释 | 静默去重 → 上下文缺一段，续聊答错 |
| 给别的插件用 | **可选宿主服务 + 缺席时优雅降级** | 服务接口要版本化 | 硬依赖 → 别人装不上 |

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 来源格式不认识 | 三级探测全失败 → 列出放弃原因 + 任务说明 + 转换技能 |
| 会话没有 `cwd` | 报"跳过"，不猜项目 |
| 单个来源文件损坏 | 计入诊断警告（malformed JSON / 文件系统错误），不中断其余 |
| Codex 标题索引缺失 | 回落到第一条真实用户提示（排除注入的页面上下文） |
| 转录被截断 | 截断记录里的时间戳可能漏，其余照导 |
| 目录不存在（Cursor） | 只接受真实存在的目录，不硬导 |
| 导入重复 | 手动隐藏行 / 回收站 / `/ignore` |
| 宿主服务缺席 | 第三方调用方优雅降级 |
