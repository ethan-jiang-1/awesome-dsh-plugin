# 闭环装配 · better-session:一个 bundle 就是一条闭环

> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3`（README 未写死版本；机制只用 `dsh.bundle.patch` 与槽位） · **读于**:2026-10-31
> **类**:`1` 壳与工作台 · **层**:**3**（槽位）→ 5（默认值）→ 4（身份/preset）
> **★ 9 / npm 月下载 8,561**（2026-10-31；目录外样本，只有 npm 口径）
> **一句话**:它把五个包（会话分支、会话库、消息动作、会话管理器、引用）装成**一条闭环**：就地编辑 → 撤回 → 重试 → 分支。装一个 bundle，五个包一起到位。
> **借鉴价值**:**① bundle 的边界是「一条闭环」,不是「一组相关功能」;② 它插的行与那些行要的配置值住在同一个包里——装配数据(rows)是发布物;③ 官方前端不 fork,只挂它的槽位;④ 一个作者按领域切五个 bundle,而不是一个巨包;⑤ 连 agent preset 的行清单都可以归某个 bundle 所有。**

## 它想干什么 · 为什么值得借鉴

**意图。** 把“改一句话、重试一轮、回到某个节点、从某处分叉”做成**一条闭环**：五个包咬合在一起，缺一个就不完整。它要交付的不是五个功能，而是**“这条闭环能走通”这件事**。

**意义。** 它把 bundle 的边界从“功能组”改成“**一条用户闭环**”，并且坚持一条纪律：**它插的行与那些行要的配置值住在同一个包里**。装配数据（`rows`）本身成为发布物——这是很多 bundle 作者没意识到的一层。

**用户价值。** 用户不用理解 session-branch / session-rdb / ui-conversation-manager 这几个名字，装一个 bundle 就得到“编辑—撤回—重试—分支”的完整体验；改错了能撤回，跑歪了能从任意闭合边界重来。代价是整包升级、以及对官方槽位的依赖。

**表达（界面与交互）。** 入口长在**消息与回合的边界**上：编辑用户消息 → 内容回填输入框（**不重放**）→ 用户改完自己发；重试与分支都带确认弹窗。最关键的一处是**克制**：不 fork 官方 `ui-conversation`，只注册它的两个槽位，所以界面的“样子”仍是官方的，多出来的是“可以动手”的能力。**好交互不是多画一个按钮，而是让“重来一次”变得没有心理负担。**

## 2. 机制（可照抄的部分）

### 2.1 一条闭环的四步

| 动作 | 发生什么 | 设计 |
|---|---|---|
| **编辑** user 消息 | 撤回该消息**及其后全部内容**到输入框；**不重放** | 用户改完自己发；带确认弹窗 |
| **重试**任意闭合回合 | 就地重放该回合输入 | 带确认弹窗；`cascade: "truncate"` |
| **分支**（fork） | 从任意闭合边界派生**新会话** | 原会话保留 |
| 直接调服务 | `ctx.sessionEditor.retry(...)` / `ctx.sessionBranch.rewind(...)` / `forkFrom(...)` | 编排层与数据层分开 |

> **抄这条**："编辑"不等于"重放"。把用户的原话放回输入框、让他自己改，比替他重跑一次更安全——**改的是意图，不是请求。**

### 2.2 不 fork 前端：只挂官方槽位

- 对话外壳走**官方 `ui-conversation` 行**；
- 扩展只注册在它的槽位上：`conversation.chat.node` / `conversation.composer.dock`；
- 仓库里有一条 ADR 专门写这个决定：*不 fork 上游前端组件，只做插槽扩展*。

> **抄这条**：想在官方界面上加交互，**先找槽位，再考虑 fork**。fork 的代价在 `91_冻结分叉` 那张反例卡里已经付过一次。

### 2.3 装配数据（`rows`）是发布物

> "每个 bundle 聚合一个领域——**它插的行与那些行要的配置值住在同一个包里**……能力包只发布实现与装配数据（`rows`）出口。"

这条是本卡的核心工程判断，拆开是三层：

1. **行由 bundle 插**：bundle 的 `cordis.patch.yml` 声明它要挂哪些行。
2. **配置跟着行走**：那一行需要的配置值放在同一个包里，不散落到"设置"或另一个包。
3. **实现与装配分离**：能力包只发布实现 + `rows`（装配数据），由 bundle 组合。

> **抄这条**：把"装配"当成**一等发布物**。否则 bundle 的 patch 会变成一份没人维护的清单，而行需要的配置会在版本间漂走。

### 2.4 preset 也可以归某个 bundle 所有

同家族的 `mydsh-profile` 做了一件更激进的事：**整段复制上游 web-app 的四份 shipped preset 行清单**（standard / ptc / minimal / cordis），只改一处——删掉 `delegation` 组的 `tool-subagent-control` / `tool-subagent` / `tool-subagent-fork`，因为 **Agent Teams 用同名工具接管直连委派**，两套并存会互相遮蔽；Workflow 的 `workflow-ptc` / `tool-workflow` 保留。

它明确**不设置** `agent-preset-registry.default`——新会话挂哪份 preset 仍用官方 web-app 的默认（`standard`）。

> **抄之前先读代价**：按行 id **整段替换** `config.plugins` 是上游语义，"不合并后续内置变更"。**上游改了 preset 行清单，你要跟着复制一遍。** 这就是"拥有 preset"的价格。

### 2.5 五个 bundle，按领域切

| bundle | 领域 |
|---|---|
| `better-session` | 会话编辑闭环 |
| `session-mode-profile` | 会话模式（如 `coding` 模式的 denySkills/denyTools 名单） |
| `sandbox-profile` | 沙箱 |
| `ollama-provider-profile` | 本地 Ollama provider |
| `mydsh-profile` | 个人默认值 + preset 行清单 |

> **抄这条**：一个作者很容易做一个"什么都有"的巨包；**按领域切成多个 bundle，用户按需装**，装坏了也只坏一个领域。

## 3. 体验

### 3.1 首次使用逐屏

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装 | 一条命令装整个 bundle（带上五个子包） | 不手工装依赖 |
| 重启后 | 会话里多出编辑/重试/分支入口 | 入口在消息与回合边界上 |
| 点编辑 | 确认弹窗 → 内容回填到输入框 | 不自动重放 |
| 点重试 | 确认弹窗 → 就地重放 | 明确"会覆盖后续" |
| 点分支 | 新会话从该边界开始 | 原会话不动 |
| 换存储 | 改 `session-rdb` 行的 config（默认 SQLite） | 配置跟行走 |

### 3.2 两处"克制"

- **不 fork 前端**：官方界面照旧，只在槽位里长东西。
- **插件详情页不挂长文**：`meta.detail` 指向一个空文件，详情页的"详细介绍"区是空的——**README 才是门面**，不在两个地方各写一份。

> 第二条值得抄：**同一个产品不要维护两份说明书**。要么详情页，要么 README，选一个。

### 3.3 模型看到的

- 闭环改的是**会话状态**（撤回/重放/分支），不是工具集；
- 分支产生的是**新会话**，模型在各自会话里看到各自的上下文；
- `mydsh-profile` 删掉子代理工具行的效果是：**模型少看到三个工具**（由 Agent Teams 接管同名能力）。

## 5. 借鉴食谱表（本卡的产出物）

| 要解决的问题 | 照它的做法 | 你要改的地方 | 抄错的后果 |
|---|---|---|---|
| 多个包要一起装 | **bundle 的边界 = 一条用户闭环** | 先写下闭环的四步 | 按"功能组"打包 → 用户不知道装齐没有 |
| 加交互又不想 fork | **只注册官方槽位**，写一条 ADR | 找到对应槽位名 | 改官方组件 → 上游一升级就断 |
| 装配与实现耦合 | 能力包只发**实现 + `rows`**，bundle 负责插行 | `rows` 的结构 | patch 清单没人维护 → 行与配置漂走 |
| 一个作者很多功能 | **按领域切多个 bundle** | 领域边界 | 巨包 → 一处坏全装不上 |
| 想拥有 preset | 复制上游行清单 + 只删冲突行，并写明"上游改了你得跟" | 记录上游版本 | 忘了跟 → preset 停在旧版本 |
| 两套同名工具冲突 | **删掉直连委派那三行**，让接管方独占 | 你的冲突清单 | 两套并存 → 互相遮蔽，行为随机 |
| 详情页与 README | **只留一份门面**（这里选 README） | 你的门面位置 | 两处各写一份 → 一份永远过期 |
| 编辑 vs 重放 | **编辑=回填输入框，不重放**；重试才重放 | 确认弹窗文案 | 替用户重跑 → 改错意图 |

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 只装了 bundle、子包版本漂移 | 同版本发布可避免；跨版本行为未定义（`[OPEN]`） |
| 官方槽位改名 | 扩展落空（`[OPEN]`：是否有检测） |
| 上游改了 preset 行清单 | `mydsh-profile` 需重新复制；不跟则停留在旧清单 |
| 与 Agent Teams 同装 | 已删冲突行；未删则两套遮蔽 |
| 换存储 | 改 `session-rdb` 行 config；默认 SQLite |
| 插件详情页 | 详情区为空是**有意**的；信息在 README |
