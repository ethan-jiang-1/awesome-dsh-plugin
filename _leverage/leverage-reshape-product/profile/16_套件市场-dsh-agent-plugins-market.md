## 它想干什么 · 为什么值得借鉴

**意图。** 让**别的 agent 的整套插件**在 DSH 里可用：Claude Code、Codex、Cursor、Kimi、agent-plugins.org……十种布局**就地读**，不转换 manifest、不复制文件，然后把“一套套件”变成可安装、可启停、可逐工作区控制的单位。

**意义。** 它把分发单位从“我的包”换成了“**别人的套件**”，等于给 DSH 开了一个跨生态入口。这比多支持一种文件格式重要得多：它让“从别的 agent 迁过来”从一次性迁移工具，变成了**长期可用的资源来源**。

**用户价值。** 从 Claude Code 过来的人，不用把技能、命令、persona、MCP 重新配一遍，直接在 DSH 里装同一套；缺凭据时面板会写 `needs-credentials`，而不是让工具静默失败。代价是十种布局的兼容深浅不一——能读，不等于原平台每个行为都能用。

**表达（界面与交互）。** 打开就是**八个标签页**：Market / Instructions / Skills / Commands / Personas / MCP / LSP / Hooks——按“我现在在回答什么问题”分页，而不是按技术模块。装一个套件时，先看内容再安装；hooks 有 dry run；删除来源默认**不删文件**。**它把“信任”做成了可见的步骤，而不是一句“放心装”。**

## 1. 它在产品里的位置

| 七层 | 动作 | 说明 |
|---|---|---|
| **7 分发** | 分发单位从"我的 bundle"变成"**别人的套件**" | 来源、镜像、刷新、安装、启停 |
| 4 身份 | persona、hooks、instructions 都属于"这个 agent 是谁" | 八页里三页在这层 |
| 3 槽位 | 一个八标签页的工作区 | 市场与资源管理同居一处 |

### 1.1 它是 profile 侧的第 6 种形态:**进口型**

前四种是"怎么把自己的东西装成一件"，第五种（`15_接管套件`）是"换掉宿主自带的"，这一种是"**把别人的整套东西变成你的可安装单位**"：

| 形态 | 谁的资产 | 例子 |
|---|---|---|
| 全家桶 / 组合包 / 聚合补丁 | 作者自己的插件 | `dsh-web` / `dsh-suite` / `dsh-plugin-kit` |
| 界面套件 | 作者自己的界面 | `codex-ui` |
| 接管型 | 宿主自带的实现 | `15_接管套件` |
| **进口型** | **别的 agent 生态的套件** | **本卡** |

> **为什么算产品而不是"一个市场插件"**：它没有自己的插件集合，却定义了**一整套"从哪来、装什么、挂到哪、缺什么凭据"的工作区**。市场的价值不在货架，在**安装单位与注入面的映射**。

### 1.2 它和 `51_分发与救生页` 的分工

| | `51_分发与救生页`（plugin 侧） | 本卡 |
|---|---|---|
| 卖什么 | DSH 插件（npm / GitHub） | **别的 agent 的套件**（十种布局） |
| 关心的失败 | 宿主起不来 → 救生页 | 套件装上了但能力没挂 → **诊断后跳过 + 凭据提示** |
| 单位 | 包 | **suite**（可含技能/命令/persona/MCP/LSP/hooks） |

## 2. 机制（可照抄的部分）

### 2.1 十种布局 = 一张兼容矩阵，不是一个 `if`

| 布局方言 | 典型来源 |
|---|---|
| Claude Code | `anthropics/claude-plugins-official` 等 |
| Codex / Cursor / Kimi Code / ZCode / Qoder CLI / GitHub Copilot CLI | 各自官方插件目录 |
| Universal `.plugin/` | 通用约定 |
| agent-plugins.org | 开放套件格式 |
| 无清单的技能集合 | 只要仓库里有 `skills/<name>/SKILL.md` |

README 把"支持哪些布局"做成**独立页面 + 布局审计 + 兼容报告**，而不是在正文里列一段。这是分发型产品的正确姿势：**兼容性要可审计**。

### 2.2 来源 → 套件 → 运行时：三级对象

```text
source（Git 仓库 / 本地目录 / 压缩包 / 已 clone 的 checkout）
  └─ 被发现 → suite（可安装单位）
        └─ 启用 → 注入六个面
              skills / commands / personas / MCP / hooks / LSP
```

三个语义值得抄：

1. **"来源"与"套件"分开**：来源可刷新、可镜像、可 6 小时自动更新；套件可单独安装/启用。
2. **"启用"不是"安装"**：装了可以不开；每个工作区还能各自开关六个挂载面。
3. **"自己的内容"有固定位置**：`~/.agents/` 下 skills/commands/personas 是 Markdown，`hooks.json` / `mcp.json` / `lsp.json` 是配置；项目自带的资源留在项目里（要开"Scan project Agent layouts"）。

### 2.3 六个注入面，逐个说清楚

| 面 | 注入成什么 |
|---|---|
| skills | 技能目录 + `/` 菜单 |
| commands | `/name` |
| personas | 子代理目录（带精确 provider/model/effort） |
| MCP | `mcp__*` 工具 |
| hooks | 生命周期事件 |
| LSP | 宿主 `lsp` 工具 |

> **抄这条**：把"装一个套件会发生什么"写成**六个面的一张表**，而不是一句"功能更丰富"。安装类产品的信任就建在这张表上。

### 2.4 凭据：缺了要看得见

- 远程 MCP 返回 `401` → 自动走 **RFC 9728 发现 → 动态客户端注册 → PKCE 授权**，令牌持久化；**套件不需要声明 OAuth**。
- 缺环境变量引用时，面板显示 `needs-credentials`；宿主托管的凭据是**只写**的。
- 单个 MCP 服务可覆盖声明、可单独关掉某个工具、可设工具调用与启动超时。

> **抄这条**：凭据失败是分发产品的头号"看起来装了其实没用"。**把缺口变成状态标签**，别让它变成一次静默的工具调用失败。

### 2.5 hooks 是"能决策的"，不只是"能观察"

十个事件会**应用** hook 的返回值：工具 deny / ask / allow、追加上下文、纠正性反馈、强制继续、以及 `continue: false` 的真停。每条 hook 有声明卡（事件、matcher、超时）和一次**在家目录里的 dry run**。

> **抄这条**：给用户的 hook 一定要有 **dry run**——"它会拦什么"必须先看得见。

## 3. 体验

### 3.1 首次使用逐屏

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装 | 插件页装 + 重启；或 `dsh plugin add` | 两条路等价 |
| 打开 | **Settings → Agent Plugins**，已有**一个第一方来源** | 开箱就有货，不是空市场 |
| 刷新 | 拉取该来源的套件列表 | 拉取与安装分开 |
| 看套件 | 打开 → 看内容 → 安装 → 保持启用 | 先看后装 |
| 补凭据 | MCP 页回答凭据提示 | 缺口有名字 |
| 日常 | 八标签页：Market / Instructions / Skills / Commands / Personas / MCP / LSP / Hooks | 按问题分页 |
| 换项目 | 项目自带资源需开"Scan project Agent layouts"；每工作区可存"资源窗口"收藏 | 作用域显式 |

### 3.2 三处"诚实"

- 坏声明：**诊断后跳过**，"never half-mounted"。
- 删来源：默认**不删文件**；只有勾了"同时删除受管市场目录"才删；`.sources/` 之外的本地目录永不删。
- 兼容性：明写"读一个布局不等于它的原平台每个行为都能用"。

### 3.3 模型看到的

- 套件里的 skills/commands 进模型可见的目录与 `/` 菜单；
- personas 进子代理目录（带模型与 effort）；
- MCP 工具以 `mcp__*` 出现；
- hooks 在生命周期事件上**读取返回值并执行**（含 deny/allow）。

> 这是本卡与"客户端套件"最大的不同：**它改的是模型能看见什么、能调用什么**。

## 5. 借鉴食谱表（本卡的产出物）

| 要解决的问题 | 照它的做法 | 你要改的地方 | 抄错的后果 |
|---|---|---|---|
| 想复用别的生态的资产 | **把"套件"当安装单位**，来源可换 | 先定义"一个套件包含什么" | 按文件导入 → 装一半、依赖断裂 |
| 支持多种格式 | **一张布局矩阵 + 独立兼容页 + 审计文档** | 每加一种布局补一行审计 | `if/else` 堆 → 兼容性不可审计 |
| 想跟随上游升级 | **就地读，不转换、不复制** | 源目录结构与刷新策略 | 复制一份 → 永远落后上游 |
| 装完之后能力没挂 | **六个注入面逐一说清**，并提供状态 | 注入面按你的宿主列 | 一句"功能更丰富" → 用户不知道装了什么 |
| 凭据缺失 | **`needs-credentials` 状态 + 只写凭据** | 你的凭据来源 | 静默失败 → 用户以为工具坏了 |
| 远程 MCP 授权 | **401 → RFC 9728 + 动态注册 + PKCE**，令牌持久化 | 回调与存储 | 要求套件声明 OAuth → 生态没人适配 |
| 声明有错 | **诊断后跳过，绝不半挂载** | 诊断码 | 半挂载 → 排查成本爆炸 |
| 删除来源 | **默认不删文件**，删要单独勾选 | 受管目录边界 | 一键删了用户的 checkout |
| 作用域混乱 | **逐工作区开关六个面 + 项目扫描开关** | 默认值 | 全局生效 → 项目间互相污染 |
| 给 hook 加能力 | **十个事件 + dry run + 声明卡** | 事件覆盖表 | 直接生效 → 用户不敢开 |

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 布局不认识 | 诊断并跳过，不半挂载 |
| 套件声明无效 | 同上；面板可见原因 |
| MCP 缺凭据 | `needs-credentials`；相关工具不可用但不崩 |
| 远程 MCP 401 | 自动 OAuth；失败则保持未授权状态 |
| 自动刷新关闭 | 只有手动刷新；开启后 6 小时一轮 |
| 删除来源未勾选 | 只移除来源记录，文件保留 |
| 项目资源未开扫描 | 项目自带 skills/MCP 不出现 |

## 7. 开放问题

- [ ] `[OPEN]` 十种布局里，**哪些是逐字保真、哪些只是"能读"**？兼容报告里的分级没在本卡展开。
