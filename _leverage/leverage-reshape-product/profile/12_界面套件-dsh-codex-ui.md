## 1. 它在产品里的位置

**七层坐标**:**2**(表层:整屏设置、侧栏、主题)+ **3**(槽位:会话行菜单、伴侣插件面板)+ **5**(默认值:7 套主题与材质)。它不碰 6/7 层——不提供首启向导,也不自带分发;更新走 npm。

**和 `dsh-web` 的区别**:`dsh-web` 是「**功能全家桶 + 自家商店**」,它是「**界面重做 + 伴侣插件管理**」。一个横向铺能力,一个纵向改体验。两者都是 `profile` 级产品,但一个靠**广度**,一个靠**深度**。

**它证明的事**:profile 产品不一定非要 20 个包;**一个包、六个微内核、一套设计语言**,也能在浏览器里长成一个"看起来不是原生 DSH"的产品。

## 2. 机制(可照抄)

### 2.1 微内核:六个子插件,各自可禁用

| 子插件 | 管什么 |
|---|---|
| `composer` | 终端式输入历史(`↑`/`↓`)、按工作区隔离、双拖拽调宽、上下文提示 |
| `settings-skin` | 全屏设置工作台、双浮岛卡片、Ambient Ground 光晕、原生搜索 |
| `theme` | 7 套配色、Stock Flat vs Mica Floating、3 档材质、地面反光开关 |
| `sidebar` | 就地手风琴、拖拽排序、折叠成官方 56px 图标轨 |
| `session-title` | 从首条 prompt 生成规范标题,支持 4096 token 推理输出 |
| `dependencies` | 官方/第三方伴侣插件的集中检视、版本检查、一键批量升级 |

> **照抄点**:把"界面产品"拆成**可单独关掉的单元**。用户不需要为"我只想要主题"而装整套。

### 2.2 fail-closed:禁用 = 物理清理 + 0 DOM

三条硬约束,缺一条就会出现"半降级":

1. **注入要可撤销**:token / root 属性 / 样式表都记在子插件生命周期里,禁用时**逐个撤**;
2. **设置卡跟着走**:子插件不可用 → 卡片 **0 DOM**(不是 disabled、不是灰掉);
3. **回落到宿主原生**:撤干净后界面应**和没装过一样**。

> **照抄点**:"关掉"必须等于"没装过"。只把开关关掉、样式留着,就是半降级。

### 2.3 与官方 primitive/slot 对齐,而不是覆盖

- 禁用自绘 CSS 控件,只用官方 `Switch` / `SegmentedControl` / `Button`;
- 折叠态严格对齐官方 56px 图标轨;
- 布局走官方 slot,不再劫持 DOM。

> **照抄点**:上游给 primitive 就用 primitive。**覆盖式美化 = 把上游的每次改版都变成你的 bug。**

### 2.4 1.x 的三条死因(反食谱)

| 死因 | 表现 | 正确做法 |
|---|---|---|
| **DOM/CSS 强覆盖** | 上游改 build-hash 类名 → 整页渲染崩 | 只吃 primitive/slot |
| **全局 token 无生命周期** | 关主题后 root 属性残留 → 玻璃没了、深色底还在 | 注入即登记,禁用即撤 |
| **视图覆盖不可回退** | 子功能禁用后,设置里留下点了没用的卡片 | 卡片随子插件 0 DOM |

> **这段是整张卡最值钱的部分**:作者用一次 2.0 重写,把"怎么抄错"写成了清单。

### 2.5 伴侣插件管理:把"生态检视"也做进产品

`dependencies` 子插件集中展示官方与第三方伴侣插件的**实时 npm 下载量、版本、更新**,支持一键批量升级。

> **照抄点**:界面产品的"最后一公里"是**帮用户管住他装的其他插件**——否则你的界面永远要适配一堆过期版本。

## 3. 体验

- **第一次**:装包 → 重启 → 硬刷新 → 整个界面变成 Codex 风(深蓝/纸白),侧栏折叠成原生 56px 图标轨。
- **日常**:`↑`/`↓` 翻输入历史;设置是全屏工作台而不是小弹窗;会话标题自动生成。
- **卸/禁用**:关掉某个子插件,对应设置卡**直接消失**,界面回宿主默认——不会留半截样式。

## 5. 借鉴食谱

| 要解决的问题 | 照它的做法 | 要改的地方 | 抄错的后果 |
|---|---|---|---|
| 一套界面产品怎么拆 | 六个微内核子插件,独立启停 | 子插件之间不能隐式依赖 | 拆成互锁 → 禁用一半就崩 |
| 关掉功能要回到原样 | fail-closed:撤 token/root 属性、设置卡 0 DOM | 注入必须登记在生命周期里 | 只关开关 → 半降级 + 僵尸设置 |
| 上游改版就崩 | 只吃官方 primitive/slot,不劫持 DOM | 上游没给 primitive 的地方**宁可不做** | 覆盖式美化 → 每次改版都是你的 bug |
| 主题切换要干净 | 7 套配色 + 布局/材质分离 + 光晕开关 | 切换要幂等,反复切不留残留 | 切回原主题仍有残影 |
| 生态版本拖累适配 | 内置伴侣插件管理器,一键批量升级 | 升级要有回滚/失败提示 | 用户装着一堆旧插件 → 你的界面天天报错 |
| 与同类产品冲突 | 明确写"不要与 ds-bot 同装" | 最好能在安装后**自动检测** | 两个都重做侧栏 → 布局叠在一起 |

## 6. 失效条件与降级

- **宿主版本**:声明 `0.2.x` 全系,但未来 0.3 的 slot 变更未验证。
- **冲突**:与 `ds-bot` 等同样重做侧栏/槽位的插件不能共存。
- **无首启/分发**:它不提供向导,也不自带更新通道——这两层仍由 npm 与宿主承担。
- **依赖 pnpm 11 + Node 22.19+**:低于此版本装不上或跑不起来。
