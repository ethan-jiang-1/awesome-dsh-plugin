## 卡片级别

**当前卡：概念 + 有边界的机制参考；不是行为参考。** 固定提交确实支撑 source acquisition/refresh/cache、format validation、source-qualified install state、runtime reconcile、credential records、hooks bridge 和迁移 ownership 等机制。但卡片现有 claims 须先修正才能整体升格：installed/enabled 是 user-dimension state，workspace 过滤是另一层；OAuth store 缺席则 memory-only；validate failures 可按 manifest fallback、MCP file、单 server 分别降级；dry run 不是 sandbox。尤其 current-state corruption/unknown version 会落到 empty state，缺少恢复措施。真实 DSH host 下的 UX、安全隔离和完整 peer 范围保持 `[OPEN]`，不称行为参考。
