## 一、`sidleo/dsh-plugins-plus`（README 7,036 字符）

**坐标**：**目录外**（不在 `data/plugins/`）· npm `@sidleo3/dsh-plugins-plus` · 版本 `0.2.0`
**指标（2026-10-31）**：★ 0 · forks 0 · issues 0 · 仓库 2026-09-25 建 / 2026-10-19 最后推送 · npm 近 30 天 6,094

### 1.1 交付物与命名（README:5-14）

> One DeepSeek Harness (DSH) bundle that ships **independently switchable components**, each replacing a built-in plugin per **agent preset**. Configuration lives in **DSH Settings**.

| Component (Loader row id) | Replaces | What it does |
|---|---|---|
| `dsh-plugins-plus` | — | Core row: owns the single configuration schema, the takeover engine, and the read-only status API |
| `agent-instructions-plus` | `agent-instructions` | AGENTS.md injection: four scan layers (cwd / project / every ancestor / global) with editable file names and budgets |
| `skill-filesystem-plus` | `skill-filesystem` | Skill discovery: four scan layers plus editable, orderable parent-directory names |

> Component naming rule: **built-in row id + `-plus`**. Adding a component later means one more export, one more `cordis.patch.yml` row, one schema section and one UI section — no new package, nothing to install twice.

### 1.2 安装与启用（README:18-40）

> Installation itself changes nothing: only the core row is enabled by default, both component rows ship `disabled: true`.

> Turning `skill-filesystem-plus` on makes the engine disable the built-in `skill-filesystem` row inside the selected presets and append this bundle's discovery row.
> Turning it off undoes exactly that; the built-in implementation returns, and DSH **deletes the override row entirely once the composition equals the shipped layer again**.

### 1.3 配置与作用域（README:42-66）

> Writes go through DSH's own pipeline (`ctx.configForms` → settings → config editor → the profile's `cordis.patch.yml`):
> - configuration lives in the **profile patch** under the core row; this bundle keeps no settings file of its own;
> - every field keeps inheritance semantics — "restore default" is an `unset`, falling back to the schema default;
> - saving applies immediately; the core row is not remounted (its fields are volatile).

> A session fixes its preset composition when it is created, so takeover changes affect **sessions created afterwards**.

### 1.4 与内置的差异（README:68-79）

| Dimension | Built-in | This bundle |
|---|---|---|
| Scope | every preset | only the presets you select (global selection may mean "all") |
| Upward scan | stops at the project root (`.git`) | `scanProject` or `scanParents` (up to `/`), mutually exclusive |
| Skill parent directories | fixed | add, edit, remove, reorder |
| Configuration | a JSON file per plugin | DSH Settings (profile patch) |

## 二、`Sivan757/dsh-agent-plugins-market`（README 11,879 字符）

**坐标**：`data/plugins/Sivan757__dsh-agent-plugins-market.yml`（`market`）· npm `dsh-agent-plugins-market` · 版本 `0.13.0`
**指标（2026-10-31）**：★ 19 · forks 1 · issues 6 · 仓库 2026-08-18 建 / 2026-10-31 最后推送 · npm 近 30 天 4,752

### 2.1 定位（README:5-9）

> **A one-stop skills, subagent, MCP and LSP manager inside DeepSeek Harness (DSH).**
> Run Claude Code, Codex, Cursor, Kimi and agent-plugins suites inside DSH. The plugin reads each layout in place, so you **convert no manifest and copy no file**.

### 2.2 核心能力（README "Core" 小节）

> - **Any skill repository works.** Add a Git URL whose repository holds `skills/<name>/SKILL.md` and the market discovers it as a suite. No manifest, no conversion, no file copying.
> - **Ten suite layouts.** Claude Code, Codex, Cursor, Kimi Code, ZCode, Qoder CLI, GitHub Copilot CLI, Universal `.plugin/`, agent-plugins and manifest-less skill collections.
> - **Runtime injection.** Enabled suites add skills to the catalog and slash menu, commands as `/name`, agent personas to the subagent catalog, MCP tools as `mcp__*`, hooks to lifecycle events, and language servers to the `lsp` tool. Installing the plugin is the whole LSP setup.
> - **One workspace.** Eight tabs cover the market, the instructions injected into a session, the resources you author, and the services that run.

### 2.3 高级能力（README "Advanced" 小节）

> - **MCP OAuth with nothing to declare.** A remote MCP server that answers `401` starts RFC 9728 discovery, dynamic client registration and PKCE authorization in your browser, and the granted token persists. OAuth is on by default.
> - **Hooks that decide, not just observe.** Ten events apply what the hook returns: tool deny, ask and allow, added context, corrective feedback, a forced continuation, and a real halt for `continue: false`.

### 2.4 八个标签页（README "Everyday use" 表）

Market / Instructions / Skills / Commands / Agent personas / MCP services / LSP servers / Hooks。每个标签页有搜索、过滤、网格或列表视图。

### 2.5 兼容与降级（README "Compatibility" / FAQ）

> Reading a layout does not guarantee every behavior of its original platform. **Invalid declarations are diagnosed and skipped, never half-mounted.**

> **Does removing a source delete its files?** Only when you tick **also delete the managed market directory** in the confirmation. A local-directory source outside `.sources/` is never deleted.

> Missing environment references show `needs-credentials`. Host-managed credentials are write-only.

## 三、`morlay/dsh-plugin`（根 README 5,306 字符；`better-session` README 另计）

**坐标**：**目录外** · npm `@morlay/better-session`（bundle）· 版本 `0.1.10`
**指标（2026-10-31）**：★ 9 · forks 4 · issues 0 · 仓库 2026-08-17 建 / 2026-10-30 最后推送 · npm 近 30 天 8,561

### 3.1 bundle 的组织原则（根 README:3）

> 一个工作区 profile = `dsh.profile.bundles` 顺序应用的一串 bundle patch；**每个 bundle 聚合一个领域——它插的行与那些行要的配置值住在同一个包里**（面向模型的功能行清单由 `packages/bundles/mydsh-profile` 复制上游四份 preset 并声明，删掉与 agent-team 冲突的子代理工具行），能力包只发布实现与装配数据（`rows`）出口。

五个 bundle：`better-session` / `session-mode-profile` / `sandbox-profile` / `ollama-provider-profile` / `mydsh-profile`；能力包在 `packages/<family>/<pkg>`，family 只是目录分组。

### 3.2 better-session 的闭环（`packages/bundles/better-session/README.md`）

> profile 聚合 bundle：一次性装配 `@morlay/session-branch`、`@morlay/session-rdb`、`@morlay/ui-conversation-message-actions`、`@morlay/ui-conversation-manager`、`@morlay/dsh-reference` 到 DeepSeek Harness 的 profile，提供**就地编辑 / 重试 / 撤回 / 分支**（rewind / retry / recall / fork）闭环。对话外壳走**官方 `ui-conversation` 行**，我们的扩展只注册在它的槽位上（`conversation.chat.node` / `conversation.composer.dock`）。

> - **编辑** user 消息 → 撤回该消息及其后内容到输入框（rewind，不重放），用户改后自行发送（带确认弹窗）
> - **重试** 任意闭合回合 → 就地重放该回合输入（带确认弹窗）
> - **分支**（fork）→ 从任意闭合边界派生**新会话**

服务 API 示例：

```ts
await ctx.sessionEditor.retry({ action: "retry", sessionId, turn: 2, cascade: "truncate" });
await ctx.sessionBranch.rewind(sessionId, 5);
await ctx.sessionBranch.forkFrom(sourceId, { atSeq: 6, childSessionId });
```

配置：默认 SQLite `$DSH_HOME/sessions/sessions.sqlite`；改配置就是改 `session-rdb` 那一行的 config。

> **插件页不挂长文**：`locale/*.json` 的 `meta.detail` 指向空文件 `docs/detail.md`，所以 bundle 详情页的"详细介绍"区是空的；本 README 仍是包门面。

### 3.3 mydsh-profile 的 preset 归属（`packages/bundles/mydsh-profile/README.md`）

> 我的 dsh 个人配置项：**按行 id 覆盖 `config`**（行由官方 base / web-app 提供），并**统一声明四份 agent preset**——从上游 web-app 的四份 shipped preset 逐行复制，唯一改动是删掉与 Agent Teams 冲突的子代理工具行。

| 配什么 | 值 |
|---|---|
| `locale` | `zh` |
| `ui-settings-general` | 欢迎提示预置成已确认（由测试守护） |
| `agent-default-model` | 默认模型（ollama 路由） |
| `ui-chat` | 对话视图展开 |
| `session-log-deepseek` | 关掉官方 DeepSeek 请求携带的会话日志 |

四份 preset 都按行 id **整段替换** `config.plugins`（上游语义如此，不合并后续内置变更）。与上游唯一差别：删掉 `delegation` 组的 `tool-subagent-control` / `tool-subagent` / `tool-subagent-fork`——Agent Teams 用同名工具接管直连委派，两套并存会互相遮蔽；`workflow-ptc` / `tool-workflow` 保留。**不指定 `agent-preset-registry.default`**。
