# 视觉资产 · dsh-wallpaper-engine:外观本身就是产品

> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3`（包声明 `engines.dsh: ^0.2.0-rc.1`） · **读于**:2026-10-31
> **类**:`1` 壳与工作台 · **层**:**5**（默认值：观感）+ 3（设置/壁纸库槽位）+ 7（预设的分发）
> **★ 4,189 / npm 月下载 109,268**（2026-10-31；GitHub API + npm last-month，全生态外观类第一）
> **一句话**:它把“桌面壁纸”整件事搬进 DSH——Scene/Web/Video 壁纸、液态玻璃、字体、吉祥物、特效，再加可导入导出的外观预设；**不注册工具、不注入提示、不花一个 token**。
> **借鉴价值**:**① 视觉身份是社区最愿意传播的资产（4,189★ 对 250★ 的界面套件）；② 玻璃拆成独立子包行 `wallpaper-engine-glass`，停用即回到原生外观，壁纸/字体/吉祥物不受影响；③ 壁纸类型按“能不能在本进程里渲染”分档，不能的（Application）直接不进库；④ 重资源有降级链：WebGL 失败逐级回退；⑤ 外观预设整套导入导出 = 皮肤的分发单位。**

## 它想干什么 · 为什么值得借鉴

**意图。** 把“你看到的 DSH”整层接管：本机 Wallpaper Engine 的 Scene/Web/Video 壁纸、液态玻璃、字体、吉祥物、点击/拖尾特效，再加一套可导入导出的外观预设。它明确不做两件“看起来该做”的事——**不注册任何工具、不注入提示词**，所以模型侧零开销。

**意义。** 它证明“外观”在 DSH 里可以是**产品资产**而不只是主题：4,189★、月下载 109,268，是界面套件（★250 / 119,610）的十几倍星标。它还改了一条边界——**外观可以拆成可独立停用的子包**：玻璃行关掉，界面回到原生，壁纸与吉祥物照旧。这让“皮肤”第一次有了“可组合”的形状。

**用户价值。** 装之前，DSH 是统一的官方外观；装之后，你每天面对的那块屏幕变成自己的——本机 WE 壁纸铺在对话后面，玻璃、字体、吉祥物一起换，外观预设还能整套发给朋友。最觉得值的是“一天要在里面待八小时”的人：它不提升任务能力，但显著降低长期使用的疲劳。代价也真实：装前要**完全退出 DSH**、依赖 `dsh-better-sidebar ≥ 0.19.0`、Scene 壁纸吃 GPU。

**表达（界面与交互）。** 第一屏就是“聊天后面在放壁纸”，入口有两个——设置里的 `Wallpaper Engine → 壁纸库`，或从聊天顶部的吉祥物**拉绳**打开壁纸仓库；选中缩略图即时生效并保存到宿主端；暂停/播放只控制当前播放，**清除壁纸不删原文件**。最讲究的一处是共存：玻璃是独立子包，关掉它界面回到原生外观而壁纸/字体/吉祥物仍在；与别的皮肤同装时另有一份共存说明。**它把“只要一部分”做成了结构，而不是设置里的一个开关。**

## 2. 机制（可照抄的部分）

### 2.1 壁纸按“能不能在本进程里渲染”分档

| 类型 | 怎么处理 | 为什么 |
|---|---|---|
| **Scene** | 内置 **WebWallGL** 实时渲染；失败按降级链回退 | 不需要 Wallpaper Engine 在后台跑 |
| **Web** | 网页挂载 + WE API 注入 + **沙箱隔离** | 效果取决于网页与浏览器能力 |
| **Video** | 浏览器播放 + 转码 + 帧率上限 + 暂停控制 | 控制资源占用 |
| **自定义** | 上传本地 JPG/PNG/MP4，文件留在本机 | 没有 WE 也能用 |
| **Application** | **不支持**，不进库、不进轮播 | 需要启动第三方程序 → 越界 |

> **抄这条**：能力矩阵要按“**在我这个进程里能不能做**”来分，不能做的**列出来并排除**，而不是静默失败。用户看到“Application 类不支持”比看到一张黑屏好。

### 2.2 玻璃是独立子包行

`wallpaper-engine-glass` 是一个**可单独停用的子包行**。停用后：除内容区壁纸外，界面回到宿主原生外观；**壁纸、字体与吉祥物不受影响**。

> **抄这条**：把“重”的那一层拆成独立行。外观产品的失败半径因此从“整个界面错乱”缩到“玻璃没了，壁纸还在”。

### 2.3 多包发布集

本仓按**多包发布集**发布：主包与同版本子包一起解析（包数、tarball 数与 `publishOrder` 在发布文档里）。

> **抄这条**：主包 + 子包必须**同版本一起发**，并给出 `publishOrder`。否则用户会在某次升级后拿到“主包新、子包旧”的半套外观。

### 2.4 外观预设 = 分发单位

壁纸库支持筛选、隐藏/恢复、自动轮播；**外观预设整套导入导出**。

> 这是本卡最像“产品”的一处：用户调好一套观感，可以整套导出、发给别人导入。**预设就是皮肤产品的“安装包”**，分发不依赖 npm。

### 2.5 零 token 的硬约束

插件不向 agent 注册工具、不注入提示文本，**不增加模型 token 开销**。

> **抄这条**：纯外观产品要主动声明“我不进模型上下文”。否则用户会怀疑每次对话都在为壁纸付费。

## 3. 体验

### 3.1 首次使用逐屏

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装前 | **完全退出 DSH**；确认 `dsh-better-sidebar ≥ 0.19.0` | 顺序敏感，写进前置条件 |
| 装 | `dsh plugin --profile web add dsh-plugin-wallpaper-engine`（桌面端 `desktop`） | 一条命令 |
| 打开 | 设置 → `Wallpaper Engine` → **壁纸库**；或聊天顶部**吉祥物拉绳** | 两个入口，一个正式一个俏皮 |
| 选壁纸 | 缩略图；按内容分级/类型筛选；隐藏/恢复；自动轮播 | 即时生效并保存到宿主端 |
| 调外观 | 配色、透明度、模糊、边框、字体 | 与壁纸分开调 |
| 暂停/清除 | 暂停只控制当前播放；**清除不删原文件** | 破坏性动作的边界写清楚 |
| 分享 | 外观预设整套导出/导入 | 皮肤的分发 |

### 3.2 三处"诚实"

- **Application 类壁纸不支持**，且“不会进入壁纸库或轮播候选”——不给用户留一个永远转不起来的选项。
- **macOS 没有 WE 客户端**：改用上传或指向 WE 项目目录，不假装支持。
- **共存说明**单独成文：与别的玻璃/UI 插件同装时先读它。

### 3.3 模型看到的

**零。** 不注册工具、不注入提示、不花 token。这是它作为“视觉资产”的自我约束，也是它敢叫“零开销”的底气。

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| Scene 渲染失败 | 按降级链逐级回退（不黑屏） |
| 显卡/WebGL 不支持 | 复杂工坊项目可能不兼容 → 降级 |
| 玻璃子包停用 | 界面回原生外观；壁纸/字体/吉祥物保留 |
| macOS 无 WE 客户端 | 上传图片/视频，或指向 WE 项目目录 |
| Application 类壁纸 | 不支持，不进库、不进轮播 |
| 未退出 DSH 就安装 | 顺序错误，需退出后重装 |
| `better-sidebar` 版本过低 | 前置不满足，安装/更新会失败 |
