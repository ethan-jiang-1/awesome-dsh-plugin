# 怎么借：从产品线拿走东西

> **这是三个 lever 的共同产出**：22 条从 24 张卡与 1 个观察样本里抽出，其中第 16 条出自 `shell` 侧。
> 各 lever 自己的"必抄清单"仍在各自 README（plugin 无单独清单，直接用本表）；**规则源是 [`00-map`](./00-map.md)，这里是按任务组织的借用层**。

## 0. 三条读法

1. **按任务找，不按样本找**——先看 §1 的需求路由，再跳到你那一行。
2. **只读一节就走**——§2 的 22 条是全部卡片的公共产出，每条都有出处与抄错后果。
3. **抄之前先过门**——不确定一个东西该不该抄，先看 [`horizon`](./horizon.md) 的 C1–C4 与七层。

## 2. 可以直接搬走的 22 条(全卡片的公共产出)

**如果你只读一节,读这一节。** 每条都在某张卡里被具体实现过,附"抄错的后果"。

| # | 规则 | 一句话说清 | 出处 | 抄错的后果 |
|---|---|---|---|---|
| 1 | **同源出数** | 凡是用户**已经见过**的数字(占用率、状态行、计费量),只允许上游那一份投影出数 | [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) | 你显示 68.4%、输入框的环显示 67% → 整套面板永久失信 |
| 2 | **估算与真实并列** | 不二选一:估算值加 `≈`,旁边给 provider 上报的真值 | [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) | 只给估算 → 用户拿它当账单,差一次就再也不看 |
| 3 | **兼容性写成可执行清单** | `Rule / Limitation / Check / Procedure` 四类,每条挂**上游源码路径**;接缝矩阵测试断言**退役接缝不存在** | [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) | 只写"支持 0.2.x" → 上游一改靠用户报错 |
| 4 | **两个版本声明分工** | `engines.dsh` 是**地板**(粗门),`dsh.compatibility.dshReleases` 是**逐版本枚举**(安装证据);两者在不同宿主线上各自是唯一门禁,所以都要写 | [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) · [`81_协作`](./plugin/81_协作-dsh-agent-teams.md) | 只写 peer → 在 `0.2.1-alpha.4+` 上不再生效 |
| 5 | **无服务 → 无能力** | 能力走**可选接缝**(延迟 `ctx.inject` / 一次性 `ctx.get`),缺服务时不挂 fiber、不抛错,面板入口自己消失 | [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) | 硬 `inject` → 少一个包就白屏 |
| 6 | **能力探测式 UI** | 别人的插件在不在,决定我的入口显不显示("装它才有,没装不显示") | [`12_厚工作台`](./plugin/12_厚工作台-better-sidebar.md) · [`31_驾驶舱`](./plugin/31_驾驶舱-dsh-context.md) | 显示一个点了没反应的按钮 → 用户以为坏了 |
| 7 | **救生页活在启动之外** | "起不来"的兜底页必须由**不依赖插件栈**的东西提供,并且能选择**下一次启用哪些** | [`51_分发与救生页`](./plugin/51_分发与救生页-dsh-market.md) | 救生页也挂在坏掉的 profile 上 → 一起起不来 |
| 8 | **版本锁不到就跳过** | 装不上精确版本时**不装**,而不是装个近似的;并把"没做"说出来 | 观察样本 [`04_首启观察`](./plugin/_证据/04_首启观察-dsh-bootstrap.md) | 装了不兼容的版本 → 首启即崩,用户归因给整个产品 |
| 9 | **配置导出要能表达"保持现状"** | 环境码里**没包含**的项 = 不改变现状,不是"卸载" | 观察样本 [`04_首启观察`](./plugin/_证据/04_首启观察-dsh-bootstrap.md) | 用户导入一次配置,反而被删掉插件 |
| 10 | **计划先行 + 唯一授权点** | 先出将要发生的计划(不执行),聊就是改同一份草稿,**只有**一个按钮开跑;否掉之后**阻止自动重建** | [`81_协作`](./plugin/81_协作-dsh-agent-teams.md) | 一按就跑/否掉又复活 → 用户再也不点第二次 |
| 11 | **接管必须保守** | 不确定能不能接管时**放过**(回落到原生/文本),并说明"我没做" | [`71_感官接入`](./plugin/71_感官接入-modlens.md) | 强行接管 → 把本来能用的模型弄坏 |
| 12 | **多端是一台要配对的设备** | 有配对码、有效期、可撤销(撤销=删除哈希)、回环准入、锁屏不含正文 | [`61_多端与远程`](./plugin/61_多端与远程-dsh-mobile.md) | 当成响应式断点 → 等于把会话开放给整个局域网 |
| 13 | **注册表方法必须是原型方法** | 自建 `ctx.myService.registerX` 只能写成 prototype 方法,不能写成实例箭头属性 | [`12_厚工作台`](./plugin/12_厚工作台-better-sidebar.md) · [`11_薄基座`](./plugin/11_薄基座-dock.md) | Cordis 服务代理会把 effect 绑到服务自己的 root → 插件卸载时注册项不回收,且只在卸载时暴露 |
| 14 | **坏数据结构分两层校验** | schema 之外再加**引用完整性**(id 对 key、序号不越界、比例和为 1、无孤儿节点) | [`12_厚工作台`](./plugin/12_厚工作台-better-sidebar.md) | schema 过了不代表状态自洽 → 恢复出半个布局,点一下就崩 |
| 15 | **降级链的终点是"人还能读的原文"** | 节点坏就丢节点,块坏就退回原始 Markdown/代码块,插件缺席也要历史不破 | [`21_生成式界面`](./plugin/21_生成式界面-dsh-genui.md) | 坏数据变空白块 → 用户连复制出来自己看都做不到 |
| 16 | **每档能力都要一条"退化为 Y"** | 先列能力矩阵,再写每一档落点;最差档必须**不静默**(响铃 / 纯文本 / 不激活) | [`14_终端即产品`](./shell/14_终端即产品-dsh-TUI.md) · [`11_薄基座`](./plugin/11_薄基座-dock.md) | 缺能力就什么都不做 → 用户当成 bug |
| 17 | **三层否定** | 用户否掉的东西要同时挡住:当前轮次 / 重建路径 / **模型侧记忆** | [`81_协作`](./plugin/81_协作-dsh-agent-teams.md) | 只挡一层 → 系统在另一层复活它,用户反复否同一件事 |
| 18 | **外部索引每次使用前再校验** | 规范形式、无凭据、无 fragment、不重复;并配超时/字节上限/`redirect:"error"`/同 URL 合并 | [`51_分发与救生页`](./plugin/51_分发与救生页-dsh-market.md) | 只在保存时校验 → settings / 环境变量绕过,schema 形同虚设 |
| 19 | **迁移先出计划，写入放最后** | 校验 → 预览 → 逐项选择 → 冲突裁决 → 路径/密钥 → 确认 → 快照 → 写入 → 校验；**冲突必须逐条裁决，不提供「稍后决定」** | [`42_环境搬家`](./plugin/42_环境搬家-dsh-config-manager.md) | 边检查边写 → 失败时不知道哪些已落盘；允许未决 → 导入卡死或默默覆盖 |
| 20 | **迁移三件套：发现 / 保真 / 可撤销** | 先回答「身份字段是什么、时间从哪来、主转录怎么判」；预览要跑真解析但零副作用；导入历史里能逐条撤回，并留一条反向导出 | [`43_会话搬家`](./plugin/43_会话搬家-dsh-chat-import.md) | 缺撤回 → 用户不敢点；缺出口 → 用户不敢试；用统一 id 猜 → 认错会话 |
| 21 | **修复前先复现** | 隔离的一次性环境里真启动一次，再决定写不写；只写一条**官方**豁免，记录、可撤销、上游发版时提醒撤销；**顺序即安全** | [`52_装坏自愈`](./plugin/52_装坏自愈-dsh-plugin-health.md) | 先豁免后测试 → 放行一个没证明能跑的东西，而门禁从此不再提醒 |
| 22 | **接管与进口都要可逆** | 替换宿主自带实现 = 停原行 + 加己行 + 按 preset 生效，**回退删覆写行**；进口别人的套件 = 就地读 + 坏声明诊断后跳过 + 缺凭据显式化 | [`15_接管套件`](./profile/15_接管套件-dsh-plugins-plus.md) · [`16_套件市场`](./profile/16_套件市场-dsh-agent-plugins-market.md) | 写一份「等于出厂」的配置 → 跟不上上游；静默跳过坏声明 → 半挂载 |

## 3. 三条「别抄」

- **[`91_冻结分叉`](./shell/91_冻结分叉-better-sidebar-N23.md)**:peer 上界钉死 (`< 0.2.0`) + 改到整个外壳 + 保留上游接口 → 分家是必然结局,而且用户会被推进"降级宿主 / 装回上游"的两难。**带显式上界的 peer 区间 = 主动设了一个死亡日期。**
- **`14_终端即产品`** 的教训:换表层不会让上面的层自动出现,**首启、分发、降级三件事从此归你**。
- **`11_薄基座` 的反面**:用私有 DOM 锚点(`data-turn-navigator`)去挪别人的布局,锚点在 `0.2.1-rc.3` 已 0 命中——**可以这么干,但必须先写"找不到就什么都不做",并且优先找上游已约定好的量(CSS 变量)。**

## 4. 借用记录

抄完一条规则后，在方案或 PR 里回写一行：

| 字段 | 写什么 |
|---|---|
| 抄了哪条 | §2 的编号 |
| 落到哪 | 文件 / 模块 |
| 改了什么 | 与规则的差异（没有就写"无"） |
| 什么时候失效 | 版本 / 输入 / 规模边界 |

**没有"失效条件"的借用不算完成**——那只是复制。
