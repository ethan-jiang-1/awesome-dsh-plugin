# 隔离实测记录

> **环境**：macOS · Node `v22.23.1` · pnpm `12.5.1` · `@deepseek-ai/dsh@0.2.1-rc.3`。
> **隔离**：`DSH_HOME=.work/feas/home`（`.work/` 已被 `.gitignore` 忽略）。**未触碰** `~/.dsh/profiles/web`、凭据、会话。

## 0. 实验台

```sh
cd <repo>
mkdir -p .work/feas/home
export H=$PWD/.work/feas/home
export E="env -u DSH_PROFILE -u DSH_PROFILE_DIR DSH_HOME=$H DSH_TELEMETRY_DISABLED=1"
```

两个探针包（`.work/feas/probe-bundle`、`.work/feas/probe-plain`）：前者声明 `dsh.bundle.patch`，后者不声明。判据是"装完能不能进 roster、行能不能出现"。

## 2. 从这组实验直接得到的五条

1. **安装有三个独立的成功**（E3/E4）——退出码只覆盖前两个。
2. **启动是分级的**（E8/E17）——row 级失败被隔离，进程继续；`pending` 是第三种状态，不是失败。
3. **home 层能覆盖、不能供货**（E6/E7/E8）。
4. **CLI 装完宿主不知道**（E13）——必须重启，且无提示。
5. **启动体验可以完全在 bundle 插件里做**（E19）：首屏注入、预置会话、工作区都在 host 服务层，不需要安装器或 launcher。约束是 `workspaceRegistry.create` 要求目录先存在。

## 3. 复现步骤

```sh
# 1. 建探针包：bundle 版与 plain 版各一个（见 §0）
# 2. 隔离 home 下跑上面 E0–E16
# 3. 打包离线分发：cd probe-client && pnpm pack --pack-destination ..
# 4. 清理：rm -rf .work/feas
```

**两条环境事实**：

- **pnpm store 会跑进工作区**：默认落在仓库根的 `.pnpm-store/`。本轮出现过两次，均已删除；`npm_config_store_dir` 在 `dsh plugin` 的转发路径上没有生效，重跑后仍需检查并清理。
- **启动握手会写授权**：跑完 token 换取后，临时 home 下出现 `.credentials.yaml`，内含 `client-connection/browser-session` 的 `kind: grant` 记录（**不是**模型 API key）。所以实验结束后必须删掉临时 home，本轮已删。
