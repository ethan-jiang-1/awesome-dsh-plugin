# 覆盖行的身份陷阱 · tinyfish

> **阶段**：装 · **载体**：host-row（对 `web` 行的 config 覆盖） · **兼看**：配
> **影响力**：npm 近 30 天 **5,933**（2026-11-01，42 个过影响力门的 bundle 之一）
> **研究范围**：`dsh-tinyfish@0.13.0`，gitHead `25dc04e6…`，tarball sha256 `b3a66cf2…`（57,966 B，12 文件）；DSH 对照 `0.2.1-rc.3`
> **证据成熟度**：源码级（patch 的覆盖行与自述注释实读；未实机装）
> **一句话**：它把"怎么覆盖宿主一行"写成了 patch 顶部的一段注释，而这段注释比代码更值钱。
> **借鉴价值**：**① 覆盖只写 `id` + `config`；② `name` 是断言语义，写别人的包名 = 冒名；③ 覆盖整体替换 config，必须带全字段。**

## 它想干什么 · 为什么值得借鉴

**意图。** 把 DSH 的搜索与抓取切到 TinyFish：插入自己的一行，再把 `web` 行的 `searchProvider` / `fetchProvider` 指过来 `[SRC-TARGET]`（`cordis.patch.yml:46-49`）。

**意义。** 这是所有"接管类" bundle 都要做的一步，也是**最容易触发安装期安全检查**的一步。作者把踩过的坑写在了 patch 顶部 `[DOC]`（`:7-11`）：

> 覆盖行只按 `id` 匹配，不写 `name`——这是刻意的。在 patch 格式里 `name` 字段**断言**目标原本的插件名，它不是重命名。所以在第三方 bundle 里写官方 web 包的 scoped 名，等于**声称那个身份**，而 patch 安全检查会把它读成冒名。

**用户价值。** 装之前，用户面对的是"搜索不好用但不知道怎么换"；装之后 provider 被指过去。代价是它改的是**全局**的 `web` 行——所有会话的搜索与抓取都换了实现。

**表达。** patch 里连"宿主该怎么覆盖回来"都写了 `[DOC]`（`:13-18`）：

```yaml
#   - id: web
#     config:
#       searchProvider: deepseek-official
#       fetchProvider: http
```

## 1. 阶段与载体

- **阶段**：装。它不新增界面，靠一条 override 行生效。
- **载体**：`host-row`（对已有行的 config 覆盖）。
- **兼看**：配。它改的是"默认 provider"这一层。

## 2. 机制

```yaml
# cordis.patch.yml:46-49
- id: web
  config:
    searchProvider: tinyfish
    fetchProvider: tinyfish
```

两件事同时成立：

1. **只给 `id`**，没有 `name`——按注释，这是为了避免"声称身份"；
2. **`config` 是整体替换**，不是合并——所以覆盖者必须把目标行原本拥有的字段重新写全，否则会被抹掉。

### 三条失败态

| 态 | 表现 | 用户看到什么 |
|---|---|---|
| **写了 `name`** | 被读成冒名，或被断言失败拦住 | 装不上，报错指向 patch |
| **只写部分 config** | 目标行其余字段被抹掉 | 搜索能用了，但别的东西坏了 |
| **宿主后层覆盖** | 用户 patch 后到即胜 `[DOC]`（`:13-16`） | 用户改回官方 provider，插件"失效"但没错 |

## 3. 设计取舍

| 取舍 | 选择 | 代价 |
|---|---|---|
| 怎么改宿主行 | config override，不新增行 | 受目标行字段约束 |
| 身份怎么表达 | 只靠 `id` | 需要作者知道 `id` 而非包名 |
| 可逆性 | 文档里给出宿主改回的写法 | 用户得知道去哪改 |
| 影响面 | 全局 `web` 行 | 所有会话都换 |

## 4. 与宿主既有行的边界

它**只改一行**，不动路由、不动槽位、不加客户端。边界清晰的好处是可逆；代价是**任何一个用户层 patch 都能把它盖掉**——所以"装完为什么没生效"很可能不是装的问题，而是后层覆盖。
