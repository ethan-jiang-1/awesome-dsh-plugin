# 三条安装路径与空安装器 · free-models-hub

> **阶段**：装 · **载体**：host-row + client-slot（面板）+ 本地代理端口 · **兼看**：首启
> **影响力**：npm 近 30 天 **2,420**（2026-11-01，42 个过影响力门的 bundle 之一）
> **研究范围**：`dsh-free-models-hub@0.3.1`，gitHead `a05a60f9…`，tarball sha256 `edabcae8…`（**32,986 B，7 文件**）；DSH 对照 `0.2.1-rc.3`
> **证据成熟度**：**实测级**（隔离 profile 真装后逐条核对脚本，[`_证据/03`](../_证据/03_样本实测记录.md) E21）+ 源码级（patch 与 core 实读）
> **DSH 立场**：**反例**——三条安装路径（三个 `.bat`）是另造分发；插件只应发 bundle、让用户在应用内装。本卡只保留“说明与包体不一致”的教训。
> **一句话**：它把"谁该怎么装"分得比谁都细，**而那三个安装器一个都不在包里**。
> **借鉴价值**：**① 反例：按用户类型分三条路径 / 自带 `.bat` 安装器不是 DSH 分发；② 可抄的只有“说明里承诺的每个产物必须随包发布”；③ 配置写宿主既有 settings 命名空间。**

> **不要抄**：按用户类型分三条安装路径、用 `.bat` 扫描磁盘并注册，是“另造分发”。插件只应发 bundle、让用户在应用内装；本卡只保留“说明里承诺的产物必须随包发布”这一条教训。

## 它想干什么 · 为什么值得借鉴

**意图。** 让用户在 DSH 里一键拿到一批可用的免费模型 provider：面板列出数据源里的条目，选中即往宿主的 `llm-pi-ai.providers` 写配置 `[SRC-TARGET]`（`lib/core.js:14-15` 的 `SETTINGS_NS` / `SECTION_NS`）。

**意义。** 这是"配"与"装"交界处最典型的一类产品：**它的全部价值是替你写配置**。而它把"怎么装"当成产品的一部分来做——按用户类型分三条路径 `[DOC]`（`README.md:47-49`）：

| 路径 | 脚本 | 适合谁 |
|---|---|---|
| 桌面版（双击 exe） | `install-free-models-hub.bat` | 扫描本机 DSH 位置、离线复制、自动注册 |
| 命令行 / npx 版 | `install-npm-cli.bat` | 走 `dsh plugin --profile web add` + pnpm |
| 卸载 | `uninstall-free-models-hub.bat` | 移除插件与注册项 |

**用户价值。** 装之前，用户面对的是"改 JSON 还是改 YAML、写到哪个命名空间"；装之后是一个面板。代价是它同时维护**三条**安装路径——而三条路径都依赖随包文件。

**表达。** patch 顶部就把可覆盖项列全了 `[SRC-TARGET]`（`cordis.patch.yml:5-24`）：`backendUrl`、`pageSize`、`requestTimeoutMs`、`uiSlot`、`providerIdPrefix`、`proxyPort`。**把"作者自营后端"写成可覆盖的配置项**，是诚实的一种写法。

## 1. 阶段与载体

- **阶段**：装。它的说明文档几乎全是安装路径。
- **载体**：`host-row`（一行 insert）+ `client-slot`（抽屉面板）+ 本地代理端口 8787 `[SRC-TARGET]`（`cordis.patch.yml:22`）。
- **兼看**：首启。面板本身就是第一次使用的地方。

## 2. 机制

- **配置写进宿主命名空间**：`llm-pi-ai.providers`，provider id 加前缀 `freehub` `[SRC-TARGET]`（`core.js:14-15`、`cordis.patch.yml:20`）。
- **面板位置可选**：`uiSlot: ''` 时是"右缘按钮 + 抽屉"，设成槽位名（如 `sidebar.workspaces`）就挂进侧栏 `[SRC-TARGET]`（`cordis.patch.yml:18`）。同一份代码适配不同构建。
- **本地多 key 轮换代理**：`proxyPort: 8787`，仅 `127.0.0.1` `[SRC-TARGET]`（`:22`）。
- **生成物**：`lib/core.js` 头两行写着 *@generated by scripts/build.mjs — do not edit by hand* `[SRC-TARGET]`（`core.js:1`）。

### 三条失败态

| 态 | 表现 | 用户看到什么 |
|---|---|---|
| **安装器不在包里** | 按 README 找 `.bat`，tarball 里没有 | 命令不存在；**仓库里一切正常** |
| **面板不出现** | `uiSlot` 配了一个不存在的槽位 | 什么都没有，也没有报错 |
| **provider 写不进** | 宿主没有 `llm-pi-ai` 命名空间 | 选完没反应 |

## 3. 反例：为什么“三条路径”反而更脆

`package.json` 的 `files` 是 `["lib","cordis.patch.yml","README.md","LICENSE"]` `[SRC-TARGET]`；tarball 解包后**只有 7 个文件**，没有任何 `.bat`，也没有 `scripts/`（而 `core.js` 自述由 `scripts/build.mjs` 生成）`[SRC-TARGET]`。

所以：**三条安装路径对仓库克隆者成立，对 npm 安装者全部落空。** 正确修法不是补齐三个 `.bat`，而是删掉这三条：只发 bundle，安装说明写“在 Plugins 页安装”，CLI 只作 `--profile web` 的自动化。

**已实测（E21）**：隔离 profile 装完后，包目录只有 `LICENSE / README.md / cordis.patch.yml / lib / package.json` 五项；三个 `.bat` 逐个检查**全部不存在** `[RUN]`。

这和 [`install/11`](./11_装后自证-cfbridge.md) 是同一个错误——两个都在"安装说明写得越细"的地方翻车，说明它不是个别疏忽，而是这类写法的**结构性风险**。

## 4. 与宿主既有行的边界

它只往宿主已存在的 settings 命名空间里写条目，**不新增命名空间、不改宿主代码**。这使得它的卸载很干净（删条目即可），但也意味着**宿主改了 `llm-pi-ai` 的形状，它就静默失效** `[OPEN]`。

## 6. 失效与开放问题

- `[OPEN]` 面板与 provider 写入的实机表现（已装并核对包内文件，但未在浏览器里点面板）。
- `[OPEN]` `backendUrl` 为作者自营服务：数据源不可用时的降级路径未见。
- `[OPEN]` `proxyPort` 与宿主已有端口冲突时的行为。
- `[OPEN]` `llm-pi-ai` 命名空间形状变化时的兼容策略。
