# 全禁状态 · isolation-gate

> **阶段**：配 · **载体**：host-row（+ own-cli：6 个 `bin`；+ client-slot） · **兼看**：装
> **影响力**：npm 近 30 天 **7,067**（2026-11-01，42 个过影响力门的 bundle 之一）
> **研究范围**：`dsh-isolation-gate@1.13.7`，gitHead `70b4b6fb…`，tarball sha256 `119832a2…`（120,862 B，30 文件）；DSH 对照 `0.2.1-rc.3`
> **证据成熟度**：**实测级**（隔离 profile 真装、真写坏状态文件、真读回，[`_证据/03`](../_证据/03_样本实测记录.md) E23–E26）+ 源码级
> **一句话**：它把"配置读不到"拆成四种情况分开报告，然后**四种全部落到拒绝**。
> **借鉴价值**：**① 默认 deny 写在状态文件里而不是代码注释里；② 坏文件不覆盖、不停机，只停在全禁；③ 读结果用 `{ok, exists, error}` 三字段，而不是一个 boolean。**

## 它想干什么 · 为什么值得借鉴

**意图。** 给 DSH 加一道**按路径的访问门禁**：名单内的对象按三级授权放行，名单外一律拒绝 `[SRC-TARGET]`（`lib/store.js:62` 的 `DEFAULT_LEVEL = 'deny'`、`:69` 的自述行）。

**意义。** 生命周期里"配"这一层最容易出的事，是**配置坏了却继续按默认放行**。绝大多数插件把配置当偏好（读不到就用默认值），而门禁类配置必须反过来——读不到应当更严。这个样本把这条反过来写进了数据结构，而不是写进注释。

**用户价值。** 装之前，用户面对的是一个白名单文件，删了、改坏了、或换台机器没同步，都可能悄悄放开权限；装之后，**每一种异常都只有一个结果：不放行**，并且状态端点会把原因原样回显 `[SRC-TARGET]`（`lib/service.js:215-225`）。代价是要维护四态语义，且用户得能看懂"为什么我被拒了"。

**表达。** 状态文件自己带一行说明书 `[SRC-TARGET]`（`lib/store.js:69`，写进文件的 `_readme`）：

> 未在本文件列出的键一律按 deny；本文件缺省也不代表授权，恰恰等于全禁。

**把使用说明写进数据文件本身**，是这份样本最值得抄的一处。

**已实测（E23–E26）**：写坏状态文件后，`/state` 返回 `stateError: "…（按全禁处理，且不覆盖它）…"`、`defaultLevel` 仍为 `deny`、`policy` 与 `roster` 均为空数组，且**坏文件原样保留** `[RUN]`。另有一条实测陷阱：它的默认路径指向真实 home（`~/.agents/…`、`~/.dsh/…`）与硬编码 `D:\…` 备份目录，**不跟随 `DSH_HOME`**——已升级为 [`practice/TRAPS`](../practice/TRAPS.md) 第 15 条。

## 1. 阶段与载体

- **阶段**：配。它不改变安装，也不改变界面骨架，管的是"什么都没配的时候是什么"。
- **载体**：`host-row`（一行 insert）+ `own-cli`（`gate` / `gate-hook-claude` / `gate-hook-gemini` / `gate-hook-generic` / `gate-mcp` / `gate-ui` 六个 bin `[PKG]`）+ `client-slot`。
- **兼看**：装。它**不声明任何 `@deepseek-ai/dsh*` peer 依赖**，因此绕开了宿主的兼容性豁免闸门 `[DOC]`（`cordis.patch.yml` 顶部说明）。

## 2. 机制

### 四种"读不到"，一个结论

`readState` 永不抛异常，返回三字段 `[SRC-TARGET]`（`lib/store.js:270-309`）：

| 情况 | 返回 | 语义 |
|---|---|---|
| 没配路径 | `{ok:false, exists:false}` | 配置缺失（按全禁） |
| 文件不存在 | `{ok:true, exists:false}` | **第一次运行，不是错误** |
| 读取失败 | `{ok:false, exists:true}` | 有文件但读不了 |
| 空文件 | `{ok:true, exists:true}` + 空状态 | 等同于"什么都没授权" |
| JSON 非法 | `{ok:false, exists:true}` + **不覆盖** | 坏文件保留原样，停在全禁 |

`ok` 与 `exists` 是两个独立维度：**`exists:false` 可以是好事（首次运行），而 `ok:false` 一定是坏事**。用一个 boolean 表达不了这层区别。

### 判定侧怎么用

`lib/service.js:222` 把它压成一个开关 `[SRC-TARGET]`：

```js
gateClosed: rosterRead.ok === false,
rosterGateMessage: rosterRead.ok ? null : `名单不可用（${...} 缺失或损坏）⇒ 按"一律拒绝"处理，请先恢复名单文件`,
```

**一个 boolean 决定要不要把整条通道关掉，同时保留一句人话原因。**

### 三条失败态

| 态 | 表现 | 用户看到什么 |
|---|---|---|
| **状态文件缺失** | `emptyState()`（全禁）但 `ok:true` | 一切被拒，但系统不报错——需要 UI 说明这是首次 |
| **状态文件损坏** | `ok:false`，原文件保留 | 一切被拒，错误信息里带 JSON 解析原因 |
| **名单文件不可用** | `gateClosed:true`，通道整体关闭 | 连"看名单"都不行，必须先恢复文件 |

## 3. 设计取舍

| 取舍 | 选择 | 代价 |
|---|---|---|
| 默认值放哪 | 状态文件里的 `defaultLevel: 'deny'`，不是代码里的兜底 | 用户改文件就能改默认，需配合"文件即唯一依据"的说明 |
| 坏文件怎么办 | **不覆盖**，`error` 带原因，停在全禁 `[SRC-TARGET]`（`lib/store.js:10`、`:300-309`） | 用户必须手动修；换来"永远不会把坏文件换成好文件" |
| 怎么写 | 临时文件 + `rename` 原子替换，无 BOM，只写当前版本形状 `[SRC-TARGET]`（`lib/store.js:311+`） | 每次写都多一个临时文件 |
| 旧版本字段 | 只在**内存里**给旧字段挂别名，**不写回盘** `[SRC-TARGET]`（`lib/store.js:85-89`） | 旧读者能用，新文件不背历史包袱 |

## 4. 与宿主既有行的边界

它**不声明 `@deepseek-ai/dsh*` peer**，也不 import 宿主包——客户端槽位是通过 `ctx.inject` 拿运行时服务 `[DOC]`（`cordis.patch.yml` 顶部）。

这条边界有代价：绕开兼容闸门意味着**宿主接口变了它不会在安装期被拦**，只能靠运行期自己发现。**这不是免费的好事，是一种交换。**

## 5. 可迁移洞察

| 触发问题 | 可迁移洞察 | 机制依据 | 为什么有效 / 代价 | 移植时改什么 | 成立边界 | 抄错后果 |
|---|---|---|---|---|---|---|
| 配置读不到时该放行还是拒绝 | 默认值写进**状态文件自身**（`defaultLevel: 'deny'`），代码只负责如实读出 | `[SRC-TARGET]` `lib/store.js:62`、`:69`（`_readme` 写进文件） | 用户看得见默认值、改文件即改策略；代价是文件被删时代码必须兜一个同样的默认 | 定义"缺省即拒绝"的字段，并把这句话写进文件的自述行 | 只对"安全语义"的配置成立；偏好类配置反而该放行 | 默认放行 → 删个文件就相当于全开 |
| 配置坏了要不要自愈覆盖 | **不覆盖**，保留原文件、上报原因、停在全禁 | `[SRC-TARGET]` `lib/store.js:10`（注释）、`:300-309`（返回 `ok:false` 且不写盘） | 坏文件是最有价值的排障证据；代价是用户必须手动修 | 规定"读取失败一律不写回"，写路径只在明确保存时触发 | 只对"读失败不等于想重置"的产品成立 | 自愈覆盖 → 排障线索被抹掉，且可能把全禁改回旧的白名单 |
| 用 boolean 表达读取结果 | 拆成 `{ok, exists, error}`：`exists:false` 可以是首次运行，`ok:false` 一定是坏 | `[SRC-TARGET]` `lib/store.js:271-309`（五种返回分支） | 首次运行与故障分开；代价是调用方要处理两个维度 | 定义读取结果的三字段契约，并给出"每个组合怎么展示" | 只对需要区分"没配过"与"配坏了"的产品成立 | 用一个 `if (!state)` → 首次运行被当成故障，或故障被当成首次 |
| 拒绝时要给不给人话 | 判定侧同时给出开关与原因文案 | `[SRC-TARGET]` `lib/service.js:222-224`（`gateClosed` + `rosterGateMessage`） | 用户知道下一步修哪个文件；代价是文案要跟实现一起改 | 每个"关掉整条通道"的分支都必须带一条可执行提示 | 只对"有面向用户的错误面"的产品成立 | 只关不给原因 → 用户只能猜，最后去关插件 |
