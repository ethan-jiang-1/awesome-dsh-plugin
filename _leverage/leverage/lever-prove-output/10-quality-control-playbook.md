# 10 · 质量控制手册：十二个生态样本的横向结论

> **状态**:`observed`(横切 [02](./02-goal-gate-hard-floor.md)–[09](./09-discipline-loop.md) 八张卡 + [01](./01-quality-chain.md) 原生层) · **基线**:DSH `0.2.1-rc.3` · 名单 @ `efe602e7b`
> **样本**:12 个生态仓库 + 5 个官方包 · **本卡不新立样本**,只做横切;六个必答字段在各源卡
> **一句话**:质量控制不是选一个更严的评审,是回答四个问题——**门装在哪、判什么、错了怎么办、谁有权说「过了」**。十二个样本给出了四种截然不同的答案,而它们的**共同失败**比共同成功更有信息量。

本卡是问答式的:先给结论表,再逐条给证据与反例。它不是新的一段论述,是前面八张深挖卡的**交叉引用网**。

## 0. 一句话结论(先看这张表)

| 问题 | 生态的答案 | 成本 | 证据 |
|---|---|---|---|
| **门能装在哪?** | `tools/pre-execute`(动作前)、`agent/turn-stopping`(轮末)、`llm/stream`(文本层)、外部进程(会话外)、UI 槽位(人事后) | 越靠前越硬、越贵、越容易误杀 | [02](./02-goal-gate-hard-floor.md) §3 · [06](./06-judge-placement.md) §2 · [07](./07-foreign-runtime-acceptance.md) §3 |
| **判什么?** | ①命令/契约是否满足 ②断言是否有出处 ③结论是否与证据矛盾 ④产物版本是否被接受 ⑤流程是否走完 | ①最便宜可机械 ②便宜但漏判 ③贵但能发现矛盾 ④不需要模型 ⑤最贵 | [02](./02-goal-gate-hard-floor.md)、[04](./04-evidence-index.md)、[03](./03-turn-end-reconciliation.md)、[08](./08-delivery-receipt.md)、[09](./09-discipline-loop.md) |
| **判错怎么办?** | fail-closed / fail-open / 转人工(REVIEW、BLOCKED、rework) | 没有「等人」状态的门,压力下会变成放行 | [02](./02-goal-gate-hard-floor.md) §3.5 · [07](./07-foreign-runtime-acceptance.md) §6.1 |
| **谁有权说「过了」?** | 门禁自己(重跑) > 外部运行时 > 另一个模型 > 同一个模型 > agent 自述 | 权限越高越可信,但越高越难落地 | [02](./02-goal-gate-hard-floor.md) §5.1 · [06](./06-judge-placement.md) §5 |

**如果只记一句**:**门禁的力量来自「它不需要被拦者同意」,而不是来自它判得多准。**

## 1. 门装在哪:一张「接缝 → 能力」表

| 接缝 | 能看到什么 | 能改变什么 | 谁用了 |
|---|---|---|---|
| `tools/pre-execute` | 待执行的工具名 + 参数 | **阻止副作用**;返回 `{kind:'deny'}` 或 `ask` | `goalloop`(拦完成声明)、`second-angle`(`ctx.tools.guard()`) |
| `agent/turn-stopping` | 轮次即将关闭这一事实(+可 `steer`) | **不关轮**,让模型再说一遍 | `answer-reviewer`、`quality-review`、`second-angle`、`quality-gate` |
| `llm/stream` | 模型的**流式字节** | **扣住文本**,发送前替换 | `self-review` |
| 外部进程 | 一切它自己去取的东西 | 会话**无法参与**的判定 | `dsh-verify`(真浏览器)、`veriscope`(读导出)、`gungnir-verify` |
| UI 槽位(`conversation.view`) | 文件与哈希 | **人**的决定(模型无权) | `workproof` |

### 三条硬事实(不是观点)

1. **`agent/turn-stopping` 拿不到本轮草稿,也不能改已发送的文本。** `[DSH]` `dsh-agent/README.md` 原文:`agent/turn-stopping` **runs before an otherwise completed turn closes and can steer to keep it open**——它能**阻止关闭**,不能**改写**。`self-review` 的 README 独立复述了同一事实(载荷只有 `{agent, turn, signal}`)。
2. **DSH 没有拦截最终文本的机制。** `[CAT]` `evidence-gate` 自己写的:「harness 没有任何机制能拦截最终文本」。要真拦,只有 `llm/stream` 扣留这一条路。
3. **`llm/stream` 全库只有 7 条自述**(),`agent/turn-stopping` 只有 **2 条**。**最硬的两个接缝,是生态用得最少的两个。**


**推论**:生态的「质量」供给(门禁/验收类样本很多 `[CAT]`)**绝大多数挤在「轮末再问一次模型」这一格**,而这一格恰好是**最不能改变结果**的一格。这不是懒,是接缝知识的分层:`turn-stopping` 有官方文档、名字直白、示例多;`llm/stream` 是传输层,没有「质量」的语义,要想清楚才知道该去那里。

## 2. 判什么:五种判据,按「可机械程度」排序

| 判据 | 需要模型吗 | 能发现什么 | 不能发现什么 | 代表 |
|---|---|---|---|---|
| **命令通过** | 否 | 契约里写下的东西坏了 | 契约没写的、命令测不到的 | `goalloop` 重跑 AC;`quality-gate` 4 条白名单 |
| **断言有出处** | 否 | 「完全没依据」的声称 | 同义改写(漏判)、出处与结论矛盾 | `evidence-gate` 五级阶梯 |
| **结论与证据矛盾** | **是** | 说反、夸大 | 证据本身错、判官被带偏 | `second-angle` 四等判决 |
| **版本被接受** | **否**(靠人) | 交付物被改后旧接受失效 | 内容对不对 | `workproof` |
| **流程走完** | 部分是 | 没跑测试就交付 | 跑了一个没用的测试 | `doublecheck` |

### 2.1 「命令通过」的边界,goalloop 自己写清楚了

它的判定是重跑每条 AC 的 check,**零模型参与**。但它同时列了三条不采信(见 [02](./02-goal-gate-hard-floor.md) §5.1),其中最锋利的一条是:**检查自己改了工作区(`check-mutated-tree`)→ 判定无效**。

**「测量不能改变被测对象」是一条常被忽略的质量要求。** 生态里大量「验收脚本」会把产物写脏(写缓存、写日志、生成 lock 文件),然后下一次判定就基于被污染的现场。

### 2.2 「断言有出处」的边界:关键词 vs 语义

`evidence-gate` 用索引 + 关键词,**同义改写即失效**;`second-angle` 用模型对账,**能发现矛盾但会误报**。两者不互补只有一处:**没人把它们串起来**(先便宜筛、再贵的判)。这是本域 [04](./04-evidence-index.md) §10 的第一条开放问题。

### 2.3 一条容易被忽略的判据:**证据的**新鲜度

`goalloop` 的 `treeDigest` 绑定、`veriscope` 的回执失效、`workproof` 的 `stale`,三者是同一件事的三个实现:

> **判决必须绑定一次具体的输入;输入变了,判决作废。**

它们的差别只在粒度:整棵树的摘要(goalloop)、策略 + 输入 + 环境(veriscope)、单文件哈希 + 大小(workproof)。

## 3. 判错怎么办:失败语义表

| 样本 | 默认失败方向 | 「等人」状态 | 谁能解 |
|---|---|---|---|
| `goalloop` | **fail-closed**(判不了就拦)+ 停手 + 重试三种并存 | `BLOCKED`(假完成 ≥2)、`rounds-exhausted`、`time-budget` | 人(`/goal-reset`、重新盖章、加预算) |
| `second-angle` | 对账 **fail-open**;动作扫描 **fail-closed** | — | — |
| `answer-reviewer` | **解析** fail-closed;上限用尽则放行 | `capped`(标在 chip 上) | 人(调阈值) |
| `self-review` | **fail-open**(任何异常/超时/拿不准 → 放行原稿) | — | — |
| `veriscope` | **三值**,`REVIEW` 永不转 PASS | **`REVIEW` 本身** | 人(必须接手) |
| `workproof` | 人决定;文件异常 → `missing`/`unverifiable`/`stale` | 无(等人看,但不阻塞) | 人 |
| `doublecheck` | **`remind` 默认不阻断** | `rework required` | 人(回计划模式) |
| `dsh-verify` | 退出码 0/1 | — | CI / 人 |

### 3.1 三条规律

**规律 1:同一插件里出现两种相反的失败方向,说明作者按「错了会怎样」分配,而不是按「严格程度」。**
`second-angle`(对账 fail-open / 动作 fail-closed)、`answer-reviewer`(解析 fail-closed / 上限 fail-open)都是这种。**这是成熟度的标志**——一刀切的 fail-closed 会让工具不被使用,一刀切的 fail-open 会让它没有价值。

**规律 2:凡是有「等人」状态的门,才真的能拦。**
`goalloop` 的 `BLOCKED`、`veriscope` 的 `REVIEW`、`doublecheck` 的 `rework required` 都给了人类一个明确的接手工位。没有这个工位的门,在流水线里只能二选一:放行,或永久卡死。

**规律 3:默认值决定门是否存在。**
`doublecheck` 默认 `remind`、`goalloop` 的 `requireStamp` 默认关、`answer-reviewer` 的 `maxChallenges` 默认 5 —— **每一个默认值都在回答「这个门默认开不开」**。评估一个质量插件时,先读默认值,再读功能。

## 4. 谁有权说「过了」:权限阶梯

```
① 门禁自己重跑命令            goalloop(AC 是命令行,第三方可复跑)
② 外部运行时执行             dsh-verify(真浏览器)、veriscope(纯阈值读导出)
③ 另一个上下文的模型         doublecheck(分叉子代理)、answer-reviewer(可换 provider/model)
④ 同一模型的另一次调用       second-angle 默认、self-review、quality-review 默认
⑤ agent 自己的结论           ← 不算验收
```

**阶梯的意义不是「越高越好」,而是「越高越贵」**:

- ① 需要把 done 写成命令;
- ② 需要可执行的规格/导出;
- ③ 需要第二个模型(钱);
- ④ 只需要一次调用(全部样本都在这一层有一份实现);
- ⑤ 零成本,零证据。

**生态真实分布**:绝大多数停在 ④。而 ④ 的问题是它**继承了同一个盲区**——同一个模型看不出自己犯的错,不管问几遍。`dsh-verify` 那个真实事故(`.dark` 类切了、CSS 规则没写、每次 agent 自测都通过)正是 ④ 失效的样子:**自测不是判错,是判了一个不存在的对象。**

### 4.1 一个不能省的权限:**模型的调用面里不能有 `decide`**

`workproof` 的工具动作是 `record/list/inspect/refresh/preview/export`——**没有 `decide`**。用户侧的决定走 UI/命令,需要回执 id 与当前版本。

**这是本域最干净的一条权限设计**:模型可以**产生待验收对象**,不能**签署验收结论**。任何让 agent 自己点「通过」的实现,**在所有权上就不是验收**。

## 5. 把八张卡缝成一条链:一个可操作的组合

生态里没有样本把这几层串起来,但把它们的**接口**摆在一起,组合是清楚的:

```
① 意图  doublecheck 的 grill(六维审问 + 规格落盘) —— 软,靠对话
② 计划  规格文件(doublecheck-spec.md / plan-lattice) —— 软,可被后续环节回查
③ 动作  quality-gate 的白名单 / second-angle 的动作守卫 —— 硬,可阻断
④ 证据  qiushi / attest-chain 记账 + evidence-gate 索引 —— 只观察,不改行为
⑤ 产物  workproof 回执(版本 + 哈希 + 人的决定) —— 硬,但只在「人点了」时
⑥ 验收  goalloop(命令)/ dsh-verify(浏览器)/ veriscope(阈值) —— 硬,但都在会话外
```

**组合的三条接口约束**(从样本里直接读出来的,不是发明的):

1. **④ 与 ⑥ 之间要有哈希对齐**:goalloop 的 `digest: sha256:` 要求证据文件落在**被评估的工作区内**;`workproof` 的基线是同一批文件的 SHA-256。**两套哈希若能对齐,「这条回执对应的产物过了那条 AC」就能被机器判。**
2. **⑥ 与 ⑤ 之间要有版本语义**:完成后若文件被改,`workproof` 判 `stale`。**没有这层,「验收通过」会在下一秒失效而无人知道。**
3. **⑤ 与人类之间要有「只有人能签」**:**模型的调用面里没有 `decide`。**这一条一旦破坏,整条链退回 ④。

## 6. 十二个样本的共同失败(比成功更有信息量)

| 共同失败 | 谁都有 | 为什么是结构性的 |
|---|---|---|
| **判定晚于副作用** | 除 `llm/stream` 派系外的全部 | 判定需要「结果」,而结果在动作之后 |
| **声明可绕过** | `goalloop`、`doublecheck` | 门挂在可选动作上,不触发就不过门 |
| **默认软** | `doublecheck`(remind)、`goalloop`(requireStamp 关) | 默认硬会劝退首次使用者 |
| **判官与被判者同模型** | 除显式配置外全部 | 换模型要花钱,钱是默认值里最贵的变量 |
| **规格/契约由 agent 写** | `dsh-verify`(自述)、`doublecheck`、`goalloop` | 独立性从「谁写规格」漏掉,而不是从「谁判」漏掉 |
| **报告不是完整审计轨迹** | `dsh-verify` 自述、`workproof` 自述 | 完整留存会撞上最小化留存([05](./05-custody-chain.md)) |
| **实测平台窄于宣传平台** | `workproof`(仅 macOS 本地) | 跨平台验证成本高 |

**最后一条「规格由谁写」是本域认为最容易被忽略的**:所有换运行时、换模型的努力,都可能被一个**由被判定者自己写的宽松规格**化解。`dsh-verify` 的处理方式是**明说**(review the spec separately),不是假装能防。

## 7. 可借鉴:可搬走的原则总表(本域的核心产出)

前面八张卡各有 6–9 条「可借鉴」,合计 **69 条**。这一节把它们**去重、编号、按用途归类**,形成一张可以贴在设计文档里的表。

**读法**:`#` 是稳定编号,可在你自己的设计评审里直接引用(「这里按 Q7 处理」)。`出处` 指向给了完整论证的卡片。`一句话` 是原则本身。**不要只看一句话就动手**——每条的「怎么搬 / 反面」在那张卡里。

### 7.1 门禁位置(Q 系列)

| # | 原则 | 一句话 | 出处 |
|---|---|---|---|
| **Q1** | 只拦「声明」,不拦「行为」 | 找那个**每个任务只出现一次**的动作(完成/提交/部署),门装在那里 | [02](./02-goal-gate-hard-floor.md) §7 B1 |
| **Q2** | 先选接缝,再写逻辑 | 接缝决定能改变什么,能力是次要的 | [01](./01-quality-chain.md) §6 L2 |
| **Q3** | 否决权按确定性分配 | 命令/路径可 deny;语义/打分只能 steer 或报告 | [03](./03-turn-end-reconciliation.md) §7 B4 |
| **Q4** | 同插件可有相反的失败方向 | 对账 fail-open、动作 fail-closed,按「错了会怎样」分配 | [03](./03-turn-end-reconciliation.md) §7 B5 |
| **Q5** | 判官必须装在被判者影响不到的地方 | 换上下文 / 换模型 / 换运行时,三种独立的成本差一个数量级 | [06](./06-judge-placement.md) §7 B1 |
| **Q6** | 独立性取决于**谁触发**,不是工具 | 同一条规格,MCP 调用是自查,CI 调用是验收 | [07](./07-foreign-runtime-acceptance.md) §7 B6 |
| **Q7** | 模型侧不能有 `decide` | 模型可产生待验收对象,不能签署验收结论 | [08](./08-delivery-receipt.md) §7 B4 |

### 7.2 判据与判决(V 系列)

| # | 原则 | 一句话 | 出处 |
|---|---|---|---|
| **V1** | 只判「有没有出处」的那一半要做成硬门 | 判语义需要模型,就不能给否决权 | [04](./04-evidence-index.md) §7 B1 |
| **V2** | 判决分级标准 = 补救动作是否相同 | 夸张 / 说反 / 无依据,三类失败三种下一步 | [03](./03-turn-end-reconciliation.md) §7 B7 |
| **V3** | 退出码给门禁,结构化判决给诊断 | 两者不可互相代替;`Exit 1` 不区分断言失败与运行时崩溃 | [07](./07-foreign-runtime-acceptance.md) §7 B2 |
| **V4** | 失败信息必须带「期望 vs 实际」 | `got "0" want "99"` 是最小充分信息 | [07](./07-foreign-runtime-acceptance.md) §7 B3 |
| **V5** | 判据要写成可匹配的形式 | 正则/路径/退出码;写不出来的那部分承认它是软的 | [09](./09-discipline-loop.md) §7 B1 |
| **V6** | 检查不能改变被测对象 | 检查前后各取一次摘要,变了就判「判定无效」 | [02](./02-goal-gate-hard-floor.md) §7 B5 |
| **V7** | 三种情况必须分开:现场变了 / 证据不支持 / 判不了 | 混成一种「失败」是误杀的最大来源 | [02](./02-goal-gate-hard-floor.md) §7 B5 |

### 7.3 防误杀与失败语义(F 系列)

| # | 原则 | 一句话 | 出处 |
|---|---|---|---|
| **F1** | 反误杀做成阶梯,不做阈值 | 先假设它对,逐级找放行理由,一路站不住才拦 | [04](./04-evidence-index.md) §7 B2 |
| **F2** | 弱证据放行要单独命名并计数 | `charity` / `capped` / `REVIEW`——没有名字的例外会变成默认路径 | [04](./04-evidence-index.md) §7 B3 |
| **F3** | 用「被拦下后翻案」衡量门禁价值 | `blocked` 高 + `converted` 0 = 制造摩擦而无产出,该下掉 | [04](./04-evidence-index.md) §7 B4 |
| **F4** | 有效失败方向按「可判定性」定 | 格式不符 fail-closed;语义拿不准 fail-open;依赖不可用单独报错 | [06](./06-judge-placement.md) §7 B5 |
| **F5** | 必须有「等人」状态,且不可自动消解 | `REVIEW` 永不转 PASS;清除它需要人的动作 | [07](./07-foreign-runtime-acceptance.md) §7 B7 |
| **F6** | 给「等人」状态配接手工位 | 谁看、多久看、看不了怎么办——否则它只是另一种卡住 | [07](./07-foreign-runtime-acceptance.md) §7 B7 |
| **F7** | 失败要有升级阶梯 | 第 1 次拒→指原因;第 2 次→冻结并要求人工介入 | [02](./02-goal-gate-hard-floor.md) §7 B3 |

### 7.9 如果只想记七条

给没时间读全部 64 条的人:

1. **Q3 否决权按确定性分配** —— 90% 的质量插件失误在这条上。
2. **E1 默认值决定门是否存在** —— 装上不等于生效。
3. **A2 重检永不替换基线** —— 一条能让整个机制从有效变成无效的细节。
4. **F5 必须有「等人」状态** —— 二值判决必然把不确定判成通过。
5. **Q7 模型侧不能有 `decide`** —— 否则它不是验收。
6. **C3 门禁自己重跑** —— 采信自报的执行记录,门禁就是回声。
7. **R1 拒绝是值,不是崩溃** —— 多门禁共存时的第一条纪律。

**这七条互不重叠,合起来覆盖了本域全部结构性结论。** 其余 57 条是它们的细节展开与工程实现。
## 8. 一份可执行的检查顺序

给任何一个「质量插件」做评估,按这个顺序问八句:

1. **它挂在哪个接缝?** 说不出接缝的,是提示词。
2. **它能改变什么?** 阻止动作 / 扣住文本 / 让模型重说 / 事后记账 / 给人看。
3. **它判什么?** 命令、出处、矛盾、版本、流程——五选一或几。
4. **它不证明什么?**(没写「不」的工具,通常把「哈希」当成了「正确」)
5. **判错时往哪边倒?** fail-closed / fail-open / 转人工。
6. **有没有「等人」状态?** 没有的话,它在压力下会静默放行。
7. **默认值是提醒还是阻断?** 默认软的门,**装上不等于生效**。
8. **谁有权说「过了」?** 模型侧若有 `decide`,它就不是验收。
