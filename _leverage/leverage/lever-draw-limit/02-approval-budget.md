# 02 · 审批预算：把「问几次」当成可耗尽的资源

> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3` · 名单 @ `efe602e7b` · **样本**:`IamNewHands/dsh-approval-gate`(回读 README/`docs/GUIDE.md`/CHANGELOG)
> **坐标**:`IamNewHands/dsh-approval-gate`(GitHub:`IamNewHands/dsh-approval-gate` · 仓库版本 **0.9.14** · ⚠️ npm 上的同名包属于 `moon09300731`,勿混)
> **一句话**:它不试图把策略写全,而是给「人工打断」记一本账——**硬拒免费、围栏一次、确认有额度、判定器只是预算花完后的兜底**。灾难由那层不可推翻的硬拒挡住,复杂度由「只加顺序、不加分支」压住。

## 1. 命题

> 审批类插件的真实成本不是「判断错一次」,而是**用户被问烦了以后开始无脑点同意**。因此「防灾难」与「少打扰」不是两个目标,而是同一个预算的两种花法:**预算花在确定性硬拒上最便宜,花在模型判定上最贵,花在重复询问上会把用户训练成自动点击器。**

可证伪点:如果存在一个同类插件,既不设硬拒层、也不设额度,仅靠模型判定就把人工提示降到阈值以下且没有误放行记录,命题不成立。

## 2. 杠杆点

| 位置 | 具体接缝 | 阶梯级 | 它在这一层做什么 |
|---|---|---|---|
| 审批决策 | `approval/request` 的应答者(与官方审批服务同一条 waterfall) | 4(policy) | 对沙箱越界请求给出 `allow / ask / deny`,并写出给人看的事实 |
| 工具前置 | `tools/pre-execute` | 4(policy) | 在请求产生之前就拦掉一部分(硬拒、围栏) |
| 会话事实 | 会话事件里的调用参数 | 3(slot) | 用真实命令与真实目标做匹配,不读「说明措辞」 |

**强制点可命名**:它在 `approval/request` 上**回答**,不自己执行动作;真正执行与否仍由官方审批服务与沙箱决定。它的「硬拒」是对该请求返回拒绝,不是绕过审批服务。

## 3. 机制

### 3.1 一条直线,不是一棵树 `[CAT]`

README 把管道写成**顺序**,而不是优先级表:

> 硬拒(凭据 / 系统路径,判定模型无权推翻)→ 硬事实人工 → 危险词 → 危险动作围栏 → 敏感路径永远人工 → DSH 配置自动放行 → 白名单(按命令锚定)→ 定域放行 → 工作区外一律人工 → denyRules → 脱敏 → 判定(JSON 硬类别优先)→ 学习沉淀

这条设计的要点是**每一层只有一个动作**,没有「层与层的组合条件」:

| 层 | 动作 | 可被推翻吗 |
|---|---|---|
| 硬拒(凭据外泄 / 系统路径销毁) | deny | **不可**,白名单也盖不过 |
| 危险词 / 危险动作围栏 | 转人工 | 可被后续层放行,但排在白名单与学习**之前** |
| 敏感路径 | 转人工 | 不可被「路径在 profile 下」或「规则命中」放行 |
| DSH 配置改动 | allow | 两个例外仍转人工:审批门自身数据目录、凭据类文件名 |
| 白名单(按命令锚定) | allow | 只匹配真实命令与真实目标 |
| 定域放行(工作区内) | allow,判定器零调用 | 可一键关闭 |
| 工作区外 | 转人工 | `unknown` 故意不拦 |
| 判定模型 | allow / ask / deny | 硬类别优先于模型文本 |
| 学习沉淀 | 写规则 | 只写你确认过的操作指纹 |

**没有「如果 A 且非 B 则 C」这种组合条件**——这是它能保持可解释的全部原因。想加一个策略,只能在直线上插一段;插进去以后不会改变其他段的语义。

### 3.2 额度:确认 N 次后自动放行 `[CAT]`

> 同一会话内,同一操作人工确认 N 次后,第 N+1 次起自动放行;沉淀规则携带**操作指纹**,只放行你确认过的操作。

这是「审批预算」最直白的实现:**重复的人工确认不再产生信息**,所以第二次以后应当折算成规则。它踩过的坑写在同一份 README 里:

- 规则原本按「说明措辞」的 `contains` 匹配,30 天 897 条自动放行里有 **30 条命令中根本没有规则词**(例:`gh run view` 被 `contains:"github"` 放行)。
- 修复是**把匹配锚定到真实命令与真实目标**(命令 + 真实目标),追认的 `contains` 改成目录级。
- 代价:人工提示 **147 → 178 次/30 天(+21%)**,换来 30 条真误放行被修掉。

**这条数字值得抄进任何审批插件的设计文档**:收紧匹配不是免费的,它直接把提示量推高两成。控制复杂度的一部分工作,是承认「收紧有价」。

### 3.3 失效方向:默认转人工,但有一处刻意的 fail-open `[CAT]`

| 情形 | 行为 | 方向 |
|---|---|---|
| 判定器不可用(**第一次**) | 转人工(v0.8.0 修正,此前是静默拒绝) | **转人工** |
| 阈值已满的 `neutral` 操作 + 判定器不可用 | 直接按已完成的确认放行(v0.8.2) | **fail-open** |
| 判定模型候选链全挂 | 三层链路(主判定模型 → 会话默认模型 → 内置兜底)后再按上面两行 | 转人工/ fail-open |
| 结构化裁决格式偏差 | 抛错 | 转人工 |

第二行是本域**唯一一处带理由的 fail-open**:它的前提是「你已经人工确认过 N 次同一操作」,所以放行的是**已确认过的动作**,不是陌生动作。这个区分很关键——它把 fail-open 的范围从「所有动作」缩到「已被人类批准过 N 次的那一个动作指纹」。

## 4. 样本(对照)

| 样本 | 与它相反的做法 | 差别在哪 |
|---|---|---|
| 官方 `dsh-user-approval` `[DSH]` | 只提供 `ask` / `never` 两个旋钮,**不判断内容**;应答者缺失 → `unavailable` → 拒绝 | 官方把「判断」完全留给应答者;本插件就是那个应答者 |
| `PerryLink/dsh-auto-review` `[CAT]` | 把同一件事交给**第二个模型**,默认拒绝 | 本插件用确定性层兜住模型层(auto-review 没有确定性硬拒) |
| `NanmiCoder/dsh-auto-mode`(已归档) `[CAT]` | 用「同一沙箱、行为不同」的第四档预设 + 一次性放宽 | 本插件不改预设,只在审批应答处决策 |
| 无硬拒层的纯判定插件 `[OPEN]` | 只靠模型说 allow/deny | 模型被绕过时没有第二道门 |

**对照给出的规律**:凡是「纯模型判定」的方案,都在文档里承认会误判;凡是「模型 + 确定性硬拒」的方案,都把硬拒写成**模型无权推翻**。这条差异比任何评测分数都更能预测实际失效形态。

## 6. 体验

**人看到的**:一条字段化的审批卡——操作类型 / 路径 / 影响范围 / 执行命令 / 模型说明,删除红、新增绿、修改蓝、推送发布琥珀;`danger-full-access` 的说明追加「不限定路径,本次授权覆盖整机」,避免被读成单路径授权。自动放行时输入框上方出现绿色提示并有时间线;被静默拒绝的记录可一键「重新审批通过」,但**确定性硬拒档与硬风险类别不显示该按钮**——给按钮就是假承诺。

**模型看到的**:拒绝理由里带**命令与目标两行**(host 没给就写 `host未提供`),而不是一句 `permission denied`。这与官方 `tools/pre-execute` 的拒绝语义一致:拒绝可以附上模型可见原因 `[DSH]`。

**这构成一条可复用的体验规则**:审批插件给模型的拒绝文本,应当包含「为什么」与「怎么改」;给人类的审批文本,应当包含「影响范围」与「是否可撤销」。两者不是同一段话。

## 7. 失败模式(具名)

| 失效条件 | 后果 | 方向 |
|---|---|---|
| 围栏被混淆写法绕过(`curl` 换成变量拼接、base64 管道) | 六类危险动作漏过 | fail-open |
| 规则表用了宽 `contains` 且未锚定 | 无关命令被放行(实测 30 条) | fail-open |
| 判定器持续不可用 + 阈值已满 | 已确认过的操作静默放行 | **刻意 fail-open** |
| 判定器联网 | 待审内容出境(它用「判定输入脱敏」缓解,不是消除) | 信息面 |
| diff 快照不清理 | 会话内存增长 | 资源面 |
| 审批门自身数据目录被改 | 等于给自己发通行证(它把该目录列为永远人工) | fail-closed 已覆盖 |

## 8. 评估清单

1. 它的硬拒层**能不能被后续层推翻**?推翻路径写在哪?
2. 匹配读的是**真实命令/真实目标**,还是「说明措辞」?后者等于把权限授予写文案的人。
3. 额度折算的前提是「同一操作指纹」还是「同一类操作」?后者会把一次批准放大成一片。
4. 判定器不可用时,第一次是转人工还是静默拒绝?阈值已满时呢?两个答案必须分开写。
5. 围栏排在白名单与学习之前还是之后?**之后**意味着一次追认可以永久放行整类动作。
6. 拒绝理由里有没有「怎么改」?没有的话,模型只会重试同一动作。
7. 规则表规模是多少?谁来删规则?
8. 它的判定器要联网吗?待审内容里有什么?

## 9. 能搬走的东西：审批预算的四张清单

> 这一节是**设计借法**,不是对样本的评价。照抄这四张表,就能在你自己的审批层里复刻「防灾难但不复杂」。

### 9.1 管道分层模板(可照抄)

每一层只写「匹配什么 → 唯一动作 → 可不可被推翻」,一行一层,不允许组合条件:

| 序 | 层 | 匹配依据 | 动作 | 可被推翻 |
|---|---|---|---|---|
| 1 | **凭据 / 系统路径** | 目标路径是否落在凭据或系统目录 | `deny` | **否** |
| 2 | **不可逆动作** | 命令是否属于删除/覆盖/推送到远端 | `ask` | 否(但可给人 `allow`) |
| 3 | **危险词 / 围栏** | 文本特征(下载、动态执行、安装依赖、持久化) | `ask` | 是,但必须排在 4、5 **之前** |
| 4 | **配置自改** | 目标是否在配置目录(**除去自身数据目录**) | `allow` | 是 |
| 5 | **白名单** | 只匹配**真实命令 + 真实目标** | `allow` | — |
| 6 | **工作区外** | 目标是否在会话工作区外 | `ask` | — |
| 7 | **判定模型** | 前面都没命中时 | 模型 `allow/ask/deny` | — |
| 8 | **学习沉淀** | 只写人类确认过的操作指纹 | 写规则 | — |

**三条照抄要点**:

1. **层的顺序就是策略本身**。第 3 层必须早于第 4、5 层——否则一次「追认」就能把「下载即执行」永久放行(样本的原话:「已沉淀的宽规则盖不过它,否则一次追认就能把『下载』永久放行」)。
2. **第 1 层不可推翻**。这是唯一需要「不可推翻」的地方,不要给第二层也加这个属性——每多一层不可推翻,就多一个把用户锁死的误报。
3. **第 8 层只能写第 5 层的规则**,不能写第 1–3 层的例外。

### 9.2 额度折算的四个必填前提

样本的「确认 N 次后自动放行」默认 `riskyThreshold: 3`(`docs/GUIDE.md`),但真正可借鉴的是它的**前提条件**——少一条就会把一次批准放大成一片:

```
① 键必须是「工具 + 模式 + 类别」三元组   ← 换一个工具就是新账
② 只对 neutral 类别生效                 ← 删除/凭据/远程/系统/批量永不折算
③ 规则携带操作指纹,只放行确认过的那一个动作
④ 折算后的规则写入第 5 层(白名单),不得越过第 1–3 层
```

**如果你只抄一条**:抄 ②。审批疲劳的危险不是「问得多」,是「把不该折算的动作也折算掉」。

### 9.3 匹配锚定的惨痛教训(可直接复用为验收项)

样本用 30 天数据发现:897 条自动放行里 **30 条命令中根本没有规则词**——因为规则按「说明措辞」的 `contains` 匹配。修复后提示量 **147 → 178(+21%)**。

**验收项(写进你自己的测试)**:

- [ ] 构造一条 `contains: "github"` 的规则,然后跑 `npm test`——它**不该**被放行。
- [ ] 构造一条 `contains: "vitest"` 的规则,然后跑 `npm test`——它**不该**被放行。
- [ ] 改掉审批卡的说明文案,规则命中数**不应变化**。

> 这三条测试的意义:它们锁定「权限来自事实,不来自措辞」。**改个文案就能改权限**,是最容易被忽略的提权通道。

### 9.4 拒绝文本的两段式模板

```
[拒绝原因]  <一句话:哪条规则、哪个事实命中>
[影响范围]  <这次会动到什么:整机 / 工作区 / 只读>
[怎么改]    <替代写法,或「把路径贴给用户,不要重试」>
```

样本的实证:字段化之后,审批卡从「一整段散文」变成「操作 / 路径 / 影响 / 命令 / 原因」五行;`danger-full-access` 时追加「不限定路径,本次授权覆盖整机」,避免被误读成单路径授权。

**为什么这能降低复杂度**:说明写清楚了,你就**不需要为每个场景写一条规则**——用户可以自己判断。**把复杂度从规则转移到说明,是最便宜的一次预算腾挪。**

## 10. 开放问题

- [ ] 「确认 N 次后自动放行」的 N 取多少?样本默认 3,但没有 A/B 数据说明 3 比 2 或 5 好——这是本域最值得实测的参数。
- [ ] 30 天 897 条自动放行的样本里,有多少是**同一动作的重复**?如果重复率很高,额度折算的收益可能远大于判定器。
- [ ] 这一族插件互相引用为 0,是否说明**安全插件之间是替代关系而不是组合关系**?若是,「装两个审批插件」本身就是一种反模式。
