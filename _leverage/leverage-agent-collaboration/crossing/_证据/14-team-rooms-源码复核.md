  - `gotFact = this.sessions.get(memberId) !== undefined`（[`:814`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L814)）；
  - `gotDelivery` 只看消息方向，不看 `agent`（[`:815-817`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L815-L817)）；
  - `wasLive = this.sessions.get(memberId) !== undefined`（[`:818`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L818)）；
  - `lastFactSeq = event.seq` **无条件**随 `gotFact` 前进（[`:821`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L821)），`lastDeliveredSeq = message.seq` 随 `gotDelivery && wasLive` 前进（[`:822`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L822)）。
- **三个具体缺口**：
  1. `deliverPosted` 的 `agent.followup` 只在 `agent !== undefined` 时执行（[`:799-802`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L799-L802)），但 `advanceCursors` 只看 `sessions` 是否存在（[`:818-822`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L818-L822)）。**若 session 在、agent 不在，cursor 前进但没有任何投递。**
  2. `lastFactSeq` 的前进不检查 `FactAppender.append` 是否真的写了事件；`append` 返回 `void`，在 forbidden 宿主上只走 fallback（[`src/facts.ts:66-75`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/facts.ts#L66-L75)、[`:77-91`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/facts.ts#L77-L91)），但 `advanceFactsForLive` 仍把 cursor 设成 `timelineSeq`（[`src/room/hub.ts:830-840`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L830-L840)）。**cursor 的语义「log carries the fact」在 0.2.1-rc.3 上是假的。**
  3. `advanceFactsForLive` 直接赋值，不是 `Math.max`（[`:837`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L837)）；task 的 fact 广播在 write chain 之外（[`createTask` :499-503](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L499-L503)、[`mutateTask` :745-750](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L745-L750)），可在一个更高 `timelineSeq` 的 post 已把 cursor 推高后再把它**回退**。这条是源码顺序推断，触发窗口标 `[OPEN]`。
- **catch-up 的 cursor 更激进**：`catchUp()` 先 `requireRooms()`（[`:548`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L548)）；若 `session` 在、`agent` 不在，它仍遍历 facts 并只对 `agent !== undefined` 的成员 `inject` backlog（[`:566-568`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L566-L568)），然后把 `lastFactSeq` 推到 `timelineNext - 1`、`lastDeliveredSeq` 推到 `busNext - 1`（[`:569-585`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L569-L585)）。**没有 agent 也推进 cursor，等于把未投递的 backlog 标成已投递。**
- **留存窗会让 catch-up 丢消息**：`busMessages(roomId, since)` 只返回当前表里 `seq > since` 的消息（[`:213-219`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L213-L219)）；`pruneRoom` 删掉 `seq <= busNext - 1 - busRetention` 的 bus 行（[`:1006-1011`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L1006-L1011)）。若成员离线超过 200 条，`catchUp` 只取到保留窗口，却把 `lastDeliveredSeq` 推到 `busNext - 1`（[`:580`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L580)）——**中间的消息永久缺失，且被标记为已投递**。
- **fact 回放同样会跳过已 prune 的消息**：`factFromTimeline` 的 `message-posted` / `message-directed` 分支要从 bus 表按 `data.seq` 取回消息（[`:892-905`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L892-L905)）；bus 行被 prune 时返回 `undefined`，事件被跳过，但 cursor 仍推到 `timelineNext - 1`。同样，`task-created`/`task-claimed`/`task-assigned` 分支要从 `tasks` 表取任务（[`:907-936`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L907-L936)）；`taskRetention` 删掉旧 done 行后，这些 fact 也会被跳过。**「重投而不是丢」只在保留窗口内成立。**

### 3. 跨会话持久化与宿主重启

- **房间记录确实跨会话/重启**：`open()` 打开 `team_rooms` 域并缓存四张表（[`src/room/hub.ts:148-188`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L148-L188)）；`rooms`/`bus`/`tasks`/`timeline` 都在域里，插件不另建内存权威。`open` 失败会设 `initError`，之后每个操作 `requireRooms()` 抛同错（[`:1041-1045`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L1041-L1045)）。
- **重启后的 catch-up 有一个竞态**：`hasMember()` 在 `this.rooms === undefined` 时直接返回 `false`（[`:253-259`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L253-L259)）；`agent/created` listener 先同步 `if (!hub.hasMember(agent.id)) return undefined`，再 `queueMicrotask` 调 `catchUp`（[`src/index.ts:225-245`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/index.ts#L225-L245)）。`hub.open()` 是异步的（[`src/index.ts:203-207`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/index.ts#L203-L207)）。**若 session 在 storage domain open 完成前创建，`hasMember` 返回 false，本次启动的 catch-up 直接跳过；代码没有重试或延后重放。** 触发窗口取决于宿主启动顺序，标 `[OPEN]`。
- **`briefed` 是进程内集合**：`private readonly briefed = new Map...`（[:120](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L120)），重启清空；这是有意的「resume 再注入一次 brief」（[`:600-622`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L600-L622)）。
- **重启会丢 inbound 的关联表**：`inboundRoomSink` 的 `openTasks` 是闭包里的 `Map`（[`src/index.ts:297-329`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/index.ts#L297-L329)）；`agent_started` 写入 `traceId → taskId`，`agent_finished` 才 `completeTask`（[`:308-321`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/index.ts#L308-L321)）。宿主重启后映射为空，之前开的卡不会被 `agent_finished` 关闭，但仍会 post 一条完成消息（`deliveriesFor` 的 `agent_finished` 同时给 `task-close` 和 `bus-post`，[`src/inbound.ts:245-254`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/inbound.ts#L245-L254)）。**「完成任务卡」只在同一进程内成立。**

### 4. 成员/房间删除

- **成员主动离开（非最后一人）**：写 `member-left` timeline、从 `members` 移除、向**剩余成员**广播 `member-left` fact（[`src/room/hub.ts:342-370`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L342-L370)）。**离开者自己的日志没有 `member-left` fact**（`broadcastFact(next, ...)` 的 `next.members` 已排除它，[`:366-368`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L366-L368)），所以若它的 `teamRoom` 投影里已有该房间，它会继续显示自己仍是成员；`catchUp` 也不会再为它处理这个已不是成员的空间。
- **最后一人离开**：`members.length <= 1` 时 `rooms.delete` + `purgeRoom`（[`:351-355`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L351-L355)）。**没有任何 fact 写给任何人**；如果这是 owner 自己的最后一个房间，它的日志里仍留着 `room-joined` 快照。
- **owner 删除房间**：仅 owner 可调用（[`:374-384`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L374-L384)）；删除 `rooms` 记录、`purgeRoom` 清 bus/tasks/timeline（[`:1027-1033`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L1027-L1033)）、清所有成员的 `briefed`（[`:383`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L383)）。**没有追加 `member-left`，没有广播，也没有 `room-deleted` fact 类型**（closed union 见 [`src/room/events.ts:29-110`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/events.ts#L29-L110)）。因此其余成员的 `teamRoom` 投影（在能写 fact 的宿主上）会永久保留一个已经不存在的房间；`room_list_rooms` 则从 store 读，立刻看不到它。**「日志是重建副本」在删除路径上不收敛。**
- **成员会话被删除/归档**：插件没有监听 session 删除/agent dispose；`index.ts` 只注册 `agent/created`（[`:225-245`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/index.ts#L225-L245)），`leaveRoom` 只有显式 `/room leave` 路径。房间记录会永久保留这个 `sessionId`，占用 `maxMembersPerRoom`；投递时 `sessions.get`/`agents.get` 找不到它，`lastDeliveredSeq` 也不前进（[`advanceCursors` :814-822](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L814-L822)），消息只能等下一次 post 触发 retention 清理（若房间不再发消息则永远不清）。**卡片没有写这条生命周期。**

### 5. 冲突与排序

- **总线顺序**：`busNext`/`timelineNext` 在 `rooms` 记录里，post 在 write chain 内自增（[`src/room/schema.ts:32-43`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/schema.ts#L32-L43)、[`src/room/hub.ts:405-436`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L405-L436)）；`postMessage` 还套了一层 per-room chain（[`:393-399`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L393-L399)、[`:659-669`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L659-L669)），per-member chain 串行 live delivery 与 catch-up（[`:672-681`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L672-L681)）。**同一进程、同一 RoomHub 实例内，bus seq 严格按写链顺序铸造；卡片 L26 成立。**
- **任务 claim 是 last-writer-wins**：`mutateTask('claim')` 只检查 `bySessionId` 是成员、task 存在，然后把 `status` 设为 `in-progress`、`assignee` 设为调用者（[`src/room/hub.ts:694-724`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L694-L724)）；**没有检查 task 是否已经 assigned / done**。`room_claim_task` 的 description 说「Claim one unassigned task」（[`src/room/tools.ts:435-440`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/tools.ts#L435-L440)），实现并没有这条约束。两个成员并发 claim 会按写链顺序后者覆盖前者；claim 一个 `done` 任务会把它拉回 `in-progress`。
- **complete 有守卫**：只有 assignee 或 owner 能完成，`done` 重复完成直接返回原记录（[`src/room/hub.ts:704-707`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L704-L707)）；`assign` 只检查目标成员存在（[`:708-713`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L708-L713)），**任何成员都能把任何任务转给任何成员**，不要求 owner 或当前 assignee。
- **approval 只覆盖 tool 路径**：`room_transfer_task` 先 `requireApproval`，无 approval service / 拒绝 / cancel 都抛 `approval-unavailable`/`approval-denied`，不改状态（[`src/room/tools.ts:42-65`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/tools.ts#L42-L65)、[`:532-550`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/tools.ts#L532-L550)）。但 `/room task assign` 直接调 `hub.assignTask`，明确注释「the human typed the command … already user-authorized」，**不过 approval seam**（[`src/room/commands.ts:1-8`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/commands.ts#L1-L8)、[`:206-219`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/commands.ts#L206-L219)）。卡片 L33/L68/L79 若读成「所有交接都 approval-gated」则过宽；准确说法是「模型工具 `room_transfer_task` approval-gated，命令路径不等 approval」。
- **跨进程没有排序权威**：`tail` 是 `RoomHub` 实例字段（[`:109-110`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L109-L110)），所以两个宿主进程各自有一条；`team_rooms` 域的写链也是 per-open 实例（见 SRC-DSH）。**若两个 DSH 进程共享同一 storage backend，`busNext` 读-改-写没有 CAS/文件锁，可能撞 seq。** 卡片只说「不跨机」，没说「同机多进程」；标 `[OPEN]`。

### 6. 留存：只在 `postMessage` 执行

- `pruneRoom()` 自己实现 bus/timeline/done-task 三个窗口（[`src/room/hub.ts:1005-1024`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L1005-L1024)）。
- **全仓唯一调用点是 `postMessage`**（[`:437`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L437)）。`createTask` 追加 timeline（[`:486-492`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L486-L492)）不 prune；`mutateTask` 追加 timeline（[`:725-739`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L725-L739)）不 prune；`joinRoom`/`leaveRoom` 追加 timeline（[`:316-325`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L316-L325)、[`:357-364`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/room/hub.ts#L357-L364)）也不 prune。**一个只创建/领取/完成任务、不发消息的房间，`timelineRetention` 和 `taskRetention` 都不会生效。** 卡片 L36「三个窗口在每次写时执行」与 L80「留存窗口在每次写时执行」**不成立**。
- bus 只在 post 增长，所以「busRetention 只在 post 执行」本身够用；但 timeline 和 done-task 不是。

### 7. inbound（P2）

- 解析/映射 fail closed：非法 JSON / 非法 envelope / 未知 method / 缺字段 / 未知字段都返回 JSON-RPC error 并丢弃（[`src/inbound.ts:165-231`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/inbound.ts#L165-L231)）；`inboundParamsSchema` 是 `.strict()`（[`:63-70`](https://github.com/PerryLink/dsh-team-rooms/blob/c1c485e9defaa5c6dee36651d04bcface767ce78/src/inbound.ts#L63-L70)）。卡片 L47「非法消息 fail closed」**成立**。
