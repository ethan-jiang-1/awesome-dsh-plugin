# 研究规程

> 规则源仍是 [`00-map`](../00-map.md)；本文件只回答「**怎么做**」。与 lifecycle 的差别见 §7。

## 0. 三条原则

1. **问题驱动**：研究从 [`00-map` §4](../00-map.md#4-十个问题全册的验收尺子) 的十个问题出发，不从插件名单出发。
2. **饱和驱动**：当一个候选只能落进已有机制族、且差异只是触发条件时，它是变体，不是新研究。
3. **证据驱动**：L1 是底线，L2 是协调类样本的底线；达不到就写 `[OPEN]`，不写「已验证」。

## 1. 找：三层漏斗

| 层 | 手段 | 产出 | 纪律 |
|---|---|---|---|
| L1 召回 | `data/plugins/*.yml` 按关键词粗筛（subagent / handoff / orchestrate / team / swarm / workflow） | 350+ 条候选（量级，非精确） | **关键词只做召回，不做分类** |
| L2 分诊 | 读 registry 清单 + README，判定机制族、是否已有典型 | 候选池 `BACKLOG` | README 只能让人进入下一层 |
| L3 取证 | 抽 tarball、grep 符号表、读固定 commit | `[SRC-TARGET]` 行号 | 没有这一层，不许立卡 |

**召回不设影响力门**。★ 与下载量写进页头作采样事实，不参与准入（理由见 [`00-map` §7](../00-map.md#7-三道门先过门再立卡)）。

## 2. 分诊：先判族，再判级

对每个候选按顺序问：

1. **它拥有什么状态？** 拥有 roster/任务板 → teams；拥有执行图/缓存 → pipelines；拥有会话/连接 → crossing；只拥有委派调用 → delegation；只拥有拦截/裁决 → coordination。
2. **已有典型覆盖这个机制了吗？** 覆盖且只差触发/载体 → 变体；覆盖且机制不同 → 新族，可立典型。
3. **它在当前宿主上活着吗？** 归档/下架/机制未发布/版本不容 → 记生命状态，不因此降级（分级管代表性，生命状态管可用性）。
4. **它回答十问里的哪一问？** 答不出就不立卡。

分诊结果写进 [`BACKLOG`](./BACKLOG.md)，**一张卡三行以内**：族、级、理由。

## 3. 五步取证

| 步 | 动作 | 判据 |
|---|---|---|
| **P1 钉版本** | `npm view <pkg> dist-tags version gitHead dist.tarball`；有 tag 则对 commit；记 DSH 基线 `0.2.1-rc.3` | memo 页头写固定版本 |
| **P2 立假设** | 读 README，列出协作主张：成员是什么、状态在哪、怎么调度、结果怎么回 | 产出「待证清单」 |
| **P3 追一条链** | 入口 → 准入/权限 → 分配/调度 → 权威状态写入 → 对端可见 → 失败回滚 | 每段标「样本负责 / 宿主负责」 |
| **P4 建状态账本** | 实体/字段、owner/scope、内存/磁盘/宿主日志、并发与幂等、崩溃后剩什么 | 协作特有：谁写、写几次、丢不丢、重不重 |
| **P5 成卡** | 判族判级 → 典型/变体/反例 → 证据等级 → 过硬检 | 过 §5 的门 |

**P4 是协作册的核心**：三笔税（状态/冲突/收敛）全部落在这一张账本上。写不出账本，说明还没读到行为。

## 4. 谁写结论

**子代理只交原始证据**：命令原文、`文件:行号`、代码片段、无法解释的现象。**不交结论、不写摘要、不改写字段含义。**

理由：fanout 会把 registry 字段描述成一句人话，把「源码里没有」写成「不支持」——那样的东西进卡就是污染。

**主代理做 P3/P4/P5**：机制还原、机制族判定、七问回答、失效条件、分级。

## 5. 质量门（五条硬检 + 两条结构门）

| # | 硬检 |
|---|---|
| 1 | 每条机制断言有标签，且 `sed -n 'Np'` 能取出原文 |
| 2 | 至少一条失效条件或反例；每条 `[OPEN]` 带「下次怎么核」 |
| 3 | 映射到十问中的至少一问（写进页头 `answers:`） |
| 4 | 页头声明 `tier`（典型/变体/反例）+ `evidence`（L0–L3）+ 生命状态 |
| 5 | 同号 memo 存在且被卡片链接；固定版本、tarball 摘要、偏差表齐全 |
| 6 | （结构）章节有 `## 证据与边界` ≥3 行，且有一句可证伪条件 |
| 7 | （结构）`node _leverage/verify.mjs` 全绿 |

**变体的额外门**：卡首必须有「定位（变体）」差异段，写明「相对哪个典型、差异是什么、为什么仍值得留」；写不出差异，说明它要么是重复，要么该升典型。

## 6. 批次与停止条件

| 批 | 产出 | 完成判据 |
|---|---|---|
| B0 | 宪章 + 本规程 + `BACKLOG` + 分诊 | 分诊 18/18；三道门可执行 |
| B1 | 五篇家族篇 + `reference/SEAMS.md` + `COMPAT.md` | 每篇 ≥3 条 `[SRC-DSH]` 行号；兼容性墙 18/18 |
| B2 | 试验台 + `_证据/00` 账本；01/05/07/11 升 L2 | ≥6 条可复现 R 记录；≥1 条推翻现有结论 |
| B3 | 按十问补 ≤3 张新样本 | 每张对应十问一问；机制谱不变则停 |
| B4 | 判断层（单 vs 多、成本/容量）+ 去重落地（tier 写进卡片） | 十问 1/8/9 转「强」 |
| B5 | `TRAPS` / `CHECKLIST` / `BORROW` 配方 | 15 条 / 12 项 / ≤8 条 |
| B6 | IA 收口 + `verify` 扩门 | 新门全绿、预算全绿、无占位文案 |

**饱和判据**：连续 3 个候选都只能映射到已有机制族、且差异只在触发条件，本批停止，不再扩样本。

**先跑通流水线再放量**：B2/B3 的第一轮只做 2 张；挖不出 L1/L2 就改流水线，不硬写。

## 7. 与 lifecycle 的三处不同

| lifecycle | 本册 | 理由 |
|---|---|---|
| 影响力门（★/npm） | **不设**，只记录 | 协作实验天然低星；筛了会把地筛空 |
| 一条被认可的路 | **接缝表 + 判定树** | 协作没有唯一解，只有「按边界选接缝」 |
| 七列「可迁移洞察」 | 五条硬检 + `answers/tier/evidence` 页头 | 避免与产品册重复造表 |

借的只有四件：单一规则源、四段式篇章、只收原始证据、实测账本。

## 8. 结论被推翻时

1. 正文改，旧结论**不删**，在 `practice/TRAPS.md` 记一条「曾经这么以为」。
2. 若推翻来自本轮实测，给 R 号；若来自上游变更，给版本与行号。
3. 若整张卡的机制不成立，`tier` 改 `反例`，`catalog` 与 `encyclopedia` 同步。
