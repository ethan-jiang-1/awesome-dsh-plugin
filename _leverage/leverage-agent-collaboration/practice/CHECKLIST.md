# 多 agent 方案上线前自检

> 每项都给**怎么核**。核不了的项就是 `[OPEN]`，不要当通过。

## 决策

- [ ] **先回答「单 agent 够不够」。** 核：写出三样买点（并行上下文/独立验证/异构角色）各占不占；一样不占就停，回单 agent。
- [ ] **写下「什么情况下否决这个方案」。** 核：能举一个具体任务，说清它为什么不该用多 agent。

## 状态

- [ ] **权威状态唯一。** 核：roster / 任务 / 消息 / 证据 四张表各写一个 owner；找出所有第二真相源。
- [ ] **并发写有串行机制。** 核：两个进程同时写同一条记录，看是否丢更新（照 R4 的方法）。
- [ ] **锁或租约带归属。** 核：让锁过期再接管，原主再写会发生什么；有没有 epoch 或单调序号。
- [ ] **owner 有释放路径。** 核：崩溃 / 退出 / interrupt 三条路径，分别谁回收；不回收会永久占位吗。

## 冲突

- [ ] **拦截在写路径上。** 核：列出所有会改文件的工具；`pre-execute` deny 覆盖了几个，shell 重定向算不算。
- [ ] **隔离方式与代价写清。** 核：用 worktree 还是共享 checkout；worktree 只带已提交文件，未跟踪状态怎么处理。

## 收敛

- [ ] **消息可重投不重复。** 核：同一消息投两次，接收方执行几次；没有幂等键就写「不保证」。
- [ ] **结果回传通道明确。** 核：父不在线时消息去哪——拒绝、排队、还是落盘？写进文档。
- [ ] **恢复 ≠ 重跑。** 核：重启后剩什么控制面；恢复要过哪几道校验（checkpoint / authority / template hash）。

## 成本与观测

- [ ] **三层额度写清。** 核：宿主池（深度/并发）、编排上限（节点/时长）、预算（token/人工）各是多少，超了报什么。
- [ ] **指标能按任务拉出。** 核：token、重投、stale、人工介入四项，分别从哪个字段/事件读。
- [ ] **失败可读。** 核：`denied` / `stale` / `blocked` 三种状态各在哪查；查不到就是不可读。

## 分发与证据

- [ ] **装得上、重启语义正确。** 核：`npm view` 有包、peer 覆盖当前宿主、装完要重启还是刷新；别只看 README。
- [ ] **关键结论可复现。** 核：每条机制断言有 R 号或 `文件:行号`；没有就标 `[OPEN]`，不进 BORROW。

## 证据与边界

|---|---|---|---|
