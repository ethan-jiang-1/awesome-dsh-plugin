# 05 · 失败收敛与选型矩阵

## 1. 三类跨家族失败

| 失败 | 典型机制 | 现有证据 |
|---|---|---|
| **覆盖写**（lost update） | 磁盘真相源 + 进程内锁；跨进程后写覆盖 | `agent-teams`、`teams-x`（锁只串行写）、`taskswarm`（无跨进程锁） |
| **假成功**（false success） | `kick()` 吞 turn 内错误；完成判据只看超时/中断 | 宿主 `dsh-agent-loop:887-890`；`remote-agent` 已修 |
| **假恢复**（stale resume） | 记录还在、控制面已丢；批次 JSON 非原子；active→interrupted | `dsh_workflow`、`team-gui`、`taskswarm` |

共同点：**“记录存在”“能力存在”“可继续”是三件事**，多数方案只保证第一件。

## 2. 选型矩阵

| 你的首要约束 | 优先家族 | 必须问清楚 |
|---|---|---|
| 成员要异构（模型/权限/技能） | teams（独立根 Agent 路线） | roster 谁写、权限冻结还是成员级可变 |
| 成员要能被反复追问 | teams（continuable） | 结果走邮箱/通知、ack 在哪一步 |
| 步骤可预先列出、要可视化 | pipelines（声明式 DAG） | 图的表达力、重放键 |
| 步骤带并行/条件/循环 | pipelines（代码即编排） | 缓存键、失败重跑成本 |
| 只是让另一台机器接上 | crossing（远端 worker） | hub 对 worker 的能力、凭证边界 |
| 只是让另一个会话接上 | crossing（handoff） | 替换的是会话还是进程、失败回滚 |
| 怕写冲突 | coordination + `file-claim` 类 | 覆盖工具、fail-open 面、fencing |

## 3. 评审七问

1. 权威状态在哪？第二真相源是什么？
2. 并发写由谁串行？锁跨进程吗？有归属/fencing 吗？
3. 完成判据包含错误事件与产物校验吗？
4. 失败后是恢复、重跑，还是留 stale 记录？
5. 冲突拦截在写路径上吗？覆盖哪些工具/形态？
6. 跨会话/跨机替换的是什么层？握手/鉴权/回滚各是什么？
7. 哪些行为没跑过？`[OPEN]` 列全了吗？

## 4. 借用与判定

- 想抄“可续团队”→ 先读 teams/01/03；想抄“可复现流水线”→ pipelines/01；想抄“跨机”→ crossing/01/03。
- 想抄“真拦写”→ coordination/04，但先接受它放弃成员模型的代价。
- 想要“状态/冲突/收敛”的统一检查表 → 本节 + `00-map §5` 判定树。
