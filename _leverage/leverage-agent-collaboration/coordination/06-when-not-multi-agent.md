# 何时不该用多 agent

> **默认是单 agent。** 多 agent 不是「更强的单 agent」，是**用协调成本换三样东西**。三样里一样都不占，就只是把同一个任务拆成更多 token 和更多失败面。

## 0. 三条买点

| 买点 | 成立条件 | 不成立时 |
|---|---|---|
| **并行上下文** | 任务能切成互不依赖的方向（breadth-first 调研、多文件审计） | 紧耦合、共享同一份上下文 → 拆分只会丢信息 |
| **独立验证** | 需要第二双「干净眼睛」审产物（代码审查、事实核验） | 验证本身依赖 writer 的上下文 → 子代理只能复读 |
| **异构角色** | 成员需要不同模型/权限/工具（强模型规划 + 便宜模型执行） | 角色同质 → 只是复制同一个 agent |

**反过来的判据**：如果这三样都不占，多 agent 的净收益是负的——你付出了协调开销、上下文复制、收敛失败的概率，却只换来「看起来更忙」。

## 1. 五步判定（按顺序，任一不过就停）

1. **写入是否单线程？** 多个 agent 同时改同一工作区时，先解决隔离或互斥（worktree / `pre-execute` deny），否则直接不做。**并行写者是这类系统最常见的翻车点。**
2. **任务能不能切成独立方向？** 能切 → orchestrator-worker 有真实收益；切不开 → 单 agent 或单 agent + 只读子代理。
3. **是否需要独立验证？** 需要 → generator-verifier 是性价比最高的一种多 agent；不需要 → 别为「多一层」而多一层。
4. **成本付得起吗？** 多 agent 的系统性成本是 token（见 §2）。**如果任务的价值撑不起 10 倍 token，收益再漂亮也不划算。**
5. **失败模式可观测吗？** 崩了能不能看出是规格、协作还是验证出的问题？看不出来，就不要上线。

## 2. 反方证据（这一节比正面案例重要）

- **并行写作者大多不成立。** Cognition 在 2026-04 的复盘里明确：真正跑通的是「写入保持单线程、其他 agent 只贡献智力」的形态；并行 writer swarm 的多数想法仍没有像样的落地；无结构 swarm 基本是干扰，实用形态是 map-reduce-and-manage `[LIT]`。
- **多 agent 很多时候是在买 token。** Anthropic 的工程复盘给出两个数：多 agent 系统约用 **15×** 聊天 token；在 BrowseComp 上 **token 用量单独解释 80% 的性能方差**。他们同时说清适用面：适合 breadth-first 调研，**编码类任务真正可并行的部分更少**，强依赖共享上下文的任务不适合 `[LIT]`。
- **收益是真的，但有边界。** 同一篇复盘里，Opus 主 + Sonnet 子的多 agent 在他们内部调研评测上比单 agent Opus 高 **90.2%**——这不是通用增益，是「可并行调研」这一类的增益 `[LIT]`。
- **失败有分类。** MAST 把多 agent 失败归成规格、协作错位、验证与终止三类；它提醒的是：**大多数失败不是模型不够强，是任务没说清、成员没对齐、完成没判据** `[LIT]`。

## 3. 三个常见误判

1. **「人多力量大」**：多 agent 的收益来自**独立上下文**，不是来自人数。上下文相同，多开一个只是重复劳动。
2. **「并行一定更快」**：同步等待会让最慢的成员拖住全体；子代理之间不能互相 steer 时，错误只能等回头才发现 `[LIT]`。
3. **「自己的 reviewer 不可信」**：恰恰相反——给 reviewer **干净上下文**（不带 writer 的长轨迹）往往能发现 writer 看不见的问题；Cognition 报告其审查代理平均每个 PR 抓 2 个 bug、约 58% 属严重级 `[LIT]`。**别把 writer 的上下文灌给 reviewer。**

## 4. 什么时候仍然该做

- 任务价值高、可并行方向多、结果可验证（调研、审计、多方案对比）；
- 需要把「做」与「验」分开，且验证方能拿到干净上下文；
- 成员必须异构（不同模型/权限/工具），单 agent 无法同时具备；
- 你已经能观测失败（见 [`07`](./07-cost-and-observability.md)）。

## 5. 失效条件

- 本文的判据是**决策框架**，不是实验结论；它没有回答「某个具体任务上多 agent 一定更好」。
- 外部文献的样本以调研/编码为主，**不能外推到所有任务**；引用时保留原文的适用面。
- 三笔税（状态/冲突/收敛）仍在；本文只回答「值不值得开始」，不回答「怎么搭」。
