# `view_ui/` 工作规则

ui 领域册。全表最大类(2351 条,20.0%),新作者的第一落点。上层纪律见 [`../AGENTS.md`](../AGENTS.md) 与 [`../_view/AGENTS.md`](../_view/AGENTS.md)。

## 册内结构(三级)

| 层 | 文件 | 作用 |
|----|------|------|
| 册 | `README.md` | 快照 + 子分类索引 + 稳定性判读 |
| 子分类 | `<子分类>/README.md` | 定义 + 已确认成员 + 立卡条件 |
| 单卡 | `<子分类>/NN-<slug>.md` | 源码级分析(八段模板) |

子分类(从头部自述归纳):`enhance-shell`(增强现有壳)/ `replace-shell`(换壳)/ `inline-genui`(内联生成式 UI)。
## 单卡八段(固定,按序)

1. 一屏事实(条目/类目/自述/星标⚠/下载⚠/扩散/commit/包形态/代码规模)
2. 它到底是什么(机制,不是自述)
3. 怎么接进 DSH(manifest、hooks、注册点、patch)
4. 关键实现(文件结构 + 核心模块 + 数据流)
5. 为什么它突出(扩散证据 + 同类对比)
6. 代价与边界(权限、依赖、失败模式、兼容负担)
7. 可信度与复现(证据等级、命令、未读部分)
8. 待验证

## 本册特有注意

- **ui 里"壳"分三种路线**,写卡时先定位属于哪种:增强现有 web 壳(better-sidebar 类)、换掉壳(TUI 类)、独立工作台。路线不同,代价不可比。
- 类内头部断层明显(2216/2009 → 394 → 224),中部空心;新卡优先从那批 2000+ 星或高扩散者里选,不按星标流水账列。
- 新作者大量以 ui 为第一落点,`01-emerging` 的新 owner 榜要回看:这些人的条目是否开始成组出现(苗子信号)。

## 刷新

`census.py` 字号数字 + `delta.py` 的类目热度;单卡不随每轮重写,只在被分析插件有新提交(commit 变化)或扩散数显著变化时复核。
