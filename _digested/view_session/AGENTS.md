# `view_session/` 工作规则

session 领域册。914 条(第三大类)、本期新增 352、owners 829(单件 92%)。上层纪律见 [`../AGENTS.md`](../AGENTS.md)。

## 册内结构(三级)

| 层 | 文件 | 作用 |
|----|------|------|
| 册 | `README.md` | 快照 + 子分类索引 |
| 子分类 | `<子分类>/README.md` | 定义 + 已确认成员 + 立卡条件 |
| 单卡 | `<子分类>/NN-<slug>.md` | 当前无;满足立卡条件后新建 |

子分类:`import-export` / `rewind-edit` / `interconnect`。

## 立卡条件(满足任一即立)

1. 类内出现 **≥500 星**或 **≥3 个第三方衍生**的条目;
2. 出现被 5 个以上条目提及的实现(扩散信号,`delta.py` ③b);
3. 某条目从 session 类跨出去成为平台(如其他类目开始点名它)。

未满足时在 `README.md` 的「册内页」写明"暂无 + 原因",不预建空文件。

## 本册特有注意

**这是供给第三大、沉淀最弱的类**:914 条对 83 星头部,说明需求广但方案未收敛(导入/导出/回退/压缩各家各做各)。这个缺口本身就是结论——写卡或改 README 时不要用"头部弱"推断"没人用",只能说"没有公认实现"。

**收敛信号优先级**:出现第二个实现同一件事的插件 → 看它们是否互相提及 → 若有互指,说明竞争开始;若一方开始被第三方点名,标准可能成形。

## 刷新

数字随 `census.py`/`delta.py`;每轮检查立卡条件是否被触发。
