# context-shaping — 上下文整形与蒸馏

> 不改记忆本身,改的是"什么进入上下文":压缩、蒸馏、自动召回。

## 定义

在会话与模型之间做剪辑:压缩历史、背景蒸馏成 skill、固定边界自动注入。判定标准:**主要作用**是改变当轮上下文构成,而不是新增长期存储;若同时写持久化,在卡内说明边界,按主要机制归类。

## 生长

这是 memory 与 session 的**交界带**:与 session 类的压缩/回退条目容易重叠,归类时以"是否产生持久化"划线。上下文工程目前是标签增速前排(+285),值得盯。

**auto-memory 是"召回/沉淀"**:动态记忆与唤回尾注走 `ctx.systemPrompt.context()` 投影成 **user 消息**、只在文本变化时追加到历史尾部;system prompt 里只放一段常量纪律,所以前缀不动。到水位后不是裁剪历史,而是**建新会话 + 投 18 000 字符三段式交接材料**。它同时写三份 Markdown,严格说也新增长期存储——按"主要作用是改变当轮上下文"暂归本分支,是 local-store 与 context-shaping 的交界样本。

**已弃用的不立卡**:DSH 原生 ACP 曾有一个实现 `billion-context-dsh`,2026-10-24 已停维护并指向上游统一版 `ranxianglei/billion-context`;它的机制已被上游覆盖,继续当选项会误导。这里只留一句记录,不进入图谱,也不占卡片位。**选型时先看"是否还在维护",再看机制。**
