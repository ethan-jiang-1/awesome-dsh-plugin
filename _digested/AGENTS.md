# `_digested/` 工作纪律

本目录消化 awesome-dsh-plugin 上游(**评估者视角**:生态长什么样、数据可不可信、哪些值得借)。两个动作会改它:**上游同步**与**视图重建**。所有数字必须可由脚本复现;复现不了的价值判断放 `_leverage/`。

## 供应链(从上游到一篇插件分析)

```text
upstream main (awesome-dsh-plugin/awesome-dsh-plugin)
  │ ① git fetch → ② merge
  ▼
data/plugins/*.yml  ├─ ③ census.py ──► 全量结构数字 ──► ecosystem/(档案:逐专题正文)
                    └─ ④ delta.py <old> <new> ──► 两期差异 ──► _view/(视图)
                                                                 │
                                        ┌────────────────────────┴──────────────────┐
                                        ▼                        ▼                  ▼
                                 01-emerging            02-heat-map          03-anchors
                                 (谁冒出来)              (哪类热闹)           (谁是锚)
                                                                                │
                                                                                ▼
                                            ⑤ view_<领域>/README.md(领域册:快照+子分类索引)
                                                                                │
                                                                                ▼
                                            ⑥ view_<领域>/<子分类>/README.md(子分类:定义+成员+立卡条件)
                                                                                │
                                                                                ▼
                                            ⑦ view_<领域>/<子分类>/NN-<slug>.md(单插件源码级分析)
```

| 产物 | 生成方式 | 消费方 | 缺了会怎样 |
|------|----------|--------|-----------|
| `ecosystem/*` 全量档案 | `census.py` + 手工解读 | 引用当前基线数字的所有场合 | 数字过期,结论静默失效 |
| `_view/01~03` 三块板 | `delta.py` 复现数字 + 手工归纳 | 外部读者第一屏 | 读者只能自己扫 11744 条 |
| `view_<领域>/README.md` | 从 `census.py`/`delta.py` 抄数 | 关注单一领域的读者 | 领域内看不到相对位置 |
| `view_<领域>/<子分类>/README.md` | 人工确认成员 + 立卡条件 | 想知道某分支有哪些做法的人 | 领域内看不到分型 |
| `view_<领域>/<子分类>/NN-<slug>.md` | 浅克隆 + 读源码 + 八段模板 | 想借鉴/判断某插件的人 | 只有星标,没有机制 |

## 每轮同步:七个动作(缺一不可)

1. **探规模**:`git rev-list --count`、`git diff --stat`;先看 `scripts/`、`.github/`、`package.json` 是否有 diff(零 diff 轮与有 diff 轮工作量差一个量级)。
2. **合入**:https 通道 + `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=60` 后台 fetch,`git merge --no-ff`;研究目录若被上游删除,先从合并前分支恢复。
3. **核分母**:`python3 _digested/ecosystem/census.py`,总数必须等于 `ls data/plugins/*.yml | wc -l`、0 解析失败。**不符先修 `census.py` 再落任何数字**——手写解析器对 js-yaml 合法形态的漏收已发生六次,每次都静默少分母;同时确认标签命中数与中文描述数没有塌缩(塌缩 = description 解析坏了)。
4. **写当期记录**:`_change_log/NNNN-<from>-to-<to>.md`,七个专题各一行判定(需复核 / 已核验 / 无对应 diff)+ 一句理由。有真实 diff 的专题:逐行读 diff、改写对应 mechanics 档案,才能降为「已核验」。
5. **回写状态**:`_coverage/00-index.md` 矩阵、`_digested/00-index.md` 审计基线行、`_faq_on_digested/` 时效提示。
6. **重建视图**:`_view/` 整页重写 + 领域册更新(细则见 `_view/AGENTS.md` 与各册 `AGENTS.md`)。
7. **验证**:`node _digested/verify.mjs` 通过,当期记录末尾回写「复核日期 + 核对到的短 hash」。

## 视图规则(三块板 + 领域册 + 单卡)

1. **视图零原创**:`_view/` 与 `view_<领域>/` 的每个数字必须能由 `census.py` 或 `delta.py <old> <new>` 复现;机制性断言必须链接档案层。发现没依据的说法,删掉或先去 `_leverage/` 补证据。
2. **覆盖式重建**:每轮同步后整页重写,不追加、不打补丁;历史归 `_change_log/`。每页顶部必须有:本期区间、基线 hash、数据截止日。
3. **星标边车是历史采样**(冻结 2026-08-19),引用必带 ⚠;「新增头部」为空是采样缺口,写成缺口,不写成「无影响力」。
4. **立册门槛**(够格才立,不预建空页):体量 ≥400 且本期新增 ≥100;存量有 ≥100 星或源码级锚;owners ≥300 且单件作者 <95%。
5. **三级结构固定**:`view_<领域>/` → `<子分类>/` → `NN-<slug>.md`。子分类是领域内的真实分型(如 ui 的 增强现有壳/换壳/内联生成式),**从头部条目的自述里归纳,不拍脑袋设**;没有成员的分支只写进领域 README 的待孵列表,不建空目录。
6. **单卡只研究自己**:一张卡只回答"这个插件是什么、怎么实现、代价是什么",**不与其他卡做对比、不评价谁更好、不搬另一张卡的事实**。对比、排序、分型归纳一律放在子分类 `README.md`(成员表)或 `_view/03-anchors.md`(锚表)。理由:卡要能独立成立、单独更新,互相引用会重复且随对方变化漂移。与本机 DSH 源码/官方包的对照属于证据,允许。
7. **单卡必须是源码级分析**:浅克隆(`--depth 1`)→ 记录 `repo@commit` → 读 manifest/入口/核心模块/patch/依赖(README 只当索引)→ 八段模板(见各册 `AGENTS.md`)。每条机制性断言指向具体文件;读不到写「待验证」,不许由自述推断。一篇装不下时在子分类内升级为 `NN-<slug>/` 子目录,不要压缩深度。
8. **证据等级**:★ 注册表自述 · ★★ 读过 README/文档 · ★★★ 源码级(须带 `repo@commit`)。
9. **「被模仿」是锚的硬判据**:第三方提及/衍生数由 `delta.py` ③b 现算,不依赖星标边车。声量(星标)× 扩散(被模仿)两轴都高才是真锚;只有声量高的是"明星"。
10. **人力预算**:每轮只给 1-5 个锚补深度(★→★★→★★★),优先两轴都高的;新卡先占位再补深度。

## 完成判据

- `node _digested/verify.mjs` 通过;
- census 分母与工作区条目数一致、0 解析失败;
- `_view/` 每页顶部一屏能回答该板问题 + 数据截止日;
- `_change_log` 当期记录末尾回写复核日期与短 hash。

数字引用前必读 [`_method/00-index.md`](_method/00-index.md)(下载/星标的时效边界)。
