# `_digested/` 工作纪律

本目录消化 awesome-dsh-plugin 上游(**评估者视角**:生态长什么样、数据可不可信、哪些值得借)。上游每周涨几千条、源码每轮都可能变,所以这里定的不是流程模板,是**底线 + 可自己判断的空间**。

---

## 一、三条底线(不可动摇)

任何一条破了,产出就是错的——不是"不够好",是**误导读者**。

### 底线 1:数字必须可复现,且分母先对上

- 所有结构数字来自 `census.py`(全量)或 `delta.py <old> <new>`(两期),不许手算、不许估。
- 跑完先核对:`census` 总数 == `ls data/plugins/*.yml | wc -l`,且 **0 解析失败**。不符就**先修解析器再落任何数字**——手写解析器对 js-yaml 合法形态的漏收已发生六次(行内注释、JSON-in-.yml、折叠标量、整文件缩进、缩进支持引入的 en/zh 回归),每次都静默少分母。
- 标签命中数与中文描述数要抽查一眼:突然塌缩 = description 解析坏了。

### 底线 2:时效永远标在数字旁边

- 星标/下载来自冻结边车(2026-08-19),引用**必须**带 ⚠ 和日期;「新增头部为空」是采样缺口,要写成缺口,不写成「无影响力」。
- 每页顶部写清:本期区间、基线 hash、数据截止日。
- 历史口径和当前口径混在一句话里,就是误导。

### 底线 3:单卡只研究自己,且必须读过源码

- 一张卡只回答"这个插件是什么、怎么实现、代价是什么"。**不与其他卡对比、不搬另一张卡的事实**——对比放子分类 `README.md` 或 `_view/03-anchors.md`。
- 卡片头必须写证据等级(★ 注册表自述 / ★★ 读过 README 或文档 / ★★★ 源码级)与日期;**★★★ 必须带 `repo@commit <hash>`**,★★ 尽量记一个参考坐标(只读 `git ls-remote` 也算),但不得因此冒充读过源码。
- 每条机制性断言指向具体文件;没读到就写「待验证」,**不许由自述推断**。
- 与本机 DSH 源码、官方包的对照属于证据,允许。

## 二、裁量空间(这些由你判断,不是规矩)

上游在变、生态在长,下面这些**每轮都可以不一样**:

| 事项 | 说明 |
|------|------|
| 子分类怎么划 | 从头部条目的自述里归纳真实分型;分型变了就重划,别守着旧目录。没有成员的分支只写进领域 README 的待孵列表,不建空目录。 |
| 立册/立卡的时机 | 参考下面的"默认门槛",但**它只是默认值**:生态涨了、门槛可以抬;某个领域突然热了、可以破例先立。 |
| 每轮补几个锚 | 建议 1-5 个,但删掉、重写、只补证据都算数;没有值得补的就不补。 |
| 每张卡的篇幅与侧重 | 八段是**骨架不是配额**,机制复杂的就长,纯配置包的就短。 |
| 是否新增板/新维度 | 读者问题变了就加;别为了对称硬凑。 |

**默认门槛(可调)**:领域体量 ≥400 条且本期新增 ≥100、有 ≥100 星或源码级锚、owners ≥300 且单件 <95%;子分类立卡参考 ≥500 星或被 ≥5 个条目点名。数字变了就改这里,不要改底线。

### 单卡八段(唯一模板,子目录不再重复)

1. 一屏事实:条目 / 类目 / 自述 / 星标 ⚠ / 下载 ⚠ / 扩散 / `repo@commit` / 包形态 / 代码规模
2. 它到底是什么:机制拆解,不是自述转述
3. 怎么接进 DSH:manifest、hooks、注册点、patch、依赖
4. 关键实现:文件结构 + 核心模块 + 数据流
5. 为什么它突出:**只用本插件自身证据**(扩散/声量/机制独特性)
6. 代价与边界:权限、外部依赖、失败模式、维护成本
7. 可信度与复现:证据等级、复现命令、未读部分
8. 待验证:确认还缺什么才能下判断

八段是骨架不是配额:机制复杂的写长,纯配置包的写短。装不下时在该子分类内升级为 `NN-<slug>/` 子目录,不要压缩深度。

### 卡片 frontmatter(单一源)

每张卡、每张参考卡都必须以 frontmatter 开头;这是卡片元数据的**唯一源**,领域册/图谱/健康表都不再手抄这些字段:

```yaml
---
kind: card              # card | reference(reference 是没读源码的参考基线)
domain: ui
subcategory: enhance-shell
repo: omdsh-dev/DSH-better-sidebar
commit: 2811573c9c0bad51d77db6c3c94d78f5aed8d38a
evidence: 3             # 1/2/3;3 必须有 commit
status: active          # active | watch | stale | deprecated | frozen | archived
asof: 2026-11-18        # 本卡结构事实的截止日
---
```

- `kind: reference` 不要求八段,但必须写清“未读源码”和参考 commit;领域册不得把它算进“全部 ★★★”。
- `status` 是**可复核的状态词**,不是编辑口径:
  - `active`:近 90 天有 push,且没有已知的宿主兼容断裂;
  - `watch`:可用,但钉了旧 peer/旧宿主,或有关键限制(需改造);
  - `stale`:主分支/发布停更 >90 天,只作机制参考;
  - `deprecated`:被宿主内置能力或官方实现取代;
  - `frozen`:版本/peer 已不可安装,不建议新装;
  - `archived`:仓库 archived(以 live 快照为准)。
- `verify.mjs` 会校验:frontmatter 必填字段、`★★★` 必须有 commit、`kind: card` 必须有八段、SVG 证据级与 frontmatter 一致、SVG 链接必须指向卡片、领域册“全部 ★★★”必须真的全 3 星、`_data/cards.json` 必须与 frontmatter 同步。
- 改卡先改 frontmatter;改完跑 `python3 _digested/ecosystem/view_data.py` 重建 `_data/cards.json`、`_data/health.md`、`_data/summary.json`。

### 健康/衰减(第三轴)

声量 × 扩散之外,再加一条**健康**轴:最近 push、archived、peer 兼容、是否被宿主取代。
判定以 `_snapshots/live-*.json` + 卡片正文的兼容性证据为准;不得只凭“最近没看到更新”写“停更”。
`_data/health.md` 是生成物,列出每张卡的 stars / pushed_at / 下载 / flags;flags 里的
`stale-candidate` 是**待复核**,不是自动判死。

## 三、供应链(从上游到一篇插件分析)

```text
upstream main (awesome-dsh-plugin/awesome-dsh-plugin)
  │ ① fetch → ② merge
  ▼
data/plugins/*.yml  ├─ ③ census.py ──► 全量结构数字 ──► ecosystem/(档案)
                    └─ ④ delta.py <old> <new> ──► 两期差异 ──► _view/(三块板)
                                                                 │
                                                                 ▼
                                            ⑤ view_<领域>/README.md(册:快照+子分类)
                                                                 │
                                                                 ▼
                                            ⑥ view_<领域>/<子分类>/README.md(分型:成员+立卡)
                                                                 │
                                                                 ▼
                                            ⑦ view_<领域>/<子分类>/NN-<slug>.md(单卡:源码级)
```

| 产物 | 生成方式 | 缺了会怎样 |
|------|----------|-----------|
| `ecosystem/*` | `census.py` + 解读 | 数字过期,结论静默失效 |
| `_view/01~03` | `delta.py` 数字 + 归纳 | 读者只能自己扫一万多条 |
| 领域册 `README.md` | 抄 census/delta 的数 + `_data/health.md` | 领域内看不到相对位置/健康度 |
| 子分类 `README.md` | 人工确认成员 + 立卡条件 | 领域内看不到分型 |
| 单卡 `NN-<slug>.md` | frontmatter + 浅克隆 + 读源码 + 八段 | 只有星标,没有机制 |

## 四、每轮同步(七步)

1. **探规模**:`git rev-list --count`、`git diff --stat`;先看 `scripts/`、`.github/`、`package.json` 有没有 diff——零 diff 轮和有 diff 轮的工作量差一个量级。
2. **合入**:https 通道 + `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=60` 后台 fetch,`git merge --no-ff`;研究目录若被上游删除,先从合并前分支恢复。
3. **核分母**:见底线 1。
4. **写当期记录**:`_change_log/NNNN-<from>-to-<to>.md`,七个专题各一行判定(需复核 / 已核验 / 无对应 diff)+ 一句理由。有真实 diff 的专题,逐行读 diff、改写对应 mechanics 档案,才能降为「已核验」。
5. **回写状态**:`_coverage/00-index.md` 矩阵、`_digested/00-index.md` 审计基线行、`_faq_on_digested/` 时效提示。
6. **重建视图**:`_view/` 三块板整页重写;领域册快照数字刷新;卡不重写,除非被分析插件有新提交或扩散数变了。
7. **验证**:`node _digested/verify.mjs` 通过,当期记录末尾回写「复核日期 + 核对到的短 hash」。

## 五、视图规则

1. **视图零原创**:`_view/` 与 `view_<领域>/` 的结构数字必须能在 `census.py`/`delta.py` 输出里找到出处;卡片级实时值必须能在 `_snapshots/live-*.json` 里找到对应仓库/包;归纳判断可以写,但要标明是判断。
2. **覆盖式重建**:三块板每轮整页重写,不追加、不打补丁;历史归 `_change_log/`。
3. **三级结构**:`view_<领域>/` → `<子分类>/` → `NN-<slug>.md`;子分类是领域内的真实分型,不是官方 23 类的复刻。
4. **锚的两轴**:声量(星标)× 扩散(第三方提及/衍生)。扩散先用 `delta.py` ③b 的**候选分层**(同名/描述),再由卡片逐条判定采纳性质;两轴都高才是真锚,只有声量高的是"明星"。不要把候选数直接写成"接入数"。
5. `view_<领域>/` 各有一份 `AGENTS.md`(写本册特有的判断线索);子分类只有 `README.md`(定义 + 成员 + 立卡条件)。通用规则只在本文件。

## 六、完成判据

- `node _digested/verify.mjs` 通过;
- census 分母与工作区条目数一致、0 解析失败;
- 三块板每页顶部一屏能回答该板问题 + 数据截止日;
- `_change_log` 当期记录末尾有复核日期与短 hash。

数字引用前必读 [`_method/00-index.md`](_method/00-index.md)(下载/星标的时效边界)。
