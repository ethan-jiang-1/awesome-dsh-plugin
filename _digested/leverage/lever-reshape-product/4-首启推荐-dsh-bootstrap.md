> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3`(它只依赖 profile 层语义,不依赖具体 CLI 参数)· **读于**:2026-10-31

## 1. 它在产品里的位置

| 七层 | 动作 | 说明 |
|---|---|---|
| **6 首启** | 装完第一屏的**推荐与安装** | 但**没有**用上游的 `settings.onboarding` 槽 |
| 7 分发 | 环境码 = 一套**可传递的 profile 快照** | 不是安装器,是"分发一个组合" |
| 5 默认值 | 只启用核心子集,其余停用;历史环境码留在浏览器本地 | 默认值是产品判断 |

### 1.1 为什么它绕开了官方的首启槽(重要)

`[DSH]` 上游确实有首启机制:`settings.onboarding` 槽(kind `list`,scope `root`),由 `ui-settings-general` 投影——**升序、一次只挂一个 step**;注册者自负 durable completion、能力就绪、文案、变更与 `inert` 生命周期;活动注册者拿到 `complete()` 与 `openSection(id)`。

| 上游那个槽是 | dsh-bootstrap 要的是 |
|---|---|
| 设置面板里的**一串模态步骤** | **装完立刻可见**的推荐面板(悬浮球 + 抽屉) |
| **一次只挂一个** | 一次要看**八个领域**的清单 |
| 有"完成"这个概念 | 没有"完成":你可以长期用它切环境 |
| 不承载"多条目产品" | 它的核心就是一张多条目表 |

> **抄这条判断**:上游的槽表达**流程**(一次一步),你要表达**目录**(一次看全),别硬塞——但要在文档里写清你为什么不用它,否则下一个人会以为你不知道有这东西。

## 2. 机制(可照抄的部分)

### 2.1 安装计划:四类状态,每类都给理由

| 状态 | 什么时候 | 用户看到 |
|---|---|---|
| **安装** | 目录里有、本地没有、版本锁到了 | 包名 + **精确版本** + 领域 |
| **已安装跳过** | `dsh.profile.bundles` 里已有 | 幂等,不重复 add |
| **版本没锁定而跳过** | 12 条补全额度内没拿到精确版本 | 明写原因,**不盲装 `latest`** |
| 装完是否启用 | 核心推荐 → 启用;其余 → installed-but-disabled | 一行布尔 |

**四条硬性行为**(原文要点):

1. **幂等**——已有的包不会重复 `add`。
2. **失败隔离**——单个包失败只进"失败"清单,不中断其余。
3. **版本锁定**——计划阶段尽量钉到精确版本并写进报告的 `lock`;环境码复刻时**还原同一版本**,而不是重新解析 `latest`。
4. **串行安装**——原文理由:"npm 会写同一个 `package.json`,并发必然互相覆盖"。

> 第 4 条值得单独抄:**这不是性能考虑,是正确性考虑**。凡是"多个操作写同一个文件"的场景(包管理、profile、锁文件),串行是唯一正确解,不是可优化项。

### 2.2 环境码:一个字符串要表达什么

```text
DSHB1.<base64url(JSON)>                # 明文
DSHB1z.<base64url(deflateRaw(JSON))>   # 压缩(默认取更短的那个)
```

```jsonc
{
  "v": 1,
  "createdAt": "2026-10-16T00:00:00.000Z",
  "profile": { "name": "desktop", "dshVersion": "1.0.0", "dshRange": "^1.0.0" },
  "plugins": [
    { "name": "dshmarket",     "version": "1.66.27", "enabled": true  },
    { "name": "dsh-cost-meter","version": "1.8.29",  "enabled": false }
  ],
  "digest": "d63144265c9adbfb"
}
```

| 设计点 | 做法 | 为什么 |
|---|---|---|
| 版本字段 | `v` 固定为 1,将来不兼容就升 `v` | 解码器可以**先看版本再解析** |
| `enabled` | 对应 `dsh.profile.bundles` **是否包含该名字**;`false` = 装了但停用 | 一个字段表达两态 |
| `dshRange` | 导入时**只提示、不阻断** | 环境码是"参考",不是"命令" |
| `digest` | 键排序规范化 JSON 的 SHA-256 前 16 位 | 防的是**粘贴被改/被截断**,不是防攻击 |
| 敏感内容 | 生成前扫**字段名与值**,命中就**阻止生成** | "不悄悄脱敏":脱敏会让码**静默变样** |
| 长度 | 上限 **6000 字符**;超了提示改用 `manifest.yaml + lock.json`(内容等价) | 聊天窗口/二维码的可粘贴边界 |
| 留存 | 历史环境码存**浏览器本地,不上传** | 隐私边界写进产品 |

### 2.3 导入:五栏差异预览,其中一栏是"不做"

| 栏 | 含义 |
|---|---|
| 需要启用 | 本地有、码里 enabled、当前停用 |
| 需要停用 | 本地有、码里 disabled、当前启用 |
| 需要安装 | 码里有、本地没有(精确版本优先) |
| 已经是启用状态 | 无需改动 |
| **环境码未包含,将保持现状** | **不删除**用户已有插件 |

`--only-toggle`(面板"仅切换开关、不安装"):只改 bundle 可见性,**缺的包只报告**。

> **这是整张卡最容易抄错、也最值得抄的一处**:配置导入有两种语义——**声明式收敛**(以码为准,多余的全删)与**增量应用**(只做码里说的事)。它选后者,并在预览里**给"不做"单独一栏**。选错的后果很具体:用户拿别人的环境码试一下,**自己的插件被删了**。

### 2.4 收敛自证:不信任自己的返回值

执行完**再读一次磁盘**,核对最终状态与计划一致,然后才出报告。

> 这条在"写配置"类插件里是分水岭:**API 调用成功 ≠ 文件真的长成你要的样子**(别的进程可能同时写、写盘可能失败、格式化可能改键序)。读回来验一遍,成本一次读盘,收益是"报告不会撒谎"。

## 3. 体验

### 3.1 首次使用逐屏

| 时刻 | 看到 | 设计 |
|---|---|---|
| 装 | `dsh plugin --profile desktop add dsh-bootstrap`,**重启一次**让插件层重载 | 说明里直接写"装完重启" |
| 打开 | 右下角 **56px 圆形按钮**(🚀);抽屉展开时挪到抽屉左侧,窄屏隐藏 | 不占布局,不改外壳 |
| 点开 | 品牌头部 + **分段式四标签** + 可滚动主体 + 底部版本条 | 四件事四种模式,不混成一个长滚动页 |
| 悬停 | 简介 + **Star / 近月下载分开写** + 需要的 dsh 版本 | 指标不混算 |
| 单击行 | 勾选;底部出现"安装选中的 N 个";行右侧还有"单独安装" | 批量与单个都在原地 |

### 3.2 两处"诚实"的文案(建议直接抄措辞)

- 离线时:UI **明确标注"离线快照,数据可能过期"**,Star/下载量是旧值。
- 失败时(英文摘要原句):"a failure only ever costs you the panel, never the host"——**失败只让你失去这个面板,永远不让你失去宿主**。

> 第二句是本域所有插件里对"**失败半径**"最直白的表述。

### 3.3 模型看到的

**为零**。推荐与安装全在人侧,不进模型请求。

> 这既是它的边界也是它的 `[OPEN]`:首启推荐**没有**让模型参与("根据你最近在做什么,先推这三个")。

## 5. 借鉴食谱表(本卡的产出物)

| 要解决的问题 | 照它的做法 | 你要改的地方 | 抄错的后果 |
|---|---|---|---|
| 一键安装让人不敢点 | **计划先于执行**:逐条列包名 / 精确版本 / 领域 / **跳过理由** / 是否启用 | 你的"安装"可能是模板/配置/技能,字段换成你的 | 直接开装 → 用户不知道发生了什么,出事无法归因 |
| 精确版本拿不到 | 有上限地补全(12 条),补不到就**跳过并说明** | 上限按你的接口速率定 | 盲装 `latest` → 版本漂移,首启即崩 |
| 多个包要装 | **串行**,理由写清"写同一个文件" | 若你的安装器不共享文件可并行,但要论证 | 并发写 `package.json` → 随机丢条目 |
| 装一半失败 | **失败隔离**,只进失败清单,不中断 | — | 一失败就整体回滚 → 用户失去已成功的部分 |
| 默认配置要保守 | 只启用"核心推荐",其余 **installed-but-disabled** | 把"核心"的定义写出来 | 全启用 → 首屏塞满,用户第一件事是关东西 |
| 配置要能传给别人 | 自包含字符串 + `v` + `digest` + **长度上限** | base64url;压缩只在更长时省事 | 无 `v` → 将来无法演进;无 `digest` → 截断的码被当成有效码 |
| 导入别人的配置 | **增量语义** + 五栏预览,**单列"未包含→保持现状"** | 若你确实要声明式收敛,必须在预览里**红字警告会删除** | 用户试一下别人的码,自己插件没了 |
| 生成含配置的字符串 | 生成前扫敏感字段与值,**命中就阻止生成** | 敏感词表至少要含 token/key/password/本机绝对路径 | 悄悄脱敏 → 码静默变样,复现不出来 |
| 写完配置要报告 | **读回磁盘做收敛自证** | — | 报告说成功、文件其实没变 → 信任一次崩掉 |
| 断网也要能用 | 缓存快照 + 内置种子 + **标注过期** + `offline` 下断言无网络调用 | 种子要带快照日期 | 断网白屏,或把旧数据当新数据 |
| 想用官方首启槽 | 先判断它是"流程"还是"目录":一次一步的槽装不下多条目产品 | 只要一步向导就用官方槽,别自建 | 硬塞 → 一次只显示一条,用户以为坏了 |
| 失败半径要小 | 明写"失败只失去面板,不失去宿主",并让这条在架构上成立 | — | 首启插件崩了 → 整个 web 起不来,用户卸载后才敢用 |

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| GitHub / npm 不可达 | 缓存快照 → 内置种子(16);`offline: true`;数据标注过期 |
| 缺版本且补全失败 | 该条标"版本没锁定,跳过"(**不装**) |
| 单个包安装失败 | 进失败清单,其余继续 |
| 环境码 > 6000 字符 | 提示改用 `manifest.yaml + lock.json`(等价) |
| 环境码 `digest` 不符 | **拒绝应用**,提示内容可能被改过 |
| 环境码 `dshRange` 与本机不符 | **只提示**,不阻断 |
| 桌面壳注入表是启动快照 | 悬浮球不出现 → 用独立页 `127.0.0.1:19387/dsh-bootstrap/panel`,或重启一次 |
| 插件自身崩溃 | 只失去面板,**不影响宿主** |
| 非 web profile | 只有命令行四子命令 |

- [ ] `[OPEN]` 它**没有**用官方 `settings.onboarding` 槽。若上游把首启槽从"步骤"扩成"可承载目录",它会不会搬回去?

- [ ] `[OPEN]` 环境码不含 `$DSH_HOME/cordis.patch.yml` 与 `--patch` 层,所以"同一环境码"在不同机器上可能配置不同。要不要扩到整个 profile 栈?
