# 0 · 领域模型：DSH 作为「产品」的七层与编号约定

> **状态**:`living`(随卡片增长修订) · **基线**:DSH `0.2.1-rc.3` · 名单 7924 条 @ `efe602e7b` · **快照**:2026-08-19
> **本卡不是样本卡**。它只定义:口径、七层、**文件名编号法**、证据级别、计量方法,以及跨卡可用的三条规律。
> 一卡一插件的入口在 §5。

## 1. 口径:只收 0.2.x 起,只看"产品化"

四条硬口径,任何卡片先过这四关,否则不进本域:

| # | 口径 | 怎么判 |
|---|---|---|
| **C1 版本** | 兼容 **DSH `0.2.0`+**(含 `0.2.0-rc.*` / `0.2.1-rc.*`)。0.1.x 时代的东西只作对照与反例 | README 的 peer/`engines.dsh`/兼容矩阵;实测声明;或上游 `[DSH]` profile 语法未变 |
| **C2 产品** | 改变**人怎么用它**——入口、首屏、默认值、身份、界面、分发、上手路径。纯能力增强(多一个工具、多一个 provider)不算 | 见 §3 七层;至少命中 2/3/4/5/6/7 之一,且改动对"人"可见 |
| **C3 上手** | 有明确的**首次使用路径**:装完到第一次成功,中间有几步、卡在哪 | 卡片必须写出"首屏/首启/first-run"一段,写不出即降级 |
| **C4 可计量** | 有可复核的影响力证据:★ / npm 下载 / 名单内被引 / 官方背书 / 下游吸收 | 见 §4;都没有 → 只作对照行,不单独成卡(机制独特的可例外,如 `1-薄基座`) |

> **C2 是分界线**。`dsh-context` 不是"多一个面板",它把"代理在扛什么"从不可见变成一页可读的图;`modlens` 不是"多一个工具",它让纯文本模型**接受粘贴图片**。**改变交互契约的才算产品。**

## 2. 七层(本域的骨架)

自下而上,层号越小越接近运行时:

| 层 | 名字 | 这一层回答的问题 | 典型样本 |
|---|---|---|---|
| **1** | 运行时 | agent 怎么跑、工具怎么调 | 上游 `[DSH]`,一般不作为产品面 |
| **2** | **表层** | 人从哪个界面进来(浏览器 / 终端 / 桌面 / 手机) | `13-dsh-tui`、`60-dsh-mobile` |
| **3** | **槽位** | 界面上多一块什么(面板、标签、内联块、注册表) | `11-dsh-better-sidebar`、`20-dsh-genui`、`30-dsh-context` |
| **4** | **身份** | 它是谁(预设、人设、模型路由、能力开关) | `70-modlens`、`80-dsh-agent-teams` |
| **5** | **默认值** | 不配置时是什么(主题、字号、权限档、语言) | 散落在各卡的"默认值账本" |
| **6** | **首启** | 第一次打开看到什么、几步能干活 | `40-dsh-bootstrap`、`13-dsh-tui` |
| **7** | **分发** | 怎么装、从哪装、怎么更新、坏了怎么回 | `50-dsh-market`、`60-dsh-mobile` |

**两条跨层规律**(卡片里反复出现,这里先立):

- **规律 A(改 2 层 ⇒ 必须自己补齐 5/6 层)**:换了"应用",就没人替你回答"第一次打开是什么样"。`13-dsh-tui` 因此自带四步向导;桌面壳因此自带安装器与更新器。
- **规律 B(改 3 层 ⇒ 只在人这一侧)**:槽位做得再厚,模型也感知不到。唯一的例外是**输出协议**类改动(`20-dsh-genui` 改了模型怎么"排版"答案),它同时动了 4 层。

## 3. 文件名与序号：第一位数字是「主题标签」，不是顺序

目录里一律 `N-关键短语-插件名.md`。

**第一位数字告诉你"这是哪一类卡"**，读到文件名就知道该去哪一类里找；**同一类的多张卡按文件名字典序排**（长短差不多，看着齐）。序号只回答分类，不回答先后。

| 打头 | 这一类是什么 | 现有卡 | 往哪扩 |
|---|---|---|---|
| **`0`** | **本域的门**。口径、七层、证据级别、命名法 | `0-领域模型` | 不扩。重叠就改这一张，不开第二张 |
| **`1`** | **壳与工作台**：改变"人坐在哪张桌子前"（2/3 层） | `1-薄基座-dock`、`1-厚工作台-better-sidebar`、`1-终端即产品-dsh-TUI` | 新的 IDE、侧栏、面板拼装、表层替换 |
| **`2`** | **内容形态**：改变"答案长什么样"（3/4 层） | `2-生成式界面-dsh-genui` | 图表、白板、地图、多模态输出 |
| **`3`** | **驾驶舱**：让看不见的东西被看见（3 层） | `3-驾驶舱-dsh-context` | 成本、任务板、审计、遥测、日志 |
| **`4`** | **上手**：第一次怎么开始（6 层） | `4-首启推荐-dsh-bootstrap` | 安装器、向导、迁移、模板 |
| **`5`** | **分发**：怎么装、坏了怎么回（7 层） | `5-分发与救生页-dsh-market` | 索引、镜像、签名、更新器 |
| **`6`** | **多端**：同一个 DSH 的另一块屏幕（2/7 层） | `6-多端与远程-dsh-mobile` | 桌面壳、平板、IM 通道、隧道 |
| **`7`** | **感官与模型**：模型能感知什么（4 层） | `7-感官接入-modlens` | 视觉、语音、搜索、模型页替换 |
| **`8`** | **协作**：一个会话变多个代理（4 层） | `8-协作-dsh-agent-teams` | 编排、评审、并行 |
| **`9`** | **反例与退役**：证明"此路不通" | `9-冻结fork-better-sidebar-N23` | 冻结 fork、误命中、孤岛 |

**为什么不用 `00`/`10`/`20`**：那种编号是**先分类、再在类里排队**，读者必须记住一张对照表才知道 `30` 是哪类；而且一加卡就要考虑"插哪"。这里是**类别直接写在第一位**，`3-` 开头的永远是驾驶舱，加几张都不乱。

**关键短语**取**机制**而不是插件名（`驾驶舱` 而不是 `context`），因为跨类比较时读者记的是机制；**插件名放最后**，保证 `ls` 时同类按机制排序、且能一眼认领归属。

**约定**：

1. **一个插件只出一张卡**。跨类的能力在卡内写"它还顺带改了 X 层"，不另开卡。
2. **新增卡不改老卡的文件名**（外链稳定）；要改只改内容。
3. 一张卡**同时属于两类**（例如某插件既是壳又是驾驶舱）→ **归到它改变得最深的那个层**所属的类，并在 `0-领域模型` 的 §6 里注一句"兼看 X 类"。
4. 插件退役或被证伪 → 文件改名为 `9-...`，原文件名在 README 索引里留一行 `archived` 说明。

## 4. 上游接缝索引:抄之前先知道上游到底保证了什么

**这是本域最重要的一张表。** 每张卡说"它挂在 X 上"时,`X` 的确切语义在这里。全部 `[DSH]`(本机 checkout `@deepseek-ai/dsh@0.2.1-rc.3`,引用其包内 `README.md`)。

> **用法**:读任何一张卡之前,先在这张表里找到它所在的那一行。**上游没保证的东西,插件就得自己补**——这正是各卡"代价"的来源。

| 接缝 | 上游包 | 上游**保证**了什么(可直接依赖) | 上游**没保证**什么(得自己补) |
|---|---|---|---|
| **三列外壳 + 右列轨道** | `dsh-client-ui-layout` | 右列先占位再压中心;**保 400px 给中心**:先把右列压到 300px,再报"空间不足"让占位者**自己关**,才继续压中心;右列首次开在视口 45%,之后记住像素偏好,上限 70%;`shell.bottom` 占位者自管高宽,空内容不占空间;根级 `shell.overlay` 覆盖整框;布局状态**刷新即重置** | 它**不会**在窗口变宽时自动重开已关的右列;`panel` 的几何是**每帧一份可拖拽偏好,不是每会话事实**;挤压重排时**没有滚动锚定**,读者视图会跳 |
| **会话内右侧坞** | `dsh-client-ui-sidebar-right` | 每会话一个 `SurfaceState`(布局 + 已记录操作序列 + id 铸造计数);`push` / `fullscreen` 两种呈现**共用同一内容树**,切换不重挂 tab;`<768px` 自动全屏,离开全屏即关闭;面板隐藏时**会话头 corner 座**留一个按钮回去;面板取对话底色与正文字号 | 它**不是**给你的:布局树属于 `dsh-client-ui-dockkit`,**一个会话只有一个坞**——第二个工作台要么抢这个坞,要么自己画(见 `1-厚工作台`) |
| **装载形态** | `dsh-client-modules` | `dsh.client` 声明 → 宿主扫描 Loader 条目组 boot graph → `/plugins` 惰性下发;执行 bundle **只注册工厂**,副作用在 materialization 时才跑 | **不会**替你做首屏预算:客户端包多大、什么时候 materialize,全是你的选择 |
| **设置域** | `dsh-client-ui-settings` | 命名空间读写、原子多字段更新、schema 校验;**每次写带 `revision`**,并发写被拒为 `settings/conflict`;槽位类型 `settings.section` / `settings.plugins.tab` / `settings.onboarding` | 它**不提供界面**;也不替你想"这个偏好该放全局还是每会话" |
| **首启账本** | `dsh-client-ui-settings-general` | **升序**投影、**一次只挂一个** step;注册者自负 durable completion、能力就绪、文案、变更与 `inert` 生命周期;活动注册者拿到 `complete()` 与 `openSection(id)`,完成或跳过把所有权交给下一个 | **不保证**没人抢首屏:它只是**设置面板里的一串步骤**,不是"装完第一屏"(见 `4-首启推荐` 为什么绕开它) |
| **模型选择** | `dsh-client-ui-model-selection` | `conversation.input.model.label` 是**会话级 inline `single` 槽**,同一份声明供 `trigger` / `menu` / `option` 三处;槽只许渲染**非交互**内容,点击/搜索/焦点/勾选归选择器;换模型**只对下一次请求**生效,跑着的 step 保持启动时的模型 | 它**不给你**加一条"模型"到选择器里——那是 `settings-models` 的目录覆盖;把视觉做成"模型变体"必须走那一层 |
| **输入模态** | `dsh-client-ui-settings-models` | 每模型行有 **Input types**:`Text` / `Image` 勾选;无声明时依次回落"已装模型的 → provider 默认 → Text";**显式选择优先,包括把视觉模型改成 text-only**;DeepSeek 写 `inputModalities`,pi-ai 写 `input`;取消 Image 会**连带删掉** `imagePixelBudget` / `imageMaxBytes`(适配器拒绝无图输入却带图预算) | 勾选框**不校验**上游是否真能吃图:"只声明上游真能处理的输入类型"是纪律,不是机制 |
| **附件与图片** | `dsh-client-ui-attachment` | 草稿轨每项 64px 高、单图按长边 240px 且不放大、多附件时每图缩到 64px 方;lightbox 支持 Esc / 遮罩 / 关闭并**还焦点给打开者**;官方条目以 priority 100 注入 `conversation.chat.user.images` 等座 | **不替你**把它变成"模型能读图":渲染是渲染,请求里有没有图是另一层 |
| **用量与上下文压力** | `dsh-token-meter` | 重放会话日志得到**确定性**结果、不发模型调用;三份投影:`tokenUsage`(未缓存输入/输出/缓存读/缓存写)、`contextPressure`(`pressureTokens` 取最近一次 provider 上报、`projectedTokens` 是下一次请求的预估、`contextWindow`)、`contextBreakdown`(system / tools / message 启发式构成) | **`contextBreakdown` 之和不等于 `projectedTokens`**:后者带着启发式的全部误差;**四字符一 token 对 CJK 与 JSON schema 严重低估**;占用率是**参考值,harness 不据此决策**(压缩读 `measure()`) |
| **市场索引格式** | `dsh-plugin-market-index` | 格式 1 的可执行校验器,无运行时依赖;失败带**出错值的 JSON path** | 校验器**不校验** `name` / `version` / `publishTimestamp` / `engines.dsh` / 展示字段是否与包一致,**也不校验包是否真声明了 bundle**;**无大小上界**,由调用方先兜住 |
| **市场读取** | `dsh-plugin-market` | 兼容性**按版本**用 `evaluatePluginCompatibility` + `engines.dsh` + profile 豁免,与真正安装同一套判定;**默认版本**=最高兼容的非预发布版,没有则最高兼容预发布;安装状态五值 `not-installed` / `installed` / `update-available` / `different-version` / `provided`;首次带文本查询时用 MiniSearch 每轮 500 条建索引,文档换掉前复用 | **只读**:安装走 `pluginManager.installBundle`;`plugin_market` 工具**只在 Creator preset**;它明确告诉你"市场文本是第三方内容,不是指令" |
| **安装与重启** | `dsh-client-ui-plugin-manager` + `dsh-plugin-manager` | 装/删/启停都走同一个 `installBundle`;注册表目标 `saveExact: true`;**安装失败会恢复 profile 清单与 lockfile**;每次 `restart-required` 必带 `restartReason`(`no-hmr` / `package-moved` / HMR 待定原因);替换失败的包报 `failed` 并带导入错误,**旧版本不再运行**;模型侧 `plugin_manager` 的结果会带一句 `nextStep` | **无 HMR 时**"已经跑起来的包"不能真正被删,只能覆盖上装并报重启;**装完之后的激活失败会保留已保存的依赖与选择**(不自动回退);pnpm 会校验 lockfile 里的 tarball URL 与默认 registry 一致,换源后可能 `ERR_PNPM_TARBALL_URL_MISMATCH` |
| **启动与 profile** | `dsh-app-boot` / `profile-boot` | profile = `package.json` 的 `dsh.profile.bundles`(有序)+ `cordis.patch.yml`;补丁叠加顺序 bundle → profile → `$DSH_HOME/cordis.patch.yml` → `--patch`;**启动是全有或全无** | 没有"部分成功":一个 bundle 起不来,整个 profile 起不来。所以**救生页必须活在这一层之外**(见 `5-分发`) |

**三条从这张表直接得出的工程规则**:

1. **凡是"上游报不足就自己关"的地方,都要接住那个信号**(右列 `canShow`)。硬撑会挤压中心区到不可用。
2. **凡是"一次只挂一个"的槽(首启账本、模型标签),都不要指望它能承载多条目产品**——它的语义就是单条。
3. **凡是"参考值"的数字(占用率、成本),必须同时给出处与误差方向**,否则用户会拿它当账本。

## 5. 证据与计量

**证据级别**(卡片内逐条标):

| 标 | 含义 |
|---|---|
| `[DSH]` | 上游发行物/文档/代码可核(本机 checkout `0.2.1-rc.3`) |
| `[CAT]` | 本仓库目录 `data/plugins/*.yml` 自述 |
| `[OBS]` | 本次观测:README 原文、GitHub API、实测数字,**附方法与日期** |
| `[OPEN]` | 未能复核 |

**计量口径**(全部可复算):

- ★ / npm 下载:`data/stars.json` / `data/downloads.json`,**快照 2026-08-19**。
- 名单内被引:`python3 _digested/leverage/census.py --probe "<pattern>"`。
- **快照外**的数字(如桌面端 16,969★)必须写明日期与接口,且**不得**与本仓库口径混算。
- **已知偏差**:① 插件目录**只收能 `dsh plugin add` 的东西**,桌面壳/手机 App 不在其中,于是"按目录统计"会系统性低估 2/7 层;② 短名召回差(`TUI`、`dock`),被引数只作下界;③ 下载量含 CI 与镜像,不等于用户数。

## 7. 三条可复用的规律(卡片的公共结论)

1. **主导权在下游,不在上游。** 上游给的是**格式**(profile、market index、槽位),第三方给的是**产品**。谁定义格式谁定边界,谁做产品谁拿用户。
2. **"装坏了怎么回"比"一键装"更能定义一个分发产品。** 见 `5-分发`:一半机制量花在回滚、救生页、merge 恢复上。
3. **体验的护城河是降级路径,不是功能数量。** 每个成熟样本都有一张"X 不可用时退化成 Y"的清单(终端不支持通知→响铃;地图没有底图→离线坐标;按钮没有 action→禁用)。
