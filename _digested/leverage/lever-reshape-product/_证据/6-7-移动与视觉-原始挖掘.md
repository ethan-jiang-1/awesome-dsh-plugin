# 一、saya-ch/dsh-mobile（手机访问网关）

## 1. 接缝的确切形状

它的接缝**不是模型选择器、不是工具**，而是三条并列的接缝：

**(a) Host face：回环代理 + 独立 HTTPS 网关。** mermaid 图给出协议关系：手机 → 局域网/独立远程网关 → `DSH Mobile Gateway Core` → **"回环代理"** → 原生 DSH Web 与 Host（mobile README §工作原理，L386–394）。即：它把 DSH 原有 `dsh web` 当上游，自己另起一层 HTTPS 监听。
- 上游那一侧的契约：`webServer` 服务的 `WebRoute`（`kind: 'exact' | 'prefix'`，`path`，`handler(req, res)` 拥有整个响应生命周期，可保持 SSE）与 `WebUpgradeRoute`（`path`，`handler(req, socket, head)` 拥有协议协商与升级后的 socket）（上游 `dsh-host-webserver/lib/types/index.d.ts:30–48`）。插件注册自己的路由就是把管理面板挂进 DSH Web。
- 端口契约：`Config.host` 必须是"某个本机接口的具体 IPv4/IPv6 字面量"，通配地址在加载期被拒（"would expose the port on every interface at once"）（上游 `dsh-host-webserver/lib/types/index.d.ts:56–66`，`isWildcardHost` L~87）；`port: 0` = 请求 OS 分配端口（同上 L67–68）。移动插件自己监听默认 3443（`dsh-mobile setup --port`），并**跟随** `dsh web --port`（默认 3080）（mobile README §连接教程·端口说明）。

**(b) 客户端：不换壳，注入启动前兼容脚本。** 专用移动页面在 **"DSH 的第一个启动脚本之前，同步加载经网关鉴权的同源 `/mobile-access/compat.js`"**（mobile README §App 与手机浏览器）。上游对应的结构化注入契约是 `webserver/index-inject` 事件的 `IndexInjection` 行（上游 `dsh-host-webserver/lib/types/index.d.ts:14–21` + `injections.d.ts`）：
- `{kind:'script-src', placement:'head'|'body', src}` → 渲染为 `<script src="...">`，**按表顺序执行**，served 形态是 **parser-blocking** 标签（上游 `dsh-host-webserver/lib/types/injections.d.ts:20–27`，渲染实现 `dsh-host-webserver/lib/index.js:39–42`）。
- 对照上游 `dsh-web-frontend/dist/index.html`：正式前端只有一个 `<script type="module" crossorigin src="./assets/index-*.js">`（该文件 L9），所以"head 里排在它前面"是可达的。这就是"在第一个启动脚本之前"的可实现机制。
- 其它行：`{kind:'global'}`（给 `globalThis` 赋值，早于后续 script 行）、`{kind:'script-preload'}`、`{kind:'style'}`、`{kind:'html'}`（`injections.d.ts:14–38`）。注意约束原文：`script.text` 不得含 `</script`，`style.text` 不得含 `</style`（`injections.d.ts:21`、`36`）。

**(c) Android 原生：`androidx.webkit` WebMessage Bridge。** "Bridge 使用 `androidx.webkit` WebMessage，每条消息都校验精确顶层 Origin 和主 Frame，并限制消息大小；**不使用 `addJavascriptInterface`**"（mobile README §工作原理）。上游没有任何 WebMessage/postMessage 桥（grep 无命中，命中项全是第三方 worker 代码）——这条接缝完全在插件侧。
- 另有 document-start 注入：Android App "在支持 document-start 注入的 WebView 中，为**配对的精确 Origin** 提前补齐 `Promise.withResolvers`"（mobile README §App 与手机浏览器）。

**(d) 扩展面（第三方能力挂载）：`extensions/<name>/host.mjs`** 以本机用户权限运行；扩展动作的 `input` 用 `api.schema.object(...)`（Schemastery schema）或带 `parse(value)` 的适配器；手机端 `api.host.invoke()` 按 JSON 请求发送，**在电脑端动作执行前完成校验和规范化**（mobile README §扩展与自定义）。→ 未使用上游 `tools.register`；这是插件自有的 IPC 动作面。

**(e) 插件管理接缝**：`dsh plugin --profile web add/exec/remove`，`cordis.patch.yml` 禁用某行（mobile README §故障排查末条），`purge --yes` 清目录+防火墙规则（§卸载）。上游 `runPlugin` 的 CLI 即 `dsh plugin`（上游 `lib/plugin-BiveYA7h.js:63`），`cordis.patch.yml` 是 profile 层 overlay（上游 `dsh-app-boot/lib/types/profile.d.ts:7`）。

## 2. 信任模型

- **配对码格式**：浏览器手动配对填 **43 位**配对码；以 `dsh1.` / `dsh2.` 开头的是 **Android App 密钥**，不是浏览器配对码（mobile README §连接教程）。43 字符 = 32 字节 base64url 无填充（上游浏览器会话 secret 正是 `SECRET_BYTES = 32` + base64url 去 `=`，见下）。
- **有效期**：局域网与 HTTPS 远程配对码**显示有效截止时间**，超时重生成；**生成新码会使旧码失效**；"复制配对链接复用当前有效码，不会另行作废二维码"（§连接教程）。
- **一次性**：Safari 首次使用的码**只能消费一次**（§PWA 步骤 4）。
- **令牌存放**：App 侧 "Token 和固定的 CA 由 **Android Keystore** 加密"；配对二维码**不含**长期设备 Token 或 CA 私钥（§设备管理）；cloudflared 命名隧道令牌"只存插件私有目录、只经**环境变量**传给 cloudflared"（§安全）。
- **精确 Origin 校验**（三层都有）：
  1. App Bridge：每条 WebMessage 校验**精确顶层 Origin + 主 Frame**（§工作原理）。
  2. 网关写请求：`GET/HEAD/POST/PUT/PATCH/DELETE` 均可代理，但写请求仍校验**配对 Session、精确 Origin 与 CSRF**（§安全）。
  3. App 发令牌："设备令牌只发往**精确 Origin**"；临时地址变化后重扫新码，"**旧设备 token 不会发送给新 Origin**"（§能做什么、§远程访问步骤 4）。
  - 上游对应物：`isTrustedApiRequest(request, trustedHosts, bindHost, protocol)` —— Host 必须是 loopback / `trustedHosts` / 自身 bind 字面量之一，`sec-fetch-site === 'cross-site'` 直接拒，`Origin` 存在时要求与 Host **同 authority**（`isSameAuthorityOrigin` 先按 Origin 的 scheme 归一化默认端口）（上游 `dsh-client-connection/lib/index.js:240–270`）。`trustedHosts` 条目必须过 `assertTrustedAuthority`：必须是**裸 authority**，经 WHATWG 解析不变（拒绝 `user@host`、多余路径、空白、悬空冒号、零填充端口、`0x7f.0.0.1`、百分号编码、未加括号 IPv6；IDN 用 punycode）（同上 `:166–182`，类型注释 `api-request-trust.d.ts:10–18`）。`--trusted-host <authority...>` 可重复（上游 `dsh-web-app/lib/startup.js:33`）。
- **管理 API 准入**：管理口**不是**靠浏览器 Origin 验的，而是 **TCP 对端必须是本机回环**（例如本机 `socat`/反向代理连到 `127.0.0.1`）；**浏览器 Host 可以是 `localhost`、RFC1918 或 IPv4 链路本地地址；公网 IP 和任意域名返回 403**；反代必须只对可信本机/内网开放，不得把 `/api/mobile-access` 公开转发（§连接教程·details）。这一条与上游 `isTrustedApiRequest` 的"Host 栅栏"同构但更严（上游默认还接受自身 bind 字面量，见 `index.js:245`）。
- **撤销语义 = 物理删除，不是标记**："电脑端撤销会**永久删除持久化存储中的设备记录及令牌摘要**，而不是保留 `revokedAt` 标记；启动时也会清理旧版留下的已撤销记录。删除后，旧令牌与未知令牌一样返回 **`401 authentication_failed`**"（§设备管理）。副作用明说："现有 App 若在离线期间被撤销，再次检测时可能显示'配对已过期'，需要重新配对；在线会话仍会收到撤销通知并立即断开"（§设备管理）。
- **局域网/远程授权两套独立**：电脑端分别开关与授权；App 端一台电脑可能两条记录；同一电脑的局域网与远程入口"**须分别配对**"（§设备管理、§连接教程）。自签 FRP 用**独立 CA 指纹**，可能另成一条记录（§设备管理）。
- **身份防覆盖**："未手动指定标识时，公开证书远程入口的新配对使用**电脑保存的随机标识**，避免相同安装路径让两台电脑的记录互相覆盖"（§设备管理）。
- **反代来源校验**："来源 CIDR 匹配代理的**直接 TCP 来源，不信任转发头**；反代须保留外部 Host（含端口）、Origin、Cookie 和 WebSocket"（§远程访问·details）。
- **信任边界自述**："配对设备拥有控制电脑端 DeepSeek Harness 的能力，应视为**完全可信设备**"；并明确"第三方插件不能把**上游回环 Host** 当成请求来自电脑物理本机的证明"（§安全）。

## 3. 兼容层

- **补了哪些 API**（精确三项 + 一组）：`Iterator` / Iterator helpers、`Promise.withResolvers`、`AbortSignal.any`（§App 与手机浏览器）。Android App 额外在 document-start 阶段、仅对**配对的精确 Origin** 补 `Promise.withResolvers`（同节）。
- **加载时机**：在 DSH **第一个启动脚本之前**、**同步**加载同源 `/mobile-access/compat.js`；且该脚本**经网关鉴权**（§App 与手机浏览器）。桌面页面与 `?frontend=stock` 页面**不加载**（同节）。
- **加载方式的三条硬约束**（原文）："兼容层**按能力检测保留或修正原生实现**，**不依赖 CDN**，也**不会放宽 CSP**"（§App 与手机浏览器）。对应上游实现手法：`script-src` 行是**同源相对/绝对路径**（`row.src` 直接进 `<script src>`，`dsh-host-webserver/lib/index.js:41`），所以不需要 CSP 例外。
  - 注：上游 `dsh-web-frontend/dist/index.html` 本身没有 CSP meta（全文 20 行），CSP 只出现在 `/api/file` 响应头 `sandbox; default-src 'none'`（上游 `dsh-api-session-controller/lib/index.js:2428`、`media-references.js:12–16`）。所以"不放宽 CSP"是对网关**自己**的页面/托管契约的承诺，不是绕开上游的 CSP。
- **修不了什么（具体语法/版本）**："API 兼容实现**不能修复内核无法解析**的 JavaScript 语法。DSH **0.2.1-rc.2** 的正式前端包含 **class static blocks**，**Chromium 92** 无法解析；该语法从 **Chrome 94** 默认可用，但这不代表 94 已通过整个 DSH 的兼容验收。App 的'内核低于 **100**'提醒只是建议，**点击继续不代表当前 DSH 可以运行**"（§App 与手机浏览器）。
- **不做什么（明确划线）**："它**不转译 DSH**、不修改 DSH 源码，也不**自动重发消息**"（同节）。
- **不靠版本号卡人**："插件保留 DSH 宿主依赖声明，但**不会仅凭 DSH 版本号拦截安装或启动**"（§兼容性 L427）。
- **验证矩阵**是逐版本的（§兼容性 L446–494），每行写明"已验证的 DSH 版本与范围"；并反复写"浏览器检查不代表所有手机内核、第三方插件或公网线路已验收"、0.6.12 "**未将 Chromium 92 真机**…写成已验收"（L457）、0.6.13 "DSH 源码、iroh P2P 和 Android 原生代码不在本版范围"（L458）。当前"已验收"的最高声明是 0.8.0 对 `0.2.1-rc.2 / rc.3` 的网页推送接口"固定在"这两个版本（L448）。
- **WebSocket 放行规则**：网关**默认只允 DSH 内置第一方 WS 路径**（含 `/sidebar/ws/terminal`），社区路径默认拦；放行时"**系统不接受带查询字符串或模糊前缀的路径**"，不支持"全部允许"，且局域网与远程**共用同一套规则**（§第三方插件适配·WebSocket 放行）。对照上游：`registerUpgrade(route)` 是按 **exact path** 注册路由、重复路径抛错（上游 `dsh-host-webserver/lib/types/index.d.ts:176`、`lib/index.js:340`）——"不接受模糊前缀"是上游 `WebUpgradeRoute` 只是 exact 路径这一事实的直译（上游类型里 `WebUpgradeRoute` 没有 `kind` 字段，只有 `path`）。
- **模块级兼容（体积而非语法）**：`excludedClientModules` 按**准确包名**排除，拒绝不存在的包、启动必需模块、以及仍被保留模块通过 `inject`/`external` 引用的包；不匹配时返回 **`409 excluded_client_modules_invalid` + 冲突详情**；优先级"本设备选择 → 电脑默认 → 插件配置"（§第三方插件适配·可选模块）。

## 4. 失败链与保险丝

- **多通道的"顺序"**：不是自动串联，而是**并列的、用户各选一个**，且局域网与远程是"两套相互独立的连接…在电脑附近优先使用局域网，延迟最低；离开当前网络时再启用远程"（§连接教程）。通道清单 9 种（iroh / cpolar / cloudflared quick / cloudflared named / Tailscale Funnel / 自建 FRP / 自有反代 / 托管 Caddy / 局域网）（§连接教程表格 L182–191）。
- **就绪判定的保险丝**：自备代理模式下"**'后端已监听'不等于公网就绪**，仍需确认公网 HTTPS 与 WebSocket 可用"（§远程访问步骤 2）。iroh "未安装组件时**不显示主操作按钮**"（§通道 details）。
- **诊断的回退链（唯一显式的"先 A 后 B"）**："诊断**先直连，失败后才尝试** DSH 进程环境变量中的 HTTP 代理；`NO_PROXY` 可排除目标。此结果只说明电脑经代理完成 HTTPS 探测，**不代表手机或实际隧道可用**；若直连和代理都失败，报告仍为**不可达，不会把离线误报为就绪**"（§故障排查）。
- **超时/重试**：App 端"连接超过**有限重试预算**后自动回到列表，**不会无限转圈**"（§设备管理·启动行为）；cpolar 旧版 App"可能在免费线路的慢速首次加载完成前**超时**"（§兼容性 L498）。网关侧对**408 接收超时 / 431 请求头过大**做了分类（§App 与手机浏览器末段，0.6.13 引入）。
- **"回退绝不静默"的落地字段/状态**（这是它最可抄的一处）：
  - 设备行状态：绿点=可达，灰点=**"检测中" / "暂不可达" / "配对已过期" / "电脑端已移除"**（§设备管理）——四种灰而非一种灰。
  - 在线收到撤销通知 → "**保留条目**并显示'电脑端已移除'，停止自动重连，提供重新配对和删除本地记录"（同节）——注意与电脑端"物理删除"不对称：电脑端删，手机端留标记。
  - 可达性检查"**直接验证 DSH Gateway，不依赖 ICMP**，也不会把暂时断网误判成电脑端撤销"（同节）。
  - 配置不匹配 → `409 excluded_client_modules_invalid` + 冲突详情，电脑端也提示（§第三方插件适配）。
  - 日志字段：Windows 初始化失败记录**阶段名**（`sid-query` = 查询当前账户 SID，`acl-apply` = 应用私有文件权限）+ **该阶段完整等待耗时**（§故障排查）。
  - 明确"**分阶段诊断不代表 #128 的启动争抢问题已经解决**"（同条）。
- **扩展的安全回退（最细的一条状态机）**："**Host 暂存失败会继续使用现有版本**；若 **Host 已更新但新手机界面激活失败，则关闭该扩展并自动重试**，避免混用新旧能力"（§扩展与自定义）。→ 规则：host/UI 两端的版本必须同代，**宁可关掉也不混搭**。
- **Worker 执行模式**："用于约束可信本地扩展的 JavaScript 阻塞；默认关闭，按扩展选择，**故障后显式恢复，不自动重放操作**。这不是权限沙箱，也不要求 App 同步版本"（§扩展与自定义）。
- **网卡消失**：日志 `saved LAN interface "XXX" is not connected` → "DSH 会继续运行，移动访问**暂时休眠**，原网卡恢复后**自动重试**"（§故障排查）。
- **密钥轮换**：**无**。README 未描述任何 API key 轮换策略（其凭据是设备 Token、隧道 Authtoken、DNS 凭据，且 Authtoken/DNS 凭据只描述"存私有目录/环境变量"，无轮换语义）。→ 该子项请以 modlens 一节为准。

## 6. 首次使用路径（装完到第一次成功）

**路径 A：Desktop + 局域网 + Android App**（共 ~7 屏动作）
1. Desktop **插件**页安装并启用 `dsh-mobile`（Desktop profile 由应用管理，**不走** `--profile web`）（§快速开始）。
2. 打开 **移动访问** 配置界面。
3. **首次打开**"移动访问"时，局域网页会**列出电脑当前网络**，确认网卡后插件**自动生成私有证书**并配置局域网（§快速开始 details）——这是最容易卡的一步之前的"免终端"捷径。
4. 按提示**重启一次 DSH**（同节）。
5. **移动访问 → 局域网 → 开启局域网访问**。
6. **生成配对二维码**（面板显示二维码）。
7. 手机 App：**局域网访问 → 扫描发现电脑 → 点设备 → 扫二维码或粘贴配对密钥** → "配对完成后会建立**持久设备信任**"（§局域网访问 1–4）。

**路径 B：Web（命令行）**：`dsh plugin --profile web add dsh-mobile@latest` → `dsh plugin --profile web exec dsh-mobile setup` → `dsh --profile web`（§快速开始·DSH Web）。`setup` "自动选择并记住当前局域网…**仅在自动选择失败时**使用 `--address 192.168.x.x`"；状态存 `$DSH_HOME/mobile-access/`（同节）。

**路径 C：iPhone/iPad PWA**（4 步，每步都有暗坑）
1. 电脑装插件 + 配通道（长期主屏**优先固定、受信任的 HTTPS**）。
2. 局域网用**复制配对链接**，远程用**生成远程配对二维码**再**复制远程配对链接**；**必须用专用移动访问链接，不是电脑普通 DSH 页面**；"Android 的 `dsh1.`／`dsh2.` 密钥**不是浏览器配对码**"。
3. Safari 打开链接完成配对 → **分享 → 添加到主屏幕 →（可选）以 Web App 打开 → 添加**。
4. 从主屏图标启动；若显示配对码表单 → 走恢复步骤；"**普通重新连接页使用已有配对，不必重新配对**"。
- 推送：**设置 → 通用设置 → 网页推送通知 → 启用**，需 iOS/iPadOS **18.4+** + 受信任 HTTPS；"普通 Safari 标签页和 Android App **不显示此入口**"（§PWA）。
- 硬前提："电脑、DSH 与 Mobile Gateway 须保持运行且手机能够连接；添加 Web App **不会**提供离线 DSH"（§PWA）。

**已知卡点（原文）**：
- 局域网私有证书"**浏览器首次访问可能提示不受信任**"（§局域网访问 L164）；"**绕过证书警告不等于满足网页推送条件**"（§App 与手机浏览器）。
- 同域名其他服务或旧 Cookie 干扰 → "反复提示重新配对或续期 `401`"（§故障排查）。
- `dsh-mobile-question-fixes: failed to import` → "**单纯重启不一定能解决**"（§快速开始）。
- 远端"页面能打开但一直'重连中'" → 需先区分 **WebSocket 升级失败 / 慢速数据同步 / 心跳超时**（§远程访问）。
- 出错时要交的元数据被写死成一份清单：**DSH／插件／App 与 WebView 版本、进入方式、脱敏后的首个控制台错误；不要发送令牌或完整配对地址**（§App 与手机浏览器末段）。

## 7. 安全 / 隐私细节

- **锁屏是否含正文**：网页推送"支持六类提醒和分类开关，页面关闭或锁屏后也可接收，**锁屏文字不含会话正文**"（§能做什么 L63）；Android 通知"使用独立的原生通知通道，**锁屏文本脱敏**"（L64）。六类提醒 = **问题、计划、审批、回复、目标和失败**（L39）。
- **推送的可见性边界**："通知可能受网络、专注模式和系统调度影响，**不是保证送达的警报服务**"；"独立配置的 dsh-ping 等通道不受影响"（§远程访问 details）。点击归属检查固定在 `0.2.1-rc.2 / rc.3`（§兼容性 L448）。
- **附件临时文件**："附件功能**优先复用 DSH 自带的文件上传**"；扩展若模拟拖放，`dataTransfer` 除 `files` 还须提供**可迭代的 `items`**，"部分 WebView 的原生拖放构造不完整"；"`dragover` 接受或事件派发成功**不代表附件已加入**，应检查输入框中的附件与预览"（§扩展与自定义）。
  - 上游一侧的事实：图片上限默认 `maxImagesPerMessage: 20`、`maxImageBytes: 20971520`（20 MiB）（上游 `dsh-attachment-local/lib/index.js:973–1000`）；**超限报 `IMAGE_TOO_LARGE` / `TOO_MANY_IMAGES`**（`dsh-attachment-local/lib/index.js:329`、`dsh-attachment/lib/index.js:219`）；模型不支持图片时 **prompt 端直接拒** `session/attachment-invalid` + `reason: 'MODEL_DOES_NOT_SUPPORT_IMAGES'`（上游 `dsh-api-session-controller/lib/index.js:940`、`types/commands.js:314`）。
  - 插件侧没有"自留附件副本"的设计——它把上传**交回 DSH 自己的附件存储**，这是隐私上最省事的一刀。
- **脱敏报告**：一键诊断"检查版本、网关、网卡、防火墙和远程通道，**生成脱敏报告**"（§能做什么）；"反馈问题时…**脱敏后的首个控制台错误**，不要发送令牌或完整配对地址"（§App 与手机浏览器）。
- **日志/状态里不得出现的字段**：FRP "**共享 Token 不会出现在状态、诊断或接入清单响应中**"（§安全）；命名隧道令牌"只存私有目录、只经环境变量传给 cloudflared"（同节）；DNS 凭据与证书存私有目录、"**不安装系统服务、不修改 PATH 或系统证书信任**"（同节）。
- **可执行组件供应链（逐条可抄的校验项）**：cpolar "校验**大小和 SHA-256**"；cloudflared "下载**固定版本**并校验**精确大小和 SHA-256**，且启动时**关闭自动更新**，以保证运行的始终是已校验的那份二进制"；Caddy 校验"**大小、SHA-256、核心与 DNS 模块版本**"；frpc 校验"来源、**精确大小、SHA-256、压缩包路径和可执行文件版本**"（§安全）。全部前提都是"**仅在用户确认后**"下载。
- **权限务实**：Windows 初始化分阶段私有 ACL（`sid-query` / `acl-apply`），并明令"**不要关闭权限检查或把敏感文件改为所有人可读**"（§故障排查）。
- **卸载/残留**："仅卸载插件**不会**删除 `$DSH_HOME/mobile-access/` 中的证书、配对记录或自定义文件"；要连数据清则"**先运行 `purge --yes`，再卸载插件**"，它删整个目录 + **插件创建的 Windows 防火墙规则**，但"**不会清理 VPS 上的文件**"（§卸载）。
- **端口/暴露面**："移动网关**开启时才监听局域网**；关闭后 DeepSeek Harness 仍正常在电脑本机运行"（§安全）；"局域网监听只用于可信家庭、办公网络或可信热点；**不要自行做端口转发**"（同节）。
- **宿主自身的安全缺口，被它主动修/提示的两条**：设置请求 `403` → "先检查 DSH 的 Host/Origin 信任校验及代理响应…**保持信任检查启用**"（§故障排查）；profile 重载 `403`/`EACCES` 类错误按错误码分诊（同节）。

## 8. 可直接复用的规则（dsh-mobile 侧）

1. **要做"换屏访问"网关，就做回环上游 + 独立 HTTPS 监听，绝不改宿主。** 插件把 `dsh web` 当回环上游、自己另起 3443，并在文档里承诺"不修改 DSH 源码或网页文件"，启动兼容层与专用布局"**按请求提供**"（§工作原理）。上游支撑：`WebServer.Config.host` 只接受具体本机字面量、通配地址加载期拒绝（上游 `dsh-host-webserver/lib/types/index.d.ts:56–66`），使"监听面=一个明确接口"成为可验证约束。
2. **要在 DSH 第一个脚本之前注入自己的东西，用 `index-inject` 的 `script-src` 行，别用字符串改写正文。** 行按表顺序执行、served 形态是 parser-blocking（上游 `injections.d.ts:20–27`、`lib/index.js:39–42`）；且 `row.src` 走 `escapeHtmlAttribute`（`lib/index.js:44`），同源路径即可，因此"**不依赖 CDN、不放宽 CSP**"（§App 与手机浏览器）是自然结果而不是妥协。
3. **兼容层只补 API、绝不转译语法，并把语法下限写进文档到具体版本号。** "按**能力检测**保留或修正原生实现"；写死"class static blocks 由 Chrome 94 默认可用、Chromium 92 无法解析、**94 也不代表通过验收**"；明说"不转译 DSH"（§App 与手机浏览器）。这是让"旧内核用户"的期望值可管理的唯一写法。
4. **配对的设备级授权：码一次性 + 显示截止时间 + 生成新码即作废旧码 + 撤销是**物理删除**，并在两端各自表达。** 码 43 位、超时重生成、Safari 码只能消费一次（§连接教程、§PWA）；撤销"永久删除记录及令牌摘要，而不是保留 `revokedAt`"，旧令牌回落为 `401 authentication_failed`（§设备管理）。手机端则**保留条目**显示"电脑端已移除"并停止自动重连（同节）——删除与可见性解耦。
5. **管理端点用"TCP 对端是回环"而不是"Origin 白名单"当第一道闸；Host 只放行 localhost / RFC1918 / 链路本地，其余 403。** 并且显式拒绝"把 `/api/mobile-access` 公开反代"（§连接教程 details）。上游同类语义可作参照：Host 栅栏"绑定每一个请求，看起来像浏览器与否都绑"，因为"plain HTTP 下浏览器对读请求不附带 Origin 或 Fetch-Metadata，**Host 是 rebinding 唯一伪造不了的头部**"（上游 `dsh-client-connection/lib/types/api-request-trust.d.ts:1–10`）。
6. **自托管二进制的校验清单固定为：仅用户确认后、固定版本、精确大小、SHA-256、（有压缩包再校）包内路径与可执行文件版本、启动时关自动更新；令牌只经环境变量传、状态/诊断/清单响应里永不回显。**（§安全 5 条原文）。
7. **任何"回退/降级"都要有命名的可见状态，不许合并成一个灰点。** 四种灰点（检测中/暂不可达/配对已过期/电脑端已移除）、可达性"直接验证 Gateway 而非 ICMP"以免误判撤销、诊断"直连失败才试代理且**离线不得报就绪**"、配置冲突给 `409 excluded_client_modules_invalid` + 详情（§设备管理、§故障排查、§第三方插件适配）。
8. **第三方 WS 放行只接受 exact path，不接受查询串或前缀，且 LAN/远程共用一套规则。**（§第三方插件适配）与上游 `WebUpgradeRoute` 只有 `path`（无 `kind`）、`registerUpgrade` 重复路径抛错（上游 `dsh-host-webserver/lib/types/index.d.ts:41–48,176`、`lib/index.js:340`）完全对齐——**照抄上游的路由粒度，天然免疫前缀匹配漏洞**。
9. **宿主代码升级、移动界面没升级时，宁可关掉扩展也不要混用新旧能力。** "Host 暂存失败→继续用现有版本；Host 已更新但新 UI 激活失败→**关闭该扩展并自动重试**"（§扩展与自定义）。这是双端（host/UI）版本化的最小正确状态机。
10. **卸载与数据清理分两个动作，且清理动作先于卸载、边界写死在文档里。** `purge --yes` 清 `$DSH_HOME/mobile-access/` + 自己创建的防火墙规则，**不碰 VPS、不碰其他通道**（§卸载、§安全）。

# 二、liustack/modlens（给纯文本模型加视觉）

## 1. 接缝的确切形状

它对**同一个目标挂了两条完全不同的接缝**，且选择权交给宿主：

**(a) 接缝一：工具 `modlens_read_image`（"Just paste"路径）。**
- 触发方式："On a text-only model the pasted image lands as a **private temp file** and its **path enters the composer**（the same interaction OpenCode and Pi ship），then the `modlens_read_image` **tool** takes it from there"（modlens README L38）。
- 上游契约：`ctx.tools.register(defineTool({...}))`（上游 `dsh-tools/lib/types/index.d.ts:637` `register(definition: ToolDefinition): () => void`）。`defineTool` 的必填字段是 `name` / `description`（发给模型）/ `parameters`（按属性声明，编译成**隐式 open object root**）/ `output: { schema, render(args, value): ContentBlock[], presentationMeta? }` / `execute(args, exec): Promise<...>`；可选 `deferLoading` / `timeoutMs` / `isConcurrencySafe` / `projectContent` / `finalizeContent` / `presentCall` / `presentResult`（上游 `dsh-tools/lib/types/schema.d.ts:177–248`）。
- 关键细节：**文件永远不以原生块下发**——"Files are never dispatched natively: every route receives handle text"（上游 `dsh-llm/lib/types/index.js:881`），handle 文本由 `fileHandleText(ref, readonlyPath)` 生成，内容是 `File "<name>" (<bytes> bytes, sha256:<8>)` + "verbatim read-only copy saved at `<path>`"，并附一句"**When delegating file work, include this saved path in the delegation prompt**"（上游 `dsh-llm/lib/types/content.js:110–124`）。→ README 说的"图片落成私有临时文件、路径进入 composer"，在 dsh 上是**文件类附件**的既有形状，不是 ModLens 发明的。

**(b) 接缝二：模型选择器条目 `<model> (modlens vision)`（结构化证据路径）。**
- 原文："**Pick a `(modlens vision)` entry** in the model selector (it remembers your choice, so once is enough), then paste: the thumbnail stays visible in your message… and the image is **converted to structured evidence at request time**, answered by **the same underlying route**. The plugin **auto-discovers every provider route carrying eligible text-only DeepSeek, GLM, or MiMo Pro models** and adds **a wrapped entry per route**"；stock 安装得到 `DeepSeek-V4-Flash (modlens vision)` 与 `DeepSeek-V4-Pro (modlens vision)`，"extra routes like opencode-go or zai get their own"（L38）。
- 上游契约（**这是它能"加一个条目"的全部依据**）：
  - `LlmModelInfo = { provider, id, name, description?, inputModalities? }`，其中 `inputModalities` 的注释是判定语义的核心："**Accepted request modalities; absent means unknown, while an explicit omission is negative capability**"（上游 `dsh-llm/lib/types/index.d.ts:317–333`）。
  - `listModels(provider): Promise<LlmModelInfo[]>` ——"**Catalog membership does not constrain core routing**"（上游 `dsh-llm/lib/types/index.d.ts:361–367`）。
  - `resolveModelInfo(provider, model, signal?): Promise<LlmResolvedModelInfo>` ——"Resolve and validate all metadata from the adapter that owns one exact route… catalog membership remains advisory and does not control request routing"（上游 `dsh-llm/lib/types/index.d.ts:369–377`）。
  - 选择器的两入口共享一份目录：`ModelDirectoryState.{current, routable, groups, failures, status, pending, error}`，`select(selection: ModelSelection)`，"**A switch made in either entry updates this shared state**"（上游 `dsh-client-ui-model-selection/lib/types/client/directory.d.ts:13–58`；`catalog.d.ts` 的 `ModelCatalogDirectory` 每 Host 代只加载一次）。
  - 模态词表可扩展：`ModelModalityMap { text: 'text'; image: 'image' }` 且注释为 "Merge-extensible provider model modality vocabulary"（上游 `dsh-llm/lib/types/types.d.ts:212–217`）。
- **"Which paste route applies is the host's per-model call"**（L38）在上游有精确落点，且是双闸：
  1. **prompt 入口硬拒**：`request.content.some(part => part.type === 'image')` 且 `model.inputModalities !== undefined && !includes('image')` → 抛 `session/attachment-invalid`，`reason: 'MODEL_DOES_NOT_SUPPORT_IMAGES'`（上游 `dsh-api-session-controller/lib/index.js:927–941`，同逻辑在 `types/commands.js:307–315`）。
  2. **adapter 派发前兜底**：若 modality 已声明且不含 image，而消息里还有 image 块 → `projectImagesForTextModel(messages)`，把每个图片块换成 `textOnlyImageText(ref)`（上游 `dsh-llm/lib/types/index.js:884–888`）。
  - `textOnlyImageText` 的**确切输出**很关键：``[image omitted because this model accepts text only; attachment sha256:<前8位>]``（上游 `dsh-llm/lib/types/content.js:47–50`）。
  - 因此 ModLens 的"`(modlens vision)` 条目"必须让 `resolveModelInfo` **对该 id 返回含 `image` 的 `inputModalities`**，否则闸 1 直接 413/422 式拒绝，"缩略图留在消息里"根本走不到。反过来说，**它对原生 vision 模型"不动手"**（L38："native vision models… are excluded automatically"）也是同一条闸的反面：只有"宿主能以元数据**正面确认** text-only"的模型才被接管，"anything unconfirmed is left alone"（L38）——对应 `inputModalities` "absent means unknown" 的语义，**未确认 ≠ 可接管**。

**(c) 不用的接缝（原文强调）**："**No hooks, no wrappers, no local proxy daemon, not a single line changed in any harness config**: on the skill harnesses it is exactly one skill folder, on dsh **exactly one plugin**. Uninstalling is deleting a folder"（L44）。→ 没有拦 `llm/stream` waterfall、没有起代理。

**(d) 配置面**：dsh 0.1.7+ 在 **Plugins 页 → Installed → `@liustack/modlens`** 有 ModLens 卡片（切引擎、勾选 `auto` 可复用的本地 CLI、保存生效）（L76）。

## 2. 信任模型

**ModLens 没有"配对"概念**：无配对码、无令牌有效期、无 Origin 校验、无管理 API。它的信任模型是**"谁的配额"+ "谁的密钥"** 两件事：

- **复用别家登录 = 显式逐项同意、记录在配置里**："Two more sources of vision need zero new keys, **each behind one explicit consent recorded in config**"（L115）；"the install flow **asks the same question for whichever harness you install into**"（L117）；"`modlens doctor` discovers them, **you grant per harness**"（L118）；授权命令是 `config set reuse.codex true` / `reuse.opencode true` / `reuse.pi true` / `reuse.grok true`（L120–125 表）。
- **复用的配额必须可见**："Granted logins **join the engine pool as equals**"（L74）；"Every reused read is **labeled in `meta.warnings` with whose quota it spent, so nothing is ever silently billed**"（L118）；表格列名直接叫 "**Rides as**"（L126）。
- **复用前的礼节**："An existing login in Claude Code, Codex, OpenCode, or Pi can be enough: **modlens asks before reusing any of them**"（L65）。
- **代理与内网例外**："Machines behind a proxy set `HTTPS_PROXY` or `modlens config set proxy <url>`… **An internal endpoint can opt out with `modlens config set openai.proxy ""`**"（L129）。→ 内网端点用**空字符串显式声明"不走代理"**，而不是靠 NO_PROXY 猜。
- **密钥形态**：`apiKey`（和对应环境变量）接受**逗号分隔列表**（L109）。
- **不确定性的显式声明**（信任的最小单元）：输出契约里有"honestly stated uncertainty"示例——演示里它"plus an honestly stated uncertainty about **the truncated filename**"（L151）。
- **法律边界**："Your use of upstream engines… is governed by their own terms and quotas, which **you are responsible for**"（L212）。
- **安全档位**：图片内容当作**不可信输入**（文档表把 `docs/security.md` 标为 "File permissions, image content as untrusted input"，L165）；远程 URL 的"who fetches what"也有专文（L129）。
- **对上游安全语义的依赖**：由于走的是"模型选择器 + 工具"两条**公开**接缝，它天然继承上游 `session/attachment-invalid` 的准入校验（§1(b) 闸 1）与附件存储的字节校验——**不需要自己实现任何鉴权**。这是它"最轻"承诺的安全学解释。

## 3. 兼容层

**它跨 5 个 harness，兼容策略是"同一份能力、两种封装"而不是 shim 某一端：**
- 封装 A：**skill**（Claude Code / Codex / Pi / OpenCode / 通用 skills.sh）——"on the skill harnesses it is **exactly one skill folder**"；安装 `npx -y skills add liustack/modlens --skill modlens --global`，装到 **user level**，装完**重启 harness**（L44、L52–59）。
- 封装 B：**dsh plugin**——"on dsh **exactly one plugin**"，一条命令 `npx -y @deepseek-ai/dsh plugin --profile web add @liustack/modlens@3.27.2`（注意钉了**精确版本** `@3.27.2`，L36）。
- 触发方式的兼容："the skill **triggers on its own**"（L82）；并有**二次自证守卫**："the skill triggers on its own, **the guard confirms the model truly has no vision**, and the slide's full content comes back"（L151）。→ 在 skill 封装里，它是否接管靠"运行时再确认一次当前模型确实无视觉"，而不是靠静态配置。
- 已验证面（不是断言而是清单）："**Verified on real machines in Claude Code, Codex, Pi, and OpenCode**"（L48）；"换行/环境差异"的官方说法只到这句，没有逐版本矩阵（对比 mobile 的逐 DSH 版本表，见 mobile README §兼容性 L446–494）。
- **不支持的事**："ModLens **does not accept pull requests**"，单作者逐行 review；贡献方式是**开 issue 或 fork**（L170–173）。
- 旧内核/旧 WebView 兼容：**无**。它不涉及前端运行时补丁；唯一与"旧环境"沾边的是"Nothing installed locally? **Antigravity CLI is a free no-key channel**"（L45）作为零配置兜底。
- 上游版本门槛：README 只说 dsh **0.1.7+** 的设置面板形态（"from dsh 0.1.7 on, open the sidebar's Plugins page"，L76），未声明模态 API 的最低版本。

## 4. 失败链与保险丝

**这是 ModLens 最可抄的部分，几乎所有细节都写死了。**

- **链路顺序**："Without a pinned provider, **every configured engine forms one failover chain**: the **fast API providers try first, the agent CLIs back them up**, the **first good result wins**"（L97）。车道划分明确：API 车道 **5–10s**，agent CLI 车道 **15–45s**（L88–95、L122–125）。
- **"回退绝不静默"的字段**：`meta.attempts` "records **every attempt** so a fallback is never silent"（L97）；`meta.warnings` 标注"**whose quota it spent**"（L118）。→ 两个固定字段名：`meta.attempts`（逐次尝试）、`meta.warnings`（配额归属/降级提示）。
- **两种路由档位**：`config set provider <name>` = **偏好**（"the chain **still backs it up**"）；`-p <name>` = **钉死单一、无回退**（L129）。→ 偏好与钉死是两个开关，不是我许可。
- **密钥轮换按错误类型区分（最精确的一条）**："`apiKey` (and the matching env var) also accepts a comma-separated list. ModLens **rotates to the next key after authentication, rate-limit, or quota failures**. **Network, 5xx, and parse failures skip remaining keys and keep provider failover**"（L109）；Highlights 复述为"rotate on auth, rate-limit, or quota failures. **Other failures skip remaining keys** and keep the existing provider failover"（L46）。
  - 分组语义：（认证 / 限流 / 配额）→ **换 key**（同一个 provider 内轮换）；（网络 / 5xx / 解析）→ **不换 key、直接跳 provider**。
- **上游侧同族的错误分类可直接对齐**（若要自建同类逻辑）：`LlmError` 码族含 `TIMEOUT` / `ABORTED` / `TRANSPORT` / `HTTP_<status>` / `INVALID_RESPONSE`（上游 `dsh-llm-deepseek/lib/types/listing.d.ts:66–78`）；限额类有 `isQuotaExceededError`、`isContextWindowExceededError`、`QUOTA_EXCEEDED_CODE`、`INVALID_CREDENTIAL_CODE`、`EMPTY_RESPONSE_CODE`、`IMAGE_OFFLOAD_REQUIRED_CODE`（上游 `dsh-llm-pi-ai/lib/index.js:2` 的 import 行）；模型列表超时有专用码 `LISTING_TIMEOUT = "MODEL_LISTING_TIMEOUT"`（上游 `dsh-llm-deepseek/lib/types/listing.d.ts:3`）。
- **引擎池的"平等"不是"优先"**："Granted logins **join the engine pool as equals**"（L74），表里另注 "they join the same failover chain **with no priority over your own keys**"（L118）。→ 复用来的凭据**不得插队**。
- **Pi 的特殊升级**："an API key **upgrades to the 5-10s inline lane**, OAuth drives Pi itself"（L124）——同一 CLI 按凭据类型落不同车道。
- **超时没写数值**，只按车道给区间（5–10s / 15–45s）（L88–95）。→ 该子项：**未给出精确超时毫秒数**（原文只到时间区间）。
- **回退的失败模式被点名**："**Dense charts are where vision bridges most often fail**"（L147）；"the guard confirms the model truly has no vision"（L151）作为前置保险丝。
- **零引擎时的失败路径**："**only if the health check comes back empty, set up a free engine**"（L67）——先体检、体检为空才引导配引擎，而不是装完就直接报错。

## 6. 首次使用路径

**dsh 上（最短路径）**
1. 一条命令安装（钉版本）：`npx -y @deepseek-ai/dsh plugin --profile web add @liustack/modlens@3.27.2`（L36）。
2. **不一定需要配置**："zero-config start"——它复用已有的 Claude Code / Codex / OpenCode / Pi 登录（L45）。
3. **跑健康检查**：skill 安装路径明确"**then ask your AI to configure modlens and run its health check**"（L59），或"run the health check and tell me the result"（L63）。README 没给 dsh 路径下对应的单条命令，只给了 `modlens doctor`（L118）。
4. **只在体检为空时才配引擎**："**only if the health check comes back empty, set up a free engine**"；推荐免费 Gemini key，**约 3 分钟**、无需信用卡（L67）。
5. **免注册替代**：`curl -fsSL https://antigravity.google/cli/install.sh | bash` → `agy` 登录后退出（L70–72）。
6. **第一次成功**：在模型选择器里选一次 `DeepSeek-V4-Flash (modlens vision)`（"**it remembers your choice, so once is enough**"），或直接粘图不带条目（L38），然后提问。演示里的成功态是：消息里**保留缩略图**、轨迹显示图片"**already transcribed by the modlens vision bridge**"、回答逐 UI 元素展开（L135）。

**其它 harness**：`skills.sh` 装到 user level → **重启 harness** → 让 AI 配置并跑体检（L52–59）；或把 INSTALL.md 那一行原文丢给 AI（L61–63）。安装第一步是"检查机器已有什么"，"modlens asks before reusing any of them"（L65）。

**卡点（原文给出的）**：① 体检为空 → 不配引擎就没有视觉（L67）；② 复用别家登录要先同意，拒绝则入池失败（L65、L74）；③ skill harness 上装完**不重启**不生效（L58）；④ 稠密图表是已知最易失败场景（L147）；⑤ dsh 设置卡片位置随版本变（0.1.7 前是 **Settings → Plugins → Plugin config**，之后是侧栏 Plugins 页 → Installed）（L76）。

## 7. 安全 / 隐私细节

- **图片内容 = 不可信输入**：Security 文档定位为 "File permissions, **image content as untrusted input**"（L165）。→ 图像里写的指令不享有指令地位；输出契约要求"the model **quotes specifics**"（L47），把"证据"与"想象"分开（"Evidence, not imagination. Full transcription, reading-order layout regions, entity and relation lists"，L47）。
- **临时文件**：纯文本模型下粘贴的图"lands as a **private** temp file"，只有**路径**进 composer（L38）。README 未给出清理时机/目录——**未披露**。
- **脱敏/外泄面**：README 只给"谁抓什么"（remote URL 的 fetcher 归属，L129）与"配额归属可见"（L118），**未给脱敏报告或日志字段清单**。→ 该子项：日志与脱敏**无**。
- **不静默计费**：`meta.warnings` 标注"whose quota it spent"，"**nothing is ever silently billed**"（L118）。
- **不写任何 harness 配置**："**not a single line changed in any harness config**"（L44）——隐私/可逆性上的最低侵入承诺；卸载 = 删一个文件夹，agent 回到 stock（L44）。
- **不跑代理、不跑守护进程**："**no local proxy daemon**"（L44）——图片不经过第三方中转进程，只直接打用户配置的端点。
- **凭据只来自用户**：API key / baseUrl / model 全由用户设（L104–106）；复用的登录必须逐项同意（L115–125）。
- **责任边界**：上游引擎的条款与配额由用户自负（L212）。
- **PR 政策也是一种供应链约束**：不接受 PR、单作者逐行审（L170）——降低第三方代码进主线的面。

## 8. 可直接复用的规则（modlens 侧）

1. **要"给纯文本模型加一种模态"，把接管条件钉在 `inputModalities` 的"正面确认"上：只有元数据明确 *不含* `image` 才接管，`undefined`（unknown）一律不动。** README：只有 "a model its metadata **positively confirms text-only**" 才接管，"anything unconfirmed is left alone"（L38）；上游把这句写成了类型注释："accepted input types… **absent means unknown, while an explicit omission is negative capability**"（上游 `dsh-llm/lib/types/index.d.ts:330–331`），并据此在 `dsh-api-session-controller/lib/index.js:940` 与 `dsh-llm/lib/types/index.js:884–888` 布了两道闸（拒绝 / 投影为 `[image omitted because this model accepts text only; attachment sha256:…]`，`dsh-llm/lib/types/content.js:47–50`）。
2. **要"加一个模型条目"，就只动 `listModels` / `resolveModelInfo` 返回的元数据，别改路由键。** 上游明文："appearing in the catalog does not constrain core routing"、"catalog membership remains advisory and does **not** control request routing"（上游 `dsh-llm/lib/types/index.d.ts:361–367, 369–377`）——所以 `<model> (modlens vision)` 作为**独立 model id** 出现、并仍由同一底层 route 回答，是唯一不制造语义分裂的做法（modlens README L38："answered by the same underlying route"）。
3. **失败链必须暴露 `meta.attempts`（逐次）与 `meta.warnings`（配额归属/降级原因）两个数组字段，否则"有回退"等于"有静默"。**（L97、L118）
4. **密钥轮换按错误族分流：认证 / 限流 / 配额 → 换 key（同 provider 内）；网络 / 5xx / 解析 → 不换 key、直接跳 provider。** 写成两个分支而不是一个 retry 循环（L109、L46）。上游可复用的错误码面：`TRANSPORT` / `HTTP_<status>` / `INVALID_RESPONSE` / `TIMEOUT` / `ABORTED`（上游 `dsh-llm-deepseek/lib/types/listing.d.ts:74–78`）、`QUOTA_EXCEEDED` / `INVALID_CREDENTIAL` / `EMPTY_RESPONSE` / `IMAGE_OFFLOAD_REQUIRED`（上游 `dsh-llm-pi-ai/lib/index.js:2`）。
5. **"偏好"与"钉死"必须是两个开关：`provider` 仍留回退，`-p` 才彻底无回退。**（L129）否则用户永远无法既"想用 X"又"X 挂了要能用"。
6. **复用他人凭据的三条硬约束：逐项显式同意、入池不得优先、每次使用标注配额归属。**（L74、L115–118、L120–125 的 "Rides as" 列）
7. **`openai` 兼容端点当作"万能插座"，并把"内网端点不走代理"做成可显式关闭的值（空字符串），而不是靠环境变量推断。**（L99–111、L129）
8. **安装流程第一步是体检、体检为空才引导配引擎；并在无 key 场景提供一条免注册通道。**（L63、L67、L70–72）
9. **零侵入承诺要可验收：不写 harness 配置、不起代理、卸载 = 删一个文件夹。**（L44）这在 dsh 上有制度支撑：插件由 profile 的 `cordis.patch.yml` 层装配（上游 `dsh-app-boot/lib/types/profile.d.ts:7`），安装/卸载走 `dsh plugin`（上游 `lib/plugin-BiveYA7h.js:63`），宿主还会对声明不兼容的插件做**精确版本豁免**（`dsh plugin allow-version`，上游 `dsh-app-boot/lib/index.js:335`）。

# 三、两份材料的交叉对照（供第三方选择接缝用）

| 维度 | dsh-mobile | modlens |
|---|---|---|
| 改的是什么 | **怎么上另一块屏幕**（通道/渲染/配对） | **模型能感知什么**（模态/视觉） |
