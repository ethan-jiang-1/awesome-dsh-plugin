# 一、dsh-bootstrap（首启推荐 + 一键安装 + 环境码）

## 1. 写入宿主的确切形态

**1.1 profile 目录里它承认的"唯一事实源"是 `dsh.profile.bundles` 数组与 `cordis.patch.yml`。**
插件自述兼容范围原文：“面向 `manifestVersion: 1` 的 profile 布局（`package.json` 的 `dsh.profile.bundles` + `cordis.patch.yml`）”（bootstrap README §已知限制 4，第 202 行）。上游契约与此逐字吻合：
- profile manifest 结构 `{ "dsh": { "profile": { "bundles": [...] } } }` 由 `initProfile` 生成，实际写盘长这样（上游 dsh-app-boot/lib/index.js:609-627）：
  ```json
  {
    "name": "dsh-profile-web",
    "private": true,
    "dependencies": {},
    "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"] } }
  }
  ```
  （2 空格缩进 + 末尾换行，见同文件 :922-925 `writeProfileManifest`。）
- 合并写回的语义是"只替换 `bundles`、保留 `dependencies` 与 `dsh.profile` 下其他字段"：`withBundles(manifest, bundles) = {...manifest, dsh: {...manifest.dsh, profile: {...manifest.dsh?.profile, bundles: [...bundles]}}}`（上游 dsh-app-boot/lib/index.js:929-941）。**你要改 bundles 就照这个 spread 顺序写，别整体覆盖 package.json。**

**1.2 `cordis.patch.yml` 的条目形状（真 YAML，照抄）**
宿主给每个 profile 生成的初始内容是一个**顶层数组**，注释明说允许 `!!js`（上游 dsh-app-boot/lib/index.js:593-597）：
```yaml
# Your patch layer for this dsh profile, applied after every bundle layer:
# a top-level YAML array of loader patch entries (id-targeted config
# overrides, disables, and insert lists; `!!js` expressions allowed).
[]
```
两种合法条目（上游 dsh-app-boot/lib/index.js:61-109 `applyEntryPatches`）：
- **insert（新增行）**：`{insert: [row, ...]}`，无 `id` 则追加到顶层；有 `id` 则必须指向一个 **group 行**，把行 push 进其 `config` 数组，否则警告 `patch insert: entry %C not found` / `is not a group` 并跳过（:74-89）。
- **覆盖（按 id 改）**：`{id, name?, ...overrides}`；`name` 出现时必须是目标行的原名，否则 `patch: name mismatch for %C (expected %C, got %C), skipping` 跳过（:100-103）；其余键逐字覆盖到目标行（:104-107）。
真实示例（上游官方 bundle 的 patch，`dsh-experimental-plugin-market-bundle/cordis.patch.yml`）：
```yaml
- insert:
    - id: plugin-market
      name: '@deepseek-ai/dsh-plugin-market'
      disabled: !!js "!ctx.get('profileContext')"
    - id: ui-plugin-market
      name: '@deepseek-ai/dsh-client-ui-plugin-market'
```
**开关插件在 patch 层的写法就是 `- id: <行id>` + `disabled: true|false`**——这正是 dsh-market 热开关自己用的形状（dsh-market README「Hot disable / enable」第 75 行："toggles write `- id: …` + `disabled: true|false` into the profile's `cordis.patch.yml`"）。

**1.3 bootstrap 自己作为 bundle 写进宿主的形态**
`package.json` 用 `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}` 声明自己是 bundle（bootstrap README §工程结构第 213 行："`package.json` # dsh.bundle.patch 指向 cordis.patch.yml"；`cordis.patch.yml` 用于"把本插件 insert 进 profile 的层栈"，第 214 行）。这正是上游 bundle 的准入条件：上游 `loadProfileDirectory` 遇到 `bundleManifest.dsh?.bundle === undefined` 直接抛 `<name> declares no dsh.bundle in its package.json`（上游 dsh-app-boot/lib/index.js:1019-1024），格式参考 `dsh-experimental-plugin-market-bundle/package.json` 的 `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}`（该文件第 45-50 行），`patch` 也允许是文件数组（上游 dsh-app-boot/lib/index.js:509-521）。**你写 `"dsh.bundle.patch"` 写错字，插件装了也不会被组进树——上游对"声明了 bundle 但读不出 `dsh.bundle`"的处理是**跳过该 bundle、stderr 打印 `dsh: skipping profile bundle "<name>": <reason>`、继续启动**，而不是崩（上游 dsh-app-boot/lib/index.js:1016-1039、531-537）。**

**1.4 环境码 manifest 结构（自描述、可复刻）**
```json
{
  "v": 1,
  "createdAt": "2026-10-16T00:00:00.000Z",
  "profile": { "name": "desktop", "dshVersion": "1.0.0", "dshRange": "^1.0.0" },
  "plugins": [
    { "name": "dshmarket", "version": "1.66.27", "enabled": true },
    { "name": "dsh-cost-meter", "version": "1.8.29", "enabled": false }
  ],
  "digest": "d63144265c9adbfb"
}
```
（bootstrap README §环境码格式第 149-160 行。）字段语义：`plugins[].enabled` 对应 `dsh.profile.bundles` 是否包含该名字，`false` = 装了但停用（第 162 行）；`digest` = 规范化 JSON（键排序）的 SHA-256 前 16 个十六进制字符（第 163 行）；`profile.dshRange` 写入但不强制阻断（第 202 行）；`v` 固定为 1，不兼容时升 `v`（第 202 行）。

**1.5 环境码外层编码（可复刻的紧凑串协议）**
```
DSHB1.<base64url(JSON)>                # 明文版
DSHB1z.<base64url(deflateRaw(JSON))>   # 压缩版（默认选更短的那个）
```
（bootstrap README §环境码格式第 142-145 行。）长度上限默认 6000 字符，超限时提示改用 `manifest.yaml + lock.json` 导出，两者内容等价（第 165 行；配置项 `maxEnvCodeLength`，§配置第 192 行）。

**1.6 写前校验 / 写后自证**
- 写前：给出计划，逐条列包名、**精确版本**、领域、`安装 / 已安装跳过 / 版本没锁定而跳过`、`装完是否启用`（§2 第 97 行）；`--json` 只输出计划不执行（第 94 行）；非交互必须 `--yes`（第 92 行）。
- 写后：**"执行完再读一次磁盘做收敛自证，不信任自己的返回值"**（§环境码格式第 172 行）；测试 #4"第二次差异为空，不产生任何新的写调用"（§测试第 261 行）。
- 报告形态：成功 / 跳过 / 失败 三类，各自包名与错误原因（§2 第 107 行）。

**1.7 明确不写的东西**
"不改插件运行时、不代理模型调用、不动 profile 之外的全局配置"（README 第 10 行）；"不代装 dsh 本体 —— 只处理 profile 层插件"（§已知限制 6，第 204 行）；环境码刻意不含路径，`file:` 依赖只能人工处理（§已知限制 5，第 203 行）。

## 2. 幂等与并发

| 场景 | 行为 | 出处 |
|---|---|---|
| `install-all` 重复跑 | `dsh.profile.bundles` 里已有的包不会重复 `add` | §2 第 101 行 |
| 同一环境码导入两次 | 第二次差异为空，**不产生任何新的写调用** | §测试 第 261 行 |
| 重复执行 `env import` | `env import` 流程固定「解析 → 差异预览 → 确认 → 执行 → 收敛报告」；差异为零时收敛报告为"无需改动"，且不产生写调用 | §4 第 130-132 行 + §测试 第 261 行 |
| 并发 `npm add` | **串行安装**：原文 "npm 会写同一个 `package.json`，并发必然互相覆盖" | §2 第 105 行 |
| 跨进程并发写 | 承认无解："同一时间只建议一个写者 …… 插件在切换后会做收敛自证并给出告警，但**无法阻止并发写**" | §已知限制 7 第 205 行 |
| 单包失败 | 失败隔离：单个包失败只进「失败」清单，不中断其余包 | §2 第 102 行；测试 #2 第 259 行（三个包里中间一个抛 404，其余两个照常装并启用） |

**上游实际提供了锁，bootstrap 没用满**：`dsh plugin --profile desktop` 走的是 `withFileLock(join(dir, "package.json"), ..., { waitMs: 12e4 })`（上游 lib/plugin-BiveYA7h.js:90-93），pluginManager 的每次变更同样在 `package.json` 锁内跑（上游 dsh-plugin-manager/lib/index.js:2373-2374），锁等待默认 120s（`lockWaitMs: 12e4`，上游 lib/plugin-BiveYA7h.js:84）。锁实现是 `wx` 独占创建 `<file>.lock`、写入持有者 PID、发现 PID 已不存在（`ESRCH`）就接管、指数退避 20ms→200ms、超时抛 `atomic-write: timed out waiting for the writer lock`，默认只等 2000ms（上游 dsh-atomic-write/lib/index.js:12-16、160-167、189-220）。**照抄点：自己写 profile 时用 `<profile>/package.json.lock` 这个同路径后缀（与宿主同一把锁互斥），而不是自造锁文件。**

失败回报的隔离粒度还有一层兜底：`apply()` 内任何异常只记录、不抛出，面板脚本加载失败也只是面板不出现（§安全说明第 292 行）；"a failure only ever costs you the panel, never the host"（README 第 19 行）。

## 3. 版本锁定策略

- **计划阶段钉版本**：目标是从已知信息"把版本钉到精确版本，写进报告的 `lock`，环境码复刻时还原同一版本，而不是重新解析 `latest`"（§2 第 103 行）。
- **拿不到锁（版本）时**：一键安装前对缺版本条目做"**有上限（12 条）**的实时补全，补不到就把它列为「版本没锁定，跳过」，**不会盲装 `latest`**"（§已知限制 1 第 199 行）。这是整套里最硬的一条：宁可少装，不装未固定的版本。
- **不做自动全启用**：只启用「核心推荐」子集，其余 installed-but-disabled（§2 第 104 行；配置 `coreOnlyDefault: true`，§配置第 191 行；`--all` 才全启用，第 93 行）。
- **市场插件不是硬依赖**（对应"只认精选源"）：候选池优先取与 dshmarket 同一份官方 registry `https://awesome-dsh-plugin.com/plugins.json`，"没装市场时，插件用内置种子清单 + npm/GitHub 实时查询照样能推荐"（§1 第 84 行）；面板"建议先安装 dshmarket"只是引导不是强制（第 86 行）。
- **原文里的硬约束**（这条在 bootstrap 里没有，在 market 里有，见第二部分的 §3）：bootstrap 侧只有"不盲装 `latest`""不跨机器还原路径""同一时间只建议一个写者""不代装 dsh 本体"这四条（§已知限制 1/5/6/7）。
- **排序权重可调、可归一化**：默认 `starWeight: 0.4` / `downloadWeight: 0.6`，"都会自动归一化到和为 1"（§1 第 71 行）——即用户给 0.7/0.3 也行，给 3/7 也等价。

**上游对应的事实**：`dsh plugin ... add <pkg>` 默认不固定版本（转发 pnpm 的 `add`）；要固定版本得显式 `--save-exact`（上游 dsh-plugin-manager/lib/index.js:2031-2037：`["add", spec, ...options?.saveExact === true ? ["--save-exact"] : [], ...registryArguments(registry)]`），而 `dsh plugin` CLI 转发是**原样透传参数**（上游 lib/plugin-BiveYA7h.js:117 "pnpm arguments, forwarded verbatim"）。所以"精确版本"在 CLI 路线下等价于 `dsh plugin --profile <p> add --save-exact <name>@<version>`。

## 4. 救生页与回滚

bootstrap 侧：**无救生页、无回滚**——原文只承认"失败只让你失去面板，永不失去宿主"（README 第 19 行）与"`apply()` 内任何异常只记录、不抛出"（第 292 行）。它的降级是"功能降级"，不是"启动救援"。（真正的救生页在 dsh-market，见第二部分 §4；上游的对应原语是 `dsh rescue --from-default-profile <name>`，见上游 lib/bin.js:42-43。）

## 6. 安全与脱敏

- **生成前扫描、命中即拒绝，不悄悄脱敏**："环境码里**不含** API key、token、密码、本机绝对路径。生成前会做一次敏感内容扫描（字段名与值都查），命中就**直接阻止生成**，而不是悄悄脱敏"（§环境码格式 第 164 行）；"不落任何字符串"（§安全说明 第 290 行）；测试用例"环境码里出现疑似 key/token 时直接拒绝生成"（§测试 第 265 行）。
- **完整性**：`digest` = 键排序规范化 JSON 的 SHA-256 前 16 hex；"导入时校验，不一致会**拒绝应用**并提示内容可能被改过"（§环境码格式 第 163 行）。
- **不上传**：历史环境码存浏览器本地、"**不上传**"（§3 第 117 行）；缓存只存指标不存凭据（§工程结构 `cache.js` 第 222 行）。
- **同源校验**：面板接口全部 `kind: 'exact'`，"会越过宿主的 `/api` 前缀栅栏，因此**路由内部自己做同源校验**：拒绝 `Sec-Fetch-Site: cross-site`，`Origin` 与 `Host` 不同源直接 403"（§安全说明 第 289 行）；"跨站请求返回 403，且**拒绝发生在读任何 profile 数据之前**"（§测试 第 266 行）。
- **凭据不进源码**：面板图标以 base64 内嵌并明确 CC BY-NC-SA 4.0，"商业场景请替换 `AVATAR` 常量"（§面板外观 第 282、297-299 行）——**这是"素材许可与代码许可分离"的写法，照抄时别漏。**
- 上游对照：`kind: "exact"` 路由登记在 `exact` 表、其余进 `prefixes` 表（上游 dsh-host-webserver/lib/index.js:327），即 `exact` 确实是"精确匹配、不挂 `/api` 前缀"的那一档。

## 7. 首次使用路径（装完→第一次成功装插件，逐屏）

1. **安装页（终端）**：`dsh plugin --profile desktop add dsh-bootstrap`（§安装 第 28 行）；"装完重启 dsh，让插件层重新加载"（第 30 行）。本地开发 `dsh plugin --profile desktop add file:C:/path/to/dsh-bootstrap`（第 36 行）。

## 8. 可直接复用的规则（bootstrap）

1. **把"计划"做成可粘到 issue 的一等公民对象**：`install-all` 先打印计划、`--json` 只出计划、`--yes` 才执行、计划里逐条列"精确版本 + 跳过理由 + 装完是否启用"。——证据：§2 第 91-97 行；§环境码格式 第 172 行（执行后回读自证）。
2. **版本拿不到就跳过，绝不 fallback 到 `latest`**：补全限量（12 条）、补不到标"版本没锁定，跳过"。——§已知限制 1 第 199 行。上游对应的固定版本参数是 `--save-exact`（上游 dsh-plugin-manager/lib/index.js:2031-2037）。
3. **"启用"和"安装"必须拆开**：装完默认只启用核心子集，其余 installed-but-disabled，开关交给用户或环境码。——§2 第 104 行；`coreOnlyDefault: true`（§配置 第 191 行）。上游对"启用"的持久化落点是 `dsh.profile.bundles` 数组本身（`enabled: bundles.includes(name)`，上游 dsh-app-boot/lib/index.js:1176）。
4. **写操作走三层后端，最后一层要显著告警**：`pluginManager`（`setBundleEnabled`/`removeBundle`）→ `dsh plugin` CLI → 直接改 profile 清单（且声明"不会更新 `cordis.patch.yml`，可能造成两处状态不一致"）。——§已知限制 3 第 201 行；§工程结构 第 246 行。
5. **自证靠回读磁盘，不靠返回值**：每次写后重新读 profile 算差异（`converged`），并且"差异为空不产生任何写调用"。——§测试 #3/#4 第 260-261 行。
6. **打包/导入协议自带版本 + 摘要 + 归一化**：`DSHB1`/`DSHB1z` 前缀 + 自描述 JSON（`v`、`createdAt`、`profile.dshRange`）+ 键排序后 SHA-256 前 16 hex 的 `digest` + 导入时校验不一致即拒绝。——§环境码格式 第 142-163 行。
7. **敏感扫描"命中即拒绝生成"，不要做"自动打码"**：字段名和值都扫，命中直接不生成，并在错误里明确说"可能含凭据"。——§环境码格式 第 164 行；§安全说明 第 290 行。理由看 bootstrap 自己的用法：环境码就是"发给别人"的东西，打码后发的其实是错误配置。
8. **面板路由绕开宿主前缀时，自己补同源校验，并把校验放在读数据之前**：`Sec-Fetch-Site: cross-site` 直接拒、`Origin≠Host` 403、且在碰 profile 数据之前返回。——§安全说明 第 289 行；§测试 第 266 行。上游 `kind: "exact"` 走独立表（上游 dsh-host-webserver/lib/index.js:327），不设这一层就是裸奔。

# 二、dsh-market（插件市场：装、升级、坏了怎么回）

## 1. 写入宿主的确切形态

**1.1 开关写 `cordis.patch.yml`（官方 patch 层），不是写别的地方。** 原文："toggles write `- id: …` + `disabled: true|false` into the profile's `cordis.patch.yml` (the official patch layer, mechanism ported from [dsh-plugin-hub]): DSH's HMR re-composes within ~1s, no restart, and the loader re-applies the choice on every boot; hand-edited patch rows show as badges, host-infrastructure plugins are protected from toggling, and a malformed patch file is never made worse"（dsh-market README「Hot disable / enable」第 75 行）。
→ 实际 YAML 形状（由上游 `applyEntryPatches` 的覆盖语义决定，上游 dsh-app-boot/lib/index.js:104-107）：
```yaml
- id: <该插件行的 id>
  disabled: true      # 或 false
```
上游对"名字不匹配"的防呆，正好解释 README 说的"hand-edited patch rows show as badges"：写了 `name` 且与目标行不一致时，整条 patch 被跳过并告警（上游 dsh-app-boot/lib/index.js:100-103）。

**1.2 恢复页（Adjust plugins）写"同一批 `cordis.patch.yml` 行"，外加 `dsh.profile.bundles` 作 disable-carrier。** 原文："the choice is written through the same `cordis.patch.yml` rows the market's own toggles use (plus `dsh.profile.bundles` for a disable-carrier)"（market README「What you get · Recovery」第 77 行）。
→ 为什么"停用"要两个落点：patch 行只是把行禁用，**bundle 还留在 `dsh.profile.bundles` 里就仍会加载**（上游按 bundles 数组逐个 resolve + parse，上游 dsh-app-boot/lib/index.js:1016-1024）；要从 bundles 数组里摘掉才真正不加载。所以"disable-carrier"指的是把该 bundle 名字从 `dsh.profile.bundles` 移除。

**1.3 自身配置写 profile patch 的 `config:` 子对象（不能写顶层）。** 原文："write it into the profile patch — where it has to sit under `config:`, because the loader passes only that sub-object to a plugin and a top-level `allowRestart:` is silently ignored (#227)"（README 第 99-100 行）。给出的真 YAML：
```yaml
- id: dsh-market
  name: dshmarket
  config:
    allowRestart: false   # NOT at the top level beside `name:`
```
```yaml
- id: dsh-market
  name: dshmarket
  config:
    buildEnv:
      CC: /usr/bin/gcc-11     # or CXX, NODE_OPTIONS, ...
      CXX: /usr/bin/g++-11
```
（README 第 101-120 行。）注意第二条里 `config` 是覆盖整块，不是深合并——上游 `target[key] = value` 是逐键赋值，`config` 键整体替换（上游 dsh-app-boot/lib/index.js:104-107）。**照抄要小心：写 `config:` 会把该行原来的 config 整块换掉。**

**1.4 本地状态：`state.json`（收藏、分组、备注）。** "Bookmarks persist in the profile's market state (`state.json`)"（README 第 65 行）；"The grouping itself is local state in the profile's `state.json`"（第 66 行）；"Stored locally beside groups and favorites, never sent anywhere"（第 67 行）。

**1.5 构建策略写 `pnpm-workspace.yaml` 的 `allowBuilds`。** 上游同款机制：非交互安装被忽略的构建脚本会被记成
```yaml
allowBuilds:
  <pkg>: "set this to true or false"
```
用户批准后改成 `true`（上游 dsh-plugin-manager/lib/index.js:1085 `UNDECIDED_BUILD`、1116-1129 `recordPendingBuilds`、1145-1153 `approveBuilds`）；解析来自 pnpm 输出里的 `Ignored build scripts: <names>`，并拒绝通配符与 YAML 锚点（同文件 1088、1101-1104）。CLI 侧对应文案："add the exact key pnpm printed above under `allowBuilds` in `<profile>/pnpm-workspace.yaml`, then re-run"（上游 lib/plugin-BiveYA7h.js:97）。README 呼应："Build scripts stay blocked by default (pnpm ≥10); allowing one is your explicit per-package choice"（第 93 行）。

**1.6 镜像/目录来源可被环境变量改写。** `DSHM_REGISTRY_URL=https://your-mirror.example/plugins.json dsh web`（README 第 144-148 行）；"`DSHM_GITHUB_PROXY` remains the operator-owned override"（第 72 行）。

**1.7 回滚/备份产物。** 上游原语：`sanitizeProfile` 把 `cordis.patch.yml` 改名为 `cordis.patch.yml.bak-<Date.now()>[-<ordinal>]` 后重写 bundles（上游 dsh-app-boot/lib/index.js:1242-1257）；安装失败回滚 `package.json` + `pnpm-lock.yaml` 到安装前内容（上游 dsh-plugin-manager/lib/index.js:1293 `RESTORED_FILES`、2267-2279 `readRestoredFiles`/`restoreFiles`）。market 的备份是把"插件列表 + 配置"导出成可读 JSON，恢复时**合并**、写前校验、失败回滚（README 第 70 行）。

## 2. 幂等与并发

- **热开关幂等**：写的是 `disabled: true|false` 这种**终态**而非"翻转"，重复写结果相同；且"the loader re-applies the choice on every boot"（market README 第 75 行）——持久层在 patch 文件里，重启后重放。
- **安装去重**：上游 `installBundle` 在 HMR 可用且包已存在依赖里时直接抛 `already-installed`（上游 dsh-plugin-manager/lib/index.js:1990-1992）；market 侧等价语义在 README 第 12 行 "Browse, search, one-click install" 与第 44-51 行的 Plugins 页/已安装态说明。
- **并发**：market 没自述并发策略；上游把所有变更塞进 `withFileLock(<profile>/package.json)`（上游 dsh-plugin-manager/lib/index.js:2373-2374），CLI 路线同样加锁、`waitMs: 12e4`（上游 lib/plugin-BiveYA7h.js:90-93）。锁实现见上面 bootstrap §2（`<file>.lock`、PID 接管、20→200ms 退避、2000ms 默认等待）。
- **并发重建 profile 的防护**（`--from-default-profile`）：在 `.<name>.staging-*` 目录组装再 rename 就位；若目标被"并发重建"，报 `profile "<name>" was recreated concurrently at <dir>`；rename 失败时把旧目录 rename 回来，再失败抛 `AggregateError` 并指明保留旧内容的 staging 路径（上游 lib/profile-boot-C14i-8IN.js:136-144、155-191）。
- **失败隔离与回报**：单个插件加载失败**不隔离**——这是全有或全无（见 §4）；安装失败则回滚文件并给 `stage: "enable"` / `application: "failed"` 的结构化结果（上游 dsh-plugin-manager/lib/index.js:2373-2400）。
- **不制造更坏的坏**：malformed patch 文件"never made worse"（market README 第 75 行）；上游对应硬规则是——patch 文件存在但解析失败，**启动即失败**，不静默跳过（上游 dsh-app-boot/lib/index.js:3935-3940："a present patch file that cannot apply is a misconfiguration and must fail loud at boot, never be silently skipped"）。

## 3. 版本锁定策略

- **更新语义**："per-plugin update checks (npm version or pinned commit vs HEAD)"（market README「What you get · Updates」第 71 行）——npm 包比版本号，git 装比 **pinned commit vs HEAD**。
- **防"更新成另一个插件"**："A plugin installed from an archive link is updated only through its own source: a catalog entry that merely shares the name is never offered as its update, so updating cannot silently replace it with a different plugin"（market README 第 71 行）。
- **Git 安装必须钉 commit（协议层强制）**：索引格式里 git 源 `commit` 必须是**小写 40 位 hex**（`/^[0-9a-f]{40}$/u`），安装 spec 拼成 `git+<url>.git#<commit>[&path:/<dir>]`（上游 dsh-plugin-market-index/lib/index.js:30、186-196、311-318）。这条是"协议保证可复现"，不是"实现自觉"。
- **Golden 版本不得是预发布**：默认版本取"兼容版本中的第一个稳定版"（`compatible.find(v => !stable || semver.prerelease(v.version) === null)`），版本列表按 SemVer 降序（上游 dsh-plugin-market/lib/index.js:600-606；排序在上游 dsh-plugin-market-index/lib/index.js:248）。
- **三级安装源优先级**（原文）："Installs prefer repo-verified npm packages, then author-supplied prebuilt GitHub Release tarballs, before falling back to full-repo GitHub source downloads. Prebuilt installs are typically seconds and do not need local build scripts; source-only plugins depend on your connection to GitHub."（market README「Speed」第 88 行）。
- **硬约束原话（三条，带出处）**：
  1. "Installs are restricted to sources listed in the curated [awesome-dsh-plugin] registry — anything else is rejected"（market README「Security」第 92 行）——**只认精选源**。
  2. "Build scripts stay blocked by default (pnpm ≥10); allowing one is your explicit per-package choice"（第 93 行）——**不跑构建脚本，逐包显式批准**。
  3. "Terminal/CLI-surface plugins are flagged before you install them into the web profile"（第 94 行）——**标记终端类插件**。
- **Release channel（自更新）**："pick a **release channel** (stable, or beta to try builds still being verified — the market only, never your other plugins; a third *dev* channel appears once developer mode is switched on, and carries builds published straight off a branch)"（market README「What you get · Settings card」第 80 行）。
- **索引源超时预算与版本自带的目录**："dsh gives a source 15 seconds"（market README 第 14 行）；"In the China download region the same catalog is read from npm first …… and it carries a version, so a bad catalog build can be rolled back instead of only being fixed forwards. The origin stays last in the list as the route that has always worked. Region detection happens once and the answer is remembered"（第 142 行）。

## 6. 安全与脱敏

- **来源白名单**："Installs are restricted to sources listed in the curated registry — anything else is rejected"（第 92 行）。
- **安装端点同源**："The install endpoint accepts same-origin POST only; the market never phones home"（第 95 行）。
- **重启端点**："additionally requires a direct loopback client (forwarded requests are rejected)"（第 98 行）。
- **日志导出脱敏**："one click produces a sanitized plain-text log for bug reports (home paths and credential shapes are masked; nothing is ever sent anywhere)"（第 79 行，market README「What you get · Log export」）；且"attaching the market's 'Export log' makes diagnosis roughly ten times faster"（第 132 行）。
- **备份含凭据要预警**："Backups can contain credentials from your profile config — the UI warns before export and upload; WebDAV sync is https-only, refuses private-network targets, and never stores your password in the browser"（第 96 行）。
- **token 不走加速**："Authenticated Gist requests always go directly to `api.github.com`; bearer tokens are never sent to a public GitHub acceleration service. GitHub source archives also stay on canonical codeload URLs so pnpm's integrity policy remains in force"（第 97 行）。
- **不写全局 PATH/CI**："Pinned values may override inherited ones but never the `PATH` or `CI` the market computes for its children (issue #336)"；"`PATH` and `CI` are always managed by the market and cannot be overridden from either place"（第 111、122 行）。
- **宿主基础设施不可关**："host-infrastructure plugins are protected from toggling"（第 75 行）；上游对应 `protectsManager(name)` → `ManagementFailure("management-required")`，且启动时把每个 `startedBundles` 登记为受保护（上游 dsh-plugin-manager/lib/index.js:1609、2287-2290）。
- **索引源 URL 硬校验**（三处，可照抄）：①schema 层 `z.array(z.string().pattern(/^https?:\/\/\S+$/u)).default([]).volatile()`（上游 dsh-plugin-market/lib/index.js:364）；②每次使用前 `normalizeIndexUrl`：必须可解析、必须 http/https、**不许带账号密码、不许带 fragment**，非规范形式直接报 `Index URL is not in canonical form; use <canon>`（上游 dsh-plugin-market/lib/types/index-url.js:8-27 + 上游 dsh-plugin-market/lib/index.js:495-521）；③`setIndexes` 拒绝重复 URL（`plugin-market/invalid-index-url ... reason: "duplicate"`，上游 dsh-plugin-market/lib/index.js:430-437）。
- **拉取侧防护**：`redirect: "error"`、`accept: application/json`、`AbortSignal.any([lifetime, AbortSignal.timeout(fetchTimeoutMs)])`；`content-length` 或累计字节超 `maxBytes` 立刻 cancel；错误信息是用 `cause` 链最多 4 层拼出来的真实原因（上游 dsh-plugin-market/lib/index.js:282-291、549-600）。
- **索引内容校验**行内细节：图标 `data:` 只允许 svg/png/jpeg/webp base64 且解码 ≤32 KiB；相对图标必须解析成 https 或**与索引同源**，否则 `must resolve to https or the index origin`；`homepage` 允许 query/fragment 但要 http(s)；`repository.url` 不许带 query/fragment；`engines.dsh` 不许是 `workspace:` 前缀（上游 dsh-plugin-market-index/lib/index.js:134-146、200-225）。

## 8. 可直接复用的规则（market）

1. **"全有或全无"的宿主必须自带救生页，且救生页由宿主进程之外的 detach helper 在用户已在轮询的那个地址上服务**；页面只做一件事——让用户勾选"下次启动启用哪些"，结果写回宿主本来就认的 patch 行（外加 `dsh.profile.bundles` 作为停用载体），然后重试启动。——README 第 77 行；上游 `dsh rescue`/`sanitizeProfile`/`--dump-default-config` 三条原语（上游 lib/bin.js:42、105；上游 dsh-app-boot/lib/index.js:1242-1257）。
2. **索引源校验放在"每次使用"而不是"配置时"**：配置可以经由 settings/文件绕过 schema，所以在 `sources()` 里逐个再判一次规范形式、凭据、fragment、重复，不合格的源**只列出错误、永不 fetch**。——上游 dsh-plugin-market/lib/index.js:495-521；`normalizeIndexUrl` 上游 dsh-plugin-market/lib/types/index-url.js:8-27。
3. **拉取一份索引要同时设 4 个上限并支持"合并进行中的同 URL 请求"**：`fetchTimeoutMs`（默认 15000）、`maxBytes`（默认 128 MiB，边收边判）、`cacheTtlMs`（默认 600000）、`redirect: "error"`，并发读同一 URL 共享一个 promise（`pending` Map + `finally` 清理）。——上游 dsh-plugin-market/lib/index.js:364-367、533-551。
4. **索引格式要有版本号并一次性拒绝第一条违规，报 JSON 路径**：`format` 必须为 1；抛 `MarketIndexError`，`path` 形如 `$.plugins[0].versions[1].version`；版本数组内不得重复、必须按 SemVer 降序；`publishTimestamp` 必须是 [0, 10^11) 的整数秒。——上游 dsh-plugin-market-index/lib/index.js:8-22、226-249、284。
5. **git 安装必须 commit 钉死，并且由协议层校验**：`commit` 是 40 位小写 hex，spec 拼 `git+<url>.git#<commit>[&path:/<dir>]`；`engines.dsh` 不许是 `workspace:` 范围。——上游 dsh-plugin-market-index/lib/index.js:30、186-196、200-207、311-318。落到 CLI 上就是 `dsh plugin --profile <p> add git+https://…git#<sha>`。
6. **给"下一次启动"预留一个显式开关，并让程序能自证它生效了**：`allowRestart: false` 写在 patch 行的 `config:` 下（顶层写了会被**静默忽略**），自证方式是一个状态端点返回 `"restart": false`。——README 第 99-110 行。
7. **"忽略"与"关闭"必须是两种不同持久度**：忽略只在本次启动有效，重启后提醒回来；关闭才是持久化。——README 第 71 行。
8. **更新通道按"来源"而不是"名字"对齐**：从 archive 链接装的插件，只用它自己的源来更新；目录里同名条目永远不作为它的更新候选。——README 第 71 行。配套：自更新分 stable/beta/dev 三通道，且**只作用于市场自己，从不作用于用户别的插件**（README 第 80 行）。

# 三、两插件的"对照差异"（同一问题两种正确解，最有借鉴价值）

| 问题 | bootstrap 的答案 | market 的答案 | 为什么两者都对 |
|---|---|---|---|
| 目录/索引拿不到时 | 本地快照 → 内置种子，**并标注"离线快照，数据可能过期"**（§已知限制 1） | **故意不做快照**，报真实原因 + 耗时 + Retry（第 138-140 行） | bootstrap 是"首启助手"：没数据就没功能，旧数据总比空白有用且它**明确标注过期**；market 是"安装入口"：过期目录会把今早发布的插件判成"不存在"，这是错误答案而非降级答案 |

## 4.2 插件市场索引格式（format 1）
- 宿主配置：`indexes`（`https?://` 数组、`volatile`）、`fetchTimeoutMs`（1..MAX，默认 15000）、`maxBytes`（默认 128 MiB）、`cacheTtlMs`（默认 600000）——上游 dsh-plugin-market/lib/index.js:363-367；类型注释同上游 dsh-plugin-market/lib/types/index.d.ts:12-21。
- 文档根：`{format: 1, title: LocalizedText, description?, metadata, plugins[]}`；`title` 是 `string` 或 `{lang: string}` 且**必须含 `en`**；未定义字段一律丢弃——上游 dsh-plugin-market-index/lib/index.js:51-61、280-303。

- 插件项：`name`（npm 包名规则、≤214）、`title?`、`description?`、`icon?`、`author?`、`homepage?`、`repository?{url, directory?}`、`versions[]`（非空、版本不重复、降序）——上游 dsh-plugin-market-index/lib/index.js:250-271、239-249。

- source：`{type:"npm", registry?}` 或 `{type:"git", url(https、规范化、≥2 段路径、非 tarball), commit(40 hex), path?}`——上游 dsh-plugin-market-index/lib/index.js:176-199。

- 校验器在 worker 里跑（`parseIndexInWorker`），先 strict UTF-8 解码（`new TextDecoder('utf-8', {fatal: true})`）再 `JSON.parse` 再 `parseMarketIndex`——上游 dsh-plugin-market/lib/types/parse.js:9-32。

## 4.4 安装命令 `dsh plugin add` 的准确形态
- 语法：`dsh plugin --profile <name> <pnpm-args...>`，"forwarding the remaining arguments to pnpm in the profile directory"；`--profile` 是 **requiredOption**；不给参数报 `plugin needs pnpm arguments to forward (e.g. add <package>)`——上游 lib/bin.js:115-126。
- 子命令集在帮助里写死：`add <pkg>`、`remove <pkg>`、`why <pkg>`，实名说明是"forwarded verbatim"——上游 lib/bin.js:117、48。
- **`desktop` profile 被独占**：`rejectElectronProfile` 对 `desktop` 直接 `error: profile "desktop" is managed exclusively by the Electron application`（除非由 Desktop 的 carrier 带着 `manageDesktopProfile` 调用）——上游 lib/bin.js:35-37、112、119。这与 dsh-market README 第 35-38 行的坑完全一致：**在装了 Desktop 的机器上 `dsh plugin --profile web add` 会成功但装进 `profiles/web`，Desktop 用的是自己的 profile。**
