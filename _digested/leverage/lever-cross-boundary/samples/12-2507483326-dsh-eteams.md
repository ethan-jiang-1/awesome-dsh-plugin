## 设计思路

**`2507483326/dsh-eteams` 证明了 `persona` 的合法路径**:它用 `ctx.subagents.startContinuable({provider, childId, label, request:{prompt, parent, persona, toolFilter, agentOptions}})`——`persona` 作为**请求参数**传入,而不是 `dsh-tool-subagent` 的 config 字段。两者同名但走不同代码路径,这解释了为什么 `dsh-expert-mode` 的 `persona` 配置会挂载失败而它不会。它的身份识别靠会话 id 反查(注册表是进程内的、重启即空,所以另有一层「按任务行 `session_id` 快照冷恢复」)。

**它的成员创建调用**(本域最值得逐字读的一行 👇):

```js
ctx.subagents.startContinuable({
  provider: 'spawn', childId, label,
  request: { prompt, parent, persona, toolFilter, agentOptions }
})
```

`persona` 在这里是**请求参数**,所以合法;`dsh-expert-mode` 把它写在 `dsh-tool-subagent` 的 **config 字段**里,所以加载即抛错。**同一个名字,两条代码路径,一条活一条死。**

**它的持久化**:SQLite `BEGIN IMMEDIATE` + 进程内团队锁;投递用 `deliverToChild` + 预先落盘的 `captain-turn/<taskId>.json` 边车,所以队长回合开始前,该投给成员的内容已经先落地了。

**身份识别的坑**:注册表是**进程内的**,重启即空——所以它另有一层「按任务行 `session_id` 快照冷恢复」。复活后的成员只能靠这个快照认领。

**两个实现缺陷**:patch 里写死了作者的 `stateDir: C:/Users/epat/.eteams`(硬编码路径);`atomicWriteText` 重试 3 次后**退化为直接写**。

## 借用指南

### 可借鉴(直接抄)

1. **`persona` 走请求参数,不走 config** —— `startContinuable({request:{persona, toolFilter}})`。这是本域**最常被抄错的一行**,抄对就同时拿到了成员异构与子代理能力。
2. **投递前先把内容落盘成边车(`captain-turn/<taskId>.json`)** —— 队长回合开始前,该投给成员的东西已经先落地;队长崩了,内容还在。
3. **SQLite `BEGIN IMMEDIATE` 做跨调用事务** —— 比「读整份 JSON → 整份写」强一个量级,且不需要额外基础设施。
4. **构建产物内联全部依赖 + `node:sqlite` 内置** —— 零运行时安装负担、不联网、不上传,这是分发上的正确取舍。

### 别照抄

- 别照抄硬编码路径:`stateDir: C:/Users/epat/.eteams` 写死在 patch 里。
- 别依赖「重试」的原子性:`atomicWriteText` 三次失败后**退化为直接写**。
- 进程内注册表重启即空,所以**任何跨重启的身份判断都必须走 `session_id` 快照**,不能靠内存。
