# 6-多端与远程 · dsh-mobile:让「多一个屏幕」变成一个产品

> **状态**:`observed` · **基线**:DSH `0.2.1-rc.3` · **读于**:2026-10-31
> **类**:`6` 多端 · **层**:**6**(另一个客户端)+ 5(默认值)+ 7(分发/通道)· npm **5,301**
> **一句话**:手机不是"响应式断点",而是**一台需要配对、需要鉴权、需要撤销的设备**;它另起一层 HTTPS 网关,把 DSH 当**回环上游**。
> **借鉴价值**:**① 要换屏幕就"回环上游 + 独立监听",绝不改宿主;② 兼容层只补 API、绝不转译语法,并把语法下限写到版本号;③ 撤销是物理删除、可见性是保留标记——删除与显示解耦;④ 每种"不可达"都是一条有名字的状态,不是一个灰点;⑤ 可执行组件的供应链校验清单。**

> **样本档案**
> **repo**:`saya-ch/dsh-mobile` · **npm**:`dsh-mobile`(+ Android App) · **版本**:—
> **目录条目**:`data/plugins/saya-ch__dsh-mobile.yml`(`remote`)
> **装法**:见卡 §3.1(Android App / 浏览器两条路)

## 1. 它在产品里的位置

```
手机(App / PWA)  ──HTTPS──▶  Mobile Gateway(3443,独立监听)
                                  │  配对码 / 设备 Token / 精确 Origin / 回环管理口
                                  ▼
                            回环代理(127.0.0.1)
                                  ▼
                       原生 dsh web(3080)+ Host
```

三条并列接缝(不是"改主题",也不是"加工具"):

| 接缝 | 做什么 | 上游对应物 |
|---|---|---|
| (a) Host 面 | 回环代理 + 独立 HTTPS 网关 | `webServer` 的 `WebRoute` / `WebUpgradeRoute`(`dsh-host-webserver/lib/types/index.d.ts:30-48`);`Config.host` **只接受具体本机字面量,通配地址在加载期被拒**(`:56-66`,`isWildcardHost`)——理由是"会在所有接口上同时暴露这个端口" |
| (b) 客户端 | 注入启动前兼容脚本 + 专用移动布局 | `webserver/index-inject` 的 `{kind:'script-src', placement:'head'}` 行 |
| (c) Android 原生 | `androidx.webkit` **WebMessage** 桥(每消息校验精确顶层 Origin + 主 Frame,限制大小;**不用 `addJavascriptInterface`**) | 上游**无** WebMessage 桥 → 这条完全在插件侧 |

**它明确没做**:不转译 DSH、不改 DSH 源码、不起本地代理守护进程、不自动重发消息。

## 2. 机制(可照抄的部分)

### 2.1 兼容层:为什么"不依赖 CDN、不放宽 CSP"是**结构结果**

| 事实 | 含义 |
|---|---|
| `script-src` 行**按表顺序执行**,served 形态是 **parser-blocking** | 所以它一定跑在 DSH 的第一个 `<script type="module">` 之前 |
| `row.src` 进 `<script src>` 前走 `escapeHtmlAttribute` | **同源相对路径即可**,不需要 CDN,也不需要 CSP 例外 |
| 上游 `dist/index.html` **本身没有 CSP meta**;仓库里唯一的 CSP 是 `/api/file` 的 `sandbox; default-src 'none'` | "不放宽 CSP"是对**网关自己托管页面**的承诺,不是绕开上游 |

**补的 API(精确清单)**:`Iterator` / Iterator helpers、`Promise.withResolvers`、`AbortSignal.any`;Android App 在 **document-start** 阶段、**仅对配对的精确 Origin** 提前补 `Promise.withResolvers`。桌面页面与 `?frontend=stock` 页面**不加载**。

**修不了的(写死的边界)**:

> DSH `0.2.1-rc.2` 的正式前端包含 **class static blocks**;**Chromium 92** 无法解析;该语法从 **Chrome 94** 默认可用,但这不代表 94 已通过整个 DSH 的兼容验收。App 的"内核低于 **100**"提醒只是建议,**点击继续不代表当前 DSH 可以运行**。

> **抄这条纪律**:"旧内核支持"的可承诺上限是**补 API**,不是**转译语法**。把语法下限写成具体版本号,是让旧设备用户期望可控的**唯一**写法。

### 2.2 信任模型:每一层都有可验证的形状

| 层 | 做法 | 可验证性 |
|---|---|---|
| 配对码 | 43 位;显示**有效截止时间**;生成新码使旧码失效;复制链接**复用当前码**、不另行作废二维码;Safari 首次**只能消费一次** | 码长、截止时间、失效规则都在 UI 上 |
| 设备令牌 | App 侧 Token 与固定 CA 由 **Android Keystore** 加密;二维码**不含**长期 Token 或 CA 私钥;令牌**只发往精确 Origin**,地址变化后旧 Token **不会**发给新 Origin | — |
| Origin / CSRF | 每条 WebMessage 校验**精确顶层 Origin + 主 Frame**;写请求仍校验配对 Session + 精确 Origin + CSRF | — |
| 管理口 | **TCP 对端必须回环**;Host 只放 `localhost`/RFC1918/链路本地;公网 IP 与任意域名 **403**;反代不得把 `/api/mobile-access` 公开转发 | 上游同构参照 `isTrustedApiRequest`(`dsh-client-connection/lib/index.js:240-270`) |
| 反代来源 | CIDR 匹配**代理的直接 TCP 来源,不信任转发头**;反代须保留外部 Host(含端口)、Origin、Cookie、WebSocket | — |

上游为什么死盯 Host(可直接引用的注释):**plain HTTP 下浏览器对读请求不附带 Origin 或 Fetch Metadata,"Host 是 rebinding 唯一伪造不了的头部"**(`dsh-client-connection/lib/types/api-request-trust.d.ts:1-10`)。

**信任边界自述(值得抄的诚实)**:"配对设备拥有控制电脑端 DSH 的能力,应视为**完全可信设备**";并明确"第三方插件**不能**把上游回环 Host 当成'请求来自电脑物理本机'的证明"。

### 2.3 撤销:删除与可见性解耦

| 端 | 行为 |
|---|---|
| 电脑端 | **永久删除**持久化存储里的设备记录与**令牌摘要**(不留 `revokedAt`);启动时清理旧版遗留的已撤销记录;此后旧令牌与未知令牌一样回落 `401 authentication_failed` |
| 手机端 | 在线收到撤销通知 → **保留条目**、显示"电脑端已移除"、**停止自动重连**、给"重新配对"与"删除本地记录" |

**副作用被明说**:离线期间被撤销的 App,再次检测时可能显示"配对已过期",需要重新配对。

> **为什么电脑端要物理删除**:标记会让库里长期存着可用凭据的哈希。**为什么手机端又要保留条目**:删掉会让用户以为"电脑没电了",于是反复重扫。两端做法相反,目标一致——**不留下可用的旧凭据,也不制造假故障**。

### 2.4 每条"不可达"都有名字(本卡最可抄的一处)

| 机制 | 做法 |
|---|---|
| 设备状态 | 绿点=可达;灰点细分四种:**检测中 / 暂不可达 / 配对已过期 / 电脑端已移除** |
| 可达性检查 | **直接验证 DSH Gateway,不依赖 ICMP**,也不会把暂时断网误判成"电脑端撤销" |
| 诊断回退链 | **先直连,失败才试** DSH 环境变量里的 HTTP 代理;`NO_PROXY` 可排除;两者都失败时**仍报不可达,不把离线误报为就绪** |
| 自备代理 | "**后端已监听 ≠ 公网就绪**",必须再确认公网 HTTPS 与 WebSocket 可用 |
| 配置冲突 | `409 excluded_client_modules_invalid` + 冲突详情(两侧都提示) |
| 日志 | Windows 初始化失败记录**阶段名**(`sid-query` 查账户 SID / `acl-apply` 应用私有权限)+ **该阶段完整等待耗时**;并明说"分阶段诊断**不代表**启动争抢问题已解决" |
| 双端版本 | **Host 暂存失败 → 继续用现有版本**;**Host 已更新但新 UI 激活失败 → 关闭该扩展并自动重试**(宁可关掉也不混搭新旧能力) |
| 有限重试 | App"连接超过有限重试预算后自动回到列表,**不会无限转圈**" |

### 2.5 可执行组件的供应链校验(逐条可抄)

| 组件 | 校验 |
|---|---|
| cpolar | **大小 + SHA-256** |
| cloudflared | 下载**固定版本**、校验**精确大小 + SHA-256**、启动时**关闭自动更新**(保证跑的就是校验过的那份) |
| Caddy | 大小、SHA-256、**核心与 DNS 模块版本** |
| frpc | 来源、精确大小、SHA-256、**压缩包内路径**、可执行文件版本 |
| 共同前提 | **仅在用户确认后**下载;令牌**只经环境变量**传、只存私有目录;**共享 Token 不出现在状态/诊断/接入清单响应里** |

## 3. 体验

### 3.1 三条首次路径(逐屏)

**A · Desktop + 局域网 + Android App(约 7 屏)**

1. Desktop **插件**页安装并启用(Desktop profile 由应用管理,**不走** `--profile web`)
2. 打开**移动访问**配置
3. 首次打开时页面**列出电脑当前网络**,确认网卡后**自动生成私有证书**并配置局域网(免终端)
4. 按提示**重启一次** DSH
5. 局域网 → **开启局域网访问**
6. **生成配对二维码**
7. 手机 App:扫描发现电脑 → 点设备 → 扫码或粘贴密钥 → 建立**持久设备信任**

**B · Web(命令行)**:`dsh plugin --profile web add dsh-mobile@latest` → `dsh plugin --profile web exec dsh-mobile setup` → `dsh --profile web`。`setup` **自动选择并记住**当前局域网,**仅在自动选择失败时**才用 `--address`;状态存 `$DSH_HOME/mobile-access/`。

**C · iPhone/iPad PWA(4 步,每步有坑)**

1. 电脑装插件 + 配通道(长期主屏**优先固定、受信任的 HTTPS**)
2. 局域网用"复制配对链接",远程用"生成远程二维码";**必须用专用移动访问链接,不是电脑普通 DSH 页面**;"Android 的 `dsh1.`/`dsh2.` 密钥**不是浏览器配对码**"
3. Safari 打开 → 分享 → 添加到主屏幕
4. 从主屏启动;显示配对码表单时走恢复步骤;**普通重连页用已有配对,不必重新配对**

> 推送入口:iOS/iPadOS **18.4+** + 受信任 HTTPS;**普通 Safari 标签页与 Android App 不显示此入口**;硬前提是"电脑、DSH 与网关都在运行"——"添加 Web App **不会**提供离线 DSH"。

### 3.2 卡点被提前写出来

局域网私有证书"浏览器首次访问可能提示不受信任";**"绕过证书警告不等于满足网页推送条件"**;同域名旧 Cookie 会反复触发 `401`;`dsh-mobile-question-fixes: failed to import` 时"**单纯重启不一定能解决**";远端"页面能打开但一直重连中"要先区分 **WS 升级失败 / 慢速同步 / 心跳超时**。

出错时该交什么被写成清单:**DSH / 插件 / App / WebView 版本、进入方式、脱敏后的首个控制台错误;不要发送令牌或完整配对地址**。

### 3.3 模型看到的

**几乎为零**。它不注册模型工具(扩展面是插件自有 IPC,不是 `tools.register`)。这是刻意的:多端是"同一会话换屏幕",不是"给模型加能力"。

## 5. 借鉴食谱表(本卡的产出物)

| 要解决的问题 | 照它的做法 | 你要改的地方 | 抄错的后果 |
|---|---|---|---|
| 想给产品加"另一个客户端" | **回环上游 + 独立监听**;宿主一行不改 | 绑定用**具体本机字面量**(上游拒通配) | 改宿主源码 → 每次升级重打一遍;绑 `0.0.0.0` → 默认暴露到整个网络 |
| 想在自己的页面里插脚本 | 用宿主的 `index-inject` `script-src` 行(parser-blocking、同源相对路径) | 若无注入点,至少别用字符串替换正文 | 正则改 HTML → 上游一改静默失效 |
| 旧内核用户 | 只补 **API**,按能力检测;**把语法下限写到版本号** | 记下你的前端用到的最新语法(如 class static blocks) | 承诺"支持旧机型"却卡在语法 → 用户以为插件坏了 |
| 设备授权 | 码一次性 + 显示截止时间 + 新码作废旧码 + 令牌只发精确 Origin | 码长给到 32 字节随机 | 长期码/可复用码 → 一张截图就能永久控制你的电脑 |
| 撤销 | 电脑端**物理删除**记录与令牌摘要;手机端**保留条目**显示"已被移除此设备" | 合规需留痕时,留**不含凭据**的审计行 | 只置 `revokedAt` → 库里长期存可用凭据哈希;两端都删 → 用户以为设备丢了 |
| 管理接口准入 | **TCP 对端必须回环** + Host 白名单(loopback/RFC1918/链路本地)+ 其余 403;文档明令不得公开反代管理路径 | 有公网需求时用**独立鉴权**,不要放宽 Host | 把 Origin 校验当第一道闸 → plain HTTP 下浏览器不发 Origin,直接绕过 |
| 实时通道放行 | 只接受 **exact path**;拒绝查询串与前缀;局域网/远程共用一套 | 上游 `WebUpgradeRoute` 本身只有 exact `path` | 前缀匹配 → 任意子路径都能挂 WS,等于开后门 |
| "不可达"的显示 | 每种原因一条**命名状态**;可达性**打业务端口而不是 ICMP** | 状态名要用用户能懂的话 | 一个灰点 → 用户分不清"没电""被撤""网络差" |
| 诊断要能下结论 | 先直连、失败再试代理;**两者都失败就报不可达**;"后端监听 ≠ 公网就绪" | 记下每一跳的失败原因 | 探测成功就报就绪 → 用户拿着一个打不开的地址 |
| 下载并运行第三方二进制 | 固定版本 + 精确大小 + SHA-256(+ 包内路径与版本)+ **关自动更新** + 仅用户确认后下载 | 校验值写进代码,不要动态拉 | 只校验版本号 → 中间人替换内容;开着自动更新 → 校验过的那份被换掉 |
| 秘密怎么传 | 令牌**只经环境变量**、只存私有目录;**不出现在状态/诊断/清单响应** | — | 诊断页回显令牌 → 用户一贴日志就泄露 |
| 锁屏 / 通知 | **锁屏不含会话正文**;通知分类可开关 | 你的敏感字段可能是路径、代码 | 锁屏显示完整回复 → 投影上就泄了 |
| 卸载与残留 | **先 `purge --yes` 再卸载**;清自己建的东西(目录、防火墙规则),**不碰别人的** | 列出"我创建过什么" | 卸载后防火墙规则留着 → 下次端口冲突 |
| 双端版本不同步 | 宁可**关掉**那个扩展也不混用新旧能力 | — | host 新 / UI 旧硬跑 → 状态错乱 |

## 6. 失效条件与降级

| 触发 | 行为 |
|---|---|
| 系统 WebView 太旧无法更新 | 用已确认正常的手机浏览器访问同一地址,**无需清除原有 App 配对** |
| 缺 API | compat.js 按能力检测补齐 |
| 缺语法 | **补不了**,只能换内核(它划的硬线) |
| 皮肤依赖原生布局容器 | 可在"移动页面模块"里**只对本设备**不加载该皮肤,不必卸载电脑插件 |
| 网关放行 HTTP iframe | 客户端仍可能拦截(**Android App 阻止 HTTPS 页面的 HTTP 混合内容**) |
| 隧道域名变化 | **不自动迁移**配对或推送同意;重扫当前二维码验证新地址,**不需要清除 App 数据** |
| 本机删除设备记录 | 二次确认 + **短暂撤销**,但撤销**只恢复本机记录**,不恢复电脑端已撤销的授权 |
| 网卡消失(`saved LAN interface … is not connected`) | DSH 继续运行,移动访问**暂时休眠**,原网卡恢复后**自动重试** |
| 移动网关关闭 | 只在开启时监听局域网;关闭后 DSH 仍在本机正常运行 |
| 平台缺能力(macOS Funnel/cpolar、非 Windows 防火墙) | 显示"**不适用**",不假装通过 |
| 扩展接口返回 `401` | 文档明令:**不要**用开放匿名访问或公开 Cookie/Token 来"修" |
