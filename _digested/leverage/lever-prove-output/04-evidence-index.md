# 04 · 证据索引：把「防误杀」做成阶梯，而不是阈值

> **状态**:`observed`(机制与指标已核) · **基线**:DSH `0.2.1-rc.3` · 名单 7924 条 @ `efe602e7b`
> **样本**:2 组(主标杆 `AaronandWork/dsh-evidence-gate` · 对照 `rootsbymenda/dsh-second-angle` 的判决分级)

[`03`](./03-turn-end-reconciliation.md) 讲的是**语义对账**(矛盾能不能被发现)。本卡讲同一条路的另一种做法:**不判语义,只判出处**——以及它必须付出的代价:一套精心设计、可被审计的**误杀防线**。

---

## 1. 命题

> 做「证据门禁」最难的不是判定,是**判错时怎么办**。任何以「无证据」为由拦截的门,都会误杀诚实但简洁的答案。所以一个成熟实现的重心不在判定逻辑,在**降级阶梯**:先假设它是对的,逐级放宽,只有一路都站不住才拦。**阶梯越清楚,门才越敢硬。**

可证伪:

- **P1**:若简单阈值(有证据/无证据)就够用,则阶梯是过度设计。
- **P2**:若拦截不产生成本,则不需要 `converted` / `charity` 这类**反向指标**。

P1 不成立:`own-session → 输出关键词 → 跨会话(子代理)→ 存在性兜底 → 才 block` 五级,每一级都对应一种真实误杀情形(见 §3.2)。P2 不成立:它专门记了一个指标叫「被拦下后又翻案的」(converted)。

## 3. 机制

### 3.1 它判什么、不判什么(这条要先说清)

`evidence_gate` 的判定对象是**「直接观察类声称」**:我跑了 X、我看到文件里是 Y、我用 curl 得到了 Z。判定依据是**索引里是否有对得上的活动**——索引来自 `tools/result` 监听,记录的是**工具参数 + 输出锚点**(路径 / URL / 特征输出词)。

它**不判**结论对不对。这是它能做成硬门禁的原因:一旦要判语义,就必须调模型,就回到 `[03]` 的概率域。

### 3.2 反误杀阶梯(本卡的核心)

| 级 | 依据 | 结果 | 对应哪种误杀 |
|---|---|---|---|
| 1 | **本会话**索引命中 | VERIFIED | — |
| 2 | 已记录的**输出关键词**命中(如 `pnpm test → SMOKE PASSED`) | VERIFIED / REFERENCED | agent 引用了输出而不是命令串 |
| 3 | **跨会话**命中 | 核验命中 | 证据是**子代理**产出的,主会话没有直接记录 |
| 4 | **存在性兜底**:引用的路径**真实存在** | 放行,标 `⚠ 弱核验`(`采信`) | 结论正确但没走「声称—验证」的形式 |
| 5 | 都不成立(含**编造路径**、空证据、`assumption`) | **block** | 真正的无依据 |

**第 3 级是本卡最有信息量的一处**:它承认了 agent 的分工现实——子代理跑了命令,主代理写结论。只认本会话活动,会把**正确的**协作结果判成无依据。
**第 4 级是最危险也最诚实的一处**:它用「路径存在」代替证据,并把这种放行单独命名为 `charity`(采信),让它**可以被统计、被审查**。比悄悄放过强得多。

### 3.3 三个指标构成一个闭环

| 指标 | 含义 | 它回答的问题 |
|---|---|---|
| `blocked` | 被降级/拦截的猜测数 | 门拦了多少次 |
| `converted` | 被拦下后,agent 真去验证并翻案的数 | **门拦对了吗** |
| `charity` | 存在性底线放行数 | 门软了多少次 |

`converted` 是本域见过的最锋利的一个指标:它把「拦截」从「行为」变成「可评估的行为」。一次 `converted` 意味着门拦的是一次**真实的猜测**并且改进了它;`blocked` 长期高而 `converted` 长期为 0,说明门在制造摩擦而没有产出。

真实会话的统计一次(README 示例):

```
实证 verified 12 · 引用 cited 3 · 拦截 blocked 5 · 无效 invalid 0
转化 converted 3 · 核验命中 cross-checked 9 · 采信 floor-passed 1(索引 index 214)
```

读法:12 条结论过门(9 条有索引佐证、1 条按存在性底线采信);5 个猜测被拦下,其中 **3 个**在 agent 真跑完验证后翻案——**拦截有效率 3/5**。

### 3.4 它把话说明白了

> 「harness 没有任何机制能拦截最终文本。」

所以它的策略是**前置**的:用 `systemPrompt.section` 在装配时就告诉模型「直接观察类结论必须带证据」,再用 `evidence_gate` 工具与 `tools/result` 索引做**事后核对**。它不试图阻止文本发出——**它试图让「无证据」这种写法在下一轮不再出现**。

### 3.5 工程细节里的三条纪律

- **按会话作用域**:开关、台账、策略段全部按 `sessionId`;未开启的会话,策略段装配为**空串**(零 token 成本,不污染别人的 prompt)。
- **启动默认静默**:挂载时不向宿主控制台打印任何内容,排障要 `EVIDENCE_GATE_DEBUG=1`。
- **UI 桥接最小面**:只接受**同源** `application/json` POST,请求体上限 64KB,会话键与 action 先校验,`status` 严格只读。存储是可直接查看/删除的纯 JSON。

### 5.1 它与 second-angle 的误差互补

| | evidence-gate | second-angle |
|---|---|---|
| 误差方向 | **漏判**:同义改写 → 采信或放过 | **误判**:思考模式下对真实句子 steer |

## 6. 对照与一处必须点名的破坏面

### 对照 · `rootsbymenda/dsh-second-angle`(判决分级)

同一条命题的对照组,区别在**判决粒度**:它把 `OVERSTATED` 与 `CONTRADICTED` 分开统计,而 evidence-gate 把「引用到了但不是结论」压成一级 `REFERENCED`。前者更贵,但能区分「夸张」和「说反」——**这两类失败对用户的伤害完全不同**:夸张是可容忍的语气问题,说反是事实错误。

### 破坏面 · 存在性兜底(`charity`)可被当成后门

级 4 的规则是:引用的路径**真实存在** → 弱核验放行。这条规则在诚实使用时非常好(agent 说「我看了 `package.json`,它有 `pnpm test`」而没真读),但它也给了**最省事的逃避路径**:任何一句结论只要挂一个存在的路径就能通过。

`charity` 计数是唯一的防线——它让这种放行**在报告里可见**。**这是一个通用设计教训:凡是给「弱证据」开了绿灯的机制,都必须给这类绿灯单独计数,否则绿灯会变成默认路径。**

## 7. 可借鉴:六条可以直接搬走的做法

### B1 · 门禁只判「有没有出处」,不判「对不对」

**做法**:`evidence_gate` 判定的是「直接观察类声称」——我跑了 X、我看到文件里是 Y。依据是索引里有没有对得上的工具活动。**它从不判结论的正确性。**

**为什么有效**:这是「能做成硬门禁」与「只能做成建议」的分水岭。判语义需要模型 → 概率 → 不能给否决权;判出处只需要匹配 → 确定 → 可以给否决权。**先想清楚你要判哪一半,再决定它有没有权力拦。**

**怎么搬**:把你的质量规则分成两组——`可匹配`(有没有跑、有没有读、路径存不存在、命令退出码)与`需判断`(写得对不对、结论是否成立)。**第一组做成门,第二组做成提示或建议。** 把两组混在一起的实现,通常最终只有提示。

**反面**:只判出处会漏掉最严重的失败——**结论与证据相反**。所以要明确它不是完整解,而是「便宜的第一道筛子」。

---

### B2 · 反误杀阶梯:五级依次放宽,而不是二元阈值

**做法**:`本会话命中 → 已记录输出关键词命中 → 跨会话(子代理)命中 → 存在性兜底(引用路径真实存在)→ 才 block`。

**为什么有效**:任何以「无证据」为由拦截的门,都会误杀**诚实但简洁**的答案。阶梯的本质是**先假设它是对的**,逐级找放行理由,只有一路都站不住才拦。**误杀率的下降不来自更聪明的判定,来自更多条免罪路径。**

**怎么搬**:给你的门禁列一张「免罪清单」,每一项对应一种真实的误杀情形。然后按代价从低到高排序,做成级联。**关键工程要求:每一级的命中都要被记录并出现在报告里**,否则你不知道免罪层有没有变成默认路径。

**反面**:级数越多,后门越多。第 4 级(存在性兜底)就是一个可被利用的漏洞——引用一个真实存在但无关的路径即可通过。

---

### B3 · 给「弱证据放行」单独命名并计数

**做法**:`charity`(采信)= 按存在性底线放行的条数,在报告里**可见**。

**为什么有效**:这是本卡最有价值的一条设计。任何给弱证据开绿灯的机制,都必须让绿灯**可统计**——否则它会在半年内悄悄变成默认路径,而没人知道。命名的力量在于:它从「放过了」变成「采信了 N 次」。

**怎么搬**:给每一类「没有严格满足、但我放行了」的情况起一个名字并计数。**没有名字的例外,会变成没有例外的名字。**

**反面**:计数本身不产生压力。若 `charity` 长期占多数而无人过问,它只是把问题记录得更好看了。需要一个**看这个数的人**。

---

### B4 · 用「被拦下后翻案」的次数衡量门禁的价值

**做法**:`converted` = 被拦下后,agent 真去验证并翻案的条数。真实会话示例:`blocked 5 · converted 3`。

**为什么有效**:这是本域见过的最锋利的一个指标。它把「拦截」从**行为**变成**可评估的行为**:

- `blocked` 高 + `converted` 高 → 门在拦住真实猜测并促成验证(**有价值**);
- `blocked` 高 + `converted` 为 0 → 门在制造摩擦而无产出(**应该下掉**)。

**怎么搬**:任何门禁都要记两个数:**拦了多少**、**拦对多少**。第二个数通常没人记,而它才是唯一能回答「要不要继续用这个门」的数据。

**反面**:`converted` 需要能把「同一条声称」在拦截前后对上号,这要求稳定的 id(而多数实现只有自由文本)。**先设计 id,再设计指标。**

---

### B5 · 把「子代理产出的证据」当成一等公民

**做法**:第 3 级是**跨会话命中**——主会话没有直接记录,但子代理有。

**为什么有效**:它承认了 agent 分工的现实——子代理跑命令,主代理写结论。只认本会话活动,会把**正确的协作结果**判成无依据,而这种误杀最难解释(用户看到的是正确结论被拦)。

**怎么搬**:索引必须**跨会话可查**,并且要带上「来自哪个会话/子代理」的标注。**同时要评估:这会不会成为绕过通道**——子代理可以被要求跑一个只是为了留下痕迹的无意义命令。

**反面**:跨会话命中扩大了证据面,也扩大了污染面。`[`02`](./02-goal-gate-hard-floor.md)` goalloop 的选择相反(忽略成员上报的 `commandsRun`),**两条路都对,取决于你是否信任子代理**。

---

### B6 · 按会话作用域装配策略段,关闭时是空串

**做法**:开关、台账、策略段全部按 `sessionId`;未开启的会话,策略段装配为**空字符串**(零 token 成本,不污染别人的 prompt)。

**为什么有效**:质量工具最容易犯的隐形成本是**给所有会话加 token**。一份 500 token 的策略段,在 100 个会话上是 5 万 token 的净支出,而收益只落在开启的那三个上。**「关闭」必须是真正的零成本,而不是「少做事」。**

**怎么搬**:任何往 prompt 里插内容的插件,都要保证:① 按会话生效;② 关闭时返回空串而不是一句「此功能已关闭」;③ 有能力测量它实际注入了多少 token。

**反面**:空串策略段的副作用是**模型不知道有这个功能存在**。若插件依赖模型主动调用某个工具,关闭策略段等于让它不可发现——这时需要把「可发现性」和「约束性」拆成两段分别控制。
## 8. 体验

**模型侧**收到的是四级不同的答复:`VERIFIED`(无事发生)、`REFERENCED`(有出处但不是结论)、`UNVERIFIED`/`INVALID`(要补证据)、`OFF`(本会话未开启,策略段为空)。**分级答复比二元答复更能教会模型怎么写下一句**——这是它与「有/无」式门禁的体验差。

**人类侧**有一个专门的报告命令 `/evidence-gate report`:按判决分组、按依据分类、`blocked/converted/采信` 三项、最近的断言列表。**质量工具能被审计,才算质量工具**;只有一个"通过/不通过"的,人类无法判断它有没有在帮忙。

## 9. 失败模式

| 失败 | 表现 | 根因 |
|---|---|---|
| 同义改写被漏判 | 正确结论被标 UNVERIFIED 或落到 charity | 索引是关键词,不是语义 |
| 长会话遗忘 | 早期工具活动被 400 条上限挤出,旧声明全变无依据 | 固定容量索引 |
| 后门采信 | 挂一个存在的路径就通过 | 存在性兜底天然可滥用 |
| 只记录不判定 | 声称「证据插件」,实际只写日志 | 无权利说「无依据」 |
| 无反面指标 | 只报 blocked,不报 converted | 把摩擦当成果 |
| 策略段污染 | 所有会话都被插入证据要求,白付 token | 未按会话作用域装配 |

## 10. 评估清单

1. 它判的是**语义矛盾**还是**有无出处**?(两者都做,还是只做一种)
2. 误杀防线有几级?每级对应哪一种真实误杀情形?
3. 有没有**反向指标**(拦下之后翻案了多少次)?
4. 「弱证据放行」是否单独计数并可见?
5. 证据索引的**容量上限**是多少?超了之后旧证据怎么办?
6. 它承认子代理产出的证据吗?
