## 生长

垂直预设的价值在**默认流程的质量**,星标通常不高但留存强。这类条目最容易被"通用编排"替代,写卡时要回答:它提供了什么通用组件给不了的东西。

**源码读完后,这张卡纠正了两个预期**:

- **它不是"薄预设"**:插件 `src/**` 23 个文件 15,323 行、测试 41 spec/13,437 行,与桌面应用 186,049 行**零代码共享**——它是在 DSH 里把小说领域重写了一遍。预设本身只有 42 行 YAML,真正的重量在 agent 掩码、host RPC 与 client 三面。
- **"preset + 工作台"的价值不在模板,在写权限**:V1 用逐文件 SHA-256 修订 + 宿主原生一次性审批,V2 用自建 SQLite 聚合 + 非权威提案箱,模型**永远不能写权威状态**。这是通用编排给不了的东西——领域状态机与审批边界是垂直预设真正的护城河。

但它的 `0.1.0` preview 已冻结,20 个 peer 里 17 个钉死 `0.1.0-rc.6`;本机 0.2.1-rc.5 已有 6 个 peer 不存在。**判断:机制值得借,实现不可直接装**——这类样本的价值在"怎么写",不在"拿来用"。
