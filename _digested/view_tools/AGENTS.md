# `view_tools/` 工作规则

tools 领域册。1639 条(第二大类)、本期新增 586、owners 1254(单件 87%,头部类目里多样性最好)。上层纪律见 [`../AGENTS.md`](../AGENTS.md)。

## 册内结构(三级)

| 层 | 文件 | 作用 |
|----|------|------|
| 册 | `README.md` | 快照 + 子分类索引 |
| 子分类 | `<子分类>/README.md` | 定义 + 已确认成员 + 立卡条件 |
| 单卡 | `<子分类>/NN-<slug>.md` | 当前无;满足立卡条件后新建 |

子分类:`single-purpose` / `toolchain-meta` / `integration-bridge`。

## 立卡条件(满足任一即立)

1. 类内出现 **≥800 星**或 **≥3 个第三方衍生**的条目;
2. 出现被 5 个以上条目提及的实现(扩散信号,`delta.py` ③b);
3. 某工具类条目成为其他类目的依赖(如被 sidebar/TUI 类点名接入)。

## 本册特有注意

**第二大类却没有千星锚**,是本领域最显著的结构特征:477 星的 `superdesigndev/treg` 之后直接掉到 147。这与 tools 的"杂类收纳"定位一致——什么都能塞,因此没有统一叙事,也难以长出单一头部。

写卡时注意区分两种突出:
- **单点工具**:解决一个问题,星标是天花板;
- **工具链元层**(如 `Noob-stupid/dsh-plugin-gating-hub`):本身不完成业务,但被其他工具依赖——这类更可能是潜在锚,优先观察。

## 刷新

数字随 `census.py`/`delta.py`;每轮检查立卡条件是否被触发。若 tools 中出现千星条目,那是本生态"工具标准化"出现的信号,应立刻立卡。
