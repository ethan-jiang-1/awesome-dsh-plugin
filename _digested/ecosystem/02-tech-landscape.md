## 0002 引入、0007 重算覆盖:历史能力扫描披露

标签是**描述文本的正则判定**——它测的是"作者说自己做了什么"。0002 起 `data/capabilities.json` 提供了另一套事实:**扫描器读安装产物本身**(npm tarball > 作者预构建 tarball > codeload 归档),报告它碰了什么。两者不可互相替代:

口径:本表在 **3745 条** URL 匹配行上重算(0005 口径是 3764 行;旧文本的 fs-read 2817 等已作废)。数值小幅下移(如 fs-read 2817 → 2804、credentials 450 → 447)与 join 行数 3764 → 3745 同向,**不宜读成"能力面收缩"**;真正变的是分母:记录行数几乎没动(边车 3813 → 3805),对当前名单的覆盖率却从 47.5% 掉到 28.5%。

三点读法:

1. **"读凭据 × 有网络"的旧扫描子集现为 344 条**(仅在 3745 条 URL 匹配上,不是本轮重新扫描;0005 口径为 348),这不是说它们恶意(代理、网关、余额看板本来就要这么做),而是说明把凭据交给第三方插件是需要逐条核对的默认风险面。
2. **披露不是判决**:scanner 的产出里 `score/band/verdict` 被有意丢弃,未扫到的条目渲染为"未检出"而不是"干净"(#209)。
3. **描述与静态扫描是两把不同的尺子**:当前描述标签命中"安全/权限"1684 条;旧能力扫描快照在当前 URL 匹配的 3745 项中检测到 credentials 447 条。名单范围、日期与测量对象都不同,不可当作两拨固定人群直接比较。

> **覆盖率继续被分母稀释**:0003 时 join 覆盖 85.2%(3826/4489),0004 降到 56.6%(3792/6704),0005 再降到 47.5%(3764/7924),0007 只剩 **28.5%(3745/13136)**——不是旧扫描丢了记录(边车 0006 合并后 3813 行、0007 合并后 **3805** 行,只随删除收缩、不随增长扩大;其中 3745 个 URL 仍能对上当前条目,60 行成孤儿),而是名单又增到 13136 条,新增条目一律不在 2026-09-24 的扫描里。0006 未重算该 join,故序列在 0005 与 0007 之间没有中间点。引用时必须带上分母。

## 方法注记(引用数字前必读)

- 标签由 34 组正则在合并后的 en+zh 描述上判定,**接受多标**,故标签命中总数远大于条目数;
- 已修正的两处系统性误报:「本地推理」曾因正则含『离线』报 44(当前 83);「图像生成」曾因泛词误报 361(当前 178)。标签是描述匹配,不是实测能力——**插件能做什么 ≠ 描述说了什么**;
- **本文的「安全/权限 1684」统计的是描述文本命中,不是这 13136 个插件构成的供给链攻击面**;能力披露仅覆盖旧扫描快照与当前名单 URL 相交的 3745 条(其中 344 条披露 credentials+network),仍不是全量新鲜审计——扫描器不做动态分析、不判断意图,门禁也不跑它(见 [submission-gates](../mechanics/submission-gates/00-map.md));
- 星标/下载等外部信号不在本文,见 [03](03-growth-maturity.md) 与 [04](04-value-trend.md)(新鲜数字以 fresh_probe 自采为准,见 [`_method/01`](../_method/01-fresh-probe.md));本文不引用任何星标/下载数字。
