## 0002 引入、0005 重新对齐覆盖:历史能力扫描披露

标签是**描述文本的正则判定**——它测的是"作者说自己做了什么"。0002 起 `data/capabilities.json` 提供了另一套事实:**扫描器读安装产物本身**(npm tarball > 作者预构建 tarball > codeload 归档),报告它碰了什么。两者不可互相替代:

| 零能力(扫描未检出) | 478 | | | |

三点读法:

1. **"读凭据 × 有网络"的旧扫描子集现为 348 条**(仅在 3764 条 URL 匹配上,不是本轮重新扫描),这不是说它们恶意(代理、网关、余额看板本来就要这么做),而是说明把凭据交给第三方插件是需要逐条核对的默认风险面。
2. **披露不是判决**:scanner 的产出里 `score/band/verdict` 被有意丢弃,未扫到的条目渲染为"未检出"而不是"干净"(#209)。
3. **描述与静态扫描是两把不同的尺子**:当前描述标签命中"安全/权限"890 条;旧能力扫描快照在当前 URL 匹配的 3764 项中检测到 credentials 450 条。名单范围、日期与测量对象都不同,不可当作两拨固定人群直接比较。

> **覆盖率继续被分母稀释**:0003 时 join 覆盖 85.2%(3826/4489),0004 降到 56.6%(3792/6704),0005 再降到 **47.5%(3764/7924)**——不是旧扫描丢了记录(边车仍有 3821 行,0004 为 3843;其中 3764 个 URL 仍能对上当前条目,57 行指向已删条目),而是名单在 7 天里又增加 1220 条,新增条目一律不在 2026-09-24 的扫描里。能力披露的"未检出"占比因此随收录速度上升,引用时必须带上分母。

## 方法注记(引用数字前必读)

- 标签由 34 组正则在合并后的 en+zh 描述上判定,**接受多标**,故标签命中总数远大于条目数;
- 已修正的两处系统性误报:「本地推理」曾因正则含『离线』报 44(当前 50);「图像生成」曾因泛词误报 361(当前 115)。标签是描述匹配,不是实测能力——**插件能做什么 ≠ 描述说了什么**;
- **本文的「安全/权限 1028」统计的是描述文本命中,不是这 7924 个插件构成的供给链攻击面**;能力披露仅覆盖旧扫描快照与当前名单 URL 相交的 3764 条(其中 348 条披露 credentials+network),仍不是全量新鲜审计——扫描器不做动态分析、不判断意图,门禁也不跑它(见 [submission-gates](../mechanics/submission-gates/00-map.md));
- 星标/下载等外部信号不在本文,见 [03](03-growth-maturity.md) 与 [04](04-value-trend.md)(新鲜数字以 fresh_probe 自采为准,见 [`_method/01`](../_method/01-fresh-probe.md))。
