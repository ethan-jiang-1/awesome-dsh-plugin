## 0002 新增:能力披露(与"描述里写了什么"完全正交的第二把尺子)

标签是**描述文本的正则判定**——它测的是"作者说自己做了什么"。0002 起 `data/capabilities.json` 提供了另一套事实:**扫描器读安装产物本身**(npm tarball > 作者预构建 tarball > codeload 归档),报告它碰了什么。两者不可互相替代:

| 能力(fs-read 起) | 条目数 | | redLine | 条目数 |
|---|---:|---|---|---:|
| fs-read | 2883 | | 既读凭据/密钥又有网络访问 | **354** |
| fs-write | 2262 | | 安装时执行代码(postinstall) | 20 |
| env | 2207 | | 明文 http:// 到若干域/字面 IP | 数十 |
| network | 2184 | | | |
| shell | 1635 | | | |
| credentials | 455 | | **有 ≥1 条 redLine** | **454 (11.8%)** |
| llm 348 · dynamic-code 347 · host-runtime 296 · subagent 87 | | | 扫描覆盖 | 3844/4392 (87.5%) |
| 零能力(纯静态/未检出) | 487 | | | |

三点读法:

1. **"读凭据 × 有网络"是 354 条的常态,不是异常**——这不是说它们恶意(代理、网关、余额看板本来就要这么做),而是说"把凭据交给第三方插件"在这个生态里是**默认成本**,披露让它可以被逐个核对,而不是被一句"安全类插件"概括。
2. **披露不是判决**:scanner 的产出里 `score/band/verdict` 被有意丢弃,未扫到的条目渲染为"未检出"而不是"干净"(#209)。
3. **与标签口径的差距可以量化**:描述里命中"安全/权限"的 601 条,与"实际碰了 credentials"的 455 条几乎是两拨人。

## 方法注记(引用数字前必读)

- 标签由约 34 组正则在合并后的 en+zh 描述上判定,**接受多标**,故各标签之和远大于条目数;
- 已修正的两处系统性误报:「本地推理」曾因正则含『离线』报 44(收紧后真实值很小,现 35);「图像生成」曾因『绘图/画图/海报』等泛匹配报 361(收紧到生图专属词后 57)。其余标签抽样核验均真实,但正则法天花板就是描述写出来的东西——**插件能做什么 ≠ 描述说了什么**;
- **本文的「安全/权限 601」统计的是插件自身声称/提供的能力,不是这 4392 个可执行插件构成的供给链攻击面**;后者的量化下界现在由 §能力披露给出(354 条读凭据且有网络),但"披露"仍不等于"审计"——扫描器不做动态分析、不判断意图,门禁也不跑它(见 [submission-gates](../mechanics/submission-gates/00-map.md));
- 星标/下载等外部信号不在本文,见 [03](03-growth-maturity.md) 与 [04](04-value-trend.md)(新鲜数字以 fresh_probe 自采为准,见 [`_method/01`](../_method/01-fresh-probe.md))。
