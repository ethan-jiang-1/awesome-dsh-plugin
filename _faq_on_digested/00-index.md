# FAQ on Digested · 基于消化材料的二次研究

这个目录不是面向学习者的 FAQ。这里的每一个问题是我们在阅读 `_digested/` 材料、翻本仓库源码的过程中**自己产生的困惑**,答案需要跨越多个专题条目、甚至结合源码才能综合出来。

简单说:**一子目录 = 一个探究过的问题,答案是自己综合出来的,不是从某一份材料里直接抄的。**

> **当前研究基线**:涉及行为的结论以 awesome-dsh-plugin `main@38976afdb5f70d1bcd1dfd5ed0e50e5a3a559fd4`(2026-09-11)为准;各问题若初问于更早快照,会在文内显式标注双基线并重算。旧 checkout 只用于变更史,不能替代当前源码验证。

## 和 `_digested/` 内置问题的区别

| | `_digested/` 各专题的待答问题 | `_faq_on_digested/` |
|---|---|---|
| 范围 | 单专题内的问题清单 | 跨专题的综合问题 |
| 答案来源 | 单一专题的整理 | 多份材料 + 源码的综合推断 |
| 本质 | 该专题的消化大纲 | 研究过程的归档 |

## 目录结构

```text
_faq_on_digested/
├── 00-index.md            # 你正在看的文件
├── <NN>_<question-slug>/  # 一个问题 = 一个子目录
│   ├── question.md        # 问题描述 + 背景
│   └── answer.md          # 答案 / 分析 / 结论
```

子目录内自由组织。关键是**引用来源要标注清楚**。

## 命名约定

子目录用英文 slug 简述问题主题,`NN_` 数字前缀按创建时间排序(01 最早)。

## 引用规范

引用 `_digested/` 用相对路径:

```markdown

```

引用源码标注 commit hash,避免链接随时间失效。

## 验证

修改后运行:

```sh
node _digested/verify.mjs
```

它检查严格 UTF-8、LF 换行与单个结尾换行、相对链接与锚点。

数字类事实的新鲜度复核仍是人工步骤:上游合入后，按 `_digested/_change_log/` 复核各答案的关键结论，不把「当前 checkout」当成新基线。
