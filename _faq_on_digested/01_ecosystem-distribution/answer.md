# A01 · 分布的三视角答案:技术上造桥,业务上修渠,体验上装窗

> 数据快照 `main@5e7dc7eb`,2026-08-27,2286 条。方法与口径见 [question.md](question.md)。

## 一句话总答案

这是一个**围绕纯文本 agent 驾驶舱的增强层经济**:技术上是"造桥"(把外部能力接进来),业务上是"修渠"(抢分发位置),体验上是"装窗"(在聊天窗口内做加法)。

## 分布的形状(先看整体,再谈三视角)

在拆三个视角之前,先回答"这 2286 条整体长什么样"——它是一个**温和偏斜的漏斗 + 一条极端长尾,几乎没有中间带**,由**极低的复制成本**塑造:

- **分类维度**(基尼 0.40):头部温和。ui 独占 15.7%,Top3 占 37%,Top5 占 49.6%,Top10 占 72.6%——**没有哪一类一家独大**,是"十来个强类把二十二类带成漏斗"的形态;真正的尾巴(占比 <2%)要到第 19 类才开始,4 类合计仅 3.3%。
- **作者维度**(基尼 0.29,但形态是双峰):**91.3% 的作者(1390/1522)只投 ≤2 件**,这层"路人级"铺底贡献了 **69.9% 的条目**(单是恰好 1 件的就占 51.7%);顶上只有一打作坊——Top10 作者合计 8.7%、Top50 合计 18.5%。**中间带几乎没有**:要么"投一件就走"的路人,要么几步跨进职业化,很少有"稳定做 3–4 件"的腰部作者。
- **生成机制(三个视角殊途同归)**:外挂桥是"调个 API"、壳件是"加个面板",**单件插件的复制成本极低**。复制便宜 → 两周堆出 2286 条;便宜 → 91% 的人投一件就走(沉没成本小);便宜 → 竞争拼的是"谁先占位"而非"谁写得好",于是星标与交付质量解耦(见下面业务/体验两视角)。**"分布为什么长这样"的答案,就是"门槛太低"。**

下面三个视角是这个形状的三个切面,每个"判断"都回指这条机制。

---

## 技术视角:一座"桥"的生态——重心在协议适配,不在算法

- **多模态外挂桥**:主模型是纯文本对话,视觉/语音全靠外挂桥补。图像理解 49、OCR/截屏 57、ASR 22、TTS 21、图像生成 32、视频 51(均为标签命中次数,允许多标、互有重叠),合计约 230 次命中都是"贴图→VLM→文字→回填纯文本模型"这一模式的变体。
- **模型路由/聚合是标准件**:OpenRouter / one-api / new-api / LiteLLM 中转 138 条——"换大脑"能力被视为 harness 应有之义。
- **MCP 已成为主要扩展协议之一**:109 条,既把外部 MCP server 注册为原生工具,也反向把 DSH 能力暴露为 MCP 服务。
- **本地推理极少**:剔除『离线』误报后仅 **10 条**——真正的本地推理生态很小。

**判断**:重活全部外包给云端 API 和本地 CLI,插件本体几乎不含模型、不含训练、甚至少含复杂前端逻辑。生态的技术含量集中在**编排与适配**(谁先把 X 接到 DSH 上)。这正是那个"分布形状"的技术来源:复制成本被压到"调个 API / 挂个中转"的量级,所以漏斗能两周灌满、长尾能拉到 2286 条。对评估者的含义:**这里没有护城河技术,有价值的是位置和先发**。

## 业务视角:渠道化与小作坊并存,变现证据薄弱

- **生产结构**:1522 个 owner 中 77.6% 只有一件作品;≥5 条的"职业化作者"仅 43 家(5–9 件 33 + 10–29 件 9 + ≥30 件 1)。头名 `omdsh-dev`(37 条)是典型工作室打法:`dsh-tool-{csv,diff,json,regex…}` 微工具全家桶 + 沙盒系列 + plugin-template 脚手架。
- **大厂渠道化**:stars Top3 全部是外部成熟项目主动挂一条 integration 进来——字节 `volcengine/OpenViking` 29567★、`vectorize-io/hindsight` 20218★、`tt-a1i/archify` 14283★;接着 `Q00/ouroboros` 5565★、`strukto-ai/mirage` 3520★ 也是外部项目接入。DSH 被当作值得卡位的分发渠道,这是平台合法性的滞后指标。
- **再包装层已经出现**:51 个聚合型仓库(dsh-plugins / dsh-plugin-hub / packs 命名)贡献了 91 条,如 `creait-nl/dsh-plugins`(8)、`wingsky-1/dsh-plugin-hub`(7)。"商店里的商店"。
- **用户画像间接可证**:成本监控 192 条且与 DeepSeek 共现最高(67),峰谷计价感知插件(如输入框下实时余额、高峰时段自动切省 token 模式)的存在说明用户对中国区 API 计价高度敏感;**描述 99.6% 是中英双语(zh 100% 齐、en 99.6% 齐**,见 data-notes.md §2)→ 这是个"中文母语作者主导但语言上不排外"的生态,而非封闭的中文圈;尚无可见的商业闭环(tools 类几乎全部免费 npm 包,dsh-market 无支付痕迹)。

**判断**:目前观察到被验证的赚钱方式基本只有一种——**把 DSH 当渠道**(大厂 integration);小作者的回报仍主要是星标和简历价值。这也解释了作者分布的双峰:既然变现只有"被当渠道"一种,多数人投一件就停手(没有第二条路值得深耕),只剩极少数把它当产品线经营的作坊,中间几乎没有腰部。

## 用户体验视角:没人替代应用,人人都在"给那一扇窗装东西"

- **壳件的跨类入侵**:聊天窗内嵌词汇命中 **434/2286(19%)**,且不止 ui(141):usage(62)、session(38)、dev(36)全都想在聊天流里放一个自己的面板/侧栏卡片。成本条、会话时间线、诊断面板——**一切信息都想 become inline UI**。
- **计量透明化成为 UX 元素**:余额显示在输入框下(`dsh-api-balance`)、实时 tok/s 与下一条消息消耗预测(`dsh-cost-crystal`)。"成本即 UX",这在其他插件生态里罕见。
- **审批流出窗外**:IM 推送 × 安全/权限共现 28 次——风险操作推到微信/QQ 远程放行,把确认动作从应用里挪到了聊天软件里。
- **多端同窗**:mobile PWA / 远程网关 70 条、TUI 与 Web 双形态、桌面集成 173 条——同一个会话表面延伸到手机、终端、桌宠上(`openpets` 1081★)。

**判断**:UX 创新模式高度一致——**in-place augmentation(原位增强)**。不做新应用,做旧窗口的新皮肤/新面板/新出口。这解释了为什么分类漏斗的头部是 ui(15.7%):"给窗装东西"是所有方向里复制成本最低、见效最快的一条,自然最先灌满。

## 收束:三个视角其实是同一件事的三个说法

- **技术"桥"** = 为什么这个东西这么便宜、这么容易复制;
- **业务"渠"** = 既然便宜,唯一的稀缺资产就变成"分发位置",于是大厂卡 integration、作坊开聚合仓竞价位;
- **体验"窗"** = 既然拼的是位置,最有位置的活法就是寄生在聊天主窗口里不断做加法。

所以"分布的形状"不是三个独立故事的并排,而是**一个因果链**:低复制成本(桥)→ 竞争转移到渠道占位(渠)→ 定位收敛到主窗口的原位增强(窗)。评估者只要抓住这条链,任何一个新插件都能被归位、也能预判它的天花板。

---

## 给评估者的三行判别清单

1. 看一个新插件,先问它是桥(接能力)、渠(占分发)、还是窗(抢面板)——三者天花板完全不同;
2. 桥类看接入速度但无护城河;渠类(市场/聚合仓/routing)越晚越难进;窗类拼的是持续更新的注意力;
3. 该生态的真实成熟度信号不是 stars 中位数(=2,无判别力),而是 npm 下载 × 是否被外部大项目挂载——**但星/下载只覆盖到 8-19 首录的条目(探针 checkedAt 全为 8-19),8-20 之后入库的 726 条是彻底的观察黑洞;所以"金字塔"结论只对 ≤8-19 的 1502 条成立,对之后的三分之一下不了判断**(详见 data-notes.md §1)。

## 遗留不确定性

- "变现薄弱"是基于免费 npm + 无支付痕迹的**缺失证据推断**,未逐条核查许可协议;
- 聚合型仓库中可能混有同名巧合命名,91 条按 repo 名归类未人工全验;
- 两个专项统计(壳件词汇 434、聚合仓库 51/91)的正则见 question.md 的方法口径,换数据快照后应重跑而非沿用本文数字;壳件命中按 en+zh 描述原文大小写敏感计数;
- 成熟度/沉默度的数据边界与口径陷阱见 [data-notes.md](data-notes.md)。
