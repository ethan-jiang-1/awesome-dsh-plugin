# A01 · 分布的三视角答案:技术上造桥,业务上修渠,体验上装窗

> 数据快照:初问于 `main@5e7dc7eb`(2026-08-27,2286 条);**0001 后按 `main@38976afd`(2026-09-12,3552 条)全量重算**,本文数字除注明"旧"外均为新基线。分类思路与 [`_digested/ecosystem/01`](../../_digested/ecosystem/01-scenario-taxonomy.md) 同口径(23 官方类 → 11 场景带)。方法与正则见 [question.md](question.md);**一图流见 [distribution-map.svg](distribution-map.svg)**。

## 一句话总答案

这是一个**围绕纯文本 agent 驾驶舱的增强层经济**:技术上是"造桥"(把外部能力接进来),业务上是"修渠"(抢分发位置),体验上是"装窗"(在聊天窗口内做加法)。0001 数据让这句话更精确了:**窗(壳)供给最少、转化最好;桥(增强)供给最大、增长最猛;渠(市场)条目最少、单条威力最大**。

## 先看分类:23 官方类 → 11 场景带 → 两大阵营

官方 23 类是收录容器,不是生态结构。按"用户拿它干什么"重聚成 11 个场景带后,生态的真实形状是(全表与解读见 ecosystem/01;**一图流见 [distribution-map.svg](distribution-map.svg)**):

三个读法:

1. **"做壳的" vs "做增强的"规模相当、分工清晰**:壳(界面+外观+娱乐)830 条 vs 增强 2421 条,但壳以 23.4% 的供给拿到 24.5% 的下载,**转化效率全场最高**;供给结构与使用结构错位最大的是多模态外挂(4.4% 供给、3.9% 下载,红利已过峰)。
2. **"渠"是 smallest-but-deadliest 带**:市场·发现仅 126 条(3.5%)却占 12.1% 的下载——`dsh-market` 一个条目 38.4 万月下载,"市场即头部插件"的生态自我强化仍在继续。
3. **wsl 是反面样本**:35 条供给、0.5 万下载,转化 ≈ 0%——环境特定的供给踩进了需求的空档。

## 分布的形状(先看整体,再谈三视角)

在拆三个视角之前,先回答"这 3552 条整体长什么样"——它仍是一个**温和偏斜的漏斗 + 一条极端长尾,几乎没有中间带**,由**极低的复制成本**塑造:

- **分类维度**(基尼 0.43,旧口径 0.40):头部温和。ui 独占 16.7%,Top3 占 37.6%,Top5 占 50.0%,Top10 占 72.7%——**没有哪一类一家独大**;真正的尾巴(占比 <2%)从第 20 类(voice)开始,5 类合计仅 4.4%。
- **作者维度**(基尼 0.31,旧口径 0.29,形态仍是双峰):**76.5% 的作者(1753/2291)只有一件作品**;≥5 条的"职业化作者"68 家,Top50 合计也只占 16.3%。**中间带几乎没有**:要么"投一件就走"的路人,要么几步跨进职业化,很少有"稳定做 3–4 件"的腰部作者。
- **生成机制(三个视角殊途同归)**:外挂桥是"调个 API"、壳件是"加个面板",**单件插件的复制成本极低**。复制便宜 → 30 天堆出 3552 条;便宜 → 76.5% 的人投一件就走(沉没成本小);便宜 → 竞争拼的是"谁先占位"而非"谁写得好",于是星标与交付质量解耦(见业务/体验两视角)。**"分布为什么长这样"的答案,就是"门槛太低"。**

下面三个视角是这个形状的三个切面,每个"判断"都回指这条机制。

## 技术视角:一座"桥"的生态——重心在协议适配,不在算法

- **多模态外挂桥**:主模型是纯文本对话,视觉/语音全靠外挂桥补。图像理解 63、OCR/截屏 77、ASR 31、TTS 41、图像生成 49、视频 80(标签命中,允许多标),合计约 341 次命中都是"贴图→VLM→文字→回填纯文本模型"这一模式的变体——但新队列里 vision 占比 −1.9pp,**第一波补感官红利已吃完**。
- **模型路由/聚合是标准件**:聚合/路由 235 条(旧 138)——OpenRouter / one-api / new-api / LiteLLM 中转几乎是必备件,"换大脑"被视为 harness 应有之义;模型阵营仍是 Claude 117 > OpenAI 91,国产阵容 GLM 35 ≈ Kimi 32 在长。
- **MCP 已成为主要扩展协议**:162 条(旧 109),既把外部 MCP server 注册为原生工具,也反向把 DSH 能力暴露为 MCP 服务。
- **本地推理仍然很小**:剔除『离线』误报后 27 条(0001 复核口径)——真正的本地推理生态只是"小",不是"无"。

**判断**:重活全部外包给云端 API 和本地 CLI,插件本体几乎不含模型、不含训练、甚至少含复杂前端逻辑。生态的技术含量集中在**编排与适配**(谁先把 X 接到 DSH 上)。这正是那个"分布形状"的技术来源:复制成本被压到"调个 API / 挂个中转"的量级,所以漏斗能源源不断灌满、长尾能拉到 3552 条。对评估者的含义:**这里没有护城河技术,有价值的是位置和先发**。

## 业务视角:渠道化与小作坊并存,变现分层清晰

- **生产结构**:2291 个 owner 中 76.5% 只有一件作品;≥5 条的职业化作者 68 家(旧 43 家——**职业化在加速**)。头名 perrylink(37)与 omdsh-dev(37)并列,173787247(31)是 WSL 全家桶单人系列。
- **大厂渠道化**:星标 Top4 全部是外部成熟项目主动挂一条 integration 进来(archify、字节 OpenViking、vectorize-io/hindsight、腾讯 WeKnora,数值见 [ecosystem/03 §3](../../_digested/ecosystem/03-growth-maturity.md))。DSH 被当作值得卡位的分发渠道,这是平台合法性的滞后指标。
- **再包装层翻倍**:聚合型仓库从 51 仓/91 条涨到 **80 仓/161 条**——"商店里的商店"在扩张,但注意 contributing 评审维度 7(0001 新增)已明确**纯聚合包不单独收录**,这一层的入口被政策关小了。
- **用户画像间接可证**:成本监控 317 条(旧 192)且与 DeepSeek 共现最高(97 次),峰谷计价感知插件的存在说明用户对中国区 API 计价高度敏感;**双语齐备结论不变(zh 99.8%、en 100%)**——中文母语作者主导但语言上不排外。变现出现新分层:**注册表自身已接入 AdSense/Giscus(0001)**,而插件作者侧仍以"被当渠道"为唯一被验证的回报。

**判断**:被验证的赚钱方式仍是**把 DSH 当渠道**;小作者的回报主要是星标和简历价值。这解释了作者分布的双峰:既然变现只有"被当渠道"一种,多数人投一件就停手,只剩极少数把它当产品线经营的作坊,中间几乎没有腰部。

## 用户体验视角:没人替代应用,人人都在"给那一扇窗装东西"

- **壳件的跨类入侵(20.7%)**:聊天窗内嵌词汇命中 **736/3552**(旧 434/2286,占比 19%→20.7% 且仍在升),不止 ui(238):usage(88)、session(57)、dev(48)、tools(48)全都想在聊天流里放一个自己的面板/侧栏卡片。**一切信息都想 become inline UI**。
- **计量透明化成为 UX 元素**:余额显示、实时 tok/s、费率切换倒计时——"成本即 UX",由 usage 带 196 条供给支撑,这在其他插件生态里罕见。
- **审批流出窗外**:IM 推送 × 安全/权限共现 33 次(旧 28)——风险操作推到微信/QQ 远程放行,把确认动作从应用里挪到了聊天软件里;但 notify 供给占比已腰斩,**这波 UX 创新过了峰**。
- **多端同窗**:移动/远程 108 条(旧 70)、桌面集成 284 条(旧 173)——同一个会话表面延伸到手机、终端、桌宠上。

**判断**:UX 创新模式高度一致——**in-place augmentation(原位增强)**。不做新应用,做旧窗口的新皮肤/新面板/新出口。这解释了为什么场景带的头部是"界面与外观"(830 条):"给窗装东西"是所有方向里复制成本最低、见效最快的一条,自然最先灌满。

## 收束:三个视角其实是同一件事的三个说法

- **技术"桥"** = 为什么这个东西这么便宜、这么容易复制;
- **业务"渠"** = 既然便宜,唯一的稀缺资产就变成"分发位置",于是大厂卡 integration、作坊开聚合仓竞价位;
- **体验"窗"** = 既然拼的是位置,最有位置的活法就是寄生在聊天主窗口里不断做加法。

所以"分布的形状"不是三个独立故事的并排,而是**一个因果链**:低复制成本(桥)→ 竞争转移到渠道占位(渠)→ 定位收敛到主窗口的原位增强(窗)。评估者只要抓住这条链,任何一个新插件都能被归位、也能预判它的天花板——按新分类说,就是先把它放进 11 个场景带之一,再看它站在壳/增强/渠哪一侧。

## 给评估者的三行判别清单

1. 看一个新插件,先按场景带归位,再问它是桥(接能力)、渠(占分发)、还是窗(抢面板)——三者天花板完全不同;
2. 桥类看接入速度但无护城河;渠类(市场/聚合仓/routing)越晚越难进,且纯聚合包已不被收录;窗类拼的是持续更新的注意力;
3. 成熟度信号:**星标中位数(=2)依旧无判别力**;旧"8-19 后入库即观察黑洞"的问题已被自采管线关闭(stars 覆盖 99.7%),但 **22% 条目未发布到 npm,永远缺下载维度**——用"npm 月下载 × 是否被外部大项目挂载"双指标,并对 22% 的盲区显式声明(详见 [data-notes.md](data-notes.md))。

## 遗留不确定性

- "插件作者变现薄弱"仍是基于免费 npm + 无支付痕迹的**缺失证据推断**;0001 起注册表自身有 AdSense,与作者侧回报是两回事;
- 聚合型仓库(80 仓/161 条)按 repo 名正则归类,可能混有同名巧合,未人工全验;
- 壳件词汇(736)与聚合仓的正则口径见 [question.md](question.md);**换数据快照后应重跑而非沿用本文数字**(壳件按 en+zh 描述原文大小写敏感计数);
- 新鲜数据的口径陷阱(冻结边车 vs 自采、npm 未发布盲区)见 [data-notes.md](data-notes.md)。
