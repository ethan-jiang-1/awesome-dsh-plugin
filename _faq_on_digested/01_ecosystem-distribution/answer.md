# A01 · 分布的三视角答案:技术上造桥,业务上修渠,体验上装窗

> 数据快照 `main@5e7dc7eb`,2026-08-27,2286 条。方法与来源见 [question.md](question.md)。

## 一句话总答案

这是一个**围绕纯文本 agent 驾驶舱的增强层经济**:技术上是"造桥"(把外部能力接进来),业务上是"修渠"(抢分发位置),体验上是"装窗"(在聊天窗口内做加法)。三句话各自的证据:

## 技术视角:一座"桥"的生态——重心在协议适配,不在算法

| 证据 | 数字 | 来源 |
|------|------|------|
| 多模态外挂桥(贴图→VLM→文字→回填纯文本模型) | 图像理解 49 + OCR 57 + ASR/TTS 43 + 生图 32 条 | [02-tech-landscape §1](../../_digested/ecosystem/02-tech-landscape.md) |
| 模型路由/聚合(OpenRouter / one-api / LiteLLM 中转)是标准件 | 138 条 | 同上 §2 |
| MCP 成为主要扩展协议 | 109 条 | 同上 §3 |
| 本地推理插件 | **仅 10 条** | 同上(剔除『离线』误报后) |

**判断**:重活全部外包给云端 API 和本地 CLI,插件本体几乎不含模型、不含训练、甚至少含复杂前端逻辑。生态的技术含量集中在**编排与适配**(谁先把 X 接到 DSH 上),这解释了为什么两周能堆出两千多条——复制成本低。对评估者的含义:**这里没有护城河技术,有价值的是位置和先发**。

## 业务视角:渠道化与小作坊并存,变现证据薄弱

- **生产结构**:1522 个 owner 中 77.6% 只有一件作品;≥5 条的"职业化作者"仅 43 家。头名 `omdsh-dev`(37 条)是典型工作室打法:`dsh-tool-{csv,diff,json,regex…}` 微工具全家桶 + 沙盒系列 + plugin-template 脚手架。[03-growth-maturity §2]
- **大厂渠道化**:stars Top3 全部是外部成熟项目主动挂一条 integration 进来(volcengine/OpenViking 29567★、hindsight 20218★、archify 14283★)——DSH 被当作值得卡位的分发渠道,这是平台合法性的滞后指标。[03 §3]
- **再包装层已经出现**:51 个聚合型仓库(dsh-plugins / dsh-plugin-hub / packs 命名)贡献了 91 条,如 creait-nl/dsh-plugins(8)、wingsky-1/dsh-plugin-hub(7)。"商店里的商店"。
- **用户画像间接可证**:成本监控 192 条且与 DeepSeek 共现最高(67),峰谷计价感知插件的存在说明用户对中国区 API 计价高度敏感;99% 中文描述齐备 → **个人开发者/爱好者主导的中文圈生态**,尚无可见的商业闭环(tools 类几乎全部免费 npm 包,dsh-market 无支付痕迹)。

**判断**:现在赚钱的方式只有一种被验证过——**把 DSH 当渠道**(大厂 integration);小作者的回报还是星标和简历价值。

## 用户体验视角:没人替代应用,人人都在"给那一扇窗装东西"

- **壳件的跨类入侵**:聊天窗内嵌词汇命中 **445/2286(19%)**,且不止 ui(144):usage(63)、session(41)、dev(36)全都想在聊天流里放一个自己的面板/侧栏卡片。成本条、会话时间线、诊断面板——**一切信息都想 become inline UI**。
- **计量透明化成为 UX 元素**:余额显示在输入框下(`dsh-api-balance`)、实时 tok/s 与下一条消息消耗预测(`dsh-cost-crystal`)。"成本即 UX",这在其他插件生态里罕见。
- **审批流出窗外**:IM 推送 × 安全/权限共现 28 次——风险操作推到微信/QQ 远程放行,把确认动作从应用里挪到了聊天软件里。
- **多端同窗**:mobile PWA / 远程网关 70 条、TUI 与 Web 双形态、桌面集成 173 条——同一个会话表面延伸到手机、终端、桌宠上(`openpets` 1081★)。

**判断**:UX 创新模式高度一致——**in-place augmentation(原位增强)**。不做新应用,做旧窗口的新皮肤/新面板/新出口。

## 给评估者的三行判别清单

1. 看一个新插件,先问它是桥(接能力)、渠(占分发)、还是窗(抢面板)——三者天花板完全不同;
2. 桥类看接入速度但无护城河;渠类(市场/聚合仓/routing)越晚越难进;窗类拼的是持续更新的注意力;
3. 该生态的真实成熟度信号不是 stars 中位数(=2,无判别力),而是 npm 下载 × 是否被外部大项目挂载。

## 遗留不确定性

- "变现薄弱"是基于免费 npm + 无支付痕迹的**缺失证据推断**,未逐条核查许可协议;
- 聚合型仓库中可能混有同名巧合命名,91 条按 repo 名归类未人工全验;
- 三个专项统计的正则均写在 question.md,换数据快照后应重跑而非沿用本文数字。
