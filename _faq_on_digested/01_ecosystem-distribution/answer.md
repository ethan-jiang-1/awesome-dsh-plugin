# A01 · 分布的三视角答案:技术上造桥,业务上修渠,体验上装窗

> 数据快照:初问于 `main@5e7dc7eb`(2026-08-27,2286 条);0001 后按 `main@38976afd`(2026-09-12,3552 条)全量重算;**0002 后按 `main@c18ba4a0d`(2026-09-30,4392 条)再重算**,本文数字除注明"旧/0001"外均为 4392 新基线。分类思路与 [`_digested/ecosystem/01`](../../_digested/ecosystem/01-scenario-taxonomy.md) 同口径(23 官方类 → 11 场景带)。方法与正则见 [question.md](question.md);**一图流见 [distribution-map.svg](distribution-map.svg)**。月下载仍是 0001 自采快照 `snap-2026-09-12`(3552 条口径,0002 轮自采未完成),凡引用下载处均已随文标注。

## 一句话总答案

这是一个**围绕纯文本 agent 驾驶舱的增强层经济**:技术上是"造桥"(把外部能力接进来),业务上是"修渠"(抢分发位置),体验上是"装窗"(在聊天窗口内做加法)。0002 数据让这句话更精确了:**桥(增强)供给最大、增长最猛;窗(壳)是转化最稳的一档;渠(市场)条目最少、单条威力最大**。

1. **"做壳的" vs "做增强的":分工清晰但体量悬殊**,壳(界面+外观+娱乐)1047 条对增强 2947 条,而壳以 23.8% 的供给拿到 24.5% 的下载(下载口径 snap-2026-09-12),**在两大阵营里转化效率最高**;曾经错位最大的多模态外挂已经归位(3.9% 供给、3.9% 下载,0002 新队列 vision 仍 −1.5pp,补感官红利过峰)。

## 分布的形状(先看整体,再谈三视角)

在拆三个视角之前,先回答"这 4392 条整体长什么样"——它仍是一个**温和偏斜的漏斗 + 一条极端长尾,几乎没有中间带**,由**极低的复制成本**塑造:

- **分类维度**(基尼 0.422,0001 口径 0.43、旧口径 0.40):头部温和。ui 独占 17.3%,Top3 占 37.6%,Top5 占 50.1%,Top10 占 72.7%——**没有哪一类一家独大**;真正的尾巴(占比 <2%)从第 18 类(market)开始,6 类合计仅 7.1%。
- **作者维度**(基尼 0.324,0001 口径 0.31、旧口径 0.29,形态仍是双峰):**75.5% 的作者(2083/2760)只有一件作品**;≥5 条的"职业化作者"90 家,Top50 合计也只占 15.6%。**中间带几乎没有**:要么"投一件就走"的路人,要么几步跨进职业化,很少有"稳定做 3–4 件"的腰部作者。
- **生成机制(三个视角殊途同归)**:外挂桥是"调个 API"、壳件是"加个面板",**单件插件的复制成本极低**。复制便宜 → 48 天堆出 4392 条;便宜 → 75.5% 的人投一件就走(沉没成本小);便宜 → 竞争拼的是"谁先占位"而非"谁写得好",于是星标与交付质量解耦(见业务/体验两视角)。**"分布为什么长这样"的答案,就是"门槛太低"。**

下面三个视角是这个形状的三个切面,每个"判断"都回指这条机制。

## 技术视角:一座"桥"的生态——重心在协议适配,不在算法

- **多模态外挂桥**:主模型是纯文本对话,视觉/语音全靠外挂桥补。图像理解 70、OCR/截屏理解 96、ASR 语音识别 36、TTS 语音合成 49、图像生成 57、视频 96(标签命中,允许多标),合计约 404 次命中都是"贴图→VLM→文字→回填纯文本模型"这一模式的变体——但新队列里 vision 占比 −1.5pp,**第一波补感官红利已吃完**。
- **模型路由/聚合是标准件**:聚合/路由 296 条(0001 235;旧 138)——OpenRouter / one-api / new-api / LiteLLM 中转几乎是必备件,"换大脑"被视为 harness 应有之义;模型阵营 DeepSeek 224(部分自指)> Claude 135 > OpenAI 107,国产阵容 GLM 42 > Kimi 37 ≈ Gemini 36 ≈ Qwen 30 在长。
- **MCP 已成为主要扩展协议**:189 条(0001 162;旧 109),既把外部 MCP server 注册为原生工具,也反向把 DSH 能力暴露为 MCP 服务。
- **本地推理仍然很小**:标签命中 35 条(0001 复核:剔除『离线』误报后约 27 条;正则收紧前还曾报 44)——真正的本地推理生态只是"小",不是"无"。
- **能力披露(0002 新增)补上了"实际碰了什么"这一维**:静态扫描器读安装产物,覆盖 3844/4392;454 条带 ≥1 条 redLine,其中 **354 条既读凭据/密钥又有网络访问**,20 条在安装时执行代码(postinstall),487 条零能力检出。它与"描述里写了安全"完全正交(描述命中"安全/权限"的 601 条,与实际碰 credentials 的 455 条几乎是两拨人)——**披露不是判决**,但第一次给了供给链攻击面一个量化下界。

**判断**:重活全部外包给云端 API 和本地 CLI,插件本体几乎不含模型、不含训练、甚至少含复杂前端逻辑。生态的技术含量集中在**编排与适配**(谁先把 X 接到 DSH 上)。这正是那个"分布形状"的技术来源:复制成本被压到"调个 API / 挂个中转"的量级,所以漏斗能源源不断灌满、长尾能拉到 4392 条。对评估者的含义:**这里没有护城河技术,有价值的是位置和先发**;0002 的能力披露则说明,"先发"之外还需要一条"这个位置碰了什么"的核对线。

## 业务视角:渠道化与小作坊并存,变现分层清晰

- **生产结构**:2760 个 owner 中 75.5% 只有一件作品;≥5 条的职业化作者 90 家(0001 68;旧 43——**职业化在加速**)。头名 173787247(60,其中 58 条是 WSL 全家桶单人系列),其后 perrylink(43)、omdsh-dev(41)、johnxu22786(36)、goodandready(30)。
- **大厂渠道化**:星标 Top4 全部是外部成熟项目主动挂一条 integration 进来(archify、字节 OpenViking、vectorize-io/hindsight、腾讯 WeKnora,数值见 [ecosystem/03 §3](../../_digested/ecosystem/03-growth-maturity.md))。DSH 被当作值得卡位的分发渠道,这是平台合法性的滞后指标。
- **再包装层翻倍**:聚合型仓库从 51 仓/91 条涨到 **89 仓/172 条**(0001 80/161)——"商店里的商店"在扩张,但注意 contributing 评审维度 7(0001 新增)已明确**纯聚合包不单独收录**,这一层的入口被政策关小了。
- **用户画像间接可证**:用量/成本监控 392 条(0001 317;旧 192)且与 DeepSeek 共现最高(116 次),峰谷计价感知插件的存在说明用户对中国区 API 计价高度敏感;**双语齐备结论不变(zh 100%、en 100%)**——中文母语作者主导但语言上不排外。变现出现新分层:**注册表自身已接入 AdSense/Giscus(0001)**,而插件作者侧仍以"被当渠道"为唯一被验证的回报。

**判断**:被验证的赚钱方式仍是**把 DSH 当渠道**;小作者的回报主要是星标和简历价值。这解释了作者分布的双峰:既然变现只有"被当渠道"一种,多数人投一件就停手,只剩极少数把它当产品线经营的作坊,中间几乎没有腰部。

## 用户体验视角:没人替代应用,人人都在"给那一扇窗装东西"

- **壳件的跨类入侵(21.9%)**:聊天窗内嵌词汇命中 **964/4392**(0001 736/3552 ≈ 20.7%;旧 434/2286 ≈ 19%,占比 19%→20.7%→21.9% 且仍在升),不止 ui(324):usage(111)、session(73)、tools(65)、dev(59)全都想在聊天流里放一个自己的面板/侧栏卡片。**一切信息都想 become inline UI**。
- **计量透明化成为 UX 元素**:余额显示、实时 tok/s、费率切换倒计时——"成本即 UX",由 usage 带 235 条供给支撑,这在其他插件生态里罕见。
- **审批流出窗外**:IM 推送 × 安全/权限共现 46 次(0001 33;旧 28)——风险操作推到微信/QQ 远程放行,把确认动作从应用里挪到了聊天软件里;但 notify 供给占比继续下滑(0002 新队列 −1.0pp),**这波 UX 创新过了峰**。
- **多端同窗**:移动/远程 133 条(0001 108;旧 70)、桌面集成 375 条(0001 284;旧 173)——同一个会话表面延伸到手机、终端、桌宠上。

**判断**:UX 创新模式高度一致——**in-place augmentation(原位增强)**。不做新应用,做旧窗口的新皮肤/新面板/新出口。这解释了为什么场景带的头部是"界面与外观"(1047 条):"给窗装东西"是所有方向里复制成本最低、见效最快的一条,自然最先灌满。

## 收束:三个视角其实是同一件事的三个说法

- **技术"桥"** = 为什么这个东西这么便宜、这么容易复制;
- **业务"渠"** = 既然便宜,唯一的稀缺资产就变成"分发位置",于是大厂卡 integration、作坊开聚合仓竞价位;
- **体验"窗"** = 既然拼的是位置,最有位置的活法就是寄生在聊天主窗口里不断做加法。

所以"分布的形状"不是三个独立故事的并排,而是**一个因果链**:低复制成本(桥)→ 竞争转移到渠道占位(渠)→ 定位收敛到主窗口的原位增强(窗)。评估者只要抓住这条链,任何一个新插件都能被归位、也能预判它的天花板——按新分类说,就是先把它放进 11 个场景带之一,再看它站在壳/增强/渠哪一侧。

## 给评估者的三行判别清单

1. 看一个新插件,先按场景带归位,再问它是桥(接能力)、渠(占分发)、还是窗(抢面板)——三者天花板完全不同;
2. 桥类看接入速度但无护城河;渠类(市场/聚合仓/routing)越晚越难进,且纯聚合包已不被收录;窗类拼的是持续更新的注意力;
3. 成熟度信号(星标已按 0002 重采,下载仍是 `snap-2026-09-12` 口径):**星标中位数(=2)依旧无判别力**(0002:覆盖 4385/4392,≥100★ 164 条);旧"8-19 后入库即观察黑洞"的问题已被自采管线关闭(stars 覆盖 99.8%),但**约 28% 的条目不可归因到 npm 下载**(未发布 772 + 撞名弃用约 222),它们永远缺下载维度——用"npm 月下载 × 是否被外部大项目挂载"双指标,并对这块盲区显式声明;0002 起再加一条**能力披露**线(354 条读凭据且有网络),它和星标、描述都正交(详见 [data-notes.md](data-notes.md))。

## 遗留不确定性

- "插件作者变现薄弱"仍是基于免费 npm + 无支付痕迹的**缺失证据推断**;0001 起注册表自身有 AdSense,与作者侧回报是两回事;
- 聚合型仓库(89 仓/172 条)按 repo 名正则归类,可能混有同名巧合,未人工全验;
- 壳件词汇(964)与聚合仓的正则口径见 [question.md](question.md);**换数据快照后应重跑而非沿用本文数字**(壳件按 en+zh 描述原文大小写敏感计数);
- 月下载等新鲜信号停在 `snap-2026-09-12`(0002 轮下载采集未完成);星标已按 0002 重采(覆盖 99.8%),两者不能拼成同一张快照;
- 能力披露是**静态扫描的披露口径**,不做动态分析、不判断意图,未扫到的 548 条渲染为"未检出"而非"干净"。
